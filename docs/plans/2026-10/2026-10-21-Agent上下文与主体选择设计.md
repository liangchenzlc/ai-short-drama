# Agent 独立上下文与主体选择设计

状态：产品规则已确认，系统正在实施与验证；本专题保留设计基线，实际进展与未完成范围见[实施记录](2026-10-21-AI创作助手实施与验证记录.md)。日期：2026-10-21。

本文配套[系统总览](2026-10-21-AI创作助手系统设计总览.md)、[记忆](2026-10-21-Agent记忆系统设计修订版.md)、[工具](2026-10-21-Agent创作工具系统设计.md)、[执行](2026-10-21-Agent执行中断与修改方向设计.md)及[前端交互](2026-10-21-Agent前端交互设计.md)。本文保留设计阶段的方案与源码快照，后续实现以实施记录和维护文档为准。

## 1. 已确认规则

| 项目 | 规则 |
| --- | --- |
| 会话独立 | 会话属于账号，不绑定当前作品、标准创作阶段或画布页面 |
| 自动正文 | 不自动传入小说、当前剧本、素材、分镜或画布节点正文 |
| 主动选择 | 用户明确选择主体，服务端校验后才读取允许字段及必要媒体 |
| 持续范围 | 选择覆盖本次完整任务，包括补充和改方向；新任务不自动继承，可再次选入 |
| 来源版本 | 保留实际读取快照；主体后来被编辑时提示刷新，不自动替换已经使用的资料 |
| 写入保护 | 执行前校验当前目标与版本，旧参考快照不是覆盖用户新编辑的许可 |
| 三类绑定 | 参考主体、记忆作用域和工具写入目标分别维护，彼此不扩权 |

统一 Agent 不需要理解或接收整部“标准工程上下文／画布工程上下文”。适配器仍需要模式与对象身份来校验工具动作，但这不意味着向模型传入作品全文。

## 2. 实施前能力快照与改造边界

| 实施前源码事实 | 设计影响 |
| --- | --- |
| AssistantConversationCreate 仍要求 project_id | 全局会话需解除项目强绑定，不能仅在前端隐藏作品标题 |
| AssistantSourceContext 区分 project／canvas，include_document 默认 true | 新协议取消自动整篇正文入口；不能只依赖前端每次记得传 false |
| AssistantContextService 已有版本检查、主体快照及真实媒体冻结 | 复用身份、来源及实际存储校验，改为任务级选择范围 |
| checkpoint 保存 context_snapshot，助手输入还带 conversation_context | 将选入快照、对话历史与任务有效状态分开装配，避免正文在历史中重复注入 |
| 当前选择与项目／画布层级关联 | 引用保留真实归属，但会话可独立；具体写入目标另存并冻结 |

## 3. 上下文组成与装配

| 来源 | 进入条件 | 处理 |
| --- | --- | --- |
| 系统职责与工具能力 | 平台固定规则及当前可用能力 | 稳定顺序，按目标裁剪工具，不注入凭据 |
| L3 当前任务 | 当前有效目标、约束、控制状态、输入水位、真实成果 | 每次决策读取，不由历史摘要覆盖 |
| L4 摘要与近期消息 | 当前本人会话 | 来源与版本可追溯，保留未闭合工具协议 |
| 主动选入主体／附件 | 本任务实际选择、允许字段及版本 | 按需读取，使用不可变快照，媒体保存稳定引用 |
| L5 记忆 | 本人用户级、当前会话、明确绑定作品范围 | 有限目录与无 embedding 检索，正文按需读取 |
| Skill | 本任务已激活冻结版本及需要的资料 | 目录、指令、资源逐级加载，不附带额外作品权限 |
| 工具结果 | 本任务实际执行的真实回执 | 默认简短结果与真实引用，大明细按需读取 |

建议顺序为系统规则、能力与记忆目录、当前任务状态、有效摘要、近期消息、当前需要的主体／技能资料及本次输入。工具调用与结果保持供应商要求的配对关系，不能为调整顺序拆开未完成调用。

大正文只注入必要片段，返回读取范围、是否截取及后续读取入口。保留明确约束、当前控制状态、真实操作身份及版本的预算，不因资料较长静默删除这些字段。

## 4. 主体的任务级生命周期

1. 用户通过选择器或提及选择真实素材、分镜、画布节点、图片组／图位或附件，不以显示名称作为稳定身份。
2. 前端等待涉及来源的编辑保存与远端回执；失败或冲突保留输入，不绕过保存继续发送。
3. 服务端校验账号、真实归属、允许字段、来源版本及媒体身份，保存选择记录与不可变快照。
4. 本任务补充和改方向复用有效选择；用户可新增或移除，选择变化记录独立版本。
5. 新任务不自动复制旧选择。界面可提供“再次选入”操作，但必须由用户主动选择。
6. 停止／暂停后明确继续仍属于同一逻辑任务，保留原选择和读取版本，检查当前可用性；不偷偷刷新正文。

建议逻辑记录包括 task_id、selection_id、subject_kind、稳定 subject_key、归属信息、allowed_fields、source_revision、snapshot_id、checksum 和选择状态。数据库 ID／版本对外保持十进制字符串，画布节点键沿用原字符串，不转 Number。

同一任务创建的卡片、节点及图片组可以通过真实回执用于后续步骤，无需每次重新点选。选中一个节点不递归读取邻居正文；图片组的一个图位不自动授权整组全部提示词和其他作品内容。

## 5. 来源变化与刷新

| 变化 | 处理 |
| --- | --- |
| 仅新增无关对象或移动节点位置 | 不自动认定选中正文变化；仍按实际字段和对象版本校验提交 |
| 已选主体正文被编辑 | 原快照保持，界面显示有新版本，用户主动刷新后生成新快照 |
| 刷新时当前工具正在执行 | 新快照作为待处理输入，在工具结束后应用，不修改已冻结参数 |
| 已选主体被删除或权限失效 | 停止新增读取，保留必要来源记录，依赖该主体的新操作返回明确原因 |
| 媒体被替换 | 校验真实 media_id、校验值及图位版本，不沿用过期展示 URL |
| 用户移除主体 | 后续不再按该选择读取正文；不能声称撤回已经发送给供应商的数据 |

发现变化可以只读取版本等必要元数据，不将最新正文自动传给模型。界面提供刷新引用与查看来源入口；未刷新前回答应能说明依据的是旧版本，写入不能跳过版本冲突。

新任务不继承主体读取或写入许可。会话中已经发生的讨论仍是历史，不等于新任务可回查旧主体正文；不能通过会话摘要重新复制整段旧正文绕过选择规则。

## 6. 与工具、记忆和前端协同

| 系统 | 规则 |
| --- | --- |
| 业务适配器 | 为布局、归属和增量保存读取必要结构，不等于向模型开放正文 |
| 媒体生成 | 参考图、音视频和提示词来源同样检查选择与真实身份，不能借连线扩大读取 |
| 长期记忆 | 可保留有来源的设定或用户明确偏好；不自动扫描整个作品建记忆 |
| 压缩 | 保留主体身份、实际读取版本和当前选择状态，大正文留在快照按需回查 |
| 前端 | 输入区显示当前任务主体与写入目标；X Suggestion／Attachments 辅助选择，二者不混为授权 |
| 调用轨迹 | 正文读取、记忆读取及 Skill 资料读取作为真实工具事件投影到 ThoughtChain，正文不作为原始日志广播 |

## 7. 实施与验收

实施建议先统一全局会话／任务／选择契约，再拆分来源冻结与上下文装配，最后接入读取工具、事件及前端选择状态。继续使用 FastAPI、Pydantic、SQLAlchemy、MySQL、MinIO 和现有模型 Gateway，不新增向量模型。

未来验收覆盖：不选择时无自动正文；同任务可延续选择而新任务不继承；版本刷新在工具边界生效；原快照可追溯；移除及权限变化禁止新增读取；图片组、节点及附件身份准确；未闭合工具和关键约束不被压缩丢失。具体参数在实施时按实际模型窗口配置。

方案编写阶段仅检查设计与本地链接；后续实际功能验证及未验证部分见实施记录。
