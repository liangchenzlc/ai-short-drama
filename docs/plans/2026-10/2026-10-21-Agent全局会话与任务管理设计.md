## 1. 已确认的产品规则

| 项目 | 规则 |
| --- | --- |
| 归属 | 按账号的全局会话，独立于标准项目、创作阶段及画布页面 |
| 归档 | 首期无会话归档、取消归档或归档列表 |
| 执行中新消息 | 默认补充当前任务，工具完整结束后统一处理；独立新任务单独发起 |
| 多任务 | 同会话串行，不同会话允许并行，冲突对象写入串行 |
| 后台 | 页面切换、刷新、关闭浏览器不停止服务端任务 |
| 停止后补充 | 消息保留，明确继续才恢复，重新连接不等于继续 |
| 历史修改 | 纯讨论支持编辑和重新回答；涉及已执行工具的历史不改写，通过新消息纠正 |
| 会话分支 | 首期不提供分支会话 |
| 删除执行中会话 | 等当前工具完整结束并停止后删除，已创建作品成果保留 |
| 删除记忆 | 清理本会话摘要和会话级记忆；账号偏好、明确作品记忆独立保留，可选择一并清理 |
| 删除恢复 | 首期无回收站，删除前确认，产品不提供删除后恢复 |

## 2. 现有链路与缺口

| 当前实现 | 新方案影响 |
| --- | --- |
| 助手会话创建要求 project_id，前端也用 accountId + projectId 解析会话 | 改为账号级列表与明确会话选择，不随页面切换创建或替换对话 |

| state、SSE、消息分页与 cursor/resume_cursor 已存在 | 扩展任务、工具、Skill 轨迹与控制状态，保留持久恢复能力 |
| 旧纯聊天及旧创作运行有不同 scope_version 限制 | 分版本迁移，不将历史讨论或旧批准自动转成新写入授权 |

## 3. 会话、任务、消息与执行尝试

| 对象 | 职责 | 关键关系 |
| --- | --- | --- |
| conversation | 私人对话历史、标题及摘要入口 | owner_user_id 为事实源；不强绑作品 |
| task | 一项完整用户目标、主体选择、写入目标、手动 Skill 和控制状态 | 一个会话多个任务，补充归原任务 |
| message | 原始输入／输出、所属任务、来源及应用状态 | 多条消息可共同推进一个任务 |
| attempt／run | 一次可恢复的执行尝试 | 停止后继续可建新 attempt，逻辑 task 保留 |
| step／operation | 工具参数、真实效果、回执与重试身份 | 不因重连或新 attempt 重放已完成工具 |

建议保留 conversation/task/run 三层身份，不直接把每次用户发送等同于独立 Run 任务。接口是否复用现有表由实施时核对，当前不是 DDL。

任务成功结束后的普通新要求可建立下一任务。任务运行期间默认补充；停止／暂停任务的补充仍归被选中的原任务，不自动恢复。用户显式新建任务时分配新身份，输入区展示当前归属，避免将新任务内容误送原任务。

## 4. 排队、并行与继续

同一会话仅有一个实际执行或媒体等待中的任务；已开始的媒体工具等待生成及回填期间继续占用该执行槽。独立新任务持久排队，不因前端断线丢失或重复创建。

停止／失败暂停／预算暂停的任务释放执行槽，其他明确新建任务可继续排队推进；原任务的待用补充留在原任务。明确继续原任务时进入同一会话队列，不抢占当前工具。

不同会话可以并行。服务端对同一冲突对象或媒体槽的写步骤实行串行领取，数据库短事务内核验版本；不因同属一个作品就禁止全部无关操作。媒体源版本和生成意图仍保护迟到结果，自动保存发生冲突时保留草稿，不能强制覆盖。

所有继续、停止及排队操作均需稳定请求身份。恢复读取真实操作账本与最新控制记录，不重发整个自然语言计划。

## 5. 历史消息编辑与重新回答

| 场景 | 产品与技术处理 |
| --- | --- |
| 尚未发送的草稿 | 正常编辑，不影响服务端任务 |
| 没有已执行工具或业务依赖的纯讨论 | 可编辑用户消息或重新回答，保存修订与来源版本 |
| 已执行工具的消息及调用／结果 | 保持原记录，通过新的补充纠正，不回写历史参数 |
| 讨论结论已被后续工具作为依据 | 保留执行依据，用新消息纠正后续方向，不能编辑旧输入造成事实不一致 |
| 重新回答 | 仅生成对应讨论回复，不隐式重新创建卡片、提交媒体或撤销成果 |

纯讨论编辑需要失效受影响摘要及未应用候选抽取，按来源版本重建；不能让旧整理任务覆盖新修订。修订记录用于追溯，不等于首期提供会话分支 UI。

## 6. 删除会话的完整流程

1. 删除前说明不可恢复，并展示会话、活动任务、已有作品保留规则及记忆清理选项，用户确认后使用稳定删除请求 ID。
2. 短事务将会话置为 deleting，阻止新消息、任务领取、明确继续和新增摘要／抽取；同会话尚未开始的排队任务不再启动。
3. 当前工具已开始时，按原参数和许可完成；媒体含生成及回填。界面显示“当前工具完成后停止并删除”，不提前消失或假报已删除。
4. 当前工具结算并停止后，执行幂等删除收尾：会话和消息退出在线读取与检索，清理摘要、会话级记忆、输入选择及会话附件引用。
5. 默认保留已形成的账号偏好和明确作品记忆；勾选一并清理时按来源与当前版本处理，不删除有独立来源或后续用户修订而未经确认的事实。
6. 保留作品表中的卡片、分镜、图片组、节点、连线与媒体。关闭会话订阅，清理本人客户端缓存，可靠投递必要的物理清理任务。

当前工具结果不明时先核实，删除保持待完成状态；不为让会话立即消失而绕过工具边界。无当前工具时可直接进入停止和删除收尾。先锁会话及任务后处理对象的顺序需与执行领取一致，避免删除与新工具启动竞争。

内部可使用删除墓碑和清理任务保证可靠处理，这不提供用户回收站。删除完成后用户不能恢复；物理清理与备份淘汰按部署策略执行，不宣称删除按钮会即时擦除全部备份。

附件只移除会话持有的引用；媒体仍被作品、其他附件或必要任务记录使用时不得物理删除。保存必要的最小执行／计费回执不代表允许再次把已删除对话正文交给模型。

## 7. 界面与交互设计

| 区域 | 推荐实现 |
| --- | --- |
| 会话列表 | 复用 Ant Design X Conversations，提供新建、搜索、重命名、删除；无归档菜单 |
| 会话正文 | Bubble.List 展示消息，每个任务挂载 ThoughtChain 过程与真实结果卡 |
| 当前任务 | 展示当前目标、主体、Skill、待处理补充及运行状态，可明确新建独立任务 |
| 输入区 | Sender 在执行中仍允许输入补充；待停止／已停止有明确说明和继续入口 |
| 错误与预算 | ThoughtChain 显示失败步骤，任务栏展示暂停原因及恢复动作 |
| 删除中 | 保留就地状态与任务详情，不用通用成功提示遮盖未完成删除 |

页面切换只变更展示位置，不改变原任务目标。窄屏折叠会话列表及明细，保留输入、当前步骤和停止／继续动作可达。组件版本与事件协议按[前端方案](2026-10-21-Agent前端交互设计.md)。

## 8. 迁移与验收

新接口不要求 project_id；每任务单独绑定执行目标。旧会话的项目与对象信息保留为历史来源，不伪造为当前任务授权。旧归档标记由兼容迁移映射为历史记录的元数据，不向新界面提供归档／恢复归档能力，也不直接删除旧历史。

实施建议依次完成逻辑身份与服务端状态、全局列表与消息契约、补充／独立任务队列、停止与继续、历史编辑规则、删除收尾与记忆联动，最后接入完整 ThoughtChain 快照及事件。

未来验收至少包括账号隔离；页面切换不换任务；补充不建新任务；停止后补充不恢复；并行冲突受保护；纯讨论重答不重放工具；删除等待当前工具并保留作品；删除来源不被后台重抽取；无归档、回收站及分支入口。当前仅核对文档，不运行功能、浏览器或真实供应商验收。
