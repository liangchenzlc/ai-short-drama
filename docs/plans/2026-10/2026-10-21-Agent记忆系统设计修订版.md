# Agent 无 Embedding 记忆系统设计（修订版）

状态：产品规则已确认，系统正在实施与验证；本专题保留设计基线，实际进展与未完成范围见[实施记录](2026-10-21-AI创作助手实施与验证记录.md)。日期：2026-10-21。

本文记录本轮确认的产品边界与记忆系统修订方案，是当前记忆方案的实施依据。取代[原设计草案](2026-10-21-Agent无Embedding记忆系统设计.md)与[原选型决策](2026-10-21-Agent记忆系统存储分层决策.md)中冲突的规则。原文保留用于追溯讨论，不作为当前行为证明。

本文只写方案，不表示已修改 ORM、创建数据库表、配置全文索引、开放工具或完成运行验收。

## 1. 已确认的边界

| 项目 | 结论 |
| --- | --- |
| 数据库 | 五层记忆使用现有 MySQL，复用运行记录与业务工具的事务基础 |
| 模型与检索 | 不使用 embedding、pgvector 或向量数据库；文本模型负责摘要与记忆整理 |
| 会话归属 | 全局会话独立于项目；采用 MySQL 不改变产品上的全局会话归属 |
| 作品上下文 | 用户主动选择主体后，指定内容才进入上下文；不自动装入小说、编辑剧本或画布节点正文 |
| 主体生命周期 | 选入主体覆盖本次完整任务，包括补充与改方向；新任务不自动继承，已读取快照不自动跟随后续编辑 |
| 跨会话记忆 | 用户偏好跨会话共享；创作设定默认留在当前会话 |
| 作品记忆 | 用户明确指定后才成为作品专属记忆，并按明确绑定的作品范围使用 |
| 工具目标 | 本次任务的写入项目或画布，与参考主体、作品记忆的绑定分别管理 |
| 会话管理 | 取消会话归档；记忆目录调整不引入会话归档功能 |
| 压缩体验 | 后台提前压缩，正常路径无需用户手动整理或新建会话 |

本轮采用 MySQL，替代此前“不使用 MySQL”的选型要求。无 embedding 是本方案约束，不设置“超过 500 条就自动转向向量检索”的规则。

## 2. 技术组成与职责

| 组件 | 职责 | 新增服务或模型 |
| --- | --- | --- |
| MySQL | 保存消息、任务状态、摘要、记忆、来源与处理任务 | 复用现有实例；未来实施新增表和索引 |
| MySQL FULLTEXT + ngram | 中文关键词候选检索，配合别名、标签和精确字段 | 使用 MySQL 内置能力，不新增模型 |
| 现有文本模型与 Gateway | 生成摘要、抽取候选、比较冲突、展开查询词 | 可以复用现有文本模型，也可单独配置整理模型 |
| PydanticAI 与 Pydantic | 记忆工具调用和结构化结果校验 | 沿用现有技术栈 |
| Celery + RabbitMQ | 后台预计算、抽取、重试与调度 | 复用现有基础设施 |
| MinIO | 大型工具明细、附件与媒体内容的持久引用 | 复用现有基础设施 |

无 embedding 不等于没有模型调用。成本来自目录输入、摘要整理、查询词展开和按需读取后的模型调用，必须分别计量。

## 3. 五层记忆

| 层 | 保存内容 | 存储与读取 |
| --- | --- | --- |
| L1 原始记录 | 完整消息、用户选入主体的引用和实际使用版本、工具调用与结果引用 | 沿用消息与执行记录；大明细走 MinIO；按需回查 |
| L2 近期上下文 | 尚未被有效摘要覆盖的完整消息 | 从 L1 查询，不复制成另一份事实源 |
| L3 当前任务状态 | 最新目标、明确约束、已确认决策、待办、工具实际完成情况 | 每次决策读取最新版本；关键状态不依赖自然语言摘要恢复 |
| L4 会话摘要 | 历史区间摘要、阶段结论及来源范围 | 后台生成，按水位线与有效摘要版本切换 |
| L5 长期记忆 | 偏好、纠正、创作设定、决策、参考来源 | 有限目录发现，关键词检索，正文按需读取 |

L1 中工具调用参数、结果身份、版本与执行回执需要可追溯。可以在模型上下文中使用简短投影，但不能仅保存一段无法复核的自然语言执行总结。

L3 区分用户明确表达、用户已确认、模型提议、工具已完成、已取消或被新方向取代。模型提议不能自动升级为用户确认，计划也不能自动升级为执行事实。现有 fixed_requirements 字段需要补齐实际写入、校验与读取链路，字段存在不等于已有记忆能力。

## 4. 作用域与分类

### 4.1 作用域

| scope_type | 可用范围 | 典型内容 |
| --- | --- | --- |
| user | 当前用户所有会话 | 稳定写作偏好、长期交互习惯 |
| conversation | 当前会话 | 本次创作的人物设定、剧情方向、临时约束 |
| project | 用户明确绑定的作品记忆 | 已指定保存到该作品的设定与创作决策 |

每次允许检索的集合为：本人用户级记忆 + 当前会话记忆 + 本次明确绑定的作品记忆。默认不执行跨作品记忆检索。用户明确要求查找历史作品记忆时，另行确定本次允许查询的作品范围。

owner_user_id 由可信 Actor 强制注入。会话、作品及记忆条目的归属均由服务端校验；模型传入的作用域不能增加可见范围。数据库 ID 和版本对外均使用十进制字符串。

作品级记忆绑定不等于作品正文读取授权；工具写入目标也不自动成为参考来源。原文中的“作品静态设定摘要每轮自动加入”删除，仅允许使用明确绑定的作品记忆或用户选入的主体内容。

### 4.2 内容分类

kind 与 scope_type 独立，可使用 preference、correction、setting、decision、reference。某个作品中的纠正默认仍属于该会话或作品，不因为 kind 是 correction 就升级为用户全局规则。

抽取来源限定为对话、用户主动选入的主体和已完成工具回执，不为了构建记忆自动扫描业务作品表。参考来源记忆只保存位置、说明与必要出处，不自动授权沿链接读取内容。

## 5. 上下文装配与目录预算

建议装配顺序为：系统职责与工具边界、版本化记忆目录及少量稳定偏好、当前任务状态与明确绑定信息、有效会话摘要、近期完整消息与选入主体、本次用户输入。工具结果通过相应的消息协议返回，避免重复拼接为互不一致的多份历史。

当前任务状态与最新用户指令优先于历史摘要；摘要内的历史目标不能恢复已取消的计划。记忆正文作为资料使用，不能改变工具权限。

目录至少包含真实 id、scope_type、kind、title 和 content_version，必要时附少量标签。不能只注入 kind + title 再要求模型凭空调用 read_memory(id)。

目录使用 token 预算，不把 150 行直接等同于固定 token 数。按用户置顶、当前任务主题和稳定排序选取；未进入本轮目录的有效记忆仍可通过检索或分页发现。

提示词缓存只作为供应商支持时的优化。系统职责和目录使用稳定顺序与版本；hit_count、last_used_at 不直接触发每轮目录重排。修正、遗忘和显式记忆立即生效，不能为了缓存延迟。内容变化不应被笼统描述成所有前缀缓存全部失效。

整体输入预算需要预留输出、工具结果和安全余量。优先压缩历史解释、冗余资料和模型提议，不静默截断已确认约束、未完成工具调用或关键执行身份。

## 6. 无 Embedding 召回

### 6.1 读取流程

1. 服务端计算本次可见的用户、会话和作品记忆范围。
2. 生成预算内、带版本的目录，让模型知道有哪些记忆主题。
3. 模型根据目录选取条目；目录不足时搜索关键词、别名、标签或分页浏览主题。
4. 批量读取条目正文，返回内容版本、作用域和来源。
5. 记录读取统计；模型利用实际读取结果回答，未命中时继续查找或说明不足。

检索先使用规范化记忆键、标签、别名和精确字段，再使用 MySQL FULLTEXT + ngram 生成文本候选。中文短词、单字及专有名词需要精确匹配或受限字符串查询兜底。全文索引的 token 大小和停用词影响召回，实施时应以实际实例配置和中文样本验收，不能将默认分词器视为完整中文检索方案。

文本模型可将用户措辞展开为有限查询词，并比较少量候选是否相关。这不使用 embedding，但也不能承诺与语义向量检索具有相同召回表现。

### 6.2 只读工具

| 工具 | 功能 | 服务端边界 |
| --- | --- | --- |
| list_memory_catalog | 按分类和主题分页发现记忆 | 仅本次允许范围；返回目录与游标 |
| search_memory | 按关键词、别名、标签和正文寻找候选 | 强制 owner 与 scope 过滤，限制结果和 token |
| read_memory | 批量读取指定条目 | 再次校验归属、状态和内容版本 |
| read_conversation_history | 回查摘要对应的原始消息区间 | 仅已授权会话；保持调用／结果配对，历史主体正文仍检查本任务选择范围 |

记忆读取工具与作品正文读取工具分开授权。工具读上限由调用次数、返回 token 和整体 run 预算共同控制，不把“最多 5 条”当成所有任务的充分条件；超限明确返回原因和分页信息。

新任务不能通过历史回查、旧工具结果或摘要自动重新取得未选入主体的整段正文。对话中用户明确表达的结论仍可作为历史；外部主体的大正文保留来源引用，回查时按当前任务的主体选择返回获准片段或有界说明，不拆散工具调用／结果协议。长期记忆保存有来源的事实，不用复制全文绕过选择边界。

现有助手为纯聊天，多处强制 tools 为空且禁止工具回传。实施时必须同步调整工具注册、模型调用预算、deferred 结果回传、运行状态校验与恢复路径。不能只在 tools.py 增加分支就宣称可用。单段模型请求与 run 总决策预算分开管理，必须允许“调用记忆工具后继续回答”的完整链路。

## 7. 逻辑数据模型

以下是实施前的逻辑设计，不是已执行 DDL。具体字段、索引、外键及迁移脚本需结合实施时 ORM 和当前数据库核对。

| 对象 | 建议调整 | 主要责任 |
| --- | --- | --- |
| agent_conversations | 增加 summary_covers_until_seq、active_summary_id、摘要代次；协调全局会话归属改造 | 指向当前有效摘要与唯一压缩分界 |
| agent_conversation_summaries | 新表；区间、基础摘要版本、来源版本或摘要、结构化内容、token、模型、状态、时间 | 保存不可变摘要候选及来源，区分 ready 与实际已启用 |
| agent_memory_items | 新表；owner、scope、kind、稳定 memory_key、标题、别名、标签、正文、来源、内容版本、状态 | 当前记忆事实源 |
| agent_memory_revisions | 新表；条目、版本、变更来源、原内容或必要变更明细、时间 | 追溯编辑、纠正、合并和显式恢复 |
| agent_memory_forget_rules | 新表；owner、scope、memory_key、来源范围、遗忘版本、恢复条件 | 阻止旧来源重新生成已遗忘事实 |
| agent_memory_jobs | 新表或经核实可复用的可靠任务记录；任务类型、幂等键、来源区间、版本、租约、状态、重试 | 可靠投递摘要与抽取任务 |

scope 可采用 scope_type + 非空 scope_key，辅以可空 conversation_id / project_id；一致性检查确保 user、conversation、project 三类字段组合正确。不能让全局偏好仍被一个必填 project_id 限制。

记忆条目使用稳定身份与递增内容版本，变更同时追加版本记录。superseded 只表示确实被其他记忆替代，forgotten 表示停止自动使用；目录未选中不改变条目事实状态。读取统计与事实内容版本分别管理。

全局会话仍需要与[会话方案](2026-10-21-Agent全局会话与任务管理设计.md)及[工具方案](2026-10-21-Agent创作工具系统设计.md)协同解除旧的项目强绑定，单次任务／工具冻结具体执行目标。采用同一 MySQL 并不意味着现有项目会话模型无需修改。

## 8. 写入、冲突与来源

### 8.1 显式通道

用户说“记住”“修改这条设定”“忘掉”或通过记忆界面操作时，立即完成持久化并更新目录版本，不等待低频后台整理。写入范围按用户表达和已确认绑定判定，不能把单次要求默认升级成全局偏好。

### 8.2 自动整理通道

run 终态与抽取投递意图可靠关联，后台处理新增消息：

1. 按来源位置和处理版本获取增量，建立幂等任务。
2. 文本模型抽取候选，Pydantic 校验内容、分类、作用域及来源。
3. 检查遗忘规则，区分用户事实、模型提议和实际执行结果。
4. 通过 scope + kind + memory_key 和文本检索获取少量冲突候选。
5. 判断新增、重复、补充、纠正或需要用户澄清。
6. 短事务检查当前条目版本与来源顺序，写入条目和版本记录。

任务完成先后不能决定事实的新旧。迟到的抽取任务不能覆盖用户刚完成的编辑、纠正或遗忘。取消或失败 run 中的用户明确表达可以保留，未执行计划和未完成提议不能记为已完成。

### 8.3 冲突规则

同一 scope 内的规范化 memory_key 是候选定位依据，标题相似不是直接替换条件。用户明确纠正优先，模型推断不能覆盖用户明确设定；无法消解时保留来源并请求澄清，不自动跨作用域合并。

## 9. 无感压缩状态机

### 9.1 分界与版本

summary_covers_until_seq 为 L2 / L4 的唯一分界，active_summary_id 指向覆盖该前缀的有效摘要状态。单条 ready 摘要不等于已经激活。摘要激活与水位线推进必须在同一事务内完成。

### 9.2 后台生成与启用

1. 预算接近软阈值时提前投递任务，不等原文已经超过模型窗口才开始。
2. 固定来源区间、基础水位线、基础摘要版本和来源内容版本。只压缩闭合消息区间，保留近期消息及未完成工具调用。
3. 在事务外调用文本模型，生成结构化摘要并校验。
4. 短事务比较基础版本与区间内容；一致时同时启用摘要并推进水位线。
5. 普通新消息追加在 to_seq 之后，不使旧区间摘要失效；新消息继续留在 L2。
6. 区间内消息被修改或删除、基础摘要被其他任务替换、来源版本不符时，候选才置 stale 并重新计算。

两个并发任务使用比较并交换式检查，只允许基于当前版本的候选推进；另一个候选不能回退水位线或重复覆盖已处理区间。模型调用期间不持有长期数据库事务或作用域锁。

### 9.3 分层摘要与方向变更

保留区间摘要供追溯，并维护有预算上限的阶段摘要。阶段摘要由前一有效摘要与新的闭合区间合成，保留来源范围，避免每轮载入无限多段摘要。

摘要至少覆盖目标与约束、已确认决策、实际完成结果、未完成事项、重要实体及出处。当前执行身份、幂等键、版本与取消状态放在 L3 / 执行记录中，不靠摘要自由改写。

用户中断或改变方向时先在 L3 持久记录待生效请求，并阻止后续工具启动，保留当前有效目标、工具参数和完成许可；已开始工具结束后才应用停止或切换计划版本，媒体工具包含生成及结果回填。请求已收到不等于已停止或已改向，摘要须保留此区别。历史摘要可以保留旧目标的来历，但不能恢复旧计划后续执行权。具体见[执行与中断方案](2026-10-21-Agent执行中断与修改方向设计.md)。已确认关键事实用结构化状态保护，减少反复摘要造成的漂移。

执行中普通新消息默认补充当前任务，独立新任务单独发起。L3 保存待处理消息及已应用水位；当前工具结束后先核对停止状态，可继续时才统一处理补充。普通补充不撤回停止，明确继续才恢复；最新明确修正优先，兼容约束累积保留。摘要不能将“补充已收到”写成“当前工具已按补充要求执行”，不能因追加消息丢弃待处理输入或自动解除停止。长期记忆仍按来源与作用域整理，不把每条任务补充自动升级为全局偏好。

## 10. 遗忘与删除

遗忘记忆时立即将条目退出自动使用、失效相应目录缓存，并创建作用域与事实身份相关的遗忘规则。仅对正文做一个哈希不足以拦截同义改写，需结合 memory_key、原来源范围和条目版本检查后台候选。

旧任务写入前必须再次检查最新遗忘版本。命中规则的旧来源不重新抽取该事实；恢复需用户明确重新记住或解除规则。合并与派生记忆保留来源，不能通过换标题绕过遗忘。

受影响的活动摘要和任务资料应按来源标记重建或停止自动注入，不能只从目录隐藏条目却继续在摘要中自动使用。

“忘掉记忆”与“删除原始消息”是两个动作。遗忘不表示原消息已经物理擦除。已确认删除会话时清理本会话摘要与会话级记忆；已形成的账号偏好和明确保存的作品记忆独立保留，并提供一并清理选项。作品卡片、节点、图片组及其他业务成果不随会话删除。

删除开始后阻止新输入、任务领取和该会话的后台摘要／抽取；等当前工具结束并停止后完成删除。删除墓碑、来源处理版本与清理任务可靠关联，旧摘要、迟到抽取和重放事件不能重新产生已清理记忆。恢复器不得因为原始来源暂时仍在内部执行记录中就将其重新注入。

选择一并清理时先展示相关账号／作品记忆，并校验版本和其他来源；保留用户后来编辑或有独立来源支持的事实，冲突项由用户选择，不简单按来源会话 ID 级联删除全部账号事实。被清理条目仍使用遗忘规则阻止旧来源重抽取。

首期无会话回收站，删除前确认，产品不提供恢复。删除完成即停止在线读取、检索及上下文使用；物理清理按可靠任务执行。备份遵守部署保留周期，必要的最小操作回执不继续用于创作上下文，不能将页面不可见描述为备份已同步物理擦除。具体流程见[会话管理方案](2026-10-21-Agent全局会话与任务管理设计.md)。

## 11. 配额、缓存与降级

| 项目 | 规则 |
| --- | --- |
| 目录大小 | 以 token 预算为准；置顶、主题选择和分页共同控制 |
| 有效记忆数量 | 超出目录容量仍可检索；不按固定条数自动失效或触发向量化 |
| 正文读取 | 批量读取，限制单次结果与 run 总 token；返回截取信息和继续读取入口 |
| 任务状态 | 保留明确约束、执行身份和待处理动作；压缩冗余解释与模型提议 |
| 摘要大小 | 区间与阶段摘要各有预算，后者合并治理，避免无限增长 |
| 缓存隔离 | 键包含 owner、允许的 scopes 及内容版本；跨用户不共用私人目录 |
| 读取统计 | 不改变事实版本，不因每次命中重排整个提示词前缀 |

| 故障 | 处理 |
| --- | --- |
| 摘要失败 | 水位线不推进，保留有效摘要与来源；后台有界重试 |
| 原文接近硬预算且摘要未就绪 | 受控等待、重试或明确反馈，保留输入；不静默丢消息 |
| 记忆目录或全文检索失败 | 用仍可用的任务状态、摘要和近期消息继续；必要时说明缺少历史资料 |
| read_memory 失败 | 工具返回明确失败；不能把未读取内容说成已知事实 |
| 抽取任务重复、乱序或恢复 | 幂等键、来源位置和版本校验，已成功部分不重复写入 |
| MySQL 整体不可用 | 按既有持久化错误流程处理，保留草稿与原请求；不能承诺消息已正常保存 |

普通后台压缩保持安静；用户可在详情查看记忆来源、作用域、摘要覆盖区间及处理状态。异常反馈沿用现有 StudioFeedback / useStudioMessage，不在编辑器正文中追加进度块。

用户可见的记忆工具调用通过统一事件进入 Ant Design X ThoughtChain。后台提前压缩不为每条整理任务新增对话条目，仅在详情展示摘要覆盖范围和必要异常；工具正文、记忆私有内容不直接广播成轨迹日志。组件与状态投影见[前端交互方案](2026-10-21-Agent前端交互设计.md)。

## 12. 实施顺序

1. 完成全局会话、任务目标与记忆作用域的契约设计，核对现有 project_id、可信 Actor 与权限约束。
2. 打通 L3 的来源、版本、明确约束与执行状态，使中断和改方向可正确延续。
3. 实现 L4 的可靠后台任务、来源快照、摘要校验、水位线激活及硬预算兜底。
4. 建立 L5 的条目、版本、作用域、关键词索引、遗忘规则和显式管理接口。
5. 开放只读记忆工具与必要的后续模型决策；保持作品操作独立授权。
6. 接入后台增量抽取、冲突处理和中文关键词召回，再接前端记忆查看、编辑、来源与遗忘。
7. 验证正确性、召回质量、延迟和费用，调整目录与预计算阈值。

实施表结构变化时再遵循 ORM、真实库 DDL、完整 SQL 与旧库迁移的项目约定。当前文档任务不执行 DDL，也不表示上述能力已经上线。

## 13. 验收与观测

关键用例至少包括：

- 用户偏好可跨会话使用，创作设定默认隔离，未绑定作品记忆不可读取。
- 切换写入目标不自动加入作品正文或其他作品记忆。
- 目录不包含条目时仍可分页或检索；中文别名、专有名词和短查询可验证。
- 摘要期间持续追加消息，旧闭合区间摘要仍可激活，后续消息不丢失。
- 并发摘要、失败重试和来源修订不会推进错误水位线或重复覆盖。
- 中断和改向请求先记录为待生效；当前工具结束后控制才生效，历史摘要不能提前撤销当前工具或恢复旧计划后续执行。
- 纠正后旧抽取任务迟到，不覆盖新版本；遗忘后同一旧来源不重新产生记忆。
- 工具调用与结果保持配对；读取记忆后可以继续回答，超限和失败有明确结果。
- 大型工具结果仅按需读取，不挤掉明确约束；硬预算兜底保留输入与来源。
- 缓存按用户和作用域隔离；目录未选中、条目被替代和用户遗忘语义可区分。

观测项包括目录与正文 token、检索未命中率、用户纠正次数、记忆工具调用轮次、后台整理费用、压缩延迟、硬预算兜底次数、来源缺口及重复抽取。测试替身、静态检查和真实模型验收分别报告。
