## 值得保留的设计

1. 保留冷黑主题、现有语义色、13px 消息正文与紧凑排版。桌面 380px 默认侧栏、320–560px 调宽和窄屏抽屉符合工具使用场景。
2. 保留贴底输入、Enter 发送、Shift + Enter 换行、中文输入法保护，以及引用选择后回到输入框的流程。
3. 保留“文字回复、折叠过程、独立成果”的层级。成功过程自动折叠能减少噪声，不应全部常驻展开。
4. 保留发送成功后素材条清空、素材属于对应消息的设计。不恢复任务级素材草稿或引用管理面板。
5. 保留停止后续聊、保存屏障、版本冲突保护、原请求核对与幂等重试。视觉简化不能删掉这些约束。
6. 保留聊天问题与文档保存状态的隔离、就近恢复入口、窄屏焦点约束，以及尊重减少动效偏好的行为。

桌面 1440×1000、窄屏 390×844 / 390×480 的空会话布局可用；未发现需要整体换版的证据。

## 应修复的 5 项

项目分级均为 🟡 应当修复；P1 表示优先处理，P2 表示下一轮处理。本次没有判定全功能阻塞的 P0。

### 1. [P1] 多素材让发送区超出窄屏

**位置**：[ai-assistant.css](../../../frontend/src/features/ai-assistant/ai-assistant.css) 第 387–397 行；[AgentContextComposer.tsx](../../../frontend/src/features/agents/AgentContextComposer.tsx)；宿主侧栏的裁剪容器。

**证据与影响**：素材条使用 `max-height: none; overflow: visible`。模拟 16 个合法待发送文本附件，长文件名在窄屏逐行排列。390×844 下，消息区只剩 28px；发送按钮底部为 864px，超出视口。390×480 下，发送按钮完全不可见。移除按钮也被 30px 高药丸裁剪；实测按钮宽 20px、高 44px，实际命中区域受父级限制。

**最小方案**：

- 素材区采用有限高度、内部纵向滚动；普通高度先按约 2–3 行控制，低高度再受可用视口高度限制。
- 保证正文输入和发送工具栏始终可达；素材数量不能挤占整个对话区。
- 窄屏单独调整素材行与移除按钮的尺寸，让完整点击区域可见。保留桌面紧凑样式，不把所有工作台控件一起放大。
- 继续展示数量与完整名称的可访问说明，不新增素材抽屉，不通过降低现有素材上限掩盖布局问题。

**验收**：390×844、390×480，1 / 8 / 16 个长名称素材时均能看到输入、发送；能滚动访问并移除最后一项；Tab 可到达移除和发送；打开软键盘后的真实设备场景另验。

### 2. [P1] 模型下拉选择与实际执行模型不一致

**位置**：[AssistantConversationBody.tsx](../../../frontend/src/features/ai-assistant/AssistantConversationBody.tsx) 第 153、282 行；[AgentRun DTO](../../../frontend/src/api/types/agents.ts) 的 `model_config_id`、`model_name`。

**证据与影响**：未结束任务仍可切换输入区模型，但续聊请求只传 `task_id`，没有提交新选择的 `model_config_id`。本地复现为：任务使用模型 A，停止后选择模型 B，再发送要求；请求仍为 `{"content":"使用新模型继续完善人物动机","task_id":"501"}`，随后恢复原任务。界面让用户以为模型已切换。

**最小方案**：

- 延续“任务内模型冻结”的语义。存在未结束任务时，模型位置显示实际任务使用的模型，取消可编辑下拉行为。
- 优先读取与该任务关联的运行记录中的模型名称；不能拿其他任务的最新运行模型或本机草稿选择冒充当前模型。暂时没有对应数据时显示“沿用当前任务模型”。
- 提供可被键盘和触控访问的简短说明：“当前任务沿用此模型，任务结束后可切换。”新任务仍保留原有模型选择能力。
- 不自动新建会话，不迁移任务，不为了切换模型改变停止后的续聊行为。

**验收**：运行中、停止后、恢复页面后均显示真实模型；不能出现“界面为 B、请求继续 A”的状态；任务完成后的下一条新任务能够选择并提交 B。

### 3. [P2] `@` 关键词没有过滤宿主传入的对象

**位置**：[AssistantMentionTextarea.tsx](../../../frontend/src/features/ai-assistant/AssistantMentionTextarea.tsx) 第 37–38、54–59 行；[画布项目页](../../../frontend/canvas/src/pages/canvas/project.tsx) 第 874 行附近。

**证据与影响**：附件会按 query 过滤，服务端资产查询也传了 query，但宿主 `references` 只参与合并去重，没有按关键词过滤。将资产查询结果设为空后，输入 `@没有匹配对象的名字`，列表仍显示“角色 · 林晚”。画布宿主传入整张画布的节点，因此这个问题会随节点数量扩大。

**最小方案**：对宿主候选名称做同样的大小写归一化匹配，再与服务端结果去重。空关键词保留现有候选，不增加拼音搜索、向量检索或新的搜索服务。无匹配时复用现有空状态。

**验收**：不匹配的当前对象和画布节点不再出现；同名项按现有身份键去重；中文名称、英文大小写、空关键词、方向键和 Enter 选择均保持可用。画布大节点量场景需补浏览器验证。

### 4. [P2] 失败步骤自动折叠，且不同失败原因被合并丢失

**位置**：[ThinkBlock.tsx](../../../frontend/src/features/ai-assistant/ThinkBlock.tsx) 第 24–33、46–48 行。

**证据与影响**：步骤一旦不再运行就自动折叠，包括失败。组头只显示“2 步未完成”；展开后，同 label、同 outcome 的两步合并成 `×2`，只保留第一条 operation 的错误。用“镜头 1 超时”和“镜头 2 内容校验失败”复现，第二种失败原因即使展开也不可见，用户无法判断应重试还是修改描述。

**最小方案**：

- 成功组继续自动折叠。失败组默认展示简短失败摘要或保持失败行可见，用户仍可主动收起。
- 只合并用户可见结果相同的步骤；错误 code 或可见错误摘要不同的失败不能合成一条。无需增加错误详情页面。
- 不在纯展示问题上新增“一键重试”写操作；继续通过已有发送、恢复和成果入口处理。

**验收**：两种失败均能被发现，且分别保留可行动的原因；成功步骤仍紧凑；用户手动收起后不会因普通重渲染反复展开；后续重试成功后的状态准确。

### 5. [P2] 进行中的成果卡使用成功对勾

**位置**：[AgentArtifactCard.tsx](../../../frontend/src/features/ai-assistant/AgentArtifactCard.tsx) 第 16–20 行。

**证据与影响**：图标只有“失败”与“其他”两个分支，`waiting_media` 的卡片实际同时显示成功对勾与“生成中”。本地浏览器确认其 `data-state="running"`，图标却为 `lucide-check`。这会削弱用户对“已经完成还是仍在等待”的判断。

**最小方案**：从现有状态派生图标：运行/等待/核实使用现有加载或等待图标，成功才使用对勾，失败/冲突继续使用警示图标。保留明确状态文字，减少动效偏好下保留静态图标和文字。不引入新的进度系统。

**验收**：`running / waiting_media / reconciling / succeeded / failed / conflict` 的图标与文字一致；等待状态不会提前表现为成功；不依赖颜色或旋转动效单独传递状态。

## 可选优化：有需求再做

### A. [P3 / 🟢] 成果卡把技术版本移到按需详情

**位置**：[AssistantOperationResults.tsx](../../../frontend/src/features/ai-assistant/AssistantOperationResults.tsx) 第 82–87 行。

当前保存版本、参数版本、主图版本、音色版本等会逐行常驻。在成果较多时，这些次级信息与“成果是什么、是否成功、去哪里查看”竞争空间。可让默认卡片优先呈现名称、用户状态、数量和查看入口，将技术版本统一放进一个轻量详情折叠区。

保留冲突、来源不可用、部分失败、已撤销等关键状态，以及撤销确认所需信息和全部数据。先看真实长对话是否存在明显干扰，再决定是否实施；不为每张卡新增菜单和独立弹窗。

### B. [P3 / 🟢] 待发送素材复用已有缩略图

**位置**：[AssistantConversationBody.tsx](../../../frontend/src/features/ai-assistant/AssistantConversationBody.tsx) 第 360 行，以及引用候选到素材条的本地数据传递。

当前结构化素材统一传入 `thumbnail: null`；引用候选中已有的图片选中后会退化为文件图标。若实际使用中有多个相似角色或镜头，可仅在已有图片 URL 的路径保留 22px 缩略图，帮助识别。

没有 URL 的条目继续用现有图标。不为了补图新增后端字段、批量请求、预览弹层或大图；也不把此项扩展为恢复任务级素材持久化。历史消息素材的预览能力另有产品约束，本项不扩大到历史消息。

## 实施顺序与边界

1. 先处理第 1、2 项：分别解决发送可达性与模型语义，改动彼此独立。
2. 再处理第 3–5 项：复用现有搜索、折叠和状态组件。
3. 可选项根据真实长对话和素材使用情况决定，不作为本轮完成前提。

对应设计动作依次为 `$impeccable adapt`（输入可达性）、`$impeccable clarify`（模型与失败说明）、`$impeccable harden`（候选与状态）、可选的 `$impeccable distill`（次级信息）。完成所选修复后只做一轮 `$impeccable polish`，不借机扩成改版。

实施时补针对用户可见结果的浏览器回归：16 素材仍能发送、模型显示与请求一致、无匹配候选、两种失败均可见、等待卡无成功标记。既有 E2E 有部分旧轨迹和旧消息按钮断言，需要随被修改的场景核对；不以测试名称推断当前功能，也不一次重写全部 E2E。

明确不建议：更换主题/字体、加装饰插画或渐变、恢复任务/记忆/上下文管理入口、恢复已取消的用户消息编辑与重新回答入口、把所有过程展开、全局加大字号/按钮、引入新的组件库或状态管理库、在没有性能证据时增加虚拟列表和缓存层。

本轮没有位图创作需求，`imagegen` 不产生新增图片素材；界面问题由现有组件和 CSS 即可解决。
