## 实施范围与真实边界

新增 `backend/tests/integration/test_project_assistant_agnes_lifecycle_broker_live.py`，
测试观测启动器 `assistant_broker_worker.py` 增加显式生命周期模式。
默认模式仍走既有正常观测网关；生命周期模式使用已经验证过的真实响应观测，
完整 raw 持久化后或真实200响应头后暂停，实际 HTTP/SSE 继续委托原模型网关。
Worker 的正常 task、Runtime、Scheduler、Publisher、Recovery 均使用生产实现。
本片没有新增生产代码、API 字段、DDL、依赖、前端驱动或源适配账本变化。

原八角色启动器保持冻结；API 使用正常 lifespan，独立 Scheduler 负责原消息和
到期恢复消息的发布。节点号980–987互不相同，fixture为1022；随机MySQL测试库、
随机MinIO三桶、随机RabbitMQ namespace，SMTP显式为空。原用户服务继续运行。
本片显式配置150秒租约，生产默认180秒保持；恢复实际等待租约自然到期，
测试监督线程只读数据库、结束自己创建的Agent进程并重新启动同版消费者。

Broker 回执观测保存每个真实执行进程与直接父进程。首次进程丢失的未完成动作
保留 `completed=false / worker_lost=true`，不会伪造SUCCESS；新消费者接到原
AMQP消息时另记一条 `redelivered=true` 的记录，携带同一 Celery task ID、run ID
和版本。到期后的回执重放使用 Scheduler 新发布的版本，终态另外发送原版本及
过期版本两条围栏探针。只有正式动作、私人权限、作品及全部后置通过才写成功
`acceptance.json`。

## 三种模式的后置合同

`stop-after-response`：真实完整回执持久化后关闭旧窗口，仅cookies恢复运行状态，
从原UI点击停止，再释放迟到回执；cancelled、原turn留raw并未应用，对话没有
助手消息，原作品不变，供应商一次。

`recover-after-response`：完整raw后中止自建Worker，同一消息由RabbitMQ重新
投递至新Worker；有效租约挡住重复执行。原Scheduler等待自然租约到期并发布
新版本，原Gateway离线重放完整raw，成功回复进入同一私人会话，原请求/raw
摘要保持，供应商一次、离线重放一次。

`interrupt-after-headers`：只收到真实200/SSE响应头即中止自建Worker，完整raw
尚未取得。重新投递先被租约挡住，原Recovery到期将turn标为unknown、run为
failed，原UI显示固定未知受理提示；没有助手delta、附件、工具或成品，没有
重放、额外POST或自动重新生成。这个模式只证明真实响应头和未知处理，不能
算一份完整模型响应。

所有组合都需原UI首次running恢复、受理后的仅cookies恢复、终态fresh恢复，
同一run/conversation、一次用户消息；原项目作品和版本保持，成员共享作品
可读，但私人会话、消息、状态、事件、run和模型对成员/外人均404。服务器
保存模型快照、来源、请求和响应，生产Worker节点号从真实turn ID核对。
全部文本报告、快照、请求/响应和日志检查不含明文供应商凭据。

```powershell
uv run python scripts/run_integration.py `
  tests/integration/test_project_assistant_agnes_lifecycle_broker_live.py -q `
  --tb=short --assert=plain -p no:cacheprovider `
  --basetemp=.runtime/assistant-lifecycle-broker-new-temp
```
