# 画布历史与本人草稿导出审计

日期：2026-10-10。固定源为 `4ca2a65a7780a8dfcaaa86c33679f84fb04e055c`；本片仅增加验证与维护记录，业务代码、源 CSS、标准模式及未批准的绘图候选没有修改。

## 本片实际范围

新增 `backend/tests/integration/test_canvas_history_export_browser.py` 和 `frontend/canvas/scripts/verify-history-export-python.mjs`。六场分别为本人云版本、本人草稿、共享成员云版本，各在 1440/390 宽度执行。使用独占随机 MySQL、随机 MinIO 桶、真实账号/API/Chrome，以及 FFmpeg 生成的可播放视频和音频。

旧版本包含图片、视频、音频节点和连接，还有仅时间线引用的视频与音频；当前图另用绿色图片。本人的旧私人提示词与成员投影分别核验。测试将旧版时间回拨六分钟以跨过历史保存间隔；本人草稿通过实际 `preserveCanvasSyncDraft` 函数准备，然后由原版本记录 UI 下载。这不代表已验原 UI 编辑产生独立草稿的全过程。

原面板的版本读取中禁止导出空项目；草稿页签实际执行 End/Home/ArrowRight。窄屏等待源抽屉动效结束，原关闭按钮返回当前图；桌面使用原“返回当前画布”。导出不提交图、不恢复旧作品、不修改私人历史快照或写回执。

首次导出让两个尚未缓存、仅时间线引用的完整媒体 GET 各受控返回 503。核验两项稳定资源 ID 均出现在错误内容中，未下载不完整 ZIP；随后原下载按钮显式重试，每项仅再读一次。最终 ZIP 只含所选项目及五份原媒体，逐字节比较项目 JSON、存储键、类型、尺寸和原文件，不混当前图图片、签名 URL 或 Blob URL。

云版本关闭旧 context 后，只恢复 cookies 的新 context 仍读同一历史。草稿测试离开页面后切成员账号，以避免刻意退出期间的背景请求竞争；源本地模式显示成员当前项目的默认草稿，但不显示主人旧版草稿，主人的独立草稿仍保留。Python 后置核验数据库版本、旧快照和私人快照不变、回执/历史数量不变、MinIO 原字节和 SHA-256，以及本人/成员可读、外人 404。

## 固定源可见反馈缺口

固定源与目标 `canvas-version-history.css` 都将 `.ant-message`、`.ant-notification` 设置为 `display: none !important`。历史导出通过 `message.error()` 报告失败，因此错误内容存在于 DOM，但用户看不到 Toast。六场明确记录 `error_feedback_visible=false`，不能描述为可见错误提示通过。源行为保持；修复交互须另行明确范围。
