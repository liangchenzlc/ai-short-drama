# Harness 可靠执行与上下文优化实施

状态：已完成。范围为评估方案第一、第二、第三批；保持模型自主调用工具、现有 L1–L5 与可靠请求账本。

| 批次 | 本次落地范围 |
| --- | --- |
| 第一批 | 用户来源交付要求、独立完成检查、Skill 分页修复、可纠正水合错误 |
| 第二批 | 有来源工作集、局部无进展监督、自动 Skill 阶段释放与原正文复用 |
| 第三批 | 有界历史及精确恢复、增量进度、按需工具组、稳定提示前缀、模型容量与成本观测 |

## 实施顺序

1. 完成验收：候选最终答复进入独立、可重放的 Turn；模型给出带用户来源和操作证据的结构化检查，程序核对证据、数量和答复引用。缺项返回当前 Agent 继续；普通讨论不执行业务操作。旧冻结请求仍按原协议重放。
2. 修复 Skill 分页；将水合失败冻结为模型可见的结构化反馈，保留单次像素与零媒体实体持久化。
3. 增加有来源的任务工作集、局部无进展诊断和 Skill 阶段释放；活动状态有界，累计执行不设次数上限。
4. 历史只查询有界近期组、活动方法和精确 manifest；旧已读进度采用增量投影，不再每轮扫描全部正文。
5. 增加按需工具能力组并保持已启用 schema 稳定；调整稳定前缀与动态任务状态位置。
6. 模型容量声明参与平台预算；统一记录 schema 成本、上下文组装耗时、实际输入／缓存用量，明确声明与实测的区别。
7. 执行单元、协议、真实 MySQL 与授权范围内的真实模型长任务验收；不调用生图或生视频节点。
8. 同步维护文档、测试映射，执行文档与质量门禁并复审。

## 目录与边界

- `agent/task/contract.py`：任务要求及完成检查契约与证据核验。
- `agent/harness/supervision.py`：候选答复、验收路由与无进展监督。
- `agent/context/working_set.py`：有来源的有界工作笔记。
- 改造现有 `harness/runtime.py`、`context/assembly.py`、`transcript.py`、`budget.py`、`resources/resolver.py`、`skill/progressive.py`、工具目录与 DAO。
- 复用 Task 的 effective_state 与 Run／Turn／Operation；不新建平行引擎，不增加数据库表，不恢复旧中断系统。
- 第四批创作一致性与交付进度 UI 不在本次范围。

收尾回归补充：记忆抽取原有 `abandoned` 终态缺少数据库 CHECK 与响应枚举，增加单项约束增量并同步 DTO；凭据等发送前确定失败不再无限排队。保留原 L1–L5 水位含义，不增加表或改变创作 Task 的累计执行策略。

## 验收

- 缺交付项、伪造证据、错误数量及过期输入不能标记成功；回执恢复不增加外发请求。
- 配额截断后的 Skill 候选可以继续翻页；释放后可继续加载，撤销／遗忘不复活旧正文。
- 裁剪越界可在原任务中修正；水合失败不伪装成已看图。
- 长任务跨多次压缩和 Run 后保留有来源事实；重复调用触发诊断，合法分页与等待不误判。
- 历史查询有界、恢复只读 manifest；按需工具降低基础 schema 开销，完整任务完成率不降低。
- 验证类型和未执行部分在最终记录中如实说明。

## 执行结果

前三批实现、专项回归、真实 MySQL 与授权网关长任务验收已完成。真实任务运行 886.55 秒，经历 37 个 Turn、30 次工具调用、L4 压缩及一次普通“继续”，实际保存并回读两角色、三分镜；没有调用媒体生成。收尾修复记忆终态后，56 项记忆及 12 项数据层／迁移回归通过，本地增量已执行，服务恢复运行。完整证据、其他测试及未验范围见[验收记录](../../reviews/2026-10-26-Harness前三批可靠性与上下文优化验收.md)。
