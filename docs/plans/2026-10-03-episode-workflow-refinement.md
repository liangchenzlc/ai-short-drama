# 分集详情页流程精细化修改方案

日期：2026-10-03；完成验收：2026-10-04。状态：已按用户确认的三项范围实施；`short_drama` 业务库迁移、历史回填、完整回归与审查完成，原有后台角色已恢复。

本方案依据两张参考截图、实际组件与后端调用链制定。保留现有 README、需求文档、截图及评审文档中的未提交改动。

## 已确认的需求范围

1. **全部候选和生成历史仅本人可见，只有明确采用后的作品共享。** 包括剧本、素材提取、分镜、图片、视频、音频及 Agent 产物；任务中心、资产库、批量生成、声音与成片入口同步遵守此规则。
2. **附件参与 Agent 理解和创作。** 图片、文本、视频、音频按所选模型的实际输入能力处理，不能只做保存与预览。
3. **Skill 支持内置选择和自定义文件上传、管理。** 本方案建议首版自定义文件为 UTF-8 Markdown，支持上传、查看、编辑、停用、删除和重新上传更新。

## 设计方向与现状

本次设计面向中文短剧创作者的分集工作台，提供紧凑、简洁的对话界面，沿用现有 Ant Design 体系。

- 改版模式：保留现有设计体系的局部调整。
- `DESIGN_VARIANCE: 3`：保持流程与作品的位置稳定，操作入口更集中。
- `MOTION_INTENSITY: 3`：动效用于加载、对话新增和浮层反馈；新回复逐步显示，降低动态效果偏好下直接显示。
- `VISUAL_DENSITY: 6`：保持紧凑工作台，移出常驻的低频设置，给作品和对话更多空间。
- 视觉沿用 `tokens.css` 和 `theme.ts`：冷黑画布、冷灰表面、蓝紫操作色、系统中文字体；控件使用 7px 圆角，卡片和面板使用 12px 圆角。
- `design-taste-frontend` 明确不面向密集产品 UI，本次采用其审查现状、视觉一致性、状态和可访问性原则，具体组件沿用项目的 Ant Design。

## 右侧 Agent 对话区域

主界面只保留简短标题、消息列表、输入框和输入工具栏。截图红框中的会话选择器、新建/更多按钮、归档开关、当前分集及运行状态条移出主界面。会话新建、重命名、归档和切换收进对话记录弹窗。

建议结构：

```text
提示词创作 / Agent 创作                    收起
对话                                     记录

                      用户消息与引用附件
Agent 回复
生成结果卡片 / 需要批准的计划 / 采用入口

已添加附件、资产引用、已加载技能
消息输入框
[添加附件▾] [资产库] [模型] [Skill]      [发送]
```

- 用户消息靠右，Agent 回复靠左；回复中的生成结果显示紧凑结果卡，点击查看详情、预览并明确采用。
- 输入框固定在右侧面板底部，消息列表独立滚动。保留 Enter 换行、Ctrl/Cmd+Enter 发送及中文输入法保护。
- 添加附件下拉提供图片、文本、视频、音频；添加后显示可移除的预览或文件条目，上传期间禁止发送。
- 按参考要求省去音频转文字按钮，音频作为附件按模型输入能力处理。
- 资产库按钮打开选择弹窗，提供当前可访问的素材和媒体，发送时保存稳定 ID 与内容版本。
- 模型按钮弹层展示当前对话模型、输入能力和媒体执行模型；已有能力核验、参数和指定任务设置放入按需展开区域。
- Skill 按钮打开“内置技能 / 我的技能”弹层，已加载技能以小标签显示在输入框上方。
- 讨论与执行保留为发送按钮的明确选项，默认讨论。多步骤执行计划的批准、拒绝和停止操作在对应消息附近出现。
- 逐步显示仅用于新回复，历史消息一次显示。动画限定在当前回复组件内，避免每个字刷新整个工作台；尊重降低动态效果偏好。
- 状态提示按需在消息或输入框附近显示；断线、受理不明、保存失败和模型不支持附件时保留草稿，提供就近处理入口。

### 附件的真实理解链路

当前 Agent gateway 的 `user_prompt` 只接受字符串，现有图片/视频生成的参考输入不能直接视为 Agent 理解能力，需要扩展模型网关和私有协议历史。

1. 上传文件后创建本人及当前私有对话归属的附件记录；图片、视频、音频复用持久媒体与 MinIO，文本提取为有长度限制的正文。
2. 发送请求包含附件引用、资产引用和所选技能；服务端再次校验归属、格式、大小、时长、数量、上下文长度和模型能力。
3. 文本解析后进入资料上下文；图片传入支持视觉的模型。视频采用所选协议实际支持的视频输入或明确标示的采样帧方式；音频仅交给支持音频输入的模型。界面明确区分视频画面理解和声音理解。
4. 不支持的组合在发送前明确阻止，不能静默丢弃附件或音轨。模型能力依据协议和配置声明展示，真实验证结果单独记录。
5. 模型输入经过现有受控传输边界，不能让 SDK 自动读取任意 URL。消息保存稳定定位值，展示时刷新临时签名 URL。
6. 资产选择器复用展示和分页，调整选择行为：为 Agent 添加上下文不会自动将个人媒体复制进共享项目库。

### 自定义 Skill 管理

- 内置技能只读，按既有版本加载；“我的技能”仅本人可见，支持上传 Markdown、预览全文、编辑、停用、删除及重新上传更新。
- 文件内容作为创作指令加载；首版只接受单文件 Markdown，自定义脚本及目录资源不进入执行链路。
- 每次修改产生新内容版本，运行冻结技能正文、版本和校验值；修改或删除技能不改变已受理任务和历史对话的含义。
- 自定义技能不扩大用户本次批准的任务范围，也不能直接采用候选或修改权限。
- 新增私有技能表及 API。账户级技能独立按 owner 校验，不能套用现有必须关联 conversation 的私有记录保护。
- 附件和技能引用可复用 `agent_messages.references`，运行快照可复用 `agent_runs.checkpoint`；不为已有 JSON 可以表达的引用重复增列。

## 小说改编

- “生成剧本”与生成记录图标同行排列，图标提供“生成记录”的可访问名称及 Tooltip。
- 点击生成后，在保存来源、提交、排队、运行期间持续显示加载状态并禁止再次提交；提交回执立即更新本地任务状态，消除等待下一次轮询期间的重复点击窗口。
- 生成失败、取消或完成后恢复按钮；受理结果不明时提供核对记录入口，不自动创建新任务。
- 删除中央作品下方的“创作候选”常驻区域。
- 本人候选保留在生成记录弹窗和 Agent 结果消息中，继续支持全文预览、采用并编辑和独立确认剧本。

## 素材准备

工具栏顺序：**从剧本提取素材 / 从项目库添加 / 新建素材**，保留现有其他必要操作。

- 从剧本提取素材打开已有弹窗，展示提取模型、要求、结果审核和本人历史。
- 素材保留卡片呈现。卡片文字和空白区域点击进入编辑；图片仍独立打开预览器。
- 去掉“编辑素材”按钮；竖三点菜单收纳“共享到项目”和“从本集删除”。现有删除实际解除本集引用，确认文案说明影响范围。
- 菜单、图片预览和批量勾选与卡片编辑入口隔离事件；编辑入口保留键盘激活与可见焦点，避免嵌套按钮。
- 中央素材库下方的编辑区域和“创作候选”区域移除。素材编辑整体搬入右侧，包括基本信息、参考图、图片生成及候选采用。
- 点击卡片时右侧显示“素材编辑”，原提示词/Agent 模式和对话草稿保持；关闭编辑回到原模式。右侧收起时自动展开，窄屏切换到右侧工作区，关闭后恢复卡片焦点。
- 关闭、返回和切换右侧上下文执行现有未保存检查；保存进行中锁定对象切换，409 或失败保留右侧草稿并提供就近反馈。
- 保留现有保存会话、切换素材时的未保存检查、Agent 发送前保存和共享素材修改影响确认。
- 个人库和项目库的现有详情弹窗保持各自原有行为，本次只移动分集内的编辑区域。

## 分镜镜头制作

工具栏顺序：**新增分镜 / 提取分镜 / 历史记录**。

- 当前分镜改为有 12px 圆角、细边线和间距的单列卡片；保留镜号、摘要、时长、状态、选中反馈以及只展开当前编辑镜头的行为。
- 提取分镜打开设置弹窗，放入文本模型、平均镜头时长、补充要求和必要的来源提示。图片模型和镜头媒体参数继续在右侧编辑区展示。
- 弹窗内“生成分镜”按钮从提交开始持续加载、禁用，直至任务结束；关闭或重新打开弹窗仍恢复当前任务状态。
- 提交状态与排队/运行状态分开管理，持续加载只作用于生成按钮；任务受理后允许关闭设置弹窗、继续编辑和查看历史，避免通用 busy 长时间锁住弹窗。
- “历史记录”打开现有历史弹窗，按 20 条分页查看本人生成记录，保留预览、整批追加/替换和版本检查。
- Agent 生成结果仍从对话结果卡进入预览与采用，不恢复中央常驻候选区。

## 后端权限与数据迁移

统一分开两类数据：**生成记录/候选是本人私有；明确采用后的正文、素材、镜头和媒体属于项目作品。** 采用后的作品可供协作者读取和编辑，私有生成参数、错误、模型信息和过程记录不随作品公开。

- 列表、详情、分页总数、预览、下载、候选采用、恢复/重试均验证当前 actor。拥有项目权限不能读取他人的候选或生成任务，即使知道 ID。
- 核对任务中心、批量生成、媒体资产库、Agent 上下文工具、素材图片、镜头图片/视频、声音候选和成片历史，关闭旁路访问。
- 作品通过独立的共享内容投影读取，不依赖读取作者的私有任务；仅发布实际采用的内容，不发布同一任务的其他产物。
- 已采用镜头、音色和成片的公开 DTO 保留正文、稳定媒体 ID、链接与业务版本，移出他人的候选 ID、任务 ID、生成记录 ID 和生成资产关联。成片聚合响应单独提供公开的当前作品，不为播放当前成片而公开完整导出任务。
- 项目活动记录不展示他人的私有生成对象与过程；保留公开作品采用、修改等协作事件。
- 移除协作者后的待执行任务撤销、Worker、Recovery 和归档仍通过受控内部访问完成，不能因本人过滤失效，也不能由 HTTP 输入开启系统 Session。
- 优先复用 `AsyncTask.initiated_by`、`AgentArtifact.created_by`、批次归属以及现有媒体创建人。
- 对缺少候选创建人的表补齐归属；例如 `asset_image_candidates` 当前没有创建人，不能仅依据被引用媒体的作者判断候选归属。
- 剧本及媒体补齐明确采用/发布状态或记录，避免当前采用指针变化后，把曾采用作品与从未采用候选混淆。
- 历史数据只依据任务、记录和采用关系等可靠证据回填。归属无法证明的未采用记录保留并隔离，不默认分配给项目主人或公开给成员。
- 新增私有 Agent 附件和技能数据模型；具体字段、索引、旧数据回填语句在实施前列明。
- 数据变更同时更新 ORM、完整建库 SQL、旧库增量迁移及数据库说明，并在当前配置的数据库实际执行 DDL。实施结果记录数据库名称、所执行语句和回填情况。
- 同步当前 `AGENTS.md`、`PRODUCT.md` 和 API 文档中的共享候选约定，以本次已确认的新规则为准。

## 验证与 Review

实施后实际执行：

- 前端 `npm test`、`npm run build` 及相关 `npm run test:e2e -- ...`。
- 后端 `uv run pytest tests/unit tests/api -q`、`uv run ruff check src tests scripts`、`uv run ruff format --check src tests scripts`。
- 权限、采用状态和迁移使用 `uv run python scripts/run_integration.py` 的随机临时 MySQL 数据库验证；跳过不算通过。
- 两个项目成员和一个无项目权限账号的权限回归覆盖列表、ID 直读、总数、下载、采用、任务中心、资产库、声音/成片聚合和项目活动记录；本人能读取，另一成员不能读取，采用作品仍可正常协作。成员移除后访问终止，待执行任务仍可正常撤销。
- 更新现有明确验收“共享候选”的测试契约，验证采用前私有、采用后仅作品共享、替换后已公开作品仍可读取、私有生成元数据始终不可读。
- UI 回归覆盖任务期间禁止重复提交、图片预览/三点菜单不误触编辑、Agent 模式素材编辑可达、409 保留草稿、发送前保存、模式和阶段切换、窄屏、焦点恢复及降低动态效果。
- 附件与 Skill 覆盖正常路径、模型不支持、越权引用、超限、上传失败、技能修改后的运行快照、SSE 断线恢复和不明请求幂等处理。
- 按 `frontend-code-review` 的证据优先方法审查本项目 `frontend/` 的最终 diff，重点检查交互可达性、状态所有者、请求契约、权限和渲染成本；不套用 Dify 专有组件规则。
- 浏览器测试和模型替身只证明工程逻辑。真实图片、视频、音频理解需用对应支持模型单独验收，明确记录哪些供应商和输入类型实际验证过。
