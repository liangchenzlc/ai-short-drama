# 创作流程修复方案：保持现有前端布局

日期：2026-10-04。状态：三批 20 项代码与对应验收已完成；逐项结果见[实施与验收记录](2026-10-04-creation-flow-fixes-verification.md)。

依据：[分集创作流程审查](2026-10-04-creation-workflow-audit.md)。本次约束是保持页面分栏、卡片排列、面板位置/尺寸、时间轴结构、主题与样式；优先修复业务逻辑、状态同步、接口一致性与异常恢复。必要动作和反馈复用现有菜单、弹窗、消息区和提示区域。

以下保留实施前的问题与方案。F05 已通过真实 ActorContext 复现并修复；测试替身、SQLite 测量与真实 MySQL、Worker 验收分别记录，不混用验收结论。

## 1. 拟修复清单

| 编号 | 优先级 | 问题与范围 | 方案 | 验收目标 |

## 2. 后续优化与原位置功能补齐

| 优先级 | 项目 | 保持布局的实现位置 | 边界 |
| --- | --- | --- | --- |
| P1 | 分镜排序/归档入口 | 原镜头操作区/菜单及现有确认弹窗，复用已有API | 不扩展拖拽、批量归档或撤销系统 |
| P1 | 分镜候选完整审核 | 原预览条目补时长、素材、来源文字；同步响应模型/DTO/文档 | 不新增审核面板或逐镜部分采用契约 |
| P1 | Agent模式原生对白审核 | 原镜头信息弹窗复用既有对白审核入口 | 仍由用户明确确认，不新增Agent声音授权 |
| P2 | 未保存正文/剪辑/声音恢复 | 后台持久化草稿与基准版本，原提示区/弹窗核对恢复 | 按账号与对象隔离，409保稿；不存密钥/签名URL |
| P2 | 数据版本契约统一 | Pydantic、Service输出、前端DTO和调用同步为十进制字符串 | 只处理数据库版本，不改媒体时间等普通数值；兼容策略先明确 |
| P2 | 长会话与轮询效率 | 先测历史事件与300片段规模，再优化快照/cursor和活跃/空闲轮询 | 快照含在途delta，不能跳cursor丢实时文字；无需改变消息区 |

## 4. 验证要求

- 每项先补可复现故障的测试，再最小修改；正常路径和错误/边界路径都验证。
- 前端执行相关Node测试与生产build；交互使用仓库已有Playwright，核对原布局与1440/1024/390视口。
- 后端执行相关unit/API与Ruff；涉及采用事务、幂等、候选记录使用项目标准配置运行随机临时MySQL库，不读取容器凭据或操作业务库作为测试。
- 必测：丢响应+刷新、409、503、A/B对象切换、第20/21/80镜、16/17参考图、活动任务退出首页、停止后延迟结果、作者/只读权限。
- 保留手动采用、来源保存、版本保护、作者隔离、unknown不自动重提；测试替身不作为真实供应商验收。
- 界面验收重点是原布局与操作位置保持，状态和异常处理明确；性能改善以实际测量为依据。
