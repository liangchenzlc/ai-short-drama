# 角色音色驱动的原生有声视频

本方案替代新项目的“逐句 TTS → 给分镜视频后配音”流程。旧项目保留 `legacy` 制作模式；启用新功能后创建的新项目使用 `native` 模式。历史项目可显式切换，原配音数据保留，原生模式导出时不叠加历史配音。

## 一、Goal 与完成条件

| Goal | 实现行为 | 完成判定 |
| --- | --- | --- |
| G1 角色固定音色 | 在角色库填写声音描述和试音文本，通过百炼设计一个候选；试听、采用后形成项目内的角色音色版本 | 使用 CosyVoice v3.5 Flash 文本音色设计接口；直接归档返回的 preview_audio，不另调用 TTS；重复提交返回原任务；保存失败可恢复原样音；只有有效样音可采用 |
| G2 分镜原生对白 | 每个分镜保存说话角色、台词、语气和画内/画外方式；向视频模型同时提交图像与角色音频参考 | 支持单角色及两角色顺序对白；最多 20 句、不支持重叠说话；无对白镜头也需确认；冻结台词、音色版本、媒体 ID 与校验和；不支持音频参考的模型提交前阻止；不回退后期 TTS |
| G3 成片与批量闭环 | 采用视频前检查解码和对白音轨；成片使用视频原声、可编辑字幕和配乐；批量按冻结输入调度 | 有对白但无音轨/静音的候选不能采用；音色或对白变化使旧视频过期，等待批次在派发前暂停；字幕草稿来自采用视频的冻结台词并要求校时；配乐仅在人工确认区间压低；已有播放恢复与批量幂等机制继续有效 |

“工程完成”指实现、离线协议测试、隔离数据库、真实 FFmpeg 及浏览器测试通过。“供应商验收完成”另要求真实视频试听：角色音色相符、台词准确、双人不串音、画内口型自然。音轨存在不代表音色已通过验收。

## 二、不能改的边界

- 不提供角色样音上传或外部样音 URL 输入。角色样音只来自百炼设计接口。
- 不自动采用音色或视频，不覆盖已采用媒体、不删除历史任务与旧项目配音。
- 不按分镜调用独立 TTS，不在供应商拒绝音频参考后偷偷换模型或发第二次请求。
- 角色音色绑定按项目隔离；说话角色必须关联当前分镜。更换音色不改写已经提交的任务快照。
- 参考音频只通过已归档媒体读取，上传前核对 SHA-256；不把签名 URL 固化进生成快照。
- 声音描述最多 500 字符；试音文本 15～200 字符。应用当前限制每个样音 3～7.5 秒、最多 10 MiB，最多两份，总计不超过 15 秒。这是本应用的保守限制，不是供应商全部能力的声明。
- 保留视频原声的整体音量和片段静音。视频内的对白与环境声不提供独立音量调节。
- 字幕时间不能从角色参考样音时长推断。当前按采用视频时长均分生成待校对草稿；裁剪、拆分可能截断台词，必须人工修正。
- 本轮不调用真实供应商，不使用历史剩余额度，不向业务数据库执行迁移；密钥不写进代码或文档。

## 部署与使用

1. 先应用原声音制作和批量生成迁移，再应用[原生音色增量迁移](../数据库模型/migrations/2026-09-30-native-video-voice/README.md)。完整建库 SQL 已更新为 32 张表。
2. API、生成 Worker、调度器和渲染 Worker 部署同版代码。配置对象存储音频桶、`ENCRYPTION_KEY`、FFmpeg/ffprobe 和中文字幕字体；加密样音恢复依赖原加密主密钥。
3. 启用 `AUDIO_PRODUCTION_ENABLED=true`、`NATIVE_VIDEO_ENABLED=true`；需要批量时同时启用 `GENERATION_BATCHES_ENABLED=true`。未迁移前保持默认关闭。
4. 模型配置添加百炼北京音频模型 `cosyvoice-v3.5-flash`，地址可用北京原生 `/api/v1` 或用户自己的北京工作空间地址。不要使用 OpenAI compatible-mode 地址进行音色设计。新增预设不替换已有配置或密钥。
5. 角色库设计并试听采用 → 分镜关联角色和参考图 → 编辑并确认对白 → 选择支持音频参考的 ModelHub `seedance-2.0-mini` → 生成后试听采用 → 校对字幕、配乐区间 → 合成预览与导出。

ModelHub 音频参考能力来自公开协议，实际路由通道可能不支持。界面和后端均阻止已知不支持的模型；上游拒绝时保留失败记录，不自动降级。此实现不保证所有路由通道的音色遵循效果。

参考：[百炼音色设计 API](https://help.aliyun.com/zh/model-studio/voice-design-api-references)、[ModelHub 接口说明](https://modelhub.cc/quick-start)。
