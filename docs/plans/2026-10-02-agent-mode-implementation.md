状态：本地实施与验收已交付，真实模型验收等待授权；线程 Goal 为 blocked。框架：PydanticAI。此文件将前期方案和用户确认的范围固定为五个可独立验证、review、交接的 Goal。

## 产品范围

在分集工作台提供「提示词创作」与「Agent 创作」。旧链接默认提示词模式；Agent 使用 `?mode=agent&conversation=<id>`，阶段导航保留这些参数。Agent 对话覆盖正文、资产、分镜及图片/视频生成；本版不含时间线、音频和导出编排。

对话仅本人可见，候选和正式成果对项目成员共享。进入其他对象不会悄悄改变正在执行的任务对象。对话上下文包含本轮要求、明确引用、分集规格和按需加载的版本化内置 Skills。

「先讨论」不授权生成；「生成候选」允许明确的单项任务直接执行。自由文本中的限制优先于界面选项。多步骤工作先给出可审查的计划，批准一次后按冻结的对象、版本、模型和生成数量执行。修改范围或增加付费重试需要新授权。生成始终产生候选，采用继续走现有确认和版本冲突检查。

工作台延续现有冷黑、紧凑的编辑界面。宽度至少 980px 时作品区至少 560px、对话默认 400px（360–480px 可调）；窄屏以「作品 / 对话」切换且保留编辑和对话状态。对话 host 位于阶段组件之上。Agent 模式收起正文旧 AI 栏；进入组装隐藏对话但保留返回和状态入口。切换模式不会停止任务。

会话支持新建、改名和归档，执行中的任务停止后才能归档。发送前复用当前编辑器保存屏障；保存失败或冲突保留草稿并阻止模型请求。同一对话只允许一个活动 Run，不暗中排队付费消息。Enter 换行，Ctrl/Cmd+Enter 发送，兼容中文输入法，支持键盘和屏幕阅读器；用户上翻阅读时不强制滚到底部。

输出以消息、计划、活动与成果卡呈现。正常界面不展示内部工具名、原始 JSON 或隐藏推理。小说采用后才覆盖正文；脚本候选选择不等于确认；提取继续使用创建/复用审核；分镜继续追加/替换；资产和镜头修改是可审查 patch；媒体采用保留来源、版本和共享影响检查。采用并继续仅唤醒指定 Run 与成果，不批量唤醒其他私有付费计划。

指定媒体任务采用渐进表单：先选图片/视频，再按素材名称或镜头位置与摘要选对象，再选本人配置的媒体模型，最后展开本次参数、数量和参考图。默认继承当前对象的设置；明确覆盖仅作用于新候选，不修改手动编辑器设置。发送后展示具体确认卡。自然语言的自由生成仍先给出计划；用户不需要手填对象或模型 ID。协作决策文本模型与执行图片/视频的模型分别选择、分别校验。

计划冻结媒体引用。新镜头须先生成并明确采用图片，再提出使用它的视频任务；采用新图改变了视频参考时，需要新计划审核或新的明确单项授权，不能把一次预批准解释为允许自动替换未来的视频参考。采用并继续可返回新上下文和计划，但不扩大原来的授权。

## 技术与数据契约

保持 FastAPI、SQLAlchemy/MySQL、Celery/RabbitMQ 和 MinIO。PydanticAI 负责模型协议和延迟工具；应用负责持久执行、授权、预算、幂等和采用。Agent 有独立队列、publisher、recovery 和租约，不新增 AsyncTask 类型。等待现有生成任务时释放 Agent worker，由恢复调度检查状态后继续。

依赖固定为 `pydantic-ai-slim[openai]==2.53.0`。首版采用单协调 Agent，模型协议复用框架，业务工具和持久化状态留在项目内；没有额外引入新的服务端语言、数据库或运行平台。

每个决策段先持久化完整模型回复、规范化历史与工具意图，再校验工具参数、权限、任务范围、来源版本与额度，然后调用业务服务，持久化结果，使用 DeferredToolResults 继续。模型请求已经发送但没有完整持久响应时标为 unknown/失败并要求关注，禁止自动重新付费请求。完整响应仅可恢复本地解析。工具重放使用冻结的原始请求和幂等键，保留字段是否出现的语义。

独立 AgentModelGateway 使用官方 PydanticAI OpenAI Chat Completions/Responses 实现，复用现有配置、加密凭据和受保护 HTTP 传输。保留 URL/DNS 固定、TLS、超时、字节限制、不重定向和 POST 不自动重试，关闭 SDK 重试。工具协议适配不放宽旧文本 schema。决策服务类型保持 text，模型偏好使用 `agent:decision`。能力证据存现有 capability_cache，绑定配置版本；仅在用户显式校验时发探测请求。

新增七张表：

| 表 | 可见性 | 职责 |
| --- | --- | --- |
| agent_conversations | 私有 | 所属用户、项目/分集、标题、固定要求、版本和消息/事件序号 |
| agent_messages | 私有 | 不可变的用户/助手正文、引用、序号和请求幂等 |
| agent_runs | 私有 | 触发消息、发起人、模型与授权快照、预算、checkpoint、调度租约 |
| agent_turns | 私有 | prepared/sent/succeeded/failed/unknown 提交证据、请求/完整回复、用量 |
| agent_tool_calls | 私有 | 校验冻结后的工具参数、hash/key、审核、业务任务和结果引用 |
| agent_events | 私有 | 会话单调递增事件，SSE 回放 |
| agent_artifacts | 项目共享 | 候选/patch/原生结果引用、不可变来源和采用回执 |

不新增审核、checkpoint、Skill、偏好或脚本 revision 表。脚本候选正文存在 episode_scripts，来源与选择范围在成果表；创建候选不移动当前编辑指针、不确认、不推进正文版本。共享读取不得连接私有历史，不返回会话标题、正文、会话 ID 或私有链接。完整决策请求与回复不得写项目共享 AIGenerationRecord。

表遵循 Snowflake unsigned bigint、API 字符串 ID、UTC DATETIME(6)、InnoDB/utf8mb4/DYNAMIC、RESTRICT 外键和显式 CHECK。会话活动 Run generated unique；消息、事件序号在锁会话后原子分配。触发消息、决策编号、工具 key、成果工具/结果序号、脚本候选引用唯一。

私有权限判断必须先于通用 project_id 规则：本人 AND 当前项目访问权。后台付费提交再检查用户有效、项目有效、发起人当前成员及父 Run 的授权状态。数据库锁顺序统一为 Project → Conversation/Run → Tool → AsyncTask/Record，禁止原任务 worker 先锁 Task 再反向锁 Run。

媒体 admission 需从现有服务窄范围提取事务内核心，保持公开 create 行为。在短事务内原子检查父 Run/授权、预留额度、创建/关联原生 task/record、设置等待。prepared→sent 再检查父授权；停止/撤权后已受理工作仍可 poll/save。仅工具意图幂等无法消除取消与媒体 admission 的竞态。

| 额度 | 讨论/单项 | 已批准流程 |
| --- | ---: | ---: |
| 决策请求 | 8 | 16 |
| 工具调用（含读取） | 16 | 32 |
| 单次输出 token | 8192 | 8192 |
| 累计输出 token | 32768 | 65536 |
| 决策请求超时 | 120 秒 | 120 秒 |
| 活动执行时限（排除审核/媒体等待） | 5 分钟 | 10 分钟 |

媒体额度等于实际批准的数量；每 Run 同时 admission 图片 2、视频 1。额度原子预留并按真实用量结算；缺失用量或 unknown 保留预留。不能先受理全部媒体再限制并发。

Run 状态：queued/running/waiting_generation/waiting_review/succeeded/failed/cancelled。SSE 按会话事件序号增量重放；流 delta 约 200ms 或 8KiB 批量写入，15 秒心跳，持续复查访问权。

AGENT_ENABLED 按用户后续要求默认 true，启用必须有认证，启动前完成显式迁移并准备独立 Agent Worker。已有库迁移维护或仅提示词部署可显式设置 false。基础 readiness 排除固定 Agent 表集合，启用时独立严格 readiness。迁移为显式、可重复、追加式，更新 canonical 建库 SQL，启动不自动迁移。功能关闭或尚未迁移时提示词流程可用；表存在但功能关闭时仍可读取/采用共享成果。

## 五段式 Goal

### Goal 1：契约、数据基础和工作台入口

- 目标：固定前后端契约和私有/共享边界，建立可迁移数据基础与真实会话管理入口。
- 交付：七表模型/DDL/可重入迁移；Agent 设置/readiness；会话 API/权限/幂等；路由、模式切换、响应布局、会话列表/新建/改名/归档；锁定 PydanticAI 依赖和受保护协议网关。
- 持续不变量：旧功能无需 Agent 迁移；私有对话不被项目成员读写；无页面自动收费；工程现有约定不被破坏。
- 验收证据：DDL/MySQL readiness 与权限集成测试、会话 API 验证、网关协议单测、前端检查/build，限定本步骤差异的 code review。
- 交接条件：契约稳定、关闭/启用路径可验证，基础改动 review 完成。

### Goal 2：持久对话、授权与事件

- 目标：对话可以停止、审核、恢复，模型/工具不会因进程重启重复收费。
- 交付：独立队列/publisher/recovery/租约；延迟工具决策段；版本历史；单 Run/预算/计划批准/停止；持久事件/SSE/前端发送和活动卡；模型工具能力显式校验。
- 持续不变量：完整回复先持久后执行工具；sent 无持久响应进入 unknown；重放只执行本地安全步骤；每个副作用重新检查授权；不隐式排队新 Run。
- 验收证据：重复发送、并发活动 Run、停止/撤权、租约过期/unknown、SSE 断线回放、预算边界和流式工具协议测试，限定本步骤 code review。
- 交接条件：讨论、计划审查、直接单任务三条路径以及恢复边界已验证。

### Goal 3：文本创作与采用

- 目标：对话产出小说、脚本、提取/分镜候选与资产/镜头修改建议，采用遵守原工作流。
- 交付：内置版本化 Skills/上下文读取；文本候选/来源快照/差异；原提取与分镜任务接入；资产/镜头 patch；共享成果来源与采用 UI/API。
- 持续不变量：生成不直接覆盖作品、不自动确认；版本冲突可见；私有信息不随共享成果泄露；采用不唤醒其他 Run。
- 验收证据：来源过期/候选选择/确认分离/重复采用/跨成员访问的 API 与必要 E2E，文本真实模型额度内验证，限定本步骤 code review。
- 交接条件：文本候选可审查、可采用、采用行为与现有规则一致。

### Goal 4：图片、视频与流程继续

- 目标：Agent 调用原生媒体生成、等待和展示候选，并在指定采用后继续批准的工作流。
- 交付：事务内 admission 核心、父授权 sent 检查、额度/并发；媒体工具和任务状态/候选卡；结果失败与独立付费重试；采用绑定的继续逻辑。
- 持续不变量：取消/admission 没有授权空窗；原生任务结果仍可归档；未知提交不自动重发；图片 2/视频 1 的受理上限；视频验证仅 480p/5 秒。
- 验收证据：取消竞态、worker/调度恢复、并发和 quota、过期媒体采用、真实图片/视频验证（限额内），限定本步骤 code review。
- 交接条件：文本/图片/视频贯通，采用后继续和失败恢复有直接证据。

### Goal 5：体验审计、故障验收与发布准备

- 目标：完整功能在实际编辑、协作和故障环境下可用且可运维。
- 交付：桌面/窄屏/长对话/IME/键盘/无障碍检查；权限撤销/缓存隔离；配置、迁移、启动/回退与排障文档；日志与观测；最终需求审计。
- 持续不变量：关闭功能保留共享成果访问；现有提示词模式没有回归；每一项完成有范围匹配的当前证据；真实兼容性不以 mock 替代。
- 验收证据：必要 unit/API/MySQL/storage-worker/E2E/build；两轮以内界面截图检查；限定本步骤 code review；逐项完成审计。
- 交接条件：所有显式要求与五阶段验收有证据，剩余缺项为零后完成 Goal。

## 验证与 review 记录

用户授权真实验证上限：文本 10 次，图片 10 次，视频 3 次（480p、5 秒）。这是整个实施过程的累计上限，不是每阶段额度。任何真实探测/付费重试都计入。最终保守累计：文本 10，图片 1，视频 1。包括此前 connection_error、agent_provider_rejected 两次文本失败尝试，后续能力探测两次成功、文本/图片/视频各两次 Agent 决策成功，以及单次图片与单次视频提交。计入全部尝试以确保不超额；文本额度已用满，不再调用。用户补充明确联网授权后继续隔离库验收，原权限阻塞已解除，三类真实流程均已闭环。完整结果与实际视频尺寸/时长见[验收记录](../agent-verification.md)。由主 agent 统一协调调用，独立隔离库与累计 ledger 均保留，不记录密钥或敏感正文。

每阶段先验证，再针对本阶段变更 code review；仅修正实际缺陷或规范违背，不扩展到无关历史代码。禁止把未通过或未运行的验证写成完成。
