# 单剧创作工作台正式接入实施计划

**目标：** 将已确认的单剧预览接入正式页面和现有服务，保留现有作品编辑、生成及声音能力。

**设计：** [单剧创作工作台正式接入设计](../../design/2026-11-07-单剧创作工作台正式接入设计.md)。沿用 API → Service → DAO、现有编辑会话及任务队列；不新增剧集模型，也不维护两套正式工作台业务流程。

**视图：** 原素材／分镜列表 │ 中央批量工具及视图切换 │ 单卡资料 + 图片或视频及生成输入。剧本继续使用原页面；成片预览节点不改。

## 1. 数据、版本与接口

- [ ] 扩展 `backend/src/short_drama/domain/creation/assets/management/assets.py`、资产 schema 和管理服务，保存类型专属资料；场景时间仍使用 `scene_time`。扩展角色版本快照、复制和资产图片上下文，历史快照及摘要保持可读可核验。
- [ ] 扩展 `domain/creation/storyboard/management/script.py`、分镜 schema 和 `service/creation/storyboard/management/`，保存机位、运镜、对白设想和声音设想并纳入生成上下文；现有角色审核对白不被覆盖。
- [ ] 写增量迁移、迁移索引与全量表结构，更新 `docs/api/` 和前端 DTO。对已有开发库执行可追溯的增量迁移，不用全量 SQL 覆盖。
- [ ] 最小验收：资产各类型和镜头资料可新建、更新、刷新；清空和切换类型正确；角色历史版本校验及拷贝通过；资料变化使新任务使用最新内容。

## 2. 生成参考与两条视频路径

- [ ] 扩展 `domain/creation/drafts/`、草稿 schema／服务和前端 DTO，保存本人的视频参考选择，明确未初始化与主动清空；资产引用在提交时解析当前主图，分镜图引用记录明确媒体。校验所属项目、可见性、数量及模型能力。
- [ ] 调整 `service/generations/admission/context.py`、`creation/storyboard/videos/`、`generations/batches/preflight.py` 和助手视频提交链：支持无参考文本生成和显式多参考生成，冻结媒体和上下文，图片、视频及原声对白分别独立。
- [ ] 调整视频归档和采用：已有视频保留，新结果可预览及主动采用；同时检查图片组、成片读取、重试、任务过期及未知受理语义。
- [ ] 最小验收：无分镜图也能发起视频；选择资产／分镜图后请求包含对应媒体；手动移除后刷新仍为空；图与视频参考互不干扰；已有视频不会被新候选替换。

## 3. 正式资产工作台

- [ ] 在 `frontend/src/features/creation/assets/editor/` 用现有工作台容器、保存会话、素材列表、图片组和生成能力装配已确认的单卡；资料和图片提示词分别写入共享作品与私人草稿。
- [ ] 接通单卡／宫格／列表、跨视图选择和真实批量预检及结果；保留原列表与管理操作。
- [ ] 最小验收：编辑后刷新、切换素材及视图不丢内容；图片组切换和采用有效；批量状态可查看并保留既有图片。

## 4. 正式分镜工作台

- [ ] 在 `frontend/src/features/creation/storyboard/workbench/` 用现有列表、编辑会话、图片组、声音与视频能力装配预览；图参考和视频参考分别保存，新增角色／场景默认带入视频参考。
- [ ] 接通三视图、分镜图与视频批量操作，保留单镜头任务、冲突恢复和主动采用。
- [ ] 最小验收：两条视频路径可提交并查看候选；切换镜头及刷新保留参考；原生对白与创作对白设想互不覆盖。

## 5. 完整验收

- [ ] 对资产、分镜、生成、草稿、角色版本和视频相关单元、API、MySQL 集成测试执行适用的测试映射；补充跨边界行为测试，覆盖并发版本、参考冻结、结果采用及失败重试。
- [ ] 在正式路由进行真实服务联调，覆盖 101 项分批、图片组、批量进度和恢复；检查 1280 / 1440 / 1920 与助手开关截图。记录真实供应商调用范围。
- [ ] 执行前端类型检查和标准构建、后端 ruff、`node scripts/test.mjs --check` 和 `node scripts/check-quality.mjs`；记录命令、输出及未验证项，更新本计划和总纲。

**执行原则：** 各项先完成最小验收再推进，最后做完整验收；本计划中的接口、文件与测试以现有代码为准，发现冲突时同步修订，不为历史兼容增加并行实现。
