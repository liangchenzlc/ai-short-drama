## 第一批：解除实际卡死与错误恢复循环

涉及 `backend/src/short_drama/service/assistant/execution/tools.py`、`agent/runtime/executor.py`、`agent/coordinator/recovery.py` 及相应运行时测试。

- 修正 `AgentOperation` 构造参数：`turn_id` 已可由关联的 `AgentToolCall` 投影获得，不为错误构造参数新增冗余 ORM 列或迁移。保留事件和公开 DTO 所需的轮次身份。
- 区分确定性代码／契约失败与可恢复的基础设施中断，避免相同 checkpoint 上的同一错误无界续投；对不可恢复错误保存安全错误码并进入明确终态。
- 修复前先在隔离库复现“模型回复已保存、首个工具尚未创建 Operation”的状态；修复后验证从检查点继续、只生成一份 Operation、不重复发送已完成的模型调用。

验收：正式 `AgentRuntime.execute`、真实 saver 与 MySQL、受控 SDK 响应；覆盖首个只读工具、提问工具、同 checkpoint 恢复，以及确定性异常不会再次无限调度。实际卡住的会话在代码验证后单独核对恢复方案，不直接删除会话或覆盖其账本。

## 第二批：保证终态与已显示内容可信

涉及 `agent/runtime/lease.py`、`agent/runtime/model_ledger.py`、`agent/runtime/events.py`、`agent/gateway/langchain.py`、`service/assistant/execution/run.py`、`service/assistant/tasks/queries.py` 与前端运行时。

- 分开续租查询异常、租约确已失效和用户停止；数据库短暂异常不得直接伪装为用户取消。继续执行必须受仍有效的租约边界限制，不容许越过失效时间外发。
- 将已显示但尚未生成正式消息的正文纳入停止结算与终态回放；保留完整已显示文字及正确 UTF-8 边界，不依赖未被执行链使用的 4000 字尾缓存。
- 轨迹归档失败单独报告为轨迹资源不可用，不能覆盖已持久化的模型响应／用量或被改写为供应商受理不明。
- 失败横幅消费稳定错误码及安全用户文案，区分配置、预算、不可恢复系统错误与可继续输入。

验收：瞬时续租异常、真正失租、主动停止三者终态不同；停止时已收到超过 4000 字含中文／emoji 的正文，刷新后仍一致；受控完整模型响应后注入轨迹存储失败，模型成功与真实账本不被改写。替身结果只证明边界处理，不代表真实供应商或 MinIO 故障演练。

## 第三批：修复长期会话与等待任务的活性

涉及 `agent/context/graph.py`、`agent/memory/context.py`、`agent/memory/runtime.py`、`service/assistant/memory/memory.py`、`dao/assistant/execution/waiting.py` 与 `service/assistant/execution/waiting.py`。

- 正式图初始化消费合格摘要及摘要水位后的历史，修复已有 501 条历史时即使摘要成功也不能开始新 Run 的问题。继续保留来源撤回、主体权限与用户约束，不以直接截掉最早消息绕开上限。
- 为原模型配置变更后失败的记忆抽取定义可执行恢复路径，分别处理明确未发送、已持久无效结果和供应商受理不明；不能把所有失败记录自动标为已放弃。
- 调整等待扫描的筛选或分页，使前 100 个长期未答问题不会永久遮住后续已就绪生成任务。保持用户回答直接唤醒原 Run 的语义。

验收：501 条以上历史加有效摘要可开始新 Run；撤回来源不会因摘要恢复；旧模型配置版本变化后失败抽取可按明确路径恢复且无重复受理；100 个未就绪问题加第 101 个已就绪生成任务能在有限扫描内得到处理。

## 第四批：修复前端时间顺序与方法生命周期

涉及 `frontend/src/features/assistant/messages/agent-timeline.ts`、`runtime/useAssistantRuntime.ts`、`composer/useAssistantComposer.ts`；后端涉及 `agent/skill/progressive.py`、`agent/tools/runtime.py`、`agent/runtime/context.py`、`agent/runtime/middleware.py`。

- 按模型轮次／事件去重流式正文，不能因为同 Run 已有旧叙述而隐藏新轮次。
- 同一 Run 中用户回答或补充输入插入时，按事件顺序切分展示片段，不能把后续助手答复整体排到用户回答之前。
- 对损坏或无法清理的本机恢复记录提供重新核对与明确清理出口；对受理未知但有效的请求继续保留原幂等身份。
- 让模式变更与已活动方法要求一致：在上下文边界明确失活不再适用的方法，或在入口解释冲突，使模型有机会纠正。
- 对同轮多个方法加载按合并后的活动集核对独立数量和正文配额，避免各自旧状态均通过、合并后超额。

验收：旧叙述加新轮次仍能实时出字；问答及运行中插话后的文本按事件顺序展示；恢复存储错误可由界面解除；模式切换不会在模型纠正前无提示失败；并行加载不能突破 8 个／8000 tokens 的既定配额。使用现有正式图、真实 reducer 与浏览器路径，不用仅匹配源码字符串的测试替代行为验收。
