# 产品设计审视与改进实施计划（对标 LibTV / Flova AI）

> 审视日期：2026-11-04｜状态：草案｜范围：产品定位、核心流程、信息架构、商业化
> 方法：代码与文档实读 + 竞品公开资料核对（2026-11）。**未做用户访谈与埋点**，文中转化率、耗时均为基于路径长度的推断，不是实测值。
> 结论口径：先判断"产品是否成立"，再谈"哪里不好用"；每条问题尽量给出位置、影响与可验收的改法。

## 0. 结论摘要

**一句话诊断**：现在这套东西是一个**做得很扎实的「单支 AI 视频手工工作台」，外加一个过于完备的 Agent 运行时**，但它被命名为"短剧工作台"——名字所承诺的那件事，恰恰是当前结构里最缺的。

三个必须先承认的事实：

1. **定位错配**。短剧的最小生产单位是"集"，而分集已经被整体删除（项目只有一层 Project）。角色一致性、跨集复用、剧集进度、按集交付这四件事因此全部无处安放。第 2 集要从零再描述一遍同样的角色。
2. **激活断裂**。平台不供模型，用户必须自己填服务商、接口地址、API Key、模型标识，且文本/图片/视频/音频四类分别配。新用户从注册到第一次导出，必然卡在这一步。
3. **商业闭环为零**。全仓没有计费、额度、定价、支付；模型成本在用户侧结算，平台既不知道用量，也没有毛利。

两个被低估的好消息（直接决定排期）：

- **批量生成其实已经实现**：素材图、分镜图、分镜视频三种批次、预检、失败重试都在，只是入口藏在"选中镜头 → 标题栏 … → 批量操作"，而 `frontend/PRODUCT.md` 还写着"未实现"。这是零迁移、两周内能拿到业务变化的一条。
- **成片与分镜的"未同步"状态后端已经算好了**，前端没有展示，导出也不拦。同样是零迁移。

**12 周路线**：先收割已有能力（W1–W2，零迁移）→ 再补结构性缺口（W3–W6，剧—集 + 角色库）→ 最后做变现与分发（W7–W12，计量 → 审片 → 代供）。

## 1. 目标用户与核心场景：不清晰，且与宣称错位

### 1.1 事实上的用户，不是"个人创作者"

从门槛反推，现在能真正跑通的人是：**自带 API Key、懂图像/视频模型协议、懂分镜语言、能忍受逐镜头手工操作的个人技术创作者**。三条硬门槛：

| 门槛 | 具体表现 | 位置 |
| --- | --- | --- |
| 必须有可用的服务商账号与密钥 | 模型配置要填服务商、接口类型、地址、API 密钥、模型标识；四类分别配，跑完四阶段至少需要文本 + 图片 + 视频三类 | `frontend/PRODUCT.md` 配置章节 |
| 必须自学"四阶段"方法论 | 阶段导航只有 4 个图标、悬停才出字、无进度无下一步 | `frontend/src/features/creation/workspace/navigation/TopStepNav.tsx` |
| 必须自己会写分镜 | 景别、运镜、时长不在设置区编辑；空镜头允许无名称直接生成 | `frontend/PRODUCT.md` 分镜章节 |

README 首屏连续几十段都在讲事件积压、租约、幂等键、checkpoint、上下文压缩，没有一句面向创作者的价值叙述。**这个仓库在按"Agent 基础设施"演进，而不是按"创作工具"演进**——宣称的用户和工程投入的方向已经分叉。

### 1.2 核心场景没有收敛

同一份产品里同时存在四种互不兼容的产出预期：

| 预期 | 需要什么 | 现状 |
| --- | --- | --- |
| 一部剧 | 集、角色一致性、批量、审片 | 集被删除，其余为零 |
| 单支 AI 视频 | 一次生成 + 一次导出 | 能力齐全，但没被当成产品卖 |
| 自由探索 | 无限画布 | 与四阶段互斥，且创建时强制二选一 |
| Agent 编程平台 | MCP、Skill、令牌 | 面向开发者，不是创作者 |

"短剧"和"单支视频"的成本结构完全不同：短剧是 N 集 × M 镜头，同一组角色、同一套风格，价值来自**复用率**与**一致性**；单支视频是一次性、单点质量。前者需要一个"剧"的容器，后者不需要。**当前产品只有后者所需的全部零件，前者所需的一件都没有。**

### 1.3 结论

- **应该服务**：3–10 人的小型短剧/内容工作室里那个既懂分镜又能配 Key 的人；以及有数据合规要求、必须私有部署的团队。后者是唯一结构性可守的人群。
- **不应该服务**：零基础小白（配置门槛挡住）、纯 C 端娱乐用户（无模板、无社区、无免费额度）、大型剧组（无协作、无权限、无审片）。
- **明确不做小白市场**，把有限工程投在"工作室的第一个付费席位"上。这个取舍会贯穿后面所有建议。

## 2. 核心功能与差异化定位

### 2.1 三列对标

| 维度 | LibTV | Flova AI | 本产品（实测） |
| --- | --- | --- | --- |
| 入口范式 | 无限画布 + 节点工作流，人/Agent 双入口 | 对话即工作流，Agent 拆解全流程 | 固定四阶段线性 + 可选右侧助手；另有一套画布，创建时二选一且创建后固定 |
| 自动化程度 | 节点编排，人工搭流程 | 一句 brief → 剧本/分镜/镜头/素材/音乐/时间线 | 半自动：AI 只做"提取"，且两个入口都被降级成无文字图标；生成逐个镜头手工提交 |
| 模型供给 | 50+ 聚合，平台供给 | 50+ 顶级模型，平台供给 | 全 BYO，无预置、无额度、无代供 |
| 一致性控制 | 角色三视图 + 多角度 + 灯光运镜 | Asset Library 跨项目复用角色/场景 | 单图工具有多角度/打光/局部重绘，但素材仅限当前作品，无三视图锁定、无跨集继承 |
| 批量生产 | 分镜组、一键导出带序号 4K 大图、20 分钟合成 | Agent 全流程批处理 | **代码已支持**三种批量 + 预检，入口在镜头"…"菜单；文档却写"未实现" |
| 资产复用 | 社区 + 画布资产 | Asset Library 跨项目 + Skills 分享 | 零。主页资产库只读、不可采用、不可跳任务；无项目复制 |
| 协作审片 | 社区精选/挑战赛，无强审片 | 定点评论只改一处；团队版 100 席 | 无分享链接、无评论、无审片页；底层有版本校验与幂等，但没做成界面 |
| 导出交付 | 4K 大图、20 分钟合成 | 剪映/CapCut 草稿 | 720p/1080p + auto/16:9/9:16 + MP4；无 4K、无水印策略、无草稿、无分享页 |
| 商业化 | 免费 + 订阅 + 积分包 + 企业采购 | Freemium + 订阅 + 按秒计费 + 团队版 | 零计费、零额度、零定价页 |

### 2.2 真正站得住的四条优势

1. **私有部署 + 自带 Key**：SaaS 做不到数据不出内网、用自家采购的模型额度。这是竞品结构性无法复制的点，也是唯一能卖出高 ARPU 的点。
2. **Agent 可编程入口**：已有 12 项对外业务工具、具名令牌、IP/CIDR 限制、权限分工作台/媒体。竞品的"双入口"停在 UI 层，我们的能接外部流水线——对"内容工厂"是真需求。
3. **真时间线编辑器**：多轨、逐帧、波形吸附、响度分析、SRT 导入导出、多步撤销。竞品多数在"导出草稿"就结束，我们做完了最后一公里。
4. **审片可控的底层语义**：来源版本校验、幂等键、不自动覆盖、批次反序撤销、"已发生费用不退回"的诚实提示。这是给客户交付必需的，但**全部被压在交互摩擦里，没有一个用户能感知到**。

### 2.3 最致命的错配：名叫"短剧工作台"，却把"集"删了

不回避地论证：

- 短剧的最小生产单位是**集**，不是镜头，也不是项目。删掉分集后，"一部剧"在数据模型里不存在，只有 N 个互不相识的 Project。
- 由此产生四个不可修补的后果：
  1. **跨集一致性无处安放**。素材明确只属于当前作品，第 2 集要把同一角色的外貌、服装、年龄再描述一遍。LibTV 的"角色三视图/多角度锁定"和 Flova 的 Asset Library 都挂在**剧级**对象上，我们没有那个对象。
  2. **进度不可表达**。项目卡片只有模式与封面，用户看不到"这部剧做到第几集、第几集没出片"。
  3. **产能无法摊销**。第二部、第二集都要从零调参与调角色，边际成本不下降，LTV 锁死在 1 部作品。
  4. **交付不可打包**。没有"本剧/本集"的导出单元，只有单条成片下载。
- 公平地说，删分集不是无脑决策——旧分集捆绑了成员邀请、共享素材库、权限一整套，负担确实重。**但正确的取舍是"砍协作、留集"，实际做成了"砍集、也砍协作"**，把婴儿和洗澡水一起倒了。

### 2.4 取舍：冻结什么、押注什么

**冻结或降级**：

- **无限画布**：存量保可用即可，不再投新功能；从新建弹窗降为剧内次级入口。理由：画布侧自认"导演台开发中""生成协议与导入导出仍未验收"，用一个未验收的第二范式做创建时的强制决策，是当前最贵的错误。
- **Skill 独立页**：本地 Markdown/ZIP 导入，无市场无分发。个人创作者不写 Skill。降级为"内置创作方法"，藏在助手输入框的 `/` 里，撤掉一级导航。
- **MCP 令牌作为配置一级页面**：目标用户一辈子不会点，移到"高级"折叠。
- **助手运行时继续加能力**：继续修 bug，但不再作为主交付物。用户感知不到幂等键。

**押注（只押一件事）**：**多集连续生产 + 角色一致性 + 按集排队 + 审片链接**。
这是 LibTV（画布自由但流程弱、无审片）与 Flova（Agent 全自动但审片弱、无私有部署）之间的真实空档。我们已经有真时间线、有审片底层语义、有私有部署，只缺"剧/集"这层骨架和把能力搬到台面上。

## 3. 关键流程断点：从创作到导出

| # | 断点 | 位置 | 用户实际感受 | 影响 | 改进方向 |
| --- | --- | --- | --- | --- | --- |
| 3.1 | 激活断点 | 注册 → 空项目列表 → 新建只填名称+模式 → 空剧本页 → 生成时卡在模型空态 | 没人告诉我要自己买 Key；点生成只看到"请先选择已启用的模型"，旁边只有"重试" | 这是转化率分母。按当前路径（四类模型 + 逐镜提交）保守估计 40–90 分钟且必挂在配置 | 给一条平台代供的默认链路或一键预设；模型空态内联"去配置"三步向导，而不是"重试" |
| 3.2 | 找模型与配密钥 | 配置 → 模型（文本/图片/视频/音频四页） | 这是运维界面，不是创作界面；四类分别配，还不知道每类该填什么协议 | 新用户流失第一因；平台无毛利、无用量数据 | Provider 预设 + 一次连通性校验；未通过校验的模型不出现在生成下拉里 |
| 3.3 | 从想法到剧本 | 剧本页四个设定输入框 + 空正文 | 面对全空白文档，工具不给任何起点；AI 只在我先手写、再选中之后才出现 | 首次进入 24h 内产生正文的比例直接受此决定 | 空态给三个"半成品起点"：一句话生成分场列表 / 结构模板 / 粘贴小说拆场 |
| 3.4 | 剧本到素材 | 素材页一个无文字的"记录"图标，点开默认进提取历史空列表 | 我要"从剧本生成角色"，却只看到历史图标；点开是空的，以为点错了 | 这一步被绕过 → 手工建角色 → 一致性、批量、音色能力全部空转 | 升级为带文字主按钮"从剧本提取角色与场景"，默认打开设置页；结果出角色卡，卡上直接"生成三视图" |
| 3.5 | 素材到分镜 | 分镜页标题旁"记录"图标 + 分镜数按钮打开同一弹窗 | 核心动作"生成分镜"被包装成"查看记录"；第一次进分镜页只有"请选择左侧镜头" | 用户不会用 AI 分镜，就退化成手写 45 条镜头，产品价值归零 | 空态直接给"从剧本生成分镜"+ 目标镜头数/单镜时长，生成后进逐镜核对；记录降为二级 |
| 3.6 | 分镜到视频（逐个镜头） | 每镜单独提交；批量藏在"选中镜头 → … → 批量操作" | 一集 40–60 个镜头 = 40–60 次提交与等待，没有"整集排队" | 单人一天做不完一集，短剧的商业前提（周更/月更）不成立 | 分镜页加"本集排队生成"：全选待制作 → 一次预检（N 任务/耗时/成本）→ 后台批次 |
| 3.7 | 改稿到成片同步 | 成片页手动点"同步分镜视频"，系统不提示有未同步变更 | 改完第 7 镜得自己记住回成片同步；忘了就导出旧片 | 交付事故，且用户会归因于"这工具不可靠" | 不放弃"不自动改写剪辑决定"，但把状态可见：第 4 步角标 + 成片横幅 + 导出前强制检查 |
| 3.8 | 导出与交付 | 720p/1080p + 三种画幅 + MP4 | 只能下载文件再自己发微信；客户说"第 12 秒改一下"，只能重导全片重发 | 无法承接商业交付；失去最强的自然增长入口 | 先做两件：导出前检查 + 只读审片链接（时间点评论、可带水印、带品牌角标） |
| 3.9 | 第二次创作 | 素材仅当前作品；主页资产库只读；无项目复制 | 第二部要从零再描述同样的霸总、同样的办公室，抽过的卡全部作废 | LTV 锁死在 1 部；调好的角色与风格无法摊销 | 剧级角色库（跨集只读引用 + 复制为素材）+ "从本集复制新建下一集" |
| 3.10 | 导航层 | 四阶段只有图标与悬停文字 | 不知道自己在第几步、做完没有、下一步干什么 | 阶段跳转靠猜；这也是"同步靠记忆"的同一病根 | 图标挂状态短标 + 头部恒定一个"下一步"主 CTA |

**三处最值得先修的**（原因不是"重要"，而是"便宜且直接改指标"）：

1. 3.6 的批量：后端能力、幂等、并发、失败重试全部已有，只缺入口与"按集"作用域。
2. 3.7 的未同步：后端已算出 stale，前端没展示，导出没拦。
3. 3.3/3.4/3.5 的空态：三处各加一个主 CTA，不需要恢复"整篇生成"按钮。

## 4. 信息架构与交互设计

### 4.1 现有 IA 的六个问题

1. **创建时就要做范式决策**：新建弹窗强制在"创作模式/无限画布"里选，且创建后固定。用户连要做什么都没想清，就被要求选工具形态；而画布侧自认"导演台开发中"。**这是把内部架构分歧外包给用户。**
2. **"素材/资产"三处命名打架**：全局导航叫"资产库"（只读），项目阶段叫"资产生成"，面板标题是"素材"，提取入口叫"资产提取记录"。同一个东西四个名字，且只读的那个占了好名字。
3. **配置区过重**：模型四页 + 助手三页 + MCP 令牌，全部平铺在一级导航。目标用户一辈子用不到一半。
4. **40px 图标导航信息量为零**：4 个无文字图标，悬停才出字。
5. **1280 视口下三栏争空间**：1280 − 阶段导航 40 − 助手 380 ≈ 860，素材页还要再切三栏，主面板实际可用约 500–600px。这是用户宁愿关掉一切的原因。
6. **只读区与生产区互不连通**：主页资产库（只读、不可采用、不可跳任务）与项目内素材职责重叠却零通路。

### 4.2 目标 IA

```
工作台
├─ 剧集列表  /projects
│   ├─ 卡片：剧名 · 进度（3/8 集已出片）· 最近修改 · 封面（自动取第 1 集第 1 镜）
│   └─ 新建：模板（3 个短剧结构）/ 从现有剧复制 / 空白
├─ 剧  /projects/:id
│   ├─ 概览        本剧设定（题材/画幅/基调）、角色库、集列表、成片状态
│   ├─ 角色库（剧级）   角色卡：三视图 + 定妆描述 + 音色；集内只读引用
│   ├─ 集  /projects/:id/e/:ep
│   │   └─ 剧本 → 素材（引用角色库）→ 分镜 → 成片   ← 四阶段保留，只多一层
│   └─ 审片（新增）  只读播放 + 时间点评论 + 分享链接管理
└─ 全局：模板库 / 创作方法（原 Skill，降级）/ 配置（模型 + 账号；MCP 移入高级）
```

改了什么、为什么：

- 插入"剧—集"两层：这是唯一能让一致性、进度、复用有地方放的结构性改动；同时把"新建时选模式"变成"新建时选模板"，范式决策下沉到剧内"另开画布"。
- 撤掉全局"资产库"一级入口，并入"角色库 + 集内素材"；素材只在有上下文的地方出现。
- 审片独立成页：审片不是播放器的附属开关，是交付动作。
- Skill 降级：从一级导航消失，改为内置方法，在助手输入框 `/` 里出现（这个交互已经存在）。

### 4.3 八条交互改法

| 改法 | 判定标准 |
| --- | --- |
| 阶段头状态化：图标 + 数量/状态（剧本 ✓ / 素材 8 / 分镜 24（12 待出视频）/ 成片 未导出） | 任意阶段页能在一屏内看出"哪一步没做完" |

## 5. 付费与增长机制

### 5.1 现状：三件事同时不成立

- 用户不知道花了多少钱：全仓 10 多处只写"可能产生费用"，0 处给数字。
- 平台不知道谁用了多少：无计量表，无用量报表。
- 平台无法对价值收费：无订阅态、无额度、无定价页。成本在用户侧以 BYO Key 结算，**等于平台把成本转嫁给了用户，也把收入让给了上游**。

### 5.2 建议模式：订阅 + 积分双轨

定价锚点用"集"，不用"秒"——因为我们卖的是产能，不是算力。

| 档位 | 价格 | 能力切分 | 积分/月 |
| --- | --- | --- | --- |
| 免费 | ¥0 | 720p + 水印；1 条默认模型链路；1 个项目并发；审片链接 1 条（7 天） | 200 |
| 创作者 | ¥59/月 | 1080p 无水印；批量排队；角色库跨集复用；审片链接 10 条；4K 图片导出 | 2000 |
| 工作室 | ¥199/席/月 | 6000 积分共享池；5 席；批量并发 4；自定义水印；商业授权书；优先队列 | 6000（池） |
| 企业/私有部署 | 年付议价 | 数据不出内网 + BYO Key + 私有 MCP | 按席位 |

### 5.3 积分口径与"一集多少钱"

按产出计，不按 token 计：

| 类型 | 口径 |
| --- | --- |
| 文本 | 1 积分 / 1k 字符 |
| 图片 | 6 / 张（1K）、12（2K）、24（4K） |
| 视频 | 1 积分 / 输出秒（720p）、2（1080p） |
| 配音 | 0.5 积分 / 10 字 |

**算例**：一集 3 分钟、45 镜 ≈ 45 张 2K 分镜图（540）+ 180 秒 1080p 视频（360）+ 1.5 倍重抽 ≈ **1350 积分**。创作者档 2000 积分 ≈ 1.5 集/月。用户能自己算出"一集多少钱"，才敢订阅。

### 5.4 免费版给什么、卡什么

给"能完整做完一集"（否则用户学不会价值），卡"交付质量与批量"（720p + 水印 + 无批量 + 审片 7 天）。这是 Flova 已验证的组合，不需要重新发明。

### 5.5 增长排序

| 动作 | 成本 | 作用点 | 优先级 |
| --- | --- | --- | --- |
| 审片链接 | 极低 | 每条链接都是带品牌角标的落地页，唯一能自传播的资产 | P0 |
| 模板 + 可 fork 的示例剧 | 低 | 解决"空剧本无起点"，同时把剧结构标准化，反喂分镜生成 | P1 |
| 邀请赠积分（双方各 200） | 低 | 直接作用于"第二部作品"这个卡点 | P1 |
| Agent/API 入口按调用计费 | 中 | 唯一的高 ARPU 增长口，且是独有项 | P2 |
| Skill/模板市场 | 高 | 需要审核与责任成本，个人创作者供给不足 | P2（最后做） |

**必须先补的顺序，不可跳步**：**计量（成本可见）→ 额度（拦截）→ 套餐（定价页 + 订阅态）→ 增长**。
没有计量就卖订阅 = 卖盲盒，会被退款与投诉打穿；没有额度就做不了免费版（现在的"免费版"等于让用户自己贴钱，这是零计费最荒谬的后果）。

## 6. 实施计划表

### 6.1 排期原则

1. **优先级不等于排期**。"不做就不成立"的标 P0，但先做"两周可交付、零迁移、直接改指标"的项，避免三个月后才有第一个可测变化。
2. **一期只放一类工作**：第 1 期全是"能力已在、入口缺失"；第 2 期才是结构改造；第 3 期才碰钱。混在一期必然同时延期。
3. **结构改造必须先于"按集"的所有功能**：集切换、按集进度、按集批量都依赖 episode 维度，否则要返工。

> 与初版优先级的一处偏离：原 P0-2"平台代供默认链路"拆成 2a（预置 + 空态 CTA，BYO Key）与 2b（平台代供）。理由：没有计量就开代供，一次脚本刷量就是真实资金损失且无法归因。2a 进第 1 期，2b 进第 3 期，且必须在计量跑稳两周后才开闸。

## 7. 风险与不可逆决策

| 风险 | 触发条件 | 影响 | 缓解动作 | 可逆 |
| --- | --- | --- | --- | --- |
| 存量迁移失败 | 唯一键重建锁表；回填漏行；生成列替换顺序错 | 分镜/成片全站不可写，回滚需停机 | 一个目录两个文件（先加列回填、后改键）不可合并；迁移前备份并预演生产副本；README 写校验 SQL 与回滚脚本；低峰执行、先停调度器 | 部分（schema 可回滚，回填是确定性映射） |
| 平台代供成本失控 | 密钥泄露 / 脚本刷量 / prompt 循环 / 突破日额度 | 直接资金损失且无法归因 | 计量先行；三层闸门（请求级余额 → 用户日额度 → 全局日预算）；一键关闸；对账差异自动降级；平台密钥只允许运维脚本写入 | 是（开关级） |
| 审片链接合规与盗链 | 客户转发给第三方；内容侵权；链接被爬 | 平台被判传播，工作室信任受损 | 默认 7 天 TTL + 可撤销 + 访问日志；媒体只发短签名直链；水印含收件人与时间；访问量异常告警 | 是 |
| 积分投诉 | 受理未知被扣费；失败未释放；用户不认同按请求计费 | 信任崩塌，客服成本高于收入 | 预占与扣费分离；受理未知默认不扣、次日自动释放；流水逐条可查；只冲正不退款 | 是（冲正条目，历史不可改） |
| 画布争夺资源 | 要求画布也接集维度 | P0 全线延期 | 画布表零改动，集字段恒为空，写进后端约定 | 是（不碰即无风险） |
| 命名分裂 | DB 叫 project，UI 叫剧，MCP 叫 project | 长期维护成本，新人做错层 | 不改表名；约定 project=剧、episode=集；MCP 只加可选参数不新增工具 | 是（纯约定） |
| 文档漂移 | 新增表或路由未同步 | 校验红、文档失真（已经发生过一次） | 每个迁移同 PR 改：全量 SQL、项目概览路由清单、所有表数句子、迁移台账 | 是 |

**四条不可逆决策（现在就要定）**：

1. episode 必须回填并设为非空。一旦允许为空，序号唯一性语义永久分裂，每次查询都要写兼容逻辑，第 2 集上线必出序号冲突。
2. 审片链接不能用对象存储长期直链。泄露即永久有效，无法撤销。
3. 积分不做成货币、不接支付。一接就引入退款、发票、合规链路，与"不服务小白、私有部署"的定位冲突。
4. 平台代供不建第二套凭据体系。与现有的凭据冻结机制双写，长期一致性成本会爆炸。

## 附录 A：与初版判断的三处修正

1. **批量生成不是"未实现"**：三种批次、预检、失败重试、并发上限都在代码里；缺的是入口与"按集"作用域，以及文档纠偏。这直接改变了第 1 期的性价比。
2. **40px 纯图标是项目内阶段导航，不是全局侧栏**：全局侧栏是 4 项带文字导航，进入项目后隐藏。两套导航并存本身也是问题。
3. **素材/分镜的提取入口仍在**，只是被降级成无文字的"记录"图标并默认打开历史列表。断点性质是"发现不了"，不是"没有"。

## 附录 B：证据边界

- 竞品信息来自官方站点与第三方评测的公开页面（2026-11），定价、模型清单会变，引用时以当时页面为准。
- 本项目结论均来自代码与文档实读；转化率、耗时、留存等数字是路径长度推断，**不是埋点实测**，上线后需用真实数据校准。
- 本计划未包含视觉设计稿与接口契约，进入开发前需按项目规范补 `docs/design/` 与 `docs/api/`。
