# Agent 上下文管理与截断恢复开发计划

状态：已完成。依据：[问题与数据库核对](../../reviews/2026-11-04-Agent上下文管理与输出截断分析.md)。用户已批准本计划并要求实施。

## 目标与约束

- 取消正式 Runtime 累计 token、240 次调用硬停止；实际用量、受理不明、权限和停止仍有效。
- 保留原模型、原思考模式；原生上限仍只有思考时准确报错，不自动关闭思考。
- 保留连接超时重试、响应空闲120秒直接失败；不重投历史失败 Run。
- 复用图、账本、Operation、检查点和事件，不新增数据库表、调度系统或成果事实源。
- 每步只检查当前修改，最后一次集中回归；子 Agent 继承主模型，不主动提交。
- 沿用当前已包含本任务前序实现的开发工作区，保存修改前副本以区分已有改动。

## 实施与本步检查

- [x] 1. 容量：有效声明优先，精确官方 DeepSeek Flash/Pro 使用1000000窗口、393216输出；去掉262144截顶。选择器2048、摘要8192、标题64，网关与预留共用实际容量。检查容量解析及出站参数。
- [x] 2. 累计额度：取消正式Run账本硬拒和ModelCallLimit，图递归与预算解耦；保留实际计量。预置超旧额度只发一轮验证。
- [x] 3. 截断分类：Chat length、Claude max_tokens、Responses明确长度incomplete返回可恢复结果；保存原响应与用量，残缺工具不执行。检查各协议分类及未知受理边界。
- [x] 4. 输出接续：仅思考时在可用容量内倍增，原生上限仍无正文则报错；正文保存片段后续写并完整交付；工具参数截断要求缩小完整调用，连续三次无进展暂停。检查接续、去重和思考配置。
- [x] 5. 原结果回读：ReadReceipt补include_result、character_offset、character_limit，默认4000最大6000；返回完整正文checksum及游标，校验scope/交接/来源资格。检查分页校验和与越权。
- [x] 6. 卸载及摘要：先持久保存，再投影大结果；首次与重放一致，阈值min(8192,input_limit/4)。保留协议组与来源，活动方法/媒体按原语义。摘要后可再紧凑一次，固定内容仍不适配则准确报错。检查结果投影及摘要。
- [x] 7. 前端：recovery_states按scope持久展示正在继续生成/正在整理上下文，快照与事件一致；终态清除、失败仅后端一条、预览截断独立。检查状态与类型。
- [x] 8. 集中验证：changed dry-run后明确选择本次功能，后端/MySQL/前端/浏览器、双前端构建、Ruff、docs/quality各一次；真实DeepSeek短任务验证，边界用受控响应。同步维护文档与验收记录，重启受影响服务并检查健康。

## 接口

- 容量声明补max_output_tokens，仍绑定模型版本、地址和凭据身份。
- RunRead补recovery_states: [{scope_id, model_call_id, kind: output_continuation|context_compaction}]。
- run.recovery事件提供当前完整recovery_states列表；终态清空。
- 回读补正文页content、total_characters、checksum_sha256、next_offset。
