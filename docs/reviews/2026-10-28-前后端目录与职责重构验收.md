# 前后端目录与职责重构验收

本轮将目录规划落实到源码、导入、运行注册、测试选择与维护文档。完整现行目录见[目录与职责维护](../instruction/目录与职责维护.md)，旧文件去向见[源码迁移映射](../data/2026-10-28-源码迁移映射.json)，实施边界见[本次计划](../plans/2026-10/2026-10-28-前后端目录与职责重构.md)。

## 目录与职责

- 前端应用壳进入 `app/{router,providers,layouts,styles}`；页面使用目录内 `index.tsx`，有独立样式时使用 `index.css`。实际交互进入 `features/<业务>/<具体能力>`，复杂能力继续按编辑、列表、历史、恢复等变化轴细分。
- 具名类型集中在 `types/<业务>/<功能>`，请求集中在 `api/<业务>/<功能>`；公共界面与纯工具进入 `shared`，跨业务的会话及反馈留在明确的业务公共目录。类型层不反向依赖功能实现。
- 后端保留 API → Service → DAO → ORM；各层内部按业务及能力组织。受理、查询、执行、归档、结算等 Service 拆分共享同一 Session，不因文件拆分增加提交边界。
- 画布内部保持独立子包，宿主访问集中到 `integrations/canvas`；会话桥接仍复用宿主唯一 HTTP 客户端。没有重新实现画布交互。
- 728 条旧源码路径全部登记，映射支持一对多；空数组表示有退役理由的删除，不是运行时兼容入口。迁移目标存在性与已删除源码覆盖均核验。

生成受理原文件 869 行，拆为 6 个职责文件，最大 483 行；生成执行原文件 917 行，拆为 6 个职责文件，最大 402 行。分镜列表、详情载入、草稿恢复、移动删除、信息编辑、工具栏与菜单也已提取，保存和选择生命周期保留在工作台。

## 中文注释与关键行为

注释集中解释不能从代码表面看出的约束：权限作用域、事务及幂等受理、版本围栏、迟到响应、409 保稿、未知受理原请求核对、控制水位、在途取消与删除收尾。不逐行翻译显而易见的代码。

- `prepare-send.ts` 说明重试必须复用冻结载荷和幂等键，不能重新采集输入。
- 助手控制明确拒绝过期 `expected_control_seq`，前端仅在能证明未受理时释放恢复记录；普通未知冲突继续保留原请求。
- 删除助手对话时，停止 Task 后仍等待在途 Run 释放并完成正文保存，再执行清理。
- 播放器时间轴坐标未变化时复用旧状态，避免无效渲染循环中断音频。
- 生成、编辑会话与资源访问的拆分保留原权限、版本及事务边界。

本轮同时修复搬迁验证发现的历史回调缺失、成片 Escape 处理范围、重复项目条件、工作台壳样式遗漏、终态助手连接动画及迁移工具旧写作表名。CSS 职责拆分时逐字符和顺序核验等价；之后的工作台布局修复属于有意调整，不能将最终全部 CSS 描述为字节等价。
