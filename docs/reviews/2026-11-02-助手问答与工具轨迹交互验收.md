## 交付行为

- 问答面板位于聊天滚动区外、输入框上方，支持单选、多选、1–12 题前后切换，以及并行问题组分别保稿。
- Agent 每题提供 2–4 个候选；单选推荐一项，多选至少推荐一项。界面追加“其他…”，选中才展开输入，推荐项不自动代选。
- 成功提交或核对到已处理后隐藏面板，刷新不重现；答案以自然语言保存为真实用户消息，结构化答案仍用于原 Run 恢复。未知请求保留原体与幂等键，409 保稿，停止后禁答。
- 已删除输入区的当前任务／开始新任务栏；独立会话使用顶部“新对话”。
- 工具轨迹仅显示操作、具体对象和状态，无参数、结果 JSON、版本、路径、耗时或详情展开。实际公开思考及独立业务成果的查看、审阅、试听、撤销继续保留。

## 原运行时的未闭环问题

合并 MySQL 回归中，`test_graph_answer_sources.py::test_current_run_sources_survive_summary_and_worker_rebuild_without_reviving_withdrawal[False]` 一次在答案来源断言失败；该测试的两种参数随后单独重跑均通过（2 passed，108.25 秒）。重跑通过不等于已消除间歇失败。

只读审查发现可解释该现象的既有时序窗口：`AgentTranscriptDAO.scope_answer_messages` 仅接受 Operation 成功且 `wait_state.consumed=true` 的答案；`finish_tool` 先提交成功，consumed 由 saver 后台 `put_writes` 另行提交，下一次 `ContextMiddleware.abefore_model` 可能在后者之前读取来源。当前普通聚合 messages 通道的这项 pending write 未纳入 checkpoint 的同步等待。未用延迟注入做确定性复现，因此尚不能断言该次失败必然由此引起。

该筛选不读取答案正文内容，相关运行时文件也未在本轮修改；本轮保留其行为，未扩大为图持久化改造。后续应围绕 pending write 与上下文读取顺序独立复现并修复，不能通过放宽答案范围或跳过断言掩盖。
