# Harness 长任务回读与续执行修复验收

## 问题与证据

本次只读核对实际验收任务的 Run、Turn、Operation 与冻结输入，没有修改业务任务或替用户继续创作。

| 现象 | 已确认原因 | 修复 |
| --- | --- | --- |
| 作品内容反复回读失败 | 实际正文已在 `results[].content` 返回；模型误把读取操作 ID 当成原保存批次，且原批次被最近 20 条回执挤掉 | 独立 `result_sources` 轻目录、分页、`receipt_operation_id` 区分身份；传错 ID 返回可用来源目录 |
| 已选对象更新后无法核对 | 原回读只允许本任务新建对象 | 允许当前仍主动选入的素材／分镜回读本任务保存快照，撤销选择后拒绝，人工后续修改不注入 |
| 图片读取先后失败 | 模型缺少图位 `item_id` 或整组来源参数，补齐后原读取能成功 | JSON schema 声明来源分支，图位目录返回 `read_content_args`；保留服务端完整校验 |
| 长任务重复核对旧步骤 | 进度压缩漏掉嵌套的 `results[]/items[]` 正文，只剩大量旧旁白 | 已读正文优先保留原文摘录、原保存来源及范围，并去重；不额外总结或载入实体 |
| “继续”没有执行 | 暂停任务的新输入复用了已失败 Run，且刷新后前端未选中该任务 | 普通消息在同 Task 下创建新 Run，恢复已结算工具历史及活动方法，保持输入幂等 |
| 任务达到执行上限 | 实际任务在第 32 次决策暂停；当时 104 次工具调用、22766 输出 tokens、约 349 秒，非供应商额度耗尽 | Harness 取消累计决策、工具、输出与活动时长上限；旧有限预算快照也按当前策略解释 |

单次请求输出、工具数、超时、上下文、媒体和来源保护仍然生效；旧引擎及中断控制保持原边界。

## 补充边界修复

新增回归发现，任务暂停期间遗忘记忆或方法加载来源时，原失效通知只更新活跃 Run，导致续执行可能带回旧工具正文。失效通知现覆盖暂停 Harness 的最新 Run，并把失效标记交给新尝试；来源撤销、方法换版和遗忘都会移动任务级历史下界。

另有一条存量记忆测试仍把 `save_delta` 当布尔返回值。经 AST 对比，HEAD 与工作区的该方法一致，实际契约为 `ok/lost/cancelled/stale`。测试改为核验 `stale` 并确认没有写入旧 `assistant.delta`，独立重跑通过。

## 真实模型长任务

使用用户授权的网关及 `gpt-6.1-sol`，密钥只在测试进程内传递。随机 MySQL 测试库与 MinIO 对象前缀在结束后清理，不使用业务库保存验收成果，不调用任何媒体生成节点。

首轮已完成工具与保存链路，但最终回答漏掉用户要求的视觉结论，验收判失败。冻结约束和已读观察实际仍在上下文中；随后补强通用交付核对提示，要求最终答复覆盖用户指定结论，避免旧进度旁白缩减任务要求。没有放宽断言。

修正后完整长任务通过：

| 指标 | 结果 |
| --- | --- |
| 模型决策／工具操作 | 20 段／19 次 |
| 任务本体耗时／pytest 总耗时 | 146.25 秒／177.29 秒 |
| 保存批次与实际成果 | 1 批，2 个角色、3 个关联分镜，逐批正文回读成功 |
| Skill 与资料 | 2 个方法加载、重复加载去重，6 段 references 按序读取，脚本只读 |
| 图片 | Skill 示例图和已选素材图位均成功读取，最终说明蓝条位于左侧 |
| 上下文压缩 | 最多移出 16 个旧工具组，2 个活动方法保留，L4 约束整理生效 |
| 恢复 | 人为模拟原回执保存后的 Worker 丢失，通过离线回执恢复，重放新增请求为 0 |
| 媒体实体泄漏 | 0，校验 Run、Turn、Operation、ToolCall、输入、消息与图状态 |
| 外部请求／供应商报告 tokens | 22 次；输入 921496，输出 6767，按供应商 usage 累加 |

该真实任务没有超过 32 次决策；跨原上限由前述本地协议＋真实 MySQL 的 41 次决策测试证明。“继续”的同任务新尝试及遗忘边界由数据库集成测试证明，未将其称为真实模型中断验收。没有验收 Claude 真实供应商、生图、生视频或音频生成。

## 代码复审

按 `code-review-skill` 执行范围、设计、逐行和结论四阶段；对较大差异运行技能的复杂度分诊。复审聚焦冻结回执兼容、并发锁顺序、任务来源范围、分页有界读取、累计预算序列化和续执行失效通知。暂停期间遗忘后旧正文复活的问题列为阻塞项并已修正，相关回归通过；没有待处理的阻塞或重要项。

当前机制见 [Harness 运行机制](../instruction/AI创作助手Harness运行机制.md) 与 [助手 API](../api/assistant.md)。不自动恢复用户业务任务，重启服务后由用户在原会话发送“继续”验收。

API、Agent Worker 与 scheduler 已在确认无活跃 Agent Run／记忆作业后重启。前端 `8080`、API `8000/openapi.json` 均返回 HTTP 200，Agent 队列有 1 个消费者、无积压；Worker 配置禁用远程控制，健康核对采用 RabbitMQ 被动队列声明。当前提示词为 `assistant-harness-v3`。前端沿用 Vite 热更新，本轮未执行浏览器交互验收。
