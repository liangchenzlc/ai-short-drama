继续使用 LangGraph、LangChain function calling、L1–L5、冻结请求与回执账本。沿用 Task JSON，无新增数据库表、环境变量或依赖。前端仅同步模型容量及记忆作业终态 DTO／请求参数；未实施第四批创作一致性检查和交付进度界面。没有增加旧中断系统、多 Agent、向量库或脚本执行。收尾有一条[记忆状态 CHECK 增量](../database/migrations/2026-10-26-agent-memory-retry/README.md)，用于补齐原运行时已有的终态。

候选文本不能先进入 SSE：新监督请求在结算前暂存流式文本，工具旁白结算后发布，最终答复经检查通过后发布；旧冻结请求按原协议恢复。独立检查使用同一有界工具历史，能核对近期实际保存正文与回读范围，不仅依据状态回执。

## 真实模型长任务

授权网关和 `gpt-6.1-sol`，凭据仅通过进程输入传递，不写入源码、配置或本记录。使用真实 MySQL、MinIO、LangGraph 和 LangChain，禁止提交任何生图、生视频或音频生成。

场景包含两个手选 Skill 与重复加载、六段按序资料及工作笔记、只读脚本、Skill 示例图与已选图位的像素理解、两个角色和三个关联分镜的真实保存、逐保存批次回读、L4 真实模型压缩、近期窗口淘汰及活动正文保留、原始回执后模拟 Worker 丢失和恢复，以及最终独立完成检查。测试驱动最多 80 个边界用于结束失控验收，不是产品 Task 上限；压缩阈值缩小以触发真实整理路径。

本轮真实模型长任务通过，机器结果归档于 [真实模型验收数据](../data/2026-10-26-Harness前三批真实模型验收.json)。pytest 共 915.34 秒，任务运行部分 886.55 秒；初始化与清理不计入任务时长。

检查首先发现实际漏做的重复加载步骤，交回原 Agent 补齐；后续补充可核对的分镜正文和回读，最终才发布完成答复。首次工具参数遗漏分镜版本时，结构化错误允许模型修正后成功保存。一次网关失败计入外发次数，后续普通消息创建新 Run；没有自动重发受理不明的原 POST。缓存数字是该次网关报告，不代表线上收益基准。

此前失败和修复如下：

1. 模型反复改述已登记要求造成重试：保留原要求表述，允许数量不降低的加强，错误回传已登记要求及无效来源 key；提示词明确无须反复登记。
2. 长请求触发 MySQL 1038 `Out of sort memory`：先后定位到历史 ID 排序的 JSON 筛选，以及工具领取／恢复中最新 Turn 的整行排序；均改为先取 ID，再读取正文。专门大行数据库回归通过，未增加全局 sort buffer 掩盖查询问题。
3. 成果目录读不存在的 Task 字段：修正为读取该任务最新 Run，四个受影响场景重跑通过。
4. 检查节点只有状态回执，缺近期正文：保留同一有界 manifest；新增数据库断言，证明实际回读结果进入检查请求。工作笔记遗漏由检查返回原 Agent 补齐，不移除该验收条件。
5. 写入与回读作为混合检查证据时误拒绝：只从实际写入计算类别和数量，允许回读辅助语义核验；单元及 MySQL 回归覆盖混合证据，回读不能虚增保存数量。
6. 模型拼接不连续原文作为工作笔记引文：保留严格连续引文校验，字段说明及失败详情提供可复制的真实短片段，避免只收到通用错误后重复同一参数。
7. 完成检查重复抄写整份要求，误改分类或来源并触发结构校验失败：检查协议 v2 改为已有要求仅提交 key 与核验字段，定义由服务端读取；漏登要求单独附真实来源。工作笔记和登记要求分别用 `observation/contract` 核验，不能误作业务保存。读取检查允许笔记辅助，但仅计算实际读取次数；工作笔记记录自身操作 ID，并保持重复记录去重。近期轻回执固定保留 64 项，仍不扫描全量正文。增加单元覆盖数量不降低、未知 key／覆盖定义拒绝、状态失效及 v1／v2 回执兼容。
8. HTTP 500 空错误体被误判为 JSON 响应不完整：空错误体沿用 HTTP 状态分类，流式／非流式专项覆盖 400、401、429、500 与发送前拒绝，确认单次发送、不暴露供应商私有正文。SDK 未分类错误仅记录异常类型等安全诊断字段。此前第七轮 `agent_provider_error` 未完成长任务，不计通过。
9. 第八轮完成检查通过，但独立验收断言发现只保留一个已加载方法，未满足两个方法的原始要求：不将该轮登记为成功。复核发现 L4 替换输入后仅有改述摘要供补漏要求使用，新增 `requirement_sources` 原文配额投影；保留初始目标和最新输入、seq、截断与遗漏状态，遗忘来源过滤，超过配额仍通过现有工具读取。新增来源配额单元检查，并在真实长任务中断言 L4 压缩后原始要求仍可精确引用。语义核验仍不能被宣称为完整证明。
10. 第九轮仍使用较早代码，把图片目录与像素混合证据误判为缺少像素；已停止该轮并保留轨迹，不计通过。图片核验现允许目录辅助，只计算真实像素交付。另为已通过执行项保留可失效的证据 ID 投影，后续仍查询真实操作，不自动批准本次检查。补充单元验证目录不能增加像素数量、要求变化及历史下界失效，以及旧成功证据后来失败仍拒绝完成。
11. 检查模型将空的配音台词视为没有剧本文字：verification 明确 `script` 与 `dialogue.document.lines` 的独立含义，按用户实际要求核对。提示版本冻结为 `assistant-harness-v8`。
12. 第十轮首次独立检查发现创作目标目录被核验器错误排除出读取证据；停止该轮，不计通过。将 `describe_creation_target` 纳入读取分类，单元确认它不能充当保存证据，数据库回执重放场景同时检查真实目录读取。真实模型验收保留原目录要求，不修改要求绕过检查。
13. 复审发现 L1–L5 来源查询仍选择完整 Operation 行：改为只投影所需元数据与显式记忆来源消息 ID，保留原完成时间、身份及来源 hash 语义。大行数据库用例额外检查来源查询不含工具结果或变更正文，并扩大到既有记忆回归。
14. 扩大记忆回归发现凭据不可用时抽取任务无限排队：发送前失败没有增加发送次数，却进入按发送次数限制的通用重试。改为只允许明确限流，以及抽取任务已持久化的无效输出，按三次发送退避；凭据／配置及鉴权直接失败，受理不明不重发。新增终态测试进一步发现原 `abandoned` 状态未进入数据库 CHECK 和响应枚举；补齐 ORM、Pydantic、前端 DTO、单项增量及幂等迁移。保留原抽取水位语义，不改为忽略所有失败范围。

先前中止／失败轮次均不计通过；本表只使用第十一轮成功运行的新结果及对应成功退出日志，没有使用旧结果文件。

场景的“同名包裹”线索断言同时读取真实保存的标题与正文：正文须有包裹，标题或正文须点明同名。已观察到模型在标题写出“同名包裹”，正文通过“为什么写我的名字”呈现误会；把两个词限定在同一正文行会产生错误否定。关键词断言只覆盖本场景，不替代创作质量评价。

当前 Skill 管理接口已移除调用方式字段并禁止新脚本导入，相关测试已同步。脚本只读场景由测试夹具追加历史包版本，保留原不可变版本；公开导入仍断言拒绝脚本。该夹具仅写入随机测试库和验收专用对象前缀，不开放脚本上传或执行。

扩大既有记忆回归时同步了迁移后的 `agent.memory.runtime` 测试替换路径，以及自动抽取使用会话作用域的旧测试夹具；没有改变 L1–L5 的作用域业务规则。Skill 服务增加延迟注解，修复类内 `list` 方法遮蔽内置泛型导致的模块导入失败，Agent 单元回归包含该导入链。

本地 `short_drama` 已实际应用记忆状态 CHECK，迁移前后均为 17 条记忆作业，第二次核验无待执行项。重启预检另发现工作区现有 Skill 管理改版的版本 CHECK 尚未同步；仅将该 CHECK 对齐当前 ORM，保留旧 `invocation_mode` 列及两条设置的全部原值，没有删除字段或设置。该兼容处理不代表已完成 Skill 管理的列清理迁移。结构预检恢复 `ready`，API、scheduler、Agent Worker 已重新启动，API 探针返回 `ok`，前端 8080／8082 保持监听。
