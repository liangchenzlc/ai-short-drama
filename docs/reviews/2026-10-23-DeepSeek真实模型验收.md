**对象：** `deepseek-v4.1-flash`（OpenAI 兼容网关 `https://sub2.de5.net/v1`）
**范围：** Agent 网关层真实调用，覆盖文本、流式、工具调用、工具续段、缓存计量、错误映射。

| 流式增量 | 通过（流式字符数与最终文本一致） |

## 二、模型 ID 校正

用户提供的 `deepseek-4.1-flash` 在该网关上返回 404；`GET /v1/models` 列出的实际 ID 为 **`deepseek-v4.1-flash`**。配置模型时必须使用带 `v` 的 ID，否则会被归类为 `agent_provider_rejected`。

## 四、供应商行为观察

- **缓存字段只在命中时出现**：首次调用 `usage` 只有 `prompt_tokens/completion_tokens/total_tokens`，命中后追加 `prompt_tokens_details.cached_tokens`。未上报时不写字段的设计是必要的，否则会把「未报告」误判为「命中 0」。
- **缓存有最小前缀**：约 40 token 的短提示连续调用不返回缓存字段；2.1K 字符（约 1.4K token）的稳定前缀稳定命中。这解释了短会话看不到缓存收益。
- **叙述与工具调用可共存**：同一次响应既有 `content` 又有 `tool_calls`，验证了 P1 从终止响应提取 `narration` 的路径成立。
- **推理 token 独立计费**：`completion_tokens_details.reasoning_tokens` 单独出现，不影响现有 `output_tokens` 统计。

## 五、本轮未覆盖

1. **应用层全链路**：需要登录态与项目数据，创建模型配置（密钥加密落库）、发起任务、执行 Worker、候选入轨。网关层通过不代替这一层验收。
2. **媒体生成**：该网关只有文本模型，图片/视频/配音未验证。
3. **浏览器观感**：时间线交错、步骤折叠、中断保留文本需要人工在页面上确认。
4. **长会话成本曲线**：只验证了单次前缀命中，未跑 10 轮以上的累计 token 与耗时对比。

以上四项应在下一轮全栈验收中单独记录，不并入本结论。
