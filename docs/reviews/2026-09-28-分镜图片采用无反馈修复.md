# 分镜图片采用无反馈修复

点击确认采用后，前端读取分镜但未发出采用请求。原生确认框恢复窗口焦点会刷新模型能力，递增生成准备的版本标记；采用已有图片共用了这个标记，因此在准备期间被判定失效并直接返回。父级提示被图片预览遮挡，成功采用时预览也未关闭。

采用图片现在使用独立的准备标记，不依赖下次生成所用模型或能力刷新。分集切换、只读状态、画幅变化、分镜保存、服务端版本和上下文检查仍生效。失败反馈显示在预览弹窗内；成功后释放操作锁、关闭预览和历史弹窗、刷新当前采用图片。

验证：

- 新增焦点刷新回归，修复前失败、修复后通过；覆盖采用期间以及旧图二次确认期间的刷新。
- 生成和采用两种操作均覆盖只读、画幅、切换分集和卸载导致的失效保护。
- 前端 105 项测试通过，TypeScript 检查及生产构建通过。
- Playwright CLI 在实际本地分镜页面验证：准备期间触发焦点刷新仍提交采用；版本冲突在预览内可见；旧上下文二次确认成功；关闭弹窗并更新当前图片。检查桌面 1440×1000 和手机模拟视口 390×844。
- 浏览器回归的 3 次采用请求全部在浏览器中拦截，成功回包及采用后的列表仅为本地模拟；没有改变真实采用记录，没有生成调用或新增费用。

浏览器脚本：`frontend/scripts/shot-image-adoption-acceptance.mjs`。在隔离浏览器打开含候选图的分镜页后，通过 `playwright-cli run-code --filename=...` 运行。脚本阻止所有真实写请求，完成后撤销拦截并重新加载页面。
