## 一、结论先行

1. **两个项目的形态根本不同**。OpenMontage 是"Agent 即编排器"的本地工具链，没有数据库、没有账号、没有事务；AI Short Drama 是有 52 张表、多人协作、候选采纳、乐观锁的产品级服务端系统。**能借鉴的是方法与判断标准，不是代码结构。**
2. **最大价值不在"补功能"，在"补判断标准"**。你的后端已实现配音、字幕烧录、混音、批量任务、原生角色对白（比根 README 描述更完整）。真正缺的是：什么样的分镜算合格、什么样的成片可以交付、模型凭什么选它。
3. **最高价值的四项**：参考视频反向拆解（93）、分镜结构质检（92）、合成前后 QC（91）、阶段导演技能（89）。前三项几乎不增加模型成本，却能直接降低废片率。
4. **合规红线**：OpenMontage 是 **AGPL-3.0**。你的平台有账号体系和对外服务，一旦复制其代码，整个服务端可能被要求开源。**只能读思路、独立实现，不要拷贝源码。**

## 四、Top 6 落地要点

### 1. 参考视频反向拆解（93）

**为什么最值钱**：这是短剧创作者真实的工作起点——"我要一个像《XX》那样的开头"。现有流程要求用户先写完小说，等于把最难的创意环节留给了人。

**怎么做**：

```
输入：视频 URL 或上传文件
  ↓ video_downloader / MinIO 直存
  ↓ ASR 转写（现有 canvas_cloud_transcription 可复用）
  ↓ ffmpeg scene detect 切分镜头 + 每镜抽 3 帧
  ↓ 多模态模型结构化输出
  ↓ reference_brief（候选，不直接改正文）
```

**结构化字段**：钩子时间点、前 3 秒信息密度、转折点位置、镜头数、平均镜长、景别分布、对白密度、情绪曲线、可复用套路。

**落点**：`service/reference_analysis_service.py`；复用 `AIGenerationRecord` 与候选采纳；新增 `reference_analysis` 表。

**验收**：输入一条 60 秒爆款，产出 ≥5 个可定位的时间点结论，且能一键转成剧本大纲候选。

---

### 2. 分镜结构质检（92）

**为什么排第二**：短剧"AI 味"的第一来源不是画质，是**分镜节奏单调**——每镜同景别、同构图、同镜长。这是纯规则能抓住的，零模型成本。

**6 个可落地的规则**（借鉴 OpenMontage 的 6 维，改成短剧语境）：

| 维度 | 检查内容 | 阈值建议 |
| --- | --- | --- |
| 镜长重复 | 相邻 3 镜时长差 < 0.3s 视为单调 | 占比 > 40% 警告 |
| 景别分布 | 近景/中景/全景是否形成递进 | 单一景别 > 50% 警告 |
| 构图重复 | 同一素材参考图复用次数 | 连续 3 镜同参考图警告 |
| 描述泛化 | "一个人""美丽的""现代感"等空词 | 命中即提示重写 |
| 对白密度 | 台词字数 / 镜头时长 | 超出 6 字/秒警告 |
| 转场单调 | 相同转场连续出现 | > 5 次连续警告 |

**落点**：`service/storyboard_quality_service.py`，纯函数、可单测；前端在分镜页顶部出质检条，点击定位到具体 shot。

---

### 3. 合成前校验 + 成片后自检（91）

**你现在的问题**：`video_render.py` 只要 FFmpeg 退出码为 0 就算成功。但黑帧、静音、字幕出画、音画不同步都不会让 FFmpeg 失败。

**检查清单**（全部用 ffprobe/ffmpeg，无额外依赖）：

| 阶段 | 检查项 | 失败处理 |
| --- | --- | --- |
| 合成前 | 素材文件缺失、旁白时长 > 视频时长、剪辑区间重叠或倒序、字幕超出片长 | 阻断，返回可定位错误 |
| 合成后 | 实际时长偏差 > 1s、前中后 4 点抽帧全黑、整体静音（mean_volume < -50dB）、峰值削波（> -0.1dB）、分辨率/码率不符 profile、字幕越界 | 标记 `qc_failed`，**不自动重试**，等人工确认 |

**落点**：`tasks/render.py` 增加 qc 阶段，产物写 `RenderQcReport`；前端成片页展示质检报告。

---

### 4. 阶段导演技能 + 审稿人自审（89）

你已有 `ai/prompts/{novel_script,script_assets,script_shots,shot_image,shot_video}` 和版本化机制，这是很好的底座。缺的是**两层分离**：

- `director`：这一阶段该怎么做（方法论、常见错误、优秀样例）
- `reviewer`：这一阶段交付前必须满足什么（可勾选清单，不满足不许提交）

**最小起步**：先只做 `script_shots`（拆镜）和 `shot_video`（分镜视频）两个阶段，各写一份 reviewer 清单。跑通后再铺开。

**关键约束**：技能文档存 DB（复用 `agent_skill_service`），支持版本号；不要把判断逻辑写进 Python 常量。

### 5. 风格 Playbook 结构化（88）

现在的 `episode.style` 是一句话，模型每次理解都不同，所以跨集必然漂移。

**最小字段集**：

```yaml
visual:      # 配色、色温、对比度、画面质感
lens:        # 焦段倾向、景深、机位高度
grammar:     # 平均镜长、景别偏好、运镜习惯
transition:  # 允许的转场类型、禁用类型
audio:       # BGM 基调、对白处理、音效密度
negative:    # 明确禁止的元素（如水印感、塑料质感）
```

**落点**：新表 `project_style_playbook`，项目级默认 + 分集可覆盖；在 `prompts/registry.py` 统一注入，禁止各 service 自己拼风格句。

### 6. 7 维服务商评分 + 自动降级（87）

你的 `adapters.py` 已经有能力标记和协议适配，改造成本比想象低。

**建议维度**（改成短剧语境）：

| 维度 | 权重 | 说明 |
| --- | --- | --- |
| 任务契合 | 30% | 该模型是否擅长这类镜头（人物特写/动作/空镜） |
| 角色一致性 | 20% | 多镜之间人物是否稳定，短剧的第一痛点 |
| 运镜质量 | 15% | 是否支持运镜指令、首尾帧 |
| 可靠性 | 15% | 历史失败率、超时率 |
| 成本 | 10% | 单秒成本 |
| 时延 | 5% | 出片等待 |
| 连续性 | 5% | 与已锁定风格/画幅的兼容 |

**降级链**：主模型失败 → 同能力次优 → 记录 `decision` → 继续，而不是把错误抛给用户手动重试。

**注意**：评分只能作为"建议 + 自动降级"，最终选择权仍应保留给用户（你的产品是人在环，不是全自动）。

## 五、不建议照搬的五件事

| 不建议项 | 原因 |
| --- | --- |
| **直接复制代码** | AGPL-3.0 有网络服务传染条款。你的平台对外提供服务，复制即可能被要求开源整个服务端。**只读思路** |
| **"无编排代码，Agent 即编排器"** | 你的系统有权限、事务、审计、协作要求，编排必须确定性。Agent 只能是发起者，不能绕过 service 直接改数据 |
| **YAML 流水线抽象** | 目前只有短剧一种形态。过早抽象会让四步流程变复杂，收益为负。等第二种内容形态出现再说 |
| **700+ 技能的规模** | 那是 Agent 工具链的产物，产品里不可维护。挑 15–20 条核心判断标准即可 |
| **文件系统状态（checkpoint JSON）** | 你已有 MySQL 事务和乐观锁，引入文件状态会造成双写不一致 |

## 七、评分方法说明

- **价值（40%）**：是否直接影响成片质量、付费意愿或留存。
- **差异化（25%）**：相对火宝、Jellyfish、CineGen、LocalMiniDrama、虾客漫是否形成区别。同类已有雏形的（如分镜规则质检）扣分。
- **落地成本（20%）**：反向计分。纯规则/复用现有服务得 5，需要新模型链路或新基础设施得 2。
- **架构契合（15%）**：能否复用现有 service、表、Celery worker、候选采纳机制。
- 综合分 = (0.40×价值 + 0.25×差异 + 0.20×成本 + 0.15×契合) ÷ 5 × 100。

> 本表为架构层面的借鉴评估，未做性能压测与真实模型效果验证。涉及具体排期需结合当前迭代负载另行确认。
