# Agent 上下文管理与截断恢复验收

日期：2026-11-04。对应[开发计划](../plans/2026-11/2026-11-04-Agent上下文管理与截断恢复开发计划.md)与[故障分析](2026-11-04-Agent上下文管理与输出截断分析.md)。本次在已有未提交改动的工作区实施，未提交代码、未重投历史失败 Run、未修改业务表结构。

## 实际改动

1. 正式 Harness 取消累计模型调用、输出 token、工具次数与活动时长硬限；保留真实用量、单次容量、权限、停止、租约和受理不明校验。图递归限额不再由累计预算推导，旧额度配置项已删除。
2. 容量声明增加 `max_output_tokens`，仍绑定模型版本、地址和凭据身份。有效声明优先；精确官方 DeepSeek Flash／V4-Pro 使用1000000上下文、393216最大输出，其它模型默认65536／8192。未知模型的8192为初值，可在窗口允许范围增长；声明与官方配置仍是单次原生上限。selector、summary、title分别使用2048、8192、64。
3. Chat `length`、Claude `max_tokens`、Responses明确输出长度原因的 `incomplete` 可恢复。原响应与实际用量先持久保存，残缺工具调用不执行；过滤、缺终止帧及受理不明保留独立错误路径。
4. 保留原主模型与思考配置。只有思考时逐步扩大单次输出；到原生上限仍无正文时返回 `agent_reasoning_output_limit`。正文通过同 Run、同 scope 的 Turn 引用登记片段，最终完整拼接；Worker恢复不重复交付片段。工具参数截断要求更小的完整调用，正文重复或同工具／参数／错误连续三轮无进展时明确停止，保留任务与成果。
5. 大工具结果先保存原文，再按 `min(8192, input_limit/4)` 投影到图；首次和重放一致。通过原 Operation 分页读取原文，默认4000、最多6000字符，返回全文校验和及下一游标。继续核验 scope、主体、交接、撤回与方法资格；活动方法及必要媒体组保持原语义。
6. 摘要按真实出站容量预留，可再紧凑一次；二次摘要仍保留当前必要媒体组，固定内容确实放不下时准确报容量错误。新输入或来源代次变化清除旧接续提示与无进展状态。
7. Run快照与 `run.recovery` 事件提供完整 `recovery_states`，按scope展示“正在继续生成”“正在整理上下文”，刷新可恢复，终态清除。失败消息只使用后端持久消息。

既有超时规则保持：首次连接30秒，确认未发送请求字节时最多重试5次，后续期限60／90／120／150／180秒；响应120秒无有效进展直接失败。连接重试只显示“连接超时，正在重试 1/5”，不增加单次最长等待文案。受理不明不自动重发。
