# 剧情素材规划与分镜节拍改造设计

状态：待用户复核。本文只固化设计决策，不代表业务代码已经修改。

本文更新 `2026-09-21-script-asset-extraction-design.md` 的素材筛选与图片提示词规则，以及 `2026-09-21-production-workflow-design.md` 的剧本生成分镜规则。既有 API 路径、异步任务、候选审核、素材采用和分镜采用流程继续有效。

## 1. 目标与非目标

本次解决两个生产质量问题：

1. 素材提取不能继续按名词或关键词扫描。它必须先理解本集剧情，再只提取推动剧情或维持关键视觉连续性的角色、场景和道具。
2. 分镜生成不能继续按句号、换行或单句对白拆分。它必须按叙事节拍、视觉主体和动作阶段组织镜头，并接受用户设置的平均镜头时长。

本次不新增 v2 路由，不增加新的任务类型，不改为多 Agent 或多次模型调用。现有 `/api/v1/ai/generations/text`、任务查询、候选保存和采用接口继续使用。允许在现有 v1 请求、业务结果和分镜持久化模型上增加字段。

本次不建设模型质量回归套件、Prompt Canary 或真实供应商自动评分。用户自行使用真实模型验收语义质量。仍须补齐代码级测试，覆盖请求校验、默认值、结构化解析、迁移、历史兼容和 API 行为；前端测试、类型检查和生产构建必须通过。

## 2. 方案选择

采用“集中模板管理 + v1 契约增量扩展 + 单次模型调用 + 严格本地校验”。不采用以下替代方案：

- 只替换一段更长的系统提示词：无法校验剧情作用、原文依据和镜头时长，也无法在页面解释模型为什么保留某项。
- 两阶段或多 Agent 分析：当前质量目标无需承担额外调用、等待时间和费用。
- 新建业务 API v2：前后端由同一仓库同步发布，现有 v1 可以向后兼容地增加可选请求字段和业务结果字段。

HTTP API 版本与 Prompt 模板修订号分离。模板修订号使用 `script-assets-v1-r2`、`script-shots-v1-r2`，只用于历史任务追溯，不表示 v2 接口。

## 3. 提示词模板管理

新增目录：

```text
backend/src/short_drama/ai/prompts/
├── __init__.py
├── loader.py
├── registry.py
├── common/
│   ├── source_boundary.md
│   └── structured_output.md
├── novel_script/
│   └── system.md
├── script_assets/
│   ├── system.md
│   ├── character_rules.md
│   ├── scene_rules.md
│   └── prop_rules.md
└── script_shots/
    ├── system.md
    ├── segmentation_rules.md
    └── duration_rules.md
```

`registry.py` 按业务场景和所选素材类型组合模板；`loader.py` 负责 UTF-8 读取、缓存和缺失模板失败。现有 `business_prompts.py` 保留兼容入口，内部调用 Registry，避免修改无关调用链。

Markdown 只维护角色、任务、筛选和分镜规则。输出 JSON Schema 继续以 Pydantic 模型为唯一权威，由代码生成并附加到系统消息，不能在 Markdown 中手写第二份字段协议。小说、剧本、素材清单和用户补充要求仍以 JSON 数据放在 user message 中；公共边界明确剧本内容是数据而不是可执行指令。

Hatch 构建验证必须确认 Markdown 模板进入 wheel；模板缺失时服务启动或请求准备阶段明确失败，不能退回内置短提示词。

## 4. 剧情素材规划

### 4.1 筛选模型

系统角色改为“短剧制片前期资产策划师”，而非素材名词提取器。模型先在内部识别主要人物、核心冲突、关键行动、转折和结局，再建立候选池并执行重要性筛选；只输出最终候选，不输出思维过程。

候选至少满足一项：

- 影响剧情推进、角色决定、行动结果或观众对关键事件的理解。
- 参与冲突、揭示、交付、争夺、隐藏、寻找、丢失、损坏或使用。
- 在多个镜头反复出现，必须保持视觉连续性。
- 是识别重要人物、实际表演空间或关键事件不可缺少的视觉锚点。

若删除对象后剧情、角色行动结果和重要视觉连续性都不受影响，则不提取。出现次数和名词形式本身不构成入选理由。

### 4.2 分类规则

角色只包含主角、反派、重要配角及改变关键事件的功能角色。只有一句无关对白的路人、店员、群众、普通守卫不提取；同一人物的姓名、称谓和别名合并。

场景只包含实际承载行动、对白、冲突、揭示或转折的空间。对白提及但未发生剧情的地点不提取；同一地点合并，只有昼夜、天气或状态变化显著影响剧情或画面时才拆分。

道具执行“删除测试”：删除后会改变剧情、人物决定、行动结果、线索理解或关键镜头连续性时才提取。关键线索、证据、信物、武器、关键工具，以及被交付、争夺、隐藏、寻找、偷走、损坏或揭示的物件应保留。桌椅、花瓶、普通餐具、背景书籍等装饰默认排除。

### 4.3 输出与校验

现有字段保留，`ExtractedAsset` 增加：

```json
{
  "importance": "core",
  "story_function": "凶案证据，推动主角确认真正嫌疑人"
}
```

`importance` 只允许 `core`、`continuity`；`story_function` 必填并限制长度。二者保存在生成任务业务结果与原始候选中，用于用户审核，不写入正式 Asset 本体。现有 `evidence` 继续要求为剧本快照中的逐字连续片段，现有名称、描述、提示词、别名、标签和场景时间规则保持。

服务端继续检查所选类型、候选数量、字段长度和原文证据。解析失败不产生候选，不自动调用模型修复，保留原始正文供诊断。

### 4.4 图片提示词规则

每项图片提示词使用“主体 → 稳定特征 → 构图 → 背景 → 光线 → 项目风格 → 排除项”。

- 角色：单一角色主体，全身或半身设定构图；突出身份、稳定外观和常用服装；背景简洁，不出现其他角色，不把剧情场面当角色设定图。
- 场景：空间本身为主体；体现时间、布局、关键功能区和光线；采用建立镜头，默认不出现明确人物，不使用剧情摘要替代空间描述。
- 道具：单一物件主体；突出形状、材质、状态、独特标记及剧情相关损伤；使用干净背景或简单承托面，不出现人物、手或装饰性陪体。

描述字段只陈述剧本支持的事实；提示词可以把这些事实组织成可用于生图的视觉表达，但不得把补充设计伪装成原文事实。

### 4.5 前端审核

素材候选卡增加 `推动剧情` 或 `维持连续性` 标签和“剧情作用”文本；现有描述、图片提示词、原文依据、编辑、新建或复用交互保持。设置页不增加“是否过滤装饰道具”开关，该过滤是业务正确性要求，不允许用户误关。

## 5. 分镜节拍与时长

### 5.1 v1 请求扩展

`TextGenerationCreate` 增加只允许用于 `script_shots` 的可选字段：

```json
{
  "storyboard": {
    "average_shot_duration_ms": 3000
  }
}
```

`average_shot_duration_ms` 为整数，范围 1000–10000，缺省为 3000。它属于业务意图，不能放入表示模型传输参数的 `parameters`。现有客户端省略该字段时保持可用。

### 5.2 镜头划分规则

模型先在内部识别场景边界和叙事节拍。标点、换行、单句台词和说话人变化本身都不是镜头边界。

仅在下列情况下拆分：

- 时间或地点变化。
- 视觉主体或观众关注点变化。
- 动作从准备、发生、反应进入新的关键阶段。
- 出现揭示、决定或明显情绪转折。
- 当前内容无法在合理镜头时长内完成。
- 景别或拍摄意图必须改变，合并会损失叙事信息。

下列情况应合并：同一时间地点、同一视觉主体、连续动作、没有新转折；多句连续对白可以由同一构图完成；拆开后只是重复人物说话而没有新增视觉信息。

明确禁止一句话一个镜头、一行对白一个镜头、为增加数量机械正反打、为停顿或语气词建镜头，以及把同一连续动作拆成没有视觉差异的多镜。

### 5.3 时长规则

平均时长是目标值，不要求每镜机械等长。提示词采用以下参考区间：建立镜头 2–4 秒、普通动作或对白 2–5 秒、快速动作 1–3 秒、重要反应或情绪停留 4–6 秒。长对白按约每秒 4 个中文字加必要停顿估算；优先延长同一镜头，只有主体、反应或镜头意图改变时才拆分。

### 5.4 输出协议

`GeneratedShot` 扩展为：

```json
{
  "title": "发现证据",
  "source_excerpt": "剧本中的连续原文",
  "story_beat": "主角发现证据并改变判断",
  "script": "近景。林夏停止翻找，拿起匕首……",
  "duration_ms": 4000,
  "asset_ids": ["素材ID"]
}
```

`title`、`story_beat` 和 `source_excerpt` 用于候选审核；`script` 继续作为现有分镜正文。解析器验证 `source_excerpt` 确实存在于来源剧本、各候选原文顺序不倒置、时长范围合法、素材 ID 来自快照且不重复、总镜头数不超过 100。

业务结果继续使用 `kind=script_shots`、`schema_version=1`；现有应用接口和 append/replace 语义不变。

### 5.5 持久化

`shot_scripts` 新增：

- `duration_ms`：非空整数，默认 3000，允许 1000–10000。
- `source_excerpt`：可空文本；手工创建分镜默认为空，AI 应用时写入。

分镜创建、读取、生成应用及更新 Schema 同步增加 `duration_ms`。用户可以在分镜编辑页修改时长；`source_excerpt` 作为生成来源依据只读展示，不通过普通分镜更新接口修改。`story_beat` 保留在生成任务结果，不进入活动分镜表。

迁移同时更新 ORM、规范建表 SQL 和数据库设计文档；历史记录回填 3000ms，不修改现有分镜正文和素材关联。

### 5.6 前端交互

分镜生成区增加“平均镜头时长”：快节奏 2 秒、标准 3 秒、叙事 5 秒、自定义 1–10 秒。提示用户这是平均目标，AI 会按对白、动作和情绪调整，不会逐句拆分。

候选结果顶部展示总镜头数、预计总时长和平均时长；每项展示标题、时长、剧情节拍、对应原文、分镜正文和关联素材名称。追加继续新增候选镜头；替换继续使用危险确认，并明确将归档的现有镜头数量。

活动分镜编辑项展示并允许修改时长，原文依据只读。旧生成结果缺少新字段时，预览使用兼容默认值：标题按序号生成、时长 3000ms、原文依据和剧情节拍为空；旧结果仍可查看和采用。

## 6. 错误处理与兼容

- `storyboard` 字段出现在非 `script_shots` 请求时返回 422；`extraction` 继续只允许 `script_assets`。
- 模板文件缺失、结果字段非法、原文依据不可信、未知素材 ID、输出截断均失败并保留原始文本，不产生半批结果。
- 现有异步状态、取消、重试、恢复、来源快照、幂等键和应用并发保护保持。
- 前端和后端同版本发布；历史任务读取路径必须容忍新字段缺失。
- 不声称消除所有缺陷。完成标准是代码审查、必要自动化测试、迁移验证、前端测试、类型检查和生产构建均通过；真实模型的素材筛选与镜头组织质量由用户人工验收。

## 7. 实施范围与顺序

1. 建立 Prompt Registry 和模板目录，迁移三个现有文本业务模板；先保持行为不变。
2. 扩展 v1 请求模型、前端类型和请求构造，加入分镜平均时长默认值与场景限定。
3. 扩展素材输出模型、解析和候选 UI，启用剧情重要性与分类提示词。
4. 扩展分镜输出模型、解析、候选预览和历史兼容，启用节拍与时长提示词。
5. 增加 `shot_scripts.duration_ms`、`source_excerpt` 迁移并贯通 CRUD、应用和页面编辑。
6. 运行后端相关及全量可行测试、Ruff、前端 Node 测试、TypeScript 检查、生产构建和差异检查。
