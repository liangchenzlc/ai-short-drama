# 已确认剧本的 AI 素材提取方案

状态：已实施。新增文本提取场景、候选查询与编辑、事务采用接口及分阶段弹窗；沿用已有表，无数据库迁移。自动化使用固定模型响应，尚未执行真实供应商提取或浏览器交互验收。

## 1. 目标与范围

在「素材准备」中，使用已启用的文本 AI 模型，从当前分集已确认剧本中提取角色、场景和道具。创作者核对候选后，将所选项加入素材库，供上传参考图和关联分镜使用。

已确认：提取结果采用后只进入本集素材库，不自动加入或共享到项目库。需要跨集复用时，由用户通过已有「共享到项目」操作手动添加。复用已有项目素材时，仅建立当前分集关联，不修改项目素材。

第一版包含：三类提取、模型选择、补充要求、异步任务、候选编辑与选择、同名匹配建议、明确采用、历史恢复、版本冲突处理。

本功能只提取文字素材，必须包含名称、描述和图片生成提示词，不提供生图按钮、不调用图片模型。第一版不改写剧本，不自动替换已有素材，也不自动修改共享素材。素材提取候选中的人物不自动变成人物关系图。

## 2. 已有实现与可复用能力

- `AssetsStage` 已接入本集素材库及项目库导入，但还未接入剧本状态或提取模型。
- `AssetLibraryPanel` 已有角色、场景、道具管理，支持文字编辑、图片候选、明确采用、共享引用与版本校验。
- 文本生成已有 `novel_script`、`script_shots` 两个业务场景，使用 API → 调度器 → RabbitMQ → 文本 Worker。
- `GenerationContextService` 从服务端读取剧本，检查当前编辑稿及确认状态，保存不可变正文快照和内容哈希。
- `GenerationBusinessService` 已将结构化分镜候选存入生成记录 JSON，采用操作与模型调用分离。
- 已有幂等请求、任务详情与轮询、错误回显、保存重试、剧本导航保护，继续沿用。

## 3. 页面与交互

使用现有深青绿色主色和工作台组件。素材准备工具栏仅增加「AI 提取素材」按钮，运行中或有待核对结果时附简短状态。提取设置、任务状态和候选结果全部在同一个弹窗内分阶段呈现，不在主页面铺开，也不叠加第二层弹窗。主页面继续专注本集素材管理。

### 发起提取

1. 默认选中全部三类，允许只选一类或两类；至少选择一类。
2. 默认使用该类型已启用的默认文本模型，允许手动选择；可复用现有 `models.analysis` 保存模型选择。
3. 当前剧本为空、未确认、未载入或存在无法完成的保存时，禁止提取并说明原因。提供「去确认剧本」入口；不阻止手动维护素材。
4. 点击后先完成现有正文保存队列；再取最新脚本 ID 和版本提交。不能把浏览器当前文本直接交给后端作为权威来源。
5. 任务受理后弹窗切换为排队或处理中，显示真实状态，不显示虚构百分比。提供「后台处理」关闭弹窗，关闭不会取消任务。若弹窗保持打开，完成后自动切换至结果；若已关闭，仅更新入口状态为「查看提取结果」，不强制重新弹出。返回或刷新后可从入口恢复任务及候选。
6. 重复点击同一次提交复用幂等键。运行中相同来源和范围的任务在当前页面不重复提交；用户明确「重新提取」时创建新任务，保留历史。

### 预览与采用

- 在弹窗结果阶段使用角色、场景、道具分类标签，显示真实候选数；未选择提取的类别标注「未提取」。支持本类全选、取消选择及逐项勾选，切换分类保留选择，底部展示跨分类总数。
- 每项以名称为标题，描述和「图片生成提示词」为明确分区，默认直接可见；提示词可复制，长文本可展开全文。原文依据、别名和标签等辅助信息按需展开。无缩略图占位、无生图操作。匹配到已有素材时显示简短复用建议。
- 点击「编辑」后在当前项内编辑名称、分类、描述、图片生成提示词、标签和场景时间，不叠加编辑弹窗；分类类型不能在采用时被静默转换。
- 原始提取内容与用户编辑稿分开保存。点击「保存候选」、关闭弹窗、采用或离开页面时保存修改；保存失败保留输入并暂停关闭或采用。浏览器刷新与页面跳转沿用未保存保护，不承诺每个按键或失焦后已保存。
- 采用按钮展示所选数量。新建素材为未确认、无图片状态，随后通过既有图片流程确认；复用素材保持原状态及图片。
- 加入素材库前先保存候选编辑稿；保存失败保留输入并暂停采用。成功后显示「新增 X 项，复用 Y 项」，刷新主页面素材列表，候选标为已采用。未选项保留，可以稍后采用；全部处理后提供「完成」关闭弹窗。
- 历史记录在同一弹窗内切换查看，支持返回当前结果。提取失败在弹窗显示原因及重试入口，保留设置；无结果时提供调整范围或补充要求的操作，不显示可用的入库按钮。
- 手机端弹窗适配为全屏，结果单列展示，分类横向切换，底部采用操作保持可达且不遮挡内容。键盘焦点限制在弹窗内，关闭后回到触发按钮；Escape 和关闭按钮遵循相同的未保存编辑保护。

## 4. 提取内容与 AI 约束

| 类别 | 提取内容 | 说明 |
| --- | --- | --- |
| 角色 | 名称、别名、身份、原文明示的外观与服饰、描述、标签 | 同一人物不同称呼合并为候选；不凭空补年龄、发色等特征 |
| 场景 | 名称、内外景、地点、场景时间、空间和环境特征 | 同地不同昼夜或明显不同状态可分开，匹配键包含场景时间 |
| 道具 | 名称、用途、外形材质、剧情作用、描述、标签 | 优先明确出现或被使用的道具，不能根据常识补齐整间房间 |

每项必须返回名称、描述和图片生成提示词，分别映射现有素材的 `name`、`description`、`prompt` 字段，新建采用时一并保存。描述用于理解素材身份、环境或剧情用途；图片生成提示词将已知视觉特征和本集风格整理为后续可用的文字，避免照搬不具视觉意义的剧情摘要。没有明确的外观细节时仅使用已知名称、类型和风格，不为凑齐提示词而杜撰特征。选择复用时提示用户沿用已有素材字段，候选文字仍保留在提取记录中。

每项带一段短的剧本原文依据。服务端校验该引文确实存在于快照中；不可信引用不能显示为已验证证据。未明确的细分信息留空或标为未说明。此次任务仅调用文本模型，不生成图像。

提示词以独立业务模板 `script-assets-v1` 管理。剧本文本和补充要求作为数据提供；剧本里的指令不能改变输出协议。首次调用一次返回所选全部类别，减少重复读取全文和跨类不一致。

结构化输出示意：

```json
{
  "schema_version": 1,
  "items": [
    {
      "kind": "character",
      "name": "林晚",
      "aliases": ["小晚"],
      "label": "主角",
      "description": "穿着被雨水打湿的黑色外套。",
      "prompt": "短剧角色设定，黑色外套，衣物被雨水打湿。",
      "tags": ["主角"],
      "scene_time": "",
      "evidence": "林晚穿着被雨水打湿的黑色外套走进客厅。"
    }
  ]
}
```

示例为协议演示，不是实际提取结果。候选 ID 由服务端在解析成功后分配，AI 不生成数据库 ID。

严格检查枚举、字段类型、字段长度、候选总数、非空名称、标签数量及场景时间适用类型。第一版建议最多 100 项；原文长度、输出预算和各类型上限可配置。超过模型可处理范围应在发起前提示拆分分集，不能静默截断正文。

JSON 无效、输出被截断或字段违规时，不自动入库；保留原始返回供诊断。空数组可表示未提取到素材，显示明确空结果；不伪造候选。已有模型结果的本地解析或保存失败应优先重做本地处理，不能因保存失败重新计费调用模型。

## 5. 重复素材和复用规则

匹配范围依次为当前分集、本项目；第一版不自动搜索和引用其他项目的素材。全局素材可先通过已有导入流程进入项目库。

| 匹配情况 | 页面建议 | 采用行为 |
| --- | --- | --- |
| 当前分集同类型、同名 | 标注「本集已有」，默认不新建 | 显式复用，记录候选映射；不改素材内容 |
| 项目库同类型、同名 | 建议「复用项目素材」 | 用户确认后新增本集关联 |
| 别名相同或多个疑似匹配 | 标注「需要核对」，不自动选择 | 用户从候选目标选择复用，或明确另建 |
| 无匹配 | 建议新建 | 保存用户核对后的文字字段 |

名称仅做温和规范化，如去首尾空白、统一全半角。场景还比较时间；不以名称相同认定为同一个角色，也不以模糊匹配自动合并。别名用于候选匹配建议，第一版无需扩展现有 Asset 表字段。

选择复用后，AI 描述与用户编辑稿不会覆盖原素材。若确需不同版本，用户明确新建并使用可辨别的名称。

## 6. 接口方案

接口均使用现有 `/api/v1` 前缀。

### 创建任务：扩展现有文本生成接口

`POST /ai/generations/text`，携带 `Idempotency-Key`：

```json
{
  "config_id": "已启用文本模型ID",
  "source": {
    "scene": "script_assets",
    "project_id": "项目ID",
    "episode_id": "分集ID",
    "script_id": "当前已确认剧本ID",
    "content_version": "当前正文版本"
  },
  "extraction": { "kinds": ["character", "scene", "prop"] },
  "instructions": "只提取实际出现或使用的素材",
  "parameters": { "max_output_tokens": 8192 }
}
```

`config_id` 可省略以选用默认文本模型。新增 `ScriptAssetsSource`；`extraction` 只允许用于该场景，旧业务输入契约保持明确区分。正文快照、摘要哈希及提示词均由后端生成。

任务查询、详情、重试、取消复用现有接口。列表增加 `source_scene=script_assets` 的支持，仍归入文本任务；页面业务名称显示「剧本素材提取」。

### 候选查询、编辑与采用

分集路径前缀：`/projects/{project_id}/episodes/{episode_id}`。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /asset-extraction-results/{generation_id}` | 候选、原文依据、当前匹配建议、采用状态、来源是否过期 |
| `PATCH /asset-extraction-results/{generation_id}` | 保存候选编辑稿，携带 `result_version`，只允许编辑未采用项 |
| `POST /asset-extraction-results/{generation_id}/apply` | 对选择项执行新建或复用，返回资产 ID 映射及数量 |

采用请求包含 `result_version`、当前 `content_version`，以及每项的 `candidate_id`、`action=create|reuse`。复用项带 `asset_id` 与 `expected_row_version`；新建使用服务器已保存的候选编辑稿。采用操作有独立幂等键及请求指纹。

匹配建议只是提示，不是授权；采用时重新验证目标归属、可引用范围、类型及版本。

## 7. 存储、并发与过期结果

建议第一版沿用已有生成记录存储，不新增专门的任务体系：

- `request_data`：已确认剧本快照、内容哈希、来源 ID、本集风格、提取范围及提示词模板版本。
- `response_data.business_result`：`kind=script_assets`、稳定候选 ID、原始结构、编辑稿、`result_version`、每项采用映射及幂等回执。
- 模型原始正文保留在既有 `text_content`，与可编辑候选区分。
- 正式素材和关联继续使用 `assets`、`episode_assets`，来源模型由服务端记录；需要共享时使用 `project_assets`。

这一路径预计不需要新增数据库表。实施时须核对所有 source_scene 白名单、索引、响应 Schema 和迁移约束；如真实库有场景枚举约束，再提供最小迁移，不能根据设计直接认定无需迁移。

一次采用在同一事务中完成。复用 AssetLibraryService 的规则，但需提炼可由调用方管理事务的创建和关联方法，不能串行调用会各自提交的公开 CRUD 来模拟批量事务。

锁顺序与既有业务保持一致，至少串行化同分集采用及同生成结果修改，并锁定复用素材核验版本。同批全成功或全回滚；同候选已采用后返回原映射，不再次新建。新的提取轮次仍需独立同名检查，不能把幂等性误认为实体去重。

发起时冻结正文，生成中允许继续编辑。返回结果与当前剧本 ID、内容哈希及确认状态对比：剧本变更或不再确认时，旧结果仍可查看，禁止直接采用，提供「基于当前确认剧本重新提取」。仅小说变化引起的 content_version 推进，可先重新读取当前版本；剧本哈希及确认状态不变时，不必强制再次调用模型。

候选编辑和采用冲突返回 409；用户当前编辑不自动覆盖服务器新版本。刷新后优先恢复同分集最近任务和服务端保存的候选草稿。

## 8. 实施拆分与验收

1. 后端扩展文本业务场景、快照、提示词和严格解析；完成结构化结果持久化。
2. 实现候选查询、编辑和事务采用，接入素材匹配建议、幂等和版本校验。
3. 前端传入当前剧本确认状态，添加 `ScriptAssetExtraction` 入口及分阶段弹窗，涵盖设置、处理中、候选选择和编辑、任务历史及保存反馈；主页面不铺开提取表单或结果。
4. 接通采用后的素材列表刷新；任务中心支持业务名称和返回来源分集。
5. 自动化测试和页面验收：未确认不可提交、三类和单类提取、空结果、坏 JSON、截断、重复调用、重复采用、部分选择后继续采用、同名复用、共享素材不覆盖、并发编辑、来源改变、刷新恢复、失败重试。补充验证弹窗关闭后任务继续、完成不强制弹出、跨分类勾选保留、名称/描述/提示词展示编辑和新建保存、提示词复制、未保存关闭保护、键盘与移动端操作，以及全程无图片模型调用。

验收以一个固定剧本样本贯通：确认剧本 → AI 提取 → 校对三类候选 → 新建和复用混合采用 → 刷新仍存在 → 分镜能够关联这些素材。自动化使用固定模型响应；真实模型效果与浏览器交互仍需实际验收。

实现限额由 `EXTRACTION_MAX_SCRIPT_CHARS`、`EXTRACTION_MAX_CANDIDATES`、`EXTRACTION_MAX_OUTPUT_TOKENS` 配置，默认分别为 30000 字、100 项、8192 输出 Token。重复候选不静默合并，需核对选择或明确另建；候选保存与采用都带版本校验。

- 后端全量 unit/API 测试首轮 352 项通过；随后补充同批重名、幂等键冲突、输入长度和 HTTP 契约测试，相关回归 46 项通过。变更 Python 文件通过 Ruff 检查。
- 前端 49 项测试通过，TypeScript 与生产构建通过；保留既有 Ant Design 分包体积提示。
- 本地 API 和文本 Worker 已重载；OpenAPI 包含新增场景与结果接口，提取历史接口正常。MySQL、RabbitMQ 只读检查通过，文本队列消费者数为 1，前端 HTTP 返回 200。
- 不新增数据库表；测试使用隔离 SQLite 与固定模型返回，不修改现有业务记录、不调用真实模型。SQLite 用例不等同于 MySQL 多连接并发验收。
- 浏览器工具未连接可用浏览器，尚未进行真实桌面/手机交互与截图验收；真实模型的提取质量需实际使用核对。
