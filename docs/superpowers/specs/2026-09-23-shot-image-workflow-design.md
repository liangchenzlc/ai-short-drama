# 分镜图片闭环设计

**状态：** 已进入实施与验收；实际完成范围和证据见 [验收记录](../../reviews/2026-09-23-shot-image-workflow-acceptance.md)。用户本轮已授权提交和推送，覆盖本文原“不提交 Git”约束；未调用付费模型。

**目标：** 跑通“素材图片生成并确认 → 关联分镜 → 使用确认图片生成分镜图 → 预览并采用”，刷新后状态可恢复，失败不丢结果，版本冲突不覆盖草稿。

## 1. 范围与现状

沿用 React/TypeScript/Ant Design、FastAPI/Pydantic/SQLAlchemy、MySQL、Celery/RabbitMQ、MinIO。现有 `asset_image`、`shot_image` 来源、任务系统、候选库及采用接口均保留。

已读取的现有实现：

- `frontend/src/features/assets/AssetImageGeneration.tsx`、`useAssetImageGeneration.ts`：素材生图、历史与恢复。
- `frontend/src/pages/projects/episode/StoryboardStage.tsx`：分镜自动保存、关联素材、图片设置。
- `frontend/src/features/projects/ShotImageCandidates.tsx`：分镜生图、候选与采用；当前按镜头全量加载历史，仅展示任务状态。
- `backend/src/short_drama/service/generation_context_service.py`：服务端从已保存分镜及关联素材冻结上下文，仅选 `confirmed` 且有 `media_id` 的图片作为参考。
- `backend/src/short_drama/service/media_asset_service.py`：采用时校验版本、当前图片、上下文与历史参数。
- `backend/tests/integration/test_asset_image_generation.py`：已有测试验证素材生成、确认与分镜任务输入，尚未在同一用例继续执行分镜任务并采用结果。

静态阅读发现的风险，不作为已复现故障：素材改图会改变分镜上下文但页面可能仍持有旧哈希；采用请求提交当前设置可能与旧候选生成参数冲突；大量镜头同时挂载图片区会放大全量历史查询；生成按钮仅依赖 React busy 状态需要并发验证。

## 2. 产品规则

### 素材与参考图

生成成功只产生候选，明确采用后才更新素材当前图及确认状态。共享确认、来源过期确认、版本比较保持原规则。

分镜图片区展示关联素材名称、类别、确认状态和当前缩略图。汇总区区分“关联素材数量”与“去重后的参考图片数量”；两个素材共用一张图片时只计一张参考图。未确认、有候选但未采用、缺图的素材提供文字上下文，不作为参考图片。找不到的关联素材显示异常，不能伪装成完整准备状态。

允许无参考图生图，不强制所有素材先出图；明确提示“本次仅使用文字信息”。模型本身要求输入图片时仍由服务端校验。缩略图显示失败不等于媒体已不存在，提供刷新，不擅自移除关联。

### 保存与生成

先保存当前镜头，再读取单镜最新数据及关联素材。准备与提交的短操作期间锁定本镜相关编辑、生成和采用；其他镜头不必锁定。分镜 `row_version`、`context_hash`、当前媒体、图片设置及本集画幅若与用户刚核对的值不同，展示变化并停止本次提交，用户核对后再点击，不静默接受其他窗口修改。

刷新不得覆盖有未保存内容的镜头；保存失败、409、归档、页面离开或请求过期都不继续生成。服务端事务校验仍为最终判断，前端预检查不能取代它。

沿用服务端 `shot-image-v1` 模板，不增加文本模型润色。客户端传 `source`、补充要求、图片设置与数量，参考图继续由服务端归集；本期不增加额外参考图选择器。

### 模型与参数

使用现有 `GET /ai-model-configs/{config_id}/capabilities`（路径均省略 `/api/v1`）。前端解析实际启用的配置，包括默认模型，并固定到提交的 `config_id`。

能力查询失败显示可重试状态；`known=false` 不解释为已支持。有参考图且本地适配能力明确不支持时阻止提交，提示更换模型。不能自动丢图、换模型或降低参数。

能力接口目前不返回各模型全部可选参数值，不在前端复制供应商尺寸表。具体画幅、分辨率、张数、参考图上限由现有服务端提交前本地校验负责；拒绝时不创建任务、不调用供应商，保留用户选择并给出可操作的错误信息。本期不增加通用预检接口。

### 历史与恢复

按打开的图片操作区加载，默认不为所有镜头挂载历史查询。每页 20 条，历史和候选按需加载更多；打开的操作区活动任务每 3 秒刷新，无活动时每 15 秒刷新，隐藏或关闭停止轮询，重新打开立即对账。

旧活动任务单独按 queued/running 完整分页补齐；从活动列表消失时查详情确认，不能简单丢弃。页面刷新恢复以服务端为准，轮询失败保留上次结果。部分输出已归档时可预览及采用，不等待全部成功。

复用 `TaskDetail` 显示实际提示词、来源快照、错误和按 `can_cancel/can_resume/can_retry` 开放的操作。安全恢复不等于重新生成；按旧输入重试明确提示可能产生费用。网络受理未知时不自动重发，不因刷新上下文而换 key 再提交。

### 采用

候选预览和当前采用分区展示。采用提交必须包含最新目标 `expected_row_version`、`expected_context_hash`、`expected_media_id`，以及用户明确同意的 `acknowledge_stale_source`。

本页只采用 `shot_image` 来源的历史候选，其布局、画幅、分辨率以原生成记录为准，客户端不再发送当前编辑设置冒充生成参数。采用前展示候选生成参数；与当前设置不同则明确提示。旧记录缺失参数时显示缺失原因，不猜测补齐，保留既有通用媒体采用入口语义。

来源过期需单独确认；目标再次变化需重新核对，不能复用上一版本的确认。重复采用同一当前图保持幂等，换图保留旧媒体及回收记录。采用历史图不自动改写下一次生成设置。

## 3. 边界与验收

- 不新增数据库表或迁移，不重构任务系统，不恢复已删除旧文档，不提交 Git。
- 不扩展批量生图、宫格切图、视频、配音、字幕；保留现有其他布局功能，首轮以单镜单图验收。
- 自动测试使用有效图片、模型/存储替身及随机 MySQL 测试库，不操作业务库。
- 模型替身证明数据与状态链路；本地 HTTP 供应商替身证明实际协议载荷；两者不能证明真实供应商视觉效果。
- 真实 RabbitMQ/MinIO 演练与真实模型验收分开记录；付费前确认配置、样本和费用上限，无自动付费重试。

最终证据包括：素材确认媒体 ID、分镜关联 ID、任务快照、供应商请求中的参考图映射、生成媒体及采用结果；浏览器刷新后结果一致。签名 URL 和密钥不进入验收文档。
