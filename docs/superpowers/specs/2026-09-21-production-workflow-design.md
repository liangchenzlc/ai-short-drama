一次审批以下五阶段，按顺序开发、逐阶段验收，最后整体验收：

1. 小说生成剧本。
2. 分镜持久化。
3. 剧本生成分镜。
4. 角色、场景、道具持久化。
5. 分镜生图与明确采用。

验收必须贯穿页面交互、HTTP 请求、后端事务、落库结果和刷新恢复；仅有 CRUD 或模拟页面不算完成。

## 2. 当前代码事实

| 能力 | 当前实现 | 本次补齐 |
| --- | --- | --- |
| 小说、剧本编辑 | `episode_writing.py` 已有聚合读取、自动保存、切换及确认 | 候选剧本列表、真实生成入口 |
| 模型生成 | `/ai/generations/text|image|video`、RabbitMQ/Celery、租约、幂等、恢复 | 两个文本业务来源、业务结果处理及筛选 |
| 生成图片 | MinIO + `media_files` + `media_assets`，已支持 `shot_image` 来源 | 分镜页面发起、历史候选、采用后的读取与冲突保护 |
| 采用图片 | `/media-library/items/{id}/apply` 已有 expected_media_id 检查 | 分镜内容版本及上下文检查；兼容公共资产库入口 |
| 分镜 | `shot_scripts` 等表及内部 Service/DAO 已有；页面使用 `sampleShots` 和浏览器草稿 | 对外 API、编辑与排序、归档、真实生成与预览 |
| 角色/场景/道具 | `assets` 和 global/project/episode/shot 关联表已有 | 页面 API、版本与确认、参考图上传和候选持久化 |
| 全局和项目资源库 | `AssetsPage`、`ProjectResourceLibrary` 使用 localStorage | 接入同一素材服务，保持共享引用一致 |

`GenerationService` 目前是“保存传入文本”的内部服务，并未调用模型；不得把它误当成已有小说改编接口。
`media_assets` 是生成图片/视频资产；`assets` 是角色/场景/道具，两者不能混用 ID。

## 3. 方案选择

| 方案 | 取舍 |
| --- | --- |
| **推荐：三个生成接口 + 有限业务来源 + 薄业务服务** | 延续现有 API，复用任务、协议判断、记录、归档；业务服务负责快照、结果校验和采用 |
| 每个业务另建生成接口 | 业务 URL 更直观，但任务创建、重试和前端调用方式容易分叉 |
| 通用工作流/DAG 引擎 | 扩展能力更强，但当前只有三个生成业务，没有必要引入节点编排、插件平台或新队列体系 |

前端仍调用文本、图片、视频三个生成接口。本次只接入文本和图片业务，不新增第四类生成 API。
后端维持 API → Service → DAO。Gateway/Worker 不处理页面表单；业务服务不实现供应商协议。

```mermaid
flowchart LR
  UI[页面保存并提交] --> API[三类生成 API]
  API --> BS[业务校验与输入快照]
  BS --> DB[(任务与生成记录)]
  DB --> MQ[RabbitMQ / Celery]
  MQ --> Model[现有模型适配器]
  Model --> Result[保存原始结果并校验]
  Result --> Candidate[剧本候选 / 分镜候选 / 图片资产]
  Candidate --> Preview[前端预览]
  Preview --> Adopt[用户明确选择或采用]
  Adopt --> Business[(当前业务数据)]
```

## 4. 五阶段交互

### 4.1 小说生成剧本

1. 页面等待小说自动保存队列完成。保存失败、冲突或来源为空时，不发送生成请求。
2. 用户选择文本模型，可填补充要求；点击“AI 生成剧本”。前端保存本次幂等键和请求快照。
3. 后端校验分集、小说与内容版本，在短事务中保存小说正文、风格、画幅、提示词版本、模型配置快照和任务。
4. 页面显示排队/执行状态，允许继续编辑小说；任务使用提交时快照，不读取后来修改的正文。
5. 成功后新增一个未确认的候选剧本和 `novel_script_records`。不改变当前编辑指针，也不取消旧剧本确认。
6. 剧本页显示候选列表、生成时间、来源与预览；“设为当前编辑”复用已有切换 API，切换前先完成当前自动保存。
7. 编辑、确认复用已有写作接口。即使首次生成时当前剧本为空，也由用户选择后才设为当前编辑。

候选入库不改变 `content_version`；该版本保护当前小说、当前编辑选择和确认状态。新增独立候选不应打断用户正在编辑的内容。现有内部候选插入路径需调整，并补充回归测试。

一次任务生成一份剧本；多次点击“重新生成”产生多个任务和候选。模型输出为空或被截断时标记失败，保留原文供查看，不生成可确认候选。

### 4.2 分镜持久化

- 进入分镜页读取服务端列表；删除页面对 `sampleShots` 的依赖。
- 增加“新增分镜”、上移、下移、删除入口。新建允许空脚本，便于先建立一行再编辑。
- 分镜正文停顿 1 秒自动保存；角色/场景/道具关联、图片设置采用串行保存。
- 当前 UI 只有一个分镜正文输入框，继续保存 `script`；不凭空拆成镜头语言、动作、对白等多套互相覆盖的字段。
- 保存图片高级设置 `layout/resolution/aspect`；“跟随本集”保存为 `inherit`，生成时解析实际画幅。
- 单行写入使用 `row_version`；整表排序、追加/替换采用 `storyboard_version`。单行内容变化也推进整表版本，防止替换覆盖刚保存的内容。
- 删除是归档。已采用图片、视频、生成记录及来源关系全部保留；活动列表不展示归档行。
- 修改分镜、关联素材或分集风格/画幅后，已有图片保留，并显示“创作内容已变化，请重新核对”。

前端每镜头一条编辑队列，同镜头串行，不同镜头可独立保存；排序/替换前等待所有编辑队列。冲突暂停相关队列并保留输入。

### 4.3 剧本生成分镜

1. 用户先确认当前剧本。点击“生成分镜脚本”前，确认自动保存完成，当前编辑 ID 等于已确认 ID。
2. 后端保存确认剧本、当前正文摘要、风格、画幅和本集素材清单快照，异步调用文本模型。
3. 模型输出结构化分镜：每项包含 `script` 与 `asset_ids`。仅允许引用快照中的素材 ID；不按同名自动匹配，不自动创建素材。
4. 后端允许去掉一层完整的 Markdown JSON 代码围栏，随后严格校验 JSON；不做正则猜测、不静默截断，不额外调用模型“自动修复”。最多 100 镜，每镜正文不超过 32 KiB UTF-8，完整规范化结果不超过 1 MiB。
5. 成功后候选保存在生成记录 JSON 中，页面预览候选。此时不写活动分镜表。
6. 用户选择“追加到现有分镜”或“替换当前分镜”。替换需显示旧分镜数量及媒体保留说明，再明确确认。
7. 应用时校验任务来源、已确认剧本内容摘要、当前 `content_version` 和 `storyboard_version`，单事务写入分镜、关联与 `script_shot_records`。
8. 同一任务只应用一次。重复提交返回已应用的 ID；不恢复已被用户修改或归档的行。

应用时若剧本已经变化，则候选仍保留供查看，但拒绝直接应用，提示基于当前剧本重新生成。若只是分镜列表变化，刷新列表和预览后可以重新确认追加或替换。
素材已从本集移除时也拒绝应用，列出失效素材；不得静默删除模型返回的关联。

### 4.4 角色、场景、道具持久化

覆盖全局素材页面、项目资源库、分集素材页及分镜关联，复用 `assets` 与三层库关联表。

- 名称、描述、提示词、分类、标签、场景时间和确认状态服务端保存。分类映射已有 `label`；标签保存 JSON 字符串数组，场景时间独立保存，不再拼入描述。
- 新建时同时创建素材本体与目标库关联；同名允许存在，不按名称自动合并。
- 从全局导入项目、从项目导入分集、共享到项目库，均按素材 ID 建立引用；重复引用幂等。
- 同一素材被多处引用时，编辑弹窗显示影响数量；修改本体/采用图片需明确“同步更新所有引用”。未确认返回 `shared_asset_confirmation_required`。本次不增加复制分支系统。
- 库中的“删除”解释为“从当前库移除”，不物理删除素材及图片。在分集内仍被活动分镜引用时，返回引用列表，由用户先解除关联。
- 图片候选选择仅用于预览；“确认采用”才更新 `assets.media_id`。名称、描述、提示词、标签或时间变化后置为未确认，图片保留。
- 上传真实图片到 MinIO，候选写数据库；也可从现有生成资产库选择图片。上传不会虚构一条模型调用记录。
- 共享素材变化不批量改写所有分镜，而是在读取和生图/采用时重新计算上下文摘要，避免已有图片被误判为最新。

新增图片上传只服务此流程，限制 PNG/JPEG/WebP、20 MiB、4000 万像素；校验真实文件内容，文件名不能决定存储路径。使用现有 Pillow、MinIO，multipart 解析新增 `python-multipart`。

### 4.5 分镜生图与采用

1. 保存镜头正文、素材关联和图片设置后点击“生成分镜图”。前端继续调用 `/ai/generations/image`。
2. 服务端验证活动分镜与版本，基于已保存正文、本集风格、关联素材描述和已确认素材图片组装有效提示词。页面可填写补充要求。
3. 后端按素材 ID 排序、去重参考图；最多 16 张，超出明确拒绝。无已确认参考图的素材仍可使用文字描述，并在提交预览中显示提示。
4. 任务详情保存请求参数、最终提示词、素材快照、模板版本和来源摘要；供应商参数依旧由系统适配，用户不选择协议。
5. 所有输出先进入 MinIO 和生成资产库。分镜页展示历史候选、时间、生成参数、失败原因；刷新后可继续查看任务与候选。
6. 点击缩略图只预览；点击“确认采用”才调用已有 apply 接口，更新唯一的 `shot_images` 槽位。
7. 采用同时检查当前媒体 ID、分镜版本和上下文摘要；若候选基于旧内容生成，界面明确提示，用户可确认采用旧结果。发生新的并发修改则仍拒绝。
8. 换图时保留旧图片资产并沿用回收记录；重放同一采用不产生重复回收记录。已保存的部分结果可独立采用，即使任务最终为失败。

四/五/九宫格本期是“一张展示本镜连续动作的整图”；`count` 是整图候选数，不是格数。自动切格、首尾帧编排和视频生成不在本期。
分辨率菜单展示请求预设，实际尺寸以媒体元数据为准；不把 2K 的估算尺寸写成真实尺寸。

## 5. 通用任务与一致性

- 任务状态保持 `queued/running/succeeded/failed/cancelled`，前端 `failed` 展示“失败”。不新增业务任务状态。
- 来源扩展为 `novel_script/script_shots/shot_image`。项目、分集关系由服务端校验，外部不能指定任意回调、表名或 URL。
- 幂等摘要由规范化的客户端意图和业务来源计算，先查既有键，再读取实时来源和模板。原请求重放不会因小说、模板或模型配置更新而创建新任务。
- `retry` 新建任务，继承原输入快照，允许换模型；“按最新内容重新生成”是新的创建请求，二者在 UI 区分。
- 在任务详情与任务列表加入业务来源筛选及返回业务页面链接；页面通过筛选查回任务，不依赖浏览器记住唯一任务 ID。
- 原始文本先持久化，再执行本地校验/业务保存。Worker 的 `save` 分支按业务来源调用有限处理函数。保存失败仅重试本地保存，不能再次请求模型。
- 本地保存重试沿用archive_budget_seconds的有界窗口，退避上限60秒，每次只调度一个新消息版本；窗口耗尽标记failed。有原始有效结果且目标存在时可由用户resume重开本地保存窗口。来源已删除则保留原始结果并失败，不无限恢复。
- 原始输出为空、被截断或结构不合法时，任务为失败；保留脱敏错误和原始正文。确定性校验失败不无限重试。
- `novel_script` 的候选写入、来源记录、处理标记及成功状态同事务提交；重复消费不新增候选。`script_shots` 的结构化结果保存后即可成功，采用是另一个同步业务动作。
- 沿用消息版本、租约和 pending/published 语义；已确认发布消息不进入周期性广播。新增业务不能绕开现有恢复和 fencing 检查。
- 数据库事务不跨模型调用或 MinIO 上传。锁顺序：如涉及既有任务先 task，再 project（需要时）、episode（ID 升序）、shot（ID 升序）、asset（ID 升序）、媒体/关联。普通资产修改只锁资产，不反向锁所有分集。
- 输入快照含正文/素材信息和提示词版本，不包含明文 API Key，不保存临时签名 URL。引用媒体 ID 在执行时转换为短时 URL。

## 6. 前端组织与恢复

- 所有请求进入 `src/api/modules`，共享 Axios 实例；组件不直接拼 URL、读密钥或实现协议探测。
- 新增分镜编辑会话、素材页面数据服务和分集任务 hook。继续复用 WritingSession，不将整页巨型 workflow JSON 写入一个后端字段。
- 业务数据以服务端为准；Tab、展开状态、未提交补充要求、模型选择可留在浏览器。模型选择属于用户偏好，本期不扩展为持久化设置系统。
- 任务轮询 2 秒开始，长任务退避到 5 秒；隐藏页面暂停，返回时立即刷新；卸载取消读请求。不能把 Axios 15 秒超时当成生成任务执行时限。
- 网络不确定时先核对服务端状态；同一意图保留幂等键；不通过自动换键重新请求付费生成。
- 历史 localStorage 不自动覆盖云端。提供下载旧草稿，用户可手动复制正文/新建素材，并重新上传本地图片。本期不新增跨模块批量导入接口；已有小说草稿导入保留。
- 演示图片、Blob URL、本机句柄不能作为云端 media_id；真实页面不再展示演示数据为已保存内容。
- 任务管理、资产库、分集页三处看到的来源、状态和采用结果保持一致。

## 7. 数据与范围

数据库方案见独立文档：复用现有表，仅新增素材图片候选表，补齐版本、图片设置、分镜归档、素材标签等必要字段。
实施时必须同时修改 Domain、迁移、`schema.mysql8.sql` 和表设计文档，先在测试库验证，再按审批范围应用正式迁移。

本期不含：AI 自动素材拆解、角色独立生图、自动切格、生视频、剪辑合成、工作流引擎、权限平台重构。对应按钮明确显示未开放，不能继续用演示结果冒充真实生成。

## 8. 验收与审批边界

本次设计阶段不修改应用代码、不修改真实表结构、不发起付费模型调用。
方案审批后按配套计划开发。基础验收使用可控模型响应加真实业务 API/测试数据库，验证成功、失败、超时、重放与恢复。
真实供应商联调单独标记：计划至少两次文本调用和一次图片调用；实施完成后明确配置、数量和预算，经授权后执行。此前授权的一次诊断调用不延用到本轮。
未完成真实供应商联调时，报告只能称基础功能验收通过，不能称真实模型全链路验收通过。
