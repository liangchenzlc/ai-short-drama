# Task 1 implementation report

Implemented the three generation creation APIs, task list/detail/records/cancel/retry/resume, model capability GET, and generated media list/detail/rename/apply.

- ORM mappings preserve the approved 19/17/9 columns, constraints, indexes and RESTRICT foreign keys. Internal model capability cache is excluded from CRUD DTOs.
- Admission validates closed request schemas, real source objects and persistent image references, then performs pure adapter parameter validation. It stores immutable model/request/credential snapshots and the initial prepared call in one transaction. Idempotency checks occur before current configuration lookup; concurrent unique-key conflicts read back the existing matching request.
- Cancellation confirms only queued/prepared work; running cancellation records intent. Retry creates linked new history only for failed/cancelled tasks. Resume advances one version under the task lock, uses prepared/provider ID/media manifest evidence, and never resubmits unknown acceptance. Media recovery requires an unsaved downloadable/stored source or enough already saved outputs to finalize; irrecoverable inline failures are not offered as recoverable. Explicit archive recovery starts a new archive window and retains cancellation intent while saving known results.
- Public DTOs stringify identifiers/versions and project safe fields; encrypted credentials, caches and full upstream response JSON are not returned. History defers generated text columns and determines recovery from the latest call.
- Asset adoption requires a real target and expected current media ID. Repeated same-file adoption is idempotent. Shot adoption uses the existing confirmed-media/recycle behavior with historical model references, including disabled configurations. Shared asset replacement requires explicit shared-impact confirmation.
- Integration fixture applies the four migrations only inside its generated disposable test database, strips published production `USE`/`SET`, validates allowed DDL, and asserts the database before each migration statement. No business database migration was performed by this task.

Verification: tests were added before implementation and observed failing. Final focused suite including all existing API tests passed 152 tests. Domain SQL contract tests cover the original tables and new migrations. All owned files passed Ruff. The parent agent reported 9 passing isolated MySQL / RabbitMQ / Celery / MinIO tests, including `tests/integration/test_ai_generations.py`; upstream responses in that integration suite use a local model fixture.

The local SQLite fixture validates service behavior only; it does not claim MySQL concurrency or real upstream generation coverage. The integration test covers actual MySQL idempotency, source JSON filtering, four candidate assets without auto adoption, optimistic adoption conflicts and replacement history.

Review follow-up: video adoption no longer merges provider-native resolved parameters into business fields. Duration precedence is explicit adoption milliseconds, measured media milliseconds, then original requested milliseconds; provider `duration=6` seconds cannot become a 6 ms shot. Three regression cases were observed failing, then passed for 6000/6500/7000 ms and preservation of business resolution. The generation/media service suite passed 16 tests and scoped Ruff passed after this fix.
