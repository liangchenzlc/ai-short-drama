# 五阶段基础功能验收清单

状态：方案已批准并实施。核心页面链路、自动化边界用例和真实基础设施已执行，证据与覆盖范围见同目录 `2026-09-21-production-workflow-verification.md`。下表保留原验收标准，不代表 53 项全部完成了逐条浏览器验收；真实供应商调用未执行。

## 1. 验收方式

每条记录必须包含：页面路径和操作、方法/URL与脱敏请求、响应状态及关键ID、数据库前后断言、刷新/重新进入后表现。
成功操作覆盖一次刷新；写入流程覆盖失败和重放；异步流程覆盖刷新后查回任务。截图不能替代数据库验证。

三种环境分开记录：

1. 单元/API测试：可控模型和MinIO失败响应，稳定验证边界。
2. 基础集成：隔离MySQL测试库、RabbitMQ、MinIO，测试上游返回固定文本/图片；只在测试配置中启用，不在正式应用加“测试成功”接口。
3. 真实模型：明确授权的两次文本调用（小说→剧本、剧本→分镜）及一次图片调用。配置能力不足、输出不合规如实记失败，不额外自动计费修复。

真实模型结果不可确定，验收的是任务/记录/来源/结果/采用流程，不以“每个模型都能输出优质剧本”作为代码验收条件。

## 2. 阶段1：小说生成剧本

| 编号 | 前端操作 | 后端执行 | 落库与基础验收 |
| --- | --- | --- | --- |
| N01 | 输入小说后立即点生成 | flush PUT novel，再POST text | 任务快照为已保存最新正文；保存失败时无任务 |
| N02 | 相同内容连续双击/模拟丢响应后重试 | 同Idempotency-Key | 一条任务、一次模型提交、一个候选，不重复计费 |
| N03 | 生成中继续编辑小说 | 任务使用旧快照 | 新小说保留；完成回调不覆盖输入、不推进当前content_version |
| N04 | 刷新或离开后返回 | 按episode/source筛选任务，GET scripts | 可恢复状态和候选，浏览器不记task ID也能找到 |
| N05 | 预览候选，不点击选择 | 只GET候选详情 | editing_script_id、确认状态不变 |
| N06 | 设为当前编辑→修改→确认→刷新 | select、save、confirm | 正文、指针、唯一确认持久化；旧候选仍可读 |
| N07 | 空小说/旧版本/其他分集ID | 422/409/404 | 不创建任务，不调用模型 |
| N08 | 模型截断/超时/本地保存失败 | failed；有证据时resume save | 原文保留；本地恢复不重复模型调用；重复消费不重复候选 |

## 3. 阶段2：分镜持久化

| 编号 | 前端操作 | 后端执行 | 落库与基础验收 |
| --- | --- | --- | --- |
| S01 | 空分镜页新增两镜 | POST E/shots | Snowflake ID、正整数position，刷新仍有两镜 |
| S02 | 连续编辑同镜正文，故意延迟响应 | PATCH带row_version串行 | 旧响应不覆盖新输入，最终数据库为最后一次正文 |
| S03 | 修改图片布局/画幅/分辨率 | PATCH image_settings | 刷新设置恢复；已有图不被清除 |
| S04 | 上下移动，刷新 | PUT shots/order | 顺序为1..N，无唯一索引中间冲突 |
| S05 | 删除含已采用图片的镜头 | DELETE带If-Match | deleted_at非空；活动列表消失；图片/生成/来源行仍在 |
| S06 | 两窗口同时编辑同一镜头 | 一成功一409 | 失败方保留输入，不能覆盖获胜内容 |
| S07 | 新增后模拟丢响应 | 同创建键重放POST | 只有一条镜头，编辑不被重放重置 |
| S08 | 网络断开后切页/后退 | 页面未确定写入守卫 | 提醒有未保存内容，支持下载；重连先核对 |

## 4. 阶段3：剧本生成分镜

| 编号 | 前端操作 | 后端执行 | 落库与基础验收 |
| --- | --- | --- | --- |
| G01 | 未确认剧本点生成 | 前端阻止；绕过前端也409 | 不创建任务 |
| G02 | 已确认剧本生成并预览 | POST text(script_shots) | 保存结构化候选，活动分镜数不变 |
| G03 | 对空列表采用，之后再次点同按钮 | apply append | 一批镜头/关系/来源记录，重复返回原ID |
| G04 | 有镜头时追加 | apply append | 旧镜头不变，新镜头在末尾 |
| G05 | 有镜头和图片时替换 | 确认replace后apply | 旧镜头归档、媒体保留、新列表1..N；刷新一致 |
| G06 | 生成中修改/取消确认原剧本 | apply拒绝source_changed | 候选保留，当前列表不变 |
| G07 | 模型无效JSON/自造素材ID/101镜 | worker校验失败 | 无半批分镜，无静默截断，无第二次模型修复调用 |
| G08 | 两窗口并发采用同一结果或保存镜头后应用旧版本 | task/episode锁、版本检查 | 同任务只落一批；旧集合版本不能覆盖刚修改的镜头 |

## 5. 阶段4：素材持久化

| 编号 | 前端操作 | 后端执行 | 落库与基础验收 |
| --- | --- | --- | --- |
| A01 | 全局分别新建角色/场景/道具 | POST global库 | 本体与库关联同事务；刷新恢复全部字段 |
| A02 | 场景填时间、分类、多标签 | create/PATCH | 时间不重复拼入描述，分类label、tags数组分别保存 |
| A03 | 从全局导入项目、再导入分集 | PUT库关联 | 相同asset ID，多次导入不重复关系 |
| A04 | 分集手动新建，共享到项目 | POST episode/PUT project | 项目和分集读取同一本体；同名不自动合并 |
| A05 | 编辑多处引用素材 | PATCH未确认共享先409 | 展示影响数量；明确确认后各页面同步显示 |
| A06 | 分镜添加/取消角色、场景、道具 | PATCH shot asset_ids | shot_assets准确增删，刷新恢复；外集引用拒绝 |
| A07 | 移除被活动分镜引用的分集素材 | DELETE episode关联 | 409列出镜头；解除后移除；媒体及其他库关联保留 |
| A08 | 上传图片/选择已有生成图片 | upload/add candidate | MinIO+media_files+候选持久；assets.media_id未自动改变 |
| A09 | 预览候选→确认采用→刷新 | confirm CAS | 已采用图与确认状态恢复；候选完整保留 |
| A10 | 确认后修改提示词 | PATCH asset | state=unconfirmed、旧图保留、关联镜头显示需核对 |
| A11 | 非图片/超20MiB/超40MP/存储故障/重复上传 | 上传校验/补偿/去重 | 不产生可选坏图；同资产同文件仅一候选；不误删既有文件 |
| A12 | 打开有旧localStorage的页面 | 服务端加载+旧稿下载 | 不自动上传/覆盖；演示图不成为云端图片ID |

## 6. 阶段5：分镜生图及采用

| 编号 | 前端操作 | 后端执行 | 落库与基础验收 |
| --- | --- | --- | --- |
| I01 | 编辑镜头/关联素材后立即生图 | flush→POST image(saved) | snapshot包含最新保存正文、风格、正确参考图 |
| I02 | 双击生成/丢响应重试/刷新 | 幂等创建+来源筛选 | 一个任务，状态恢复；不自动新建付费请求 |
| I03 | 请求两张图并等待完成 | worker归档 | 两个media_files/media_assets，shot_images仍不变 |
| I04 | 点候选缩略图 | 只读预览 | 不调用apply，不改变当前图 |
| I05 | 确认采用其中一图并刷新 | apply检查三个expected | 唯一shot_images更新；另一图留资产库 |
| I06 | 再次采用另一图/重放采用 | CAS+回收逻辑 | 旧图保留、回收记录不重复，任务历史不改 |
| I07 | 生成后修改镜头或共享素材，再采用旧图 | 先stale提示，再明确确认 | 新并发冲突不能被确认参数绕过；明确核对后记录新context_hash |
| I08 | 两窗口同时采用不同图 | 一个成功，一个409 | 不静默覆盖用户选择，失败窗口刷新可见获胜图 |
| I09 | 生成中归档镜头、部分结果归档失败、URL过期 | 保留任务资产/部分可采用/重签名 | 归档镜头不能采用；可用部分图保留；重签名不生新图 |
| I10 | 单图/四/五/九宫格切换 | 请求布局进prompt和快照 | count代表整图数；不虚构切格结果，真实尺寸读取media_files |

## 7. 跨阶段必验

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| X01 | 小说→剧本→确认→分镜→素材关联→生图→采用→刷新 | 页面、任务管理、素材/资产库显示同一组服务端ID和状态 |
| X02 | API重启、worker在本地保存前中断 | 有原始结果只恢复save；不会因重启重复付费或重复落业务行 |
| X03 | RabbitMQ重复消息/已发布消息等待执行 | 租约和版本拦截重复消费；scheduler不周期性重复广播published |
| X04 | 新建库与迁移后测试库比较 | 字段、默认、索引、CHECK与schema.mysql8.sql一致；旧数据保留 |
| X05 | 访问其他分集/项目ID、未持久化媒体、超限输入 | 后端拒绝，不能只靠前端隐藏控件 |
| X06 | 通用文本/图片/视频任务与现有写作自动保存回归 | 本次业务扩展不破坏原请求、状态和采用入口 |
| X07 | 退出浏览器重新进入 | 业务内容从服务器恢复；允许Tab/模型选择偏好仍为本地 |

允许只在基础验收中注入固定上游响应；真实供应商失败必须单独报告。
