# 模型生成、任务管理与资产库

## 已接入流程

- `POST /api/v1/ai/generations/text`、`image`、`video` 分别创建任务，均要求 `Idempotency-Key`。同键重发返回原任务，异体冲突返回 409。
- `GET /api/v1/ai/generations`、`/{id}`、`/{id}/records` 查询任务与调用；`POST /{id}/cancel|retry|resume` 分别请求取消、创建新生成、仅恢复已有任务安全动作。
- `GET /api/v1/media-library/items`、`/{id}` 查询生成资产；`PATCH /{id}` 修改名称；`POST /{id}/apply` 用户确认后更新真实业务目标。
- 前端 `/tasks/text|image|video` 创建生成、查看记录；`/media-library/image|video` 预览、改名、确认采用。素材库下方新增任务管理，再下方为资产库。
- 分镜生图使用 `source={scene:"shot_image",shot_id:"真实ID",layout:"single"}`。业务校验、输入快照、生成执行和确认采用分别由 Service 处理。省略来源支持独立生成。

任务成功表示结果完整保存，用户不采用也长期保留。生成过程不改 `shot_images`，确认采用才写入当前图片及替换历史；采用失败只处理业务写入，不重新调用模型。

目前原项目/分镜编辑器仍有浏览器本地演示数据，不能作为真实后端 ID。新生成页面可独立使用；采用弹窗要求真实服务端目标 ID，不伪装演示分镜已连接后端。真实项目数据的编辑器迁移需要单独接入现有业务 CRUD。

## 运行

后台需要五个进程：FastAPI、Publisher/Recovery、文本 Worker、图片 Worker、视频 Worker。Windows 启动脚本及手动命令见 [backend/README.md](../backend/README.md)。前端在 `frontend` 执行 `npm run dev -- --port 5173`。

用户给定的 RabbitMQ 已写入本地 `backend/.env`，默认 vhost `/`，AMQP `5672`，无 TLS。密码不出现在本文或 `.env.example`。不要重新执行已运行过的建表脚本。

每个 Python 进程的 `SNOWFLAKE_WORKER_ID` 必须唯一；示例分配 API=1、文本=2、图片=3、视频=4、调度=10。Worker 使用线程池，一个进程内复用线程安全雪花生成器。

队列和 exchange 持久化，消息持久化并开启 publisher confirms/mandatory 检查。Celery 使用 late ACK，无结果 backend，无 Redis。Worker 不在数据库事务中等待 HTTP/MinIO。

## 恢复规则

1. `published` 不因时间过长重新发布；检查消费者或积压。
2. 未确认投递同版本最多尝试三次，随后暂停 `message_delivery_unknown`。任务详情的“恢复”只在记录证明可安全 submit/poll/save 时可用，且以行锁推进新版本。
3. 任务只保留 `queued/running/succeeded/failed/cancelled` 五种状态，前端 `failed` 展示为“失败”。提交超时、受理不明和投递暂停统一归为 `failed`，记录结束时间；达到生成等待时限后停止自动查询。是否允许重新生成仍依据内部调用记录判断，受理不明不能快捷重发。已有 unknown 任务通过 `006_remove_task_unknown.sql` 转换；调用记录内部的受理证据不变。
4. 已获得媒体结果后开启独立 24 小时归档窗口；窗口耗尽保留清单和已保存资产。明确“恢复保存”可开启新保存窗口，不调用生成 API。
5. 先持久化结果清单，再上传 inline/base64 图片；清单没有 base64 内容和 Worker 本地文件路径。已上传未入库的文件可按定位恢复。
6. 对象键使用 `generations/{task_id}/{record_id}/{asset_id}-{sha256}.{ext}`。相同内容重试保持同一键，旧 Worker 的不同内容不会覆盖当前引用文件；失效写入可能留下未引用对象，当前不自动删除。
7. 用户请求取消但供应商不支持取消时继续追踪和归档，不能把“已请求取消”伪装成“已取消且不计费”。

## 协议范围与边界

文本任务默认生成等待上限调整为 3600 秒（1 小时），可通过 `GENERATION_TEXT_BUDGET_SECONDS` 配置（10–3600 秒）。预算在任务创建时快照保存，新配置只作用于新任务。流式避免网关长时间无响应导致的部分 524，但不会取消本地任务时限；等待超时不自动重新调用。原超时任务不会因调大配置而重新执行。

RabbitMQ 3.12+ 的文本队列需要匹配更长的消费确认时限。当前使用队列策略 `short-drama-text-consumer-timeout`：vhost `/`、pattern `^tasks\.ai\.text$`、apply-to `queues`、priority `10`、definition `{"consumer-timeout":4200000}`（70 分钟）。它只作用于文本队列，不清空或重新创建队列。部署到新 RabbitMQ 时同步设置，否则 broker 默认的消费确认时限可能早于应用的一小时预算。

状态升级已在当前业务库执行：3 条旧 unknown 任务转换为 failed，五状态约束已生效。原任务信息及约束备份位于本地忽略目录 `backend/.runtime/task-status-migration-backup.json`。API、调度器和三类 Worker 已重新启动。验证包括 282 项 unit/API、迁移与执行相关 12 项隔离集成测试、前端构建及类型检查；升级过程中未发起真实模型调用。

文本 Worker 向 Chat Completions / Responses 请求内部流式响应（`stream: true`），收齐后保存完整文本，前端仍通过任务查询获取结果。SSE 心跳不作为正文，Chat 必须有结束原因和 `[DONE]`，Responses 必须有终态事件；流中断或终态缺失记为受理不明，不自动重新生成。兼容服务返回普通 JSON 时仍按原协议解析。响应字节上限与任务时间预算继续生效。

2026-09-20 排查中，`gpt-5.6-sol` 的非流式任务在约 126 秒后收到中转站 HTTP 524。524 表示网关等待源站响应超时；非流式等待可能触发这一限制，不能仅靠延长本地超时解决。内部流式可以减少长时间无响应数据带来的风险，但若中转站不及时输出或不发送心跳，仍可能超时。流式改动已通过 76 项相关 unit/API 测试及 12 项隔离集成测试。

用户明确批准一次真实诊断后，任务 `359995498431516672` 使用原中转站、原 `gpt-5.6-sol` 配置与 Chat Completions 接口，`stream=true`、`max_completion_tokens=64`，约 4 秒返回 `OK` 并完成保存。调用记录仅 1 条，供应商报告输入 17、输出 5、总计 22 Token。原两条受理不明任务没有重发。本次结果证明该模型的流式文本链路可用，不代表所有长文本或其他模型已完成真实验收。

已实现 OpenAI Chat/Responses/Images、Ark Images/Video、DashScope Images/Video 的显式适配器。协议按配置地址/路径和匹配指纹的成功缓存自动选择，前端不选协议。模型列表不是协议兼容的证明；普通 404/405 不自动切换另一个可能收费的生成入口。

不支持的参数直接拒绝，不悄悄丢弃或改换模型。目前 OpenAI multipart 图片编辑尚未接入；GPT-Image-2 专属分辨率档位未经官方正文验证时不猜测映射，可使用已支持的显式像素参数。未知视频私有协议返回未适配。厂商适配的契约验证与真实模型联调分别记录。

图片入库校验内容、尺寸和 SHA256；视频目前校验大小与 MP4/WebM 容器标识，不执行转码或完整解码探测，实际时长缺失时不伪造元数据。
