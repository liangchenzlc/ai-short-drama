# 标准创作流程反馈规则

适用范围：分集详情的剧本创作、素材生成、分镜制作、成片合成，以及其中的模型选择、图片工具、声音编辑、保存恢复和标准模式 AI 助手。保持现有冷黑主题、主色、面板布局和紧凑间距。共享助手仅在 `layout="standard"` 分支适用；无限画布继续遵守原有迁移边界。

## 1. 分类与展示

| 类别 | 判断规则与例子 | 展示方式 | 后续处理 |
| --- | --- | --- | --- |
| 报错 `error` | 操作或必要读取实际失败：上传失败、保存失败、能力读取失败、网络中断 | 公共 Message；6 秒后收起，可手动关闭 | 未解决的问题保留在详情；提供原有重试、重连或下载动作 |
| 警告 `warning` | 需要用户核对或调整：版本冲突、受理不明、备份损坏、参数不支持、来源变化 | 公共 Message；5 秒后收起 | 核对、恢复等入口保持可达，不能随提示消失 |
| 正常准备 | 读取设置、加载模型、核对模型能力、恢复查询中 | 选择器或原按钮 loading，按需禁用相关动作 | 不创建 Message、Alert、说明段落或进度横条 |
| 用户任务进度 | 已提交、排队、生成、合成中 | 原按钮 loading、已有任务记录或固定状态入口 | 保留取消、停止、重连；不在提示词后追加任务块 |
| 成功 `success` | 上传完成、复制成功、明确操作已完成 | 确有必要时短提示 2 秒 | 结果本身已明确可见时可省略；自动保存成功不提示 |
| 必要确认 | 永久删除、清除损坏记录、共享影响、重新生成可能计费 | 保留原有确认 Dialog / Modal | 说明对象和后果，必须由用户明确操作 |

不要用警告色表达正常进度。首次进入页面尚未选择模型、必填项尚未填写时，不自动弹警告；使用控件状态、禁用按钮及可聚焦的禁用原因提示。主动提交时才反馈具体校验问题。

## 2. 布局与视觉

- 错误和警告不参与工作台正常文档流，不新增状态行、侧栏或预留空白，不改变编辑器、提示词、预览、卡片列表和时间轴的宽高。
- Message 同时最多显示 2 条，页面顶部偏移 72px；局部操作层偏移 12px。单条最大宽度为 `min(420px, 100vw - 24px)`，摘要最多两行，完整内容进入详情。
- 复用 `StudioProvider` 的 Ant Design 主题和 `studio-feedback.css`；不另建配色。提示支持手动关闭，错误使用 `alert`、其他使用 `status` 通知。
- 顶部原有保存图标保持固定尺寸。问题计数、保存状态通过可访问名称、悬浮说明和详情提供，不插入变长状态文字。弹窗的详情入口定位在原标题区，不增加标题行高度。
- 原有数据区域内部的 loading / 空态 / 错误态仍需保留，例如失败图位、播放器错误覆盖、空列表及加载更多失败。任务记录中的业务错误、助手消息中的失败结果属于内容，可继续在其原区域呈现；不能据此在编辑器外增加提示块。
- 静态帮助使用字段或操作的 Tooltip。纯说明浮层不得遮挡相邻操作；可点击的恢复动作必须放入可交互详情，不能塞入纯文本 Tooltip。

## 3. 公共组件

实现位于：

- `frontend/src/components/ui/StudioFeedback.tsx`：公共 Message、声明式反馈和详情入口。
- `frontend/src/components/ui/studio-feedback-store.ts`：每个 Provider 独立的详情存储与去重。
- `frontend/src/components/ui/studio-feedback.css`：主题及浮层尺寸。

`StudioProvider` 已接入页面级 `StudioMessageProvider`。标准工作台的 `StandardSaveStatus` 提供持久详情；统一 `Dialog` 自带局部 Provider、Message 容器和 `StudioFeedbackIndicator`。独立测试夹具也应使用真实 Provider，不能依赖兼容回退的行内 Alert 验收布局。

### 有恢复操作的反馈

```tsx
{saveError && <StudioFeedback
  type="error"
  title="素材保存"
  message="保存失败，当前输入已保留。"
  description={saveError}
  noticeKey={`asset:${assetId}:save`}
  actions={<Button onClick={retrySave}>重试保存</Button>}
/>}
```

- `StudioFeedback` 在 Provider 内不输出布局节点。`type` 明确传入；`title` 是来源，`message` 是摘要，`description` / `children` 放完整原因，`actions` 放原有恢复操作。兼容旧调用的 `action` 属性。
- 错误、警告，以及带操作的反馈默认登记详情。`persistent` 可显式控制；`quiet` 仅抑制短提示，仍保留详情，适合非阻断限制或已经有明确入口的核对信息。
- 源问题解决后清除相应错误状态或卸载反馈，详情随之移除。关闭 Message 只关闭浮层，不能清除源问题、输入、备份或恢复操作。
- `noticeKey` 按操作与资源稳定命名。同一键、相同类型和摘要在 30 秒内不重复弹出；轮询和重新渲染不得反复提示。新的明确尝试如需立即再次提醒，可纳入该尝试的稳定编号，不使用每次渲染变化的时间戳。
- `feedbackType` 仅用于既有成功/失败共用字符串通道的兼容。新业务从错误类型和业务状态明确决定级别，禁止依靠中文关键词猜测类别。

### 简单短提示

```tsx
const message = useStudioMessage();
message.success('已复制提示词');
```

`useStudioMessage().error / warning / success` 适用于无需持续核对的简单操作。需要重连、版本选择、恢复备份、下载输入或核对原请求时，使用 `StudioFeedback` 并保留详情入口。

### 弹窗和抽屉

- 原生 `showModal()` 的 top layer 无法通过给页面 Message 增加 `z-index` 穿透。统一 `Dialog` 已在内部挂载局部 Message 和下拉容器，应直接复用。
- 自建操作层需要自己的 `StudioMessageProvider`、定位到当前操作层的 `getContainer`、以及同作用域的 `StudioFeedbackIndicator`。错误由当前顶层操作层内发布，不能只登记在被遮住的页面入口。
- Ant Design Drawer / Modal 内的操作失败也遵守该规则；任务详情中的错误记录和固定内容区域失败态按前述内容例外处理。
- Escape 先关闭当前下拉或详情浮层，再关闭底层弹窗；关闭后恢复入口焦点。Tab 不得进入被遮住的页面。桌面浮层限制宽高并使用内部滚动，在支持视口内不产生整页横向滚动。

## 4. 状态与安全恢复

视觉迁移不改变生成请求、串行自动保存、版本校验、账号隔离和导航保护。

- 409 冲突保留当前输入和服务端版本，继续提供下载、核对及明确重新载入；不能自动覆盖。
- 受理不明保留原幂等键和请求快照，通过原请求核对；不能把断网认定为任务未受理，不能自动重新付费生成。
- 轮询断开不等于生成失败。说明上次已知状态、后台是否继续，并保留原重连/取消入口。
- 恢复记录损坏不静默删除。保留下载、重试和明确清除流程；必要确认不能被短提示取代。
- 本地自动保存成功、正常能力读取及自动重连过程保持安静；用户主动操作仍需明确 loading，不能无响应。

## 5. 后续修改的验收

按 `test-map.json` 选择当前功能测试。公共反馈修改需检查 1280×720、1440×900 及 1920×1080 桌面视口，不再验收手机或平板适配；具体场景增加对应功能浏览器验证。

1. 触发正常准备、错误、警告和恢复状态，前后比较编辑器/提示词、设置面板及预览的 `boundingBox`；原有 Dialog 动画结束后再测量。
2. 关闭短提示后仍能从原保存/详情入口重试、核对或下载，原输入保持不变。
3. 原生 Dialog 内能看到 Message、下拉及恢复按钮；验证 Escape、焦点回归和桌面支持范围内无整页横向滚动。
4. 同类轮询错误不刷屏；故障变化和新的明确尝试可以正常通知；不同页面/弹窗 Provider 不串状态。
5. API 测试替身通过只能证明界面和契约行为；真实收费模型、实际生成品质及供应商恢复需单独验收。

实施前各出口盘点见 [2026-10-20 提示信息清单](2026-10-20-创作流程提示信息清单.md)。该清单描述当时问题，后续开发以本文及当前源码为准。

剧本建议及最近变更是专门的数据审阅区域，其读取失败、建议过期和恢复提交后重读失败在原区域显示原因与恢复动作，不只依赖标题详情浮层。生成按钮的禁用原因通过邻近可聚焦的可交互详情保留；模型能力失败、未知受理和保存冲突分别提供对应动作。正常准备仍使用loading，不新增常驻错误横条。
