## 1. 本版方向与范围

**以当前工作台为基础，只修改“剧本创作、资产生成、分镜制作、成片合成”四个节点。剧本页参考 Laper 的场次目录和连续剧本正文，其余三页保留现有制作路径，精简 v3 额外增加的界面负担。**

AI 创作助手的入口、文案、面板、宽度、会话、输入、引用、附件、Skill、发送与停止均不在本轮修改范围。也不照搬 Laper 的浮动 AI 面板。下文线框只表示流程节点内部。

设计采用 Impeccable 的 Operate 模式：创作者首先要找到内容、编辑、生成、回看和导出。结合 frontend-design，页面以剧本正文、资产图片、分镜画面和剪辑时间轴分别作为视觉中心，沿用项目中性炭黑主题、中文系统字体和近白主操作。

| 流程节点 | 修改后的主任务 | 本轮重点 | 保留的使用习惯 |
| --- | --- | --- | --- |
| 剧本创作 | 写作、定位场次、对比修改 | 场次目录更清楚，正文呈连续稿，设定和辅助提示减少占位 | 原有来源、格式快捷键、AI 生成、记录、导出、选文改写与采用规则 |
| 资产生成 | 制作角色、场景、道具的视觉资产 | 统一命名，恢复缩略图与完整生图操作 | 左侧选资产，中间看图，在现有生成区修改要求 |
| 分镜制作 | 逐镜生成和调整图片、视频 | 默认回到逐镜制作，明确分镜图与分镜视频 | 左侧选镜头，当前预览中迭代，按需打开记录与设置 |
| 成片合成 | 编排、裁剪、调整声音与导出 | 对齐当前完整编辑器，去掉常驻检查区 | 原时间轴、属性、同步、历史、专注剪辑与导出入口 |

四节点仍可直接切换。名称调整不增加阶段完成确认、解锁条件或额外的“继续下一步”按钮。

## 2. 参考依据与取舍

### 2.1 Laper：重点参考剧本页

已查看 [Laper 官网的公开编辑器演示](https://laper.ai/)，并核对 [剧本编辑器说明](https://laper.ai/docs/script-editor/overview/)和[工作区说明](https://laper.ai/docs/getting-started/workspace-and-episodes/)。未登录其完整工作台，不将演示当作全部功能验收。

| Laper 可见组织方式 | 本项目如何借鉴 | 原因与边界 |
| --- | --- | --- |
| 场次目录与正文并列 | 用当前左侧场次导航服务正文定位，正文占主要空间 | 长稿需要快速跳转；本项目已有场次解析，无需再建场次卡片墙 |
| 连续剧本文档，场头、动作、人物、对白有层级 | 强化现有中文剧本高亮和场头排版，各场沿同一正文轴连续排列 | 提高阅读和改稿连贯性；保留中文短剧格式，不直接照搬英文居中对白和等宽字体 |
| 紧凑的剧本格式工具 | 保留当前“场次、△ 动作、对白、OS、VO”一条工具栏 | 覆盖现有能力，不为相似外观先加入八种段落类型和编辑器迁移 |
| 根据光标、选区确定修改范围 | 保留当前选文浮条和改写入口 | 局部操作跟随内容出现，不再永久占一块改写面板 |
| 修改可回看与检查 | 保留当前候选对比、按已有粒度选择改动并明确采用 | 作者能判断变化，原稿不因查看候选被替换 |
| 右侧信息面板、浮动 AI、分集、多维工作区 | 本轮不引入 | 本项目为单作品四流程；助手已被明确排除，信息栏也会再次挤压正文 |

因此，借鉴范围是**剧本文档的组织与阅读层级**。Laper 的浅色页面、绿色点缀、封面、分页切换、协作、人物关系网、选角和知识库均不进入本轮。

### 2.2 其他节点延续第一版的成熟平台依据

[Runway 的参考图流程](https://help.runwayml.com/hc/en-us/articles/40042718905875-Creating-with-Gen-4-Image-References)支持保留可见参考与围绕同一画面迭代的方向；[LTX Studio 的单镜编辑](https://ltx.io/studio/platform/shot-video-editor)支持把逐镜修改作为制作任务；[Google Flow 的片段编排](https://support.google.com/flow/answer/16935718)用于对照生成与剪辑的职责划分。

这些依据用于判断操作组织，不用于扩大本项目能力。第一版对即梦、可灵等产品的研究继续作为背景，本版不再重复增加竞品功能。

## 3. 节点一：剧本创作

### 3.1 布局：场次目录＋连续正文

```text
┌──────────────────┬─────────────────────────────────────────────────┐
│ 剧本结构    收起 │ 剧本正文             AI 生成  记录  导出  专注  │
│                  ├─────────────────────────────────────────────────┤
│ 故事设定    展开 │ 场次   △ 动作   对白   OS   VO                 │
│                  ├─────────────────────────────────────────────────┤
│ 场次        新增 │                                                 │
│ 01 医院走廊      │     场 01 · 夜 · 内 · 医院走廊                 │
│    夜／内        │     人物：林晚、陈医生                          │
│ 02 医院门口      │                                                 │
│    夜／外        │     △ 林晚把报告按在桌上，挡住医生伸来的手。    │
│ 03 出租车        │     林晚（压低声音）：报告，是谁改的？          │
│    夜／内        │     陈医生：你先把门关上。                      │
│                  │                                                 │
│                  │     场 02 · 夜 · 外 · 医院门口                 │
│                  │     ……                                          │
│ 从小说拆场       ├─────────────────────────────────────────────────┤
│                  │ 字数 / 场次数 / 估算时长〔只保留这一处〕       │
└──────────────────┴─────────────────────────────────────────────────┘
```

这是节点内的默认编辑态，右侧不新增常驻信息栏。现有页内“AI 生成”是原有生成表单入口，继续沿用当前开关和执行路径；它与独立 AI 创作助手保持现有关系，本轮不重做任何助手界面。

- **左栏先服务场次定位。** 场号、地点为主信息，日夜／内外和已有出场人物为次信息。当前场保留清楚的选择底与文字标识，点击跳转，不因浏览而改动正文。
- **故事设定改成一个可折叠区。** 保留原来的一句话卖点、故事大纲、人物小传及编辑入口；有正文时默认收起，展开后仍在原结构栏中操作，不增加新的设定页或必填步骤。保留用户本次展开状态。
- **正文形成一条连续阅读轴。** 沿用当前约 720px 的阅读宽度，空间不足时自适应；场间通过留白与场头区分，不给每场增加独立大卡片、阴影和工具条。
- **场头醒目，正文安静。** 场号、时间、内外、地点组成一个标题层；动作、人物／对白、OS／VO 沿用当前中文语法，通过现有高亮区别。人物小传不混进正文。
- **不要模拟纸张。** 不加纸纹、装订边、A4 固定宽高和虚拟页码；本轮仍是连续文本编辑与现有导出。

### 3.2 保留、删除与新增

| 对象 | 处理 | 原因 |
| --- | --- | --- |
| 场次导航、结构栏收起、专注模式 | 保留并强化层级 | 当前已有，是借鉴 Laper 组织方式的基础 |
| 小说原文、原有导入／空稿起点、从小说拆场 | 保留入口与处理规则 | 避免改版后失去现有创作来源，不增设来源管理中心 |
| 一句话卖点、故事大纲、人物小传 | 保留字段，增加折叠组织 | 不删除已有能力，同时把默认空间让给场次 |
| AI 生成、记录、导出 | 保留当前正文标题栏位置 | 高频动作不用重新寻找；不在左栏和正文各放一套相同入口 |
| 场次、△ 动作、对白、OS、VO | 保留一条紧凑格式工具栏 | 延续当前插入格式片段的行为，帮助中文剧本输入 |
| 更狠／更短／更口语／加动作 | 保留选文后的浮条 | 有明确作用对象时才出现，不额外增加永久改写栏 |
| 当前稿与候选对比、明确采用 | 保留当前流程 | 不增加第二次确认，也不把候选预览当作已保存的新正文 |
| 长期格式教程 | 有内容后收起 | 写作区首先展示剧本；空稿留一个例子，其他说明按需查看 |
| 多处字数、时长、钩子计数 | 合并为一处必要统计，去掉常驻钩子计数 | 关键词不能证明戏剧质量；相同数字反复展示会分散注意力 |
| 固定“目标 3 分钟”与完成比例 | 去掉无真实目标来源的部分 | 当前硬编码目标不能冒充用户设定；实际时长只标为估算 |
| 人物未登记警示 | 从常驻体检移到有关操作的非阻塞提示 | 人物小传未写不等于剧本错误，不要求先填设定才能写作或采用 |
| 当前禁用的场次搜索图标 | 本轮稿不展示 | 不把尚未实现的搜索画成可用控件 |
| 常驻剧本检查器、节奏图、质量评分 | 不增加 | 会把写作变成处理指标；本轮没有足够的数据依据 |

本轮新增交互只有故事设定的折叠组织，其余主要是现有能力的重排、补回和精简。场次搜索、拖动排序、人物关系网均不作为本轮承诺。

### 3.3 编辑与数据边界

当前剧本是文本加场次解析，并非 Laper 的语义段落编辑器。“场次／动作／对白”按钮仍是现有格式插入操作，不画成可以任意转换段落角色的控件。用户已有的不规范文本继续可编辑，不强制格式化或要求先修复全部场头。

现有透明输入层与高亮层必须使用一致的字体、字号、行高和文字度量。第一版视觉落地通过颜色和独立场头组织层级，不只在高亮层给对白加缩进、换字号或改行距，防止光标与文字错位。中文输入法、选区和复制粘贴优先于仿照英文剧本外观。

故事设定目前保存在本机浏览器。本轮不承诺设定已经服务端同步、可靠参与每次生成或自动关联所有资产；相关说明保留在设定操作层，不能写成“全局已同步”。如要实现完整语义编辑、分页、FDX／PDF 或设定数据契约，应另立功能设计。

### 3.4 必须画出的节点状态

1. **空稿：** 正文只给一个简短格式例子，原有来源起点继续保留，不叠加多张引导卡与质量检查。
2. **已有剧本：** 场次目录与正文为主，设定可展开，工具栏与底部统计各一处。
3. **未识别场次：** 保留原文编辑，提示一个场头格式示例，不把已有文字表现成空稿或丢失。
4. **选文改写：** 使用现有浮条，正文选区保持可见，不新增一套范围选择器。
5. **候选对比：** 按当前对比流程显示原稿与变化，返回编辑不丢原位置；候选仍须明确采用。

## 4. 节点二：资产生成

### 4.1 命名与布局

阶段名统一为 **资产生成**。该节点内的“素材”在指角色、场景、道具对象时统一称“资产”，例如“新增资产”“资产描述”“参考资产”。“从剧本提取”“参考图片”“模型”“生成记录”等含义明确的原按钮不因改名而重写。

这只是用户界面的术语调整，仍是一张卡对应一个角色、场景或道具对象。媒体资产库继续是原有媒体选择入口，不新增“项目资产库／全局资产库”，不更名接口、路由或数据库实体。

布局继续使用**左侧缩略图资产列表＋当前图片组预览＋现有生成设置**。资产名称和类型在一行，描述与本次提示词各有原来的作用；不增加资产资料首页。

| 对象 | 处理 | 原因 |
| --- | --- | --- |
| 角色／场景／道具分类、搜索、新增、从剧本提取 | 保留 | 是现有资产组织和录入路径 |
| 缩略图卡片 | 在 v3 中补回 | 靠图识别人和场景，比只有名称、角度、状态的文字列表快 |
| 资产描述与本次提示词 | 保留，标签清楚区分 | 前者定义对象，后者表达本次画面要求，不能为了少一个框盲目合并 |
| 图片组 1／2／4、第一张默认主图、切换主图 | 保留现有规则 | 结果已直接保存，不增加“确认资产／采用候选”流程 |
| 上传、媒体资产库选择、参考图片与 `@` 引用 | 补回现有完整入口 | 参考输入直接影响角色一致性，是核心制作能力 |
| 模型选择、实际可用参数、生成、历史、图片编辑与下载 | 保留并补齐 | 静态模型名称、尺寸文字和大按钮不能替代现有制作控件 |
| 六类角度按钮、独立角度区、角度说明墙 | 删除常驻区 | 多角度不是每次制作都需要；原通用标签也不能直接解释成角度 |
| 对照面板、最近生成横条、多处状态／参数摘要 | 本轮不加或收进原记录 | 避免图片旁再叠一组重复结果和元信息 |
| 按类型强制画幅 | 删除强制规则 | 比例由当前模型、用户设置和实际媒体决定 |
| 新资产层级、复制资产、多角度批量生成 | 本轮不新增 | 名称改变无需引出新的对象管理和自动生成规则 |

图位用编号与“主图”表达，不写会误导采用流程的“候选 2”。删除受分镜引用保护的资产时，继续解释限制，不提供不存在的“强制删除”。

## 5. 节点三：分镜制作

默认进入**逐镜制作**：左侧镜头缩略图，中央当前镜头预览，原有设置区编辑脚本、参考和生成要求。标题栏保留清楚的“分镜图／分镜视频”切换，不再先进入网格和批量控制台。

| 对象 | 处理 | 原因 |
| --- | --- | --- |
| 镜头列表、名称、脚本、新增、提取、前后镜切换 | 保留 | 延续已有逐镜制作习惯 |
| 分镜图／分镜视频 | 在 v3 中完整补回 | 同一镜头的两种产物有不同输入、模型和记录，不能合成一个模糊的生成按钮 |
| 图片组、参考资产／图片、`@`、模型、提示词、参数 | 保留现有生图能力 | 与资产节点共用熟悉的制作语言，不重做一套图片工具 |
| 当前主图参考、运动提示词、视频模型、实际清晰度／时长参数 | 保留并补齐视频制作 | 固定的演示模型与“每镜候选数”不能代表真实视频能力 |
| 对白与音色 | 保留当前视频内折叠入口 | 不新增并行的台词表单、音效字段和声音绑定流程 |
| 图片编辑、历史、当前视频播放 | 保留 | 必须能修改、回看和继续迭代 |
| 网格／表格／单卡三段切换 | 从默认稿删除 | “单卡”就是现有制作；表格另增学习和维护成本 |
| 左侧镜头序列＋中间同一套网格 | 删除重复呈现 | 同屏只展示一套对象导航，空间留给可辨认的画面 |
| 常驻“本批生成”、统计大卡、重复批量按钮 | 删除 | 无批量任务时不应占据一整栏 |
| 已有批量能力 | 保留原有单一入口及实际范围 | 执行前区分生成图还是视频，不追加队列管理中心 |
| 全屏看图 | 保留为预览浮层 | 查看大图无需引入另一个制作模式 |
| 分镜总览、表格编辑、结构化运镜面板 | 本轮不新增 | 先恢复熟悉的默认路径，有实际需要后独立评估 |

状态只说明当前媒体和真实任务。例如有图但没有视频时，视频页显示“还没有分镜视频”，不把整镜标成“已完成”。图片组生成后直接保存；视频成功归档后按现有规则自动成为当前视频，不新增采用按钮。

模型、比例、时长按实际能力展示。没有真实任务数据就不显示“生成中 45%”“队列第 2 位”“约 66 秒”等精确值，也不预画当前任务没有的暂停与整队列取消。

## 6. 节点四：成片合成

使用现有成片编辑器作为设计底稿。顶部保留必要动作，上半区放媒体与预览，下半区放时间轴，右侧属性按当前选择展开；不以 v3 的简化演示时间轴替换真实编辑能力。

| 对象 | 处理 | 原因 |
| --- | --- | --- |
| 媒体入轨、预览、时间轴、裁剪、分割、撤销／重做、缩放 | 保留现有能力与入口 | 已能完成真实剪辑，不应因改稿缺失或改变规则 |
| 画面、原声、对白、字幕、配乐、音效 | 按当前轨道补齐，空轨可收起 | v3 不能遗漏独立原声；减少露出不等于删除轨道能力 |
| 锁定、静音、声音／字幕／画面属性 | 保留，跟随选中对象显示 | 只在需要时呈现相关参数 |
| 同步分镜视频、历史、专注剪辑、导出 | 保留原工具区 | 不把导出移动到新的常驻侧栏，也不另建同步向导 |
| 常驻导出检查清单、成功项列表 | 删除 | “素材齐全”等正常项无需逐条展示；真实问题在相关操作层说明 |
| 多处画幅、清晰度与固定 24fps 说明 | 删除重复或失实部分 | 输出配置在原导出设置中统一；当前代码使用 30fps 口径，设计稿不能自定数值 |
| 独立检查中心、第二条剪辑时间轴、新素材箱页面 | 本轮不增加 | 与现有工具重复，不解决本次流程陌生与界面过载问题 |

同步继续遵循已有来源版本与剪辑保护规则，已有成片与当前编辑预览保持区分。导出沿用当前弹窗和处理流程，不追加“先通过全部检查”步骤。

## 7. 四节点共用的界面与文案规则

以下规则仅用于节点内部，不改变外层顶栏、保存组件或 AI 创作助手。

| 调整项 | 具体做法 | 原因 |
| --- | --- | --- |
| 主视觉 | 剧本看正文、资产看图、分镜看当前镜头、成片看预览与时间轴 | 四节点各有主任务，无需强套同一种三栏模板 |
| 颜色与字体 | 沿用当前设计令牌与中文系统字；不用 Laper 营销页配色和英文等宽正文 | 让参考融入当前产品，避免再次产生陌生感 |
| 重复信息 | 每项统计保留一处；不在预览标题、图片和面板底部重复报状态 | 让用户扫一眼即可继续操作 |
| 生成动作 | 保留现有发送方式，用标签或悬浮说明明确“生成资产图／分镜图／分镜视频” | 不用“生成这一镜”混淆媒体类型，也不增设第二个提交按钮 |
| 图片与视频比例 | 预览按实际比例完整显示，生成配置服从真实模型能力 | 不为固定宫格裁掉关键人物和画面 |
| 空态 | 区分暂无内容、筛选无结果与读取失败，分别给新增／提取、清空筛选、重试 | 不用同一张空白页掩盖不同问题 |
| 异常与来源变化 | 在当前对象或操作层说明，保留输入、旧图与已有视频 | 减少常驻提示，同时保留恢复能力 |
| 窄屏 | 只调整节点内的列、标题和滚动：目录／设置沿用现有收起方式，正文与媒体适应剩余空间 | 不挤压成不可用的三栏，不改变助手当前响应式行为 |
| 可访问性 | 图片工具支持焦点和触屏；选中与异常有文字；弹层关闭后回到原入口 | 精简不能只剩悬停工具和颜色圆点 |

“资产”指当前流程的角色／场景／道具；“图片／视频”指媒体；“当前稿／候选”用于文本对比。不同对象继续遵守各自已有的保存与采用规则，不统一成一套“生成后确认”。
