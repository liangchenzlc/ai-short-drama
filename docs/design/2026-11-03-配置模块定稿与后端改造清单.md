## 2. 页面与交互约束

- 仅支持桌面，最低内容视口宽度为 **1280 CSS px**；核对 1280×720、1440×900。
- 配置内子导航的选中背景等宽；刷新、前进、后退保留当前页面与媒体标签。
- 删除模型搜索框及重复的页面标题、说明。编辑、测试用图标，提供 tooltip 和可访问名称。
- 输入框聚焦不增加边框、outline 或 shadow，沿原型以底色变化表示焦点；保留键盘可辨识状态。
- 助手三页及记忆编辑不出现保存、放弃修改、正常状态「已保存」。文本停止输入 **600ms** 后提交，开关和清空立即提交。
- **模型新增／编辑弹窗仍保留取消、保存；MCP 创建仍保留创建令牌按钮。** 这两种显式受理不改成输入即创建。
- 自动保存串行，切页不销毁待保存状态，旧响应不得覆盖新输入；失败保稿、可重试，409 比较实际修改字段后处理，结果未知先核对。

## 4. 模型配置与官方媒体覆盖

### 4.1 统一连接契约

普通表单字段顺序：服务商与接口类型同行 → 服务地址 → 密钥 → 模型标识 → 显示名称（选填）→ 启用／设为默认。弹窗宽 600px，最大高度为视口减 80px，内部滚动、标题和操作区固定。

新增公开字段 `interface_type`，由服务端规范化到现有 `runtime_profile`；**不新增与它重复的数据库协议列**。同一请求不得同时提交相互覆盖的 `interface_type` 与 `runtime_profile`。保留画布仍在使用的能力信息、扩展凭据与适配器，普通表单不再编辑这些 JSON。

自动识别保存为 `runtime_profile.api_format="auto", protocol="auto"`，扩展现有 schema 接受这个明确的未决状态；解析后的适配器只进入绑定连接指纹的缓存和运行快照，不覆盖用户的自动选择。显式 Google 图片使用 `api_format="gemini", protocol="gemini-image"`，不能继续用「非 Claude 一律 OpenAI」的校验规则。

文本只提供：`auto`（自动识别）、`chat-completion`（OpenAI Chat Completions）、`openai-response`（OpenAI Responses）、`claude-messages`（Claude Messages）。移除文本页 Gemini 原生选项，不影响新增 Google 图片接口。

创建示例：

```json
{
  "service_type": "text",
  "provider": "openai",
  "interface_type": "openai-response",
  "base_url": "https://api.openai.com/v1",
  "model_key": "用户实际选择的官方标识",
  "name": "",
  "apikey": "本次输入的密钥",
  "enabled": 1
}
```

- 空显示名由服务端回落到 `model_key`。API 密钥省略表示保留，非空表示替换，空字符串／null 表示删除；不返回已保存密钥。
- 改地址不弹出强制换密钥说明。目录请求不能把旧地址的已存密钥自动发送给新地址；跨地址使用需用户在当前表单明确输入密钥，不能借 `config_id` 偷渡旧密钥。
- 获取目录后原模型输入框原位变成可输入下拉；失败保留手填 ID。地址、密钥、接口类型变化使旧目录失效，迟到结果不覆盖新连接。
- 创建使用 `Idempotency-Key`，数据库按账号及 key 唯一，并校验原请求摘要；同 key 异体 409，同体返回原记录。列表可按 `create_key` 精确核对，不按名称认领。
- 默认按 text/image/video/audio 分别设置；没有默认时明确反馈，不能按 ID 找另一个服务商悄悄代用。用户显式选择的有效模型仍可使用。

### 4.3 能力矩阵与最小界面补充

每个型号维护服务端能力记录：文生／编辑／参考图，文生视频／图生视频／首尾帧／参考视频／参考音频，时长、比例、分辨率、原生音频、输出数量、输入文件限制、任务查询与取消能力。未知能力保持未知，不因接口名兼容就打开。

能力以可信官方资料和实际契约验证更新；不让用户填写 capability JSON、headers 或默认参数。普通用户仍只填写连接与模型。官方型号标识、接口修订、资料日期、证据链接由后端目录维护。

可灵鉴权的表单补充固定为条件字段：选择官方 Kling 接口后，原「API 密钥」位置展示 **Access Key、Secret Key** 两个密码输入；复用 `apikey` 与已存在的加密 `secret_key`，两者均可省略保留、直接替换、清空删除。其他服务商仍是一颗 API 密钥输入。服务端生成短期签名，不要求用户保存临时 JWT，也不恢复「高级接入」。此为原型字段区的必要补充，开发前更新媒体原型并完成桌面核对。

选择服务商时带入官方地址和接口类型；仍允许显式修改接口类型。官方服务没有可查询模型目录时，使用维护的型号目录或手填，不能伪造 `/models` 成功，也不能把「列出型号」解释为账号已经获准调用。

### 4.4 自动识别与测试

- 优先使用可信服务商域名、接口目录及型号映射；凭据只能发送到已校验的当前连接。
- 文本未知服务在测试或首次调用时识别；只有明确「协议不支持」才允许换协议。401、403、429、超时、受理未知都不得触发换站或重复生成。
- 媒体只按可信目录识别，禁止试生成探测。未知地址要求手选接口类型；不能默认猜成 OpenAI。
- 缓存绑定规范地址、凭据身份、模型、接口选择及解析器版本；修改连接即失效。
- 测试必须由用户点击开始，使用已保存配置，不写入项目成果；媒体结果来自该次实际任务。关闭测试框不等于取消任务。
- 复用现有受理、轮询、取消、未知结果恢复和结算机制，不新增另一套测试 Worker 或任务表。

### 4.6 图片协议的策略与适配器架构

2026-11-03 补充：用户确定在现有协议基础上扩展，使用策略模式与适配器模式。现有 `select_adapter`、`build_submission`、`parse_result` 等入口保留职责和调用签名，图片分支改为注册表分发；已经实现的请求／解析逻辑迁入对应适配器。不建立另一套生成任务、HTTP 出站或前端直连系统。

#### 协议保留矩阵

| 图片接口族 | 保留标识 | 实施动作 |
| --- | --- | --- |
| OpenAI Images | `openai-image` | 将已有生成、编辑与型号限制封装为 OpenAIImagesAdapter，复用现有计算及结果解析 |
| 火山方舟 Images | `volcengine-ark-image` | 封装为 ArkImagesAdapter，扩展 Seedream 型号能力，不改协议身份 |
| 通义／万相 Images | `qwen-image`、`dashscope-qwen-image` | 两个标识对应同一个 DashScopeImagesAdapter 注册项；按型号区分请求修订，不维护两套实现 |
| Google Gemini Image | `gemini-image` | 前端已有图片请求／解析；保留名称与功能，补 GeminiImagesAdapter 后端受控执行 |
| Grok Image | `grok-image` | 前端已有生成／编辑分支；补 GrokImagesAdapter，按实际差异组合共用 Images 处理，不假定与 OpenAI 全部一致 |
| RunningHub 图片工作流 | `runninghub-workflow-image` | 退役图片目录、配置入口和执行注册；不改名映射成其他图片协议 |

正式图片下拉展示「自动识别＋五个接口族」。通义的两个代码标识在注册项中作为现有别名处理，界面只展示一个接口族。现有模型的稳定 ID、密钥和真实调用历史保留；RunningHub 图片配置按第 9 节的退役步骤单独处理。

```mermaid
    A[业务生成与模型测试] --> B[现有任务受理与 Worker]
    B --> C[显式选择或可信目录策略]
    C --> D[静态协议注册表与型号能力]
    D --> E[对应图片协议适配器]
    E --> F[现有受控网关]
    F --> G[适配器解析为 GenerationResult]
    G --> H[现有恢复、结算与归档]
```

准入时冻结适配器 ID、型号能力及协议修订，Worker 使用同一快照；不能在任务等待期间因为目录更新重新选择协议。授权仍按实际执行时当前权限复核。适配器声明鉴权要求，已有网关从服务端加密凭据注入认证；密钥不进入公开目录或前端响应。

#### 统一内部契约

新增的 `ImageProtocolAdapter` 使用 Python `Protocol` 描述结构，不引入 DI 容器或插件扫描。下列为实现契约，省略号仅表示协议方法声明，不代表运行时空实现：

```python
from typing import Protocol
from pydantic import JsonValue
from short_drama.ai.types import GenerationResult

class ImageProtocolAdapter(Protocol):
    adapter_id: str

    def capabilities(self, snapshot: dict[str, JsonValue]) -> dict[str, JsonValue]: ...

    def build_submission(
        self, snapshot: dict[str, JsonValue], request: dict[str, JsonValue]
    ) -> tuple[str, dict[str, str], dict[str, JsonValue]]: ...

    def parse_result(
        self, body: dict[str, JsonValue], *, submitted: bool, task_id: str | None = None
    ) -> GenerationResult: ...

    def poll_endpoint(self, snapshot: dict[str, JsonValue], task_id: str) -> str: ...
```

同步协议不会触发轮询，意外调用沿用现有 `unsupported_poll` 错误。需要异步任务的协议继续返回现有 `GenerationResult(status="submitted", provider_task_id=...)`，由现有 Worker 轮询。认证失败、限流、超时、结果未知的分类和恢复仍统一由现有运行链处理，适配器不另起重试循环。

`registry.py` 静态注册接口标识、别名、适配器实例及安全元数据，供配置 options、发现、普通生成、画布和模型测试共同消费。`ai/model_protocols.py` 仅汇总公开协议元数据；选择和执行都不能再维护互相矛盾的图片协议名单。适配器不得反向 import Service 或从 facade 调用回自身。

扩展步骤固定为：

1. 同一协议的新型号：增加或更新可信型号能力，验证现有适配器即可；已有型号的能力不可被无关新型号覆盖。
2. 请求／响应出现真实协议变化：修改该适配器；确有同时使用的官方修订时在型号配置中明确修订，不删除其他现有协议。
3. 新接口族：增加一个适配器、一个注册项和契约测试；页面从 options 获取选项，业务生成入口不新增供应商分支。

验证先覆盖现有三个后端图片协议的组装／解析等价，再补 Gemini／Grok 的受控端到端测试。必须证明别名命中同一适配器、未知地址要求手选、配置与测试分发一致、RunningHub 图片入口确实退役，而视频／音频工作流未被误删。本次只更新设计与计划，适配器类尚未写入业务代码。

## 5. 助手设置与运行权限

### 5.1 一份账号设置、部分字段更新

推荐响应：

```json
{
  "custom_instructions": null,
  "default_instructions": "服务端默认个性化指令",
  "workbench_enabled": true,
  "media_generation_enabled": true,
  "long_term_memory_enabled": true,
  "settings_version": "1"
}
```

PATCH 必须带 `settings_version`，并至少包含一个实际修改字段；省略不更新。`custom_instructions` 为 0–16000 字符，空字符串规范化为 null，使用默认；三个布尔开关拒绝 null。原用户额度与 `deployment_limits` 从此公开设置 DTO 移除。

```json
{"settings_version":"1","workbench_enabled":false}
```

服务端在同一事务中进行 CAS 并返回新版本。前端三页共用串行队列，提交 dirty 字段，不能继续用完整替换覆盖另一个页面。结果未知时 GET 核对版本和原修改字段；相同目标值只说明已收敛，不能声称能证明该次请求一定执行。版本变化且字段不同则进入冲突处理，禁止盲目重发。

个性化指令下一 Run 生效，当前 Run 保持冻结指令；它位于系统规则之下，不能替代工具授权。工作台、媒体、记忆权限按后续实际执行边界读取当前值。

### 5.2 权限矩阵

| 工作台 | 媒体偏好 | 有效能力 |
| --- | --- | --- |
| 关闭 | 任意，隐藏但保留 | 只读分析主动引用资料、文字建议；禁止业务修改、采用、生成 |
| 开启 | 关闭 | 可修改／采用作品，禁止媒体提交 |
| 开启 | 开启 | 可修改／采用，并允许图片、视频、音频生成 |

去掉代码执行开关与三个分媒体开关。沙箱内计算不等于工作台写权限；沙箱或 Skill 间接调用业务写入也必须经过同一授权边界。

这些开关控制内置助手的操作，MCP 使用令牌授权；用户本人在工作台中的编辑、采用、生成按钮仍按原账号权限工作，不能因复用 Service 而被助手开关一起关闭。

为工具增加明确的业务能力标签，而非只看名称前缀或 `effect=write`。工作台修改、媒体生成、长期记忆读写分别判断：记忆写入不应误受工作台开关控制。目录过滤用于减少无效调用，Service 和实际外发边界负责授权。

主助手、子助手、Skill、运行时调用均受约束。`runtime__propose_script_patch` 当前只保存建议，不能误当已写正文；关闭工作台可给文字建议，可执行提案和真正采用入口按工作台权限检查。

权限关闭不取消已经外发的媒体任务；后续尚未外发的任务不得继续发送。已有收据、恢复、账本、归档与已发任务结算保留。

## 6. 账号级长期记忆

### 6.1 存储与管理

- 记忆只归 `owner_user_id`，不含 `scope_type`、`scope_key`、`project_id`、`conversation_id` 或来源会话／消息外键；修订快照也不携带这些归属。
- 管理页只保留开关及管理入口。560px 抽屉内服务端搜索、分页，按 `updated_at DESC, id DESC` 排序；**移除全部／个人／作品／会话筛选及来源对话展示**。
- 列表只查当前账号，标题、内容、更新时间足够支撑管理；详情复用已有 GET。标题最多 200、正文最多 12000 且非空；PATCH 使用 `content_version`，编辑自动保存。
- 页面不提供手动新建，内部显式记住／更新／遗忘／恢复能力保留并改为账号级。
- 删除需确认，不删除原对话、作品或必要上下文；删除会话也不删除账号记忆。
- 自动提炼仅收录适合跨作品使用的用户偏好和长期事实，不把角色设定、剧情事实、当前作品细节提升为账号偏好。

### 6.2 开关的执行语义

默认开启。关闭后已有记忆保留且可人工管理，但 Agent 不召回、不读写、不后台抽取；必要当前会话历史与上下文摘要继续工作。重新开启不补抽关闭期间输入。

具体实现约束：

1. `agent_preferences.memory_generation` 只在长期记忆开关变化时递增；消息受理记录 `memory_capture_generation`，关闭时为 null。
2. 抽取只选择符合当前 generation 的已应用真实用户输入，覆盖普通发送、补充及工具问答。重新开启后旧 generation 的输入不能被扫描补抽。
3. 抽取任务冻结 generation，在排队、外发、落库处复核。即使关闭后又开启，旧任务结果也不能落成记忆。排除的输入推进已处理水位，不阻塞之后新消息。
4. 每次后续模型请求核对当前开关和记忆目录版本／指纹；关闭、修改、删除后，撤去缓存的记忆正文及其派生注入，不清空真实当前对话。
5. 抽取任务仍需消费某次对话的输入、维护任务水位；这些属于运行队列和上下文，不成为记忆归属，不建立记忆条目到会话／抽取任务的关系。

### 6.3 无会话关联时的遗忘

现有 `agent_memory_sources` 从会话／消息关联改为账号记忆的**不可逆来源内容指纹**，删除会话 ID、消息 ID、序号和作品主体关联。记忆接口不返回这些指纹。

保留账号级规范 `kind + memory_key`、来源内容指纹和遗忘标记，阻止旧输入或在途抽取把已删条目立即写回。Agent 显式记住时仍在运行现场核对实际用户输入，校验后不把其消息 ID 保存到长期记忆实体。恢复必须有新的明确用户意图，后台抽取不能自行解除遗忘。

现有会话摘要、工具审计、任务消息继续记录各自运行来源；这不赋予记忆会话范围，也不允许按来源对话检索长期记忆。不能为取消长期记忆关联而一并删除正在使用的任务上下文系统。

## 7. MCP 独立授权

### 7.1 项目与工具范围

令牌动态作用于账号当前有权访问的全部项目，包括后来新建项目；失去权限的项目立即不可访问。无项目也可创建。删除 `project_ids` 入参、持久列及固定项目快照校验，不隐藏前端多选后偷偷传全量项目 ID。

工具授权由后端将开关展开为**当前明确工具名单并存储快照**，将来新增工具不自动授权：

| 预设 | 当前工具 |
| --- | --- |
| 默认只读 8 项 | `workbench__list_projects`、`workbench__read_project`、`workbench__read_assets`、`workbench__read_storyboard`、`workbench__read_current_script`、`workbench__read_image_group`、`workbench__read_image_content`、`workbench__get_generation_status` |
| 工作台增加 3 项 | `workbench__apply_standard_patch`、`workbench__apply_canvas_patch`、`workbench__set_image_group_primary` |
| 媒体再增加 1 项 | `workbench__submit_generation_batch` |

创建接收 `name`、`workbench_enabled`、`media_generation_enabled`、`expires_at`、`allowed_ips`；默认只读。父级关闭时前端隐藏媒体项，提交时有效媒体为父 AND 子。省略有效期由服务端给 90 天，显式 null 为永久，界面提供 30／90／180 天及永久。

`options` 返回 `connection_url`、`transport="streamable-http"`、工具及能力分组，不返回 projects。接入地址由现有 `public_origin` 和 `/mcp/` 生成，不取前端开发端口。每次请求 Bearer 认证，沿用 IP/CIDR 限制、账号状态校验与审计，不新增 OAuth。

### 7.2 令牌与结果未知

列表列为名称、MCP 令牌、授权范围、有效期、状态、操作；密钥提示独立一列。完整 secret 仅首次成功创建响应展示，关闭弹窗清理；列表及精确核对均无真实 secret。

创建使用 `Idempotency-Key`，存储 `create_key/create_hash` 并按账号唯一。同体重放返回同一令牌的安全元信息，HTTP 200、`secret=null`；首次 HTTP 201、`secret` 有值。不同体重用 key 返回 409。`GET /account/mcp-tokens?create_key=...` 精确核对原次结果，含必要的撤销状态。

请求摘要基于规范化的原始请求意图；省略的「90 天」只在首次受理时计算绝对到期时间，重放不能因当前时间变化算出新摘要或新有效期。

响应丢失后不能按名称认领，不能自动撤销可能属于别次操作的令牌；准确核对后由用户显式撤销、重建。服务端不为重放密钥存明文或可还原 secret。

### 7.3 解除当前隐性耦合

当前 MCP 与助手媒体操作共用的受理 Service、最终生成外发检查会读取助手媒体开关，尚未达到独立授权。按可信 `BusinessInvocation.source` 分流：

- `assistant`：检查当前工作台与媒体开关、Run／任务对象范围。
- `mcp`：检查实际 token ID 的有效、到期、撤销、工具名单及当前项目访问权，不读取内置助手开关。

生成受理和 Worker 最终外发前均执行来源对应的检查，可信来源与 token ID 随原业务收据保存，不能由普通请求体伪造。不能通过把 `assistant_managed/agent_managed` 改为 false 绕开检查，因为这些标记还参与恢复和归档。

项目尚未上线，采用一次同版本切换，不保留两套旧新 API 或数据读取路径：

1. 实施时先核对真实库版本，不能仅凭 schema 文件假设旧 Agent 迁移已应用。按项目规范修改 ORM、生成增量 SQL、在目标开发库执行并重新导出 schema。
2. 停止新写入，核对未决创建请求；让 Agent 与 Worker 到可恢复边界后停旧进程，再执行删列迁移。已外发任务保留原收据和恢复结算，不误判为未发送。
3. 记忆迁移前导出受影响记录到受控、忽略提交的 `.runtime/` 备份。原个人条目保留为账号记忆；旧作品／会话条目备份后移出在线记忆，不能静默提升为全局偏好。修订和来源同步处理，不建立历史兼容表。
4. 旧逐项目 MCP 令牌统一撤销后重建，不能静默扩大到全账号项目；明确告知重新配置外部客户端。
5. 前后端同版上线；旧媒体配额／memory_project_ids 未决请求不得修改请求体后沿用原幂等 key 自动重发。
6. RunningHub 图片退役前导出受影响配置，使用现有逻辑删除机制撤下该类图片配置并清除对应默认。已外发图片工作流先完成结算，再撤图片执行注册；未外发的停止受理。不把存量工作流 ID 自动转换成普通图片模型，也不为退役图片协议保留长期双路径。视频／音频配置及工作流正常保留。

本轮只形成这些迁移步骤，不执行数据清理或撤销真实令牌。
