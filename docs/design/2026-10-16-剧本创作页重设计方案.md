> 关联：[产品范围](../../frontend/PRODUCT.md)、[设计约定](../../frontend/DESIGN.md)、[2026-10-08 确认设计](2026-10-08-标准模式创作流程设计.md)。

## 1. 背景与目标

现状（对应 `frontend/PRODUCT.md`「小说改编」一节）：标准分集第一步以「小说改编」命名，左侧为「剧本改编设置」（本集画幅、视觉风格、改编要求），小说原文藏在「查看原文」抽屉，整页默认「先有小说，才能开始」。

但本集剧本的真实来源至少有三类：

1. **小说改编**——AI 从小说原文生成；
2. **故事梗概/创意**——AI 将几段话扩写为剧本；
3. **外部已生成**——用户在其它平台或线下写好，粘贴文本或上传文件导入。

此外还存在「空白起稿、直接手写」的用法。

**设计目标**

- 步骤一从「小说改编」改为中立的「**剧本创作**」，唯一目标是产出一份「已确认剧本」，不预设来源；
- 三种来源 + 手写在一页内都有清晰入口，小说只是来源之一；
- 保持既有产品约束：左设置 / 右正文布局、串行自动保存、候选先预览后明确采用、确认定稿后才进入下游步骤。

## 2. 市场参考

同类产品均采用「多通道入口 + 统一编辑器」，不绑定单一来源（据公开资料）：

- **剧云（jucloud）**：进入创作先选通道——新建原创 / 网文改编 / 剧本改写 / 对标拉片，再渐进式生成（梗概→大纲→分集→正文）。
- **StoryPlay**：工作台先选「新建原创剧本 / 网文改编 / 剧本改写 / 对标拉片」；「小说拆书」与「灵感策划」并列为起点。
- **量子起源（一站式 AI 短剧工作台）**：「上传小说 → 解析生成分集剧本」与「输入创意 → AI 澄清 → 大纲剧本」两种入口并列展示。

**结论**：把「小说改编」降为来源之一、新增「梗概创作」与「导入剧本」入口，是市场共识做法。

## 3. 设计策略

1. **步骤更名**：顶部步骤一「小说改编」→「剧本创作」；步骤 2/3/4 与状态文案不变。
2. **空态即入口**：无剧本时，正文区呈现三张来源卡片（从梗概创作 / 从小说改编 / 导入已有剧本）+「空白起稿」次级链接。
3. **来源可见可换**：有剧本后，左列新增「**来源素材**」行（小说原文 / 故事梗概 / 外部导入 + 查看），点击打开全高抽屉；素材与剧本分离，改素材不自动改剧本。
4. **一条生成流水线**：所有 AI 来源共用「**创作要求**输入框（含模型选择与发送）→ 候选只读预览 → 采用并编辑 → 确认剧本」，与原「改编要求」链路一致，仅术语泛化。
5. **导入不覆盖**：导入的剧本先作为新候选预览，「采用并编辑」后才替换当前稿；已有剧本时弹窗明确提示「当前稿会保留」。

## 4. 页面结构（桌面 ≥1700px 基准，1440 截图）

### S1 空态（无剧本）

- 左列「剧本设置」：本集画幅、视觉风格照常可配；下方为提示卡——「还没有剧本 / 从右侧选择一种开始方式。开始后，这里会显示来源素材与 AI 创作要求，用于生成或改写剧本。」
- 右面板「本集剧本」标题栏下为居中引导：标题「开始创作本集剧本」，副标题「从小说、梗概或已有剧本开始，之后都可以用 AI 继续改写」。
- 三张来源卡片（每张 288×196，`#1f1f20`、圆角 12）：
  - **从梗概创作**：用几段话讲清本集故事，AI 扩写为完整剧本 →「开始创作」
  - **从小说改编**：导入或粘贴小说原文，按创作要求生成剧本 →「导入小说」
  - **导入已有剧本**：粘贴文本或上传文件，直接在本页继续调整 →「导入剧本」
- 卡片下方次级入口：「或者，直接写空白剧本，稍后再用 AI 润色」。
- 顶部步骤一状态显示「无剧本」（低强调色）。

### S2 编辑态（示例：来源 = 小说改编，剧本待确认）

- 左列「剧本设置」：
  - 本集画幅 / 视觉风格（同现状）；
  - **来源素材**行：图标 + 「小说原文 · 12.4 万字」+ 更新时间 + 「查看」→ 打开抽屉；梗概源显示「故事梗概 · 约 320 字」，导入源显示「外部导入 · 10 月 16 日」；
  - **创作要求**输入框（180px，圆角 12）：描述对 AI 创作/改写的要求；底部左侧模型选择、右侧圆形发送按钮；
  - 生成前先完成来源素材与要求的保存（沿用现有串行保存与受理不明核对规则）。
- 右面板「本集剧本」：
  - 标题栏：标题 + 状态标签（待确认 = 警告色，已确认 = 成功色）；右侧「生成记录」「导出」「确认剧本」（仅待确认时出现）；
  - 工具栏：加粗 / 斜体 / 引用 / 撤销 / 重做 + 「1,286 字 · 3 场」+「场次定位」；
  - 正文：14px、1.95 行距、760px 居中阅读宽度；场次标题（亮色加粗）/ 动作描述（次级灰）/ 角色名（加粗）/ 括注（弱化灰）/ 对白（亮色）分层。
- 步骤一状态显示「待确认」。

### S3 导入剧本弹窗（560px 宽）

- 说明：「粘贴剧本正文，或上传文件。导入内容会先作为新候选预览，不会直接覆盖当前稿。」
- 保护提示条（警告色）：**「当前剧本（待确认）会保留；导入内容采用后才替换本集剧本。」**
- 粘贴框（高 210px）：占位「在此粘贴剧本正文…」，右下角实时字数「0 字」；
- 「或」分隔 →「选择文件」按钮 + 「UTF-8 / GB18030 · 最大 1 MiB」（沿用小说导入约束）；
- 辅助说明：「导入后自动按空行整理段落与场次；可随时在编辑器中调整。」
- 页脚：「取消」/「导入并预览」（主按钮）。

### S4 来源素材抽屉（左侧全高 500px，示例：小说原文）

- 标题栏：「小说原文」+「导入小说」+ 关闭；**梗概模式同位置标题改为「故事梗概」**，内容更短、更口语；
- 信息行：「共 12 章 · 12.4 万字」+「自动保存」；
- 正文：可编辑原文（与现行「查看原文」抽屉一致，关闭不丢输入）；
- 底部提示：「原文修改不会自动更新剧本；生成新一稿时会使用最新原文。」

### S5 从梗概创作（点击「从梗概创作」之后）

- 右面板整体切换为梗概输入面板：顶部「返回选择其他方式」；标题「从梗概创作」；说明「用几段话讲清本集故事：人物、核心冲突、结尾钩子」；
- 梗概文本域（640×210，含示例占位）＋「0 / 2000 字」计数与「建议 200 字以上」提示；
- 底部主按钮「生成剧本」：保存梗概并触发生成（与左列创作要求 + 发送等效）；生成后进入候选预览（S7）；
- 左列同步进入待生成状态：来源素材显示「故事梗概 · 正在右侧输入…」，创作要求变为「可选：补充生成要求…」。

### S6 空白起稿（点击「空白剧本」之后）

- 直接进入可编辑空稿：右面板为完整编辑器（工具栏 + 空正文 + 写入提示占位），落笔即自动保存；
- 步骤一状态与标题栏标签均为「草稿中」；「确认剧本」在空稿时禁用（半透明），有内容后可定稿；
- 左列来源素材显示「空白剧本 · 手写」；创作要求 + 发送可随时让 AI 生成一版新候选（不覆盖正在写的内容）。

### S7 候选预览（点「发送 / 生成剧本 / 导入并预览」之后）

- 标题栏：标签变「候选预览」；动作区只保留「生成记录」与「采用并编辑」（导出与格式工具栏隐藏）；
- 提示条：「正在预览新生成的候选稿；「采用并编辑」后成为当前稿，当前稿不受影响。」；
- 正文只读展示候选内容；点「采用并编辑」→ 候选成为当前稿并回到编辑态（S2）；在此之前当前稿始终不变；
- 生成期间同一区域显示「剧本正在生成…」与骨架占位；失败就近提示并可核对重试（受理不明只核对原请求，不自动重发）。

### S0 交互总览（画布第二行）

- 四条流程链：AI 生成（选择来源 → 准备素材 S5/S4 → 创作要求 + 发送 → 生成中 → 候选预览 → 采用并编辑 → 编辑态 → 确认）、导入剧本、空白起稿、改稿再生成；
- 两条规则注：候选先预览、不覆盖当前稿；受理不明只核对、不自动重发。

### 「剧本设置」列的作用

「剧本设置」是本集剧本创作的全部前置配置，对所有来源通用，分两组：

- **本集规格**（画幅、视觉风格）：影响本集全流程——素材、分镜、成片的画面比例与风格基准；
- **AI 创作**（来源素材 + 创作要求 + 模型）：来源素材是 AI 的输入材料（小说原文 / 故事梗概 / 空白 / 外部导入），创作要求是"怎么改"的指令；改素材或要求不会自动改剧本，点「发送 / 生成剧本」才会生成新一稿。

因此它不是"只为小说改编服务"——换成梗概、导入或手写来源时，同一区域显示对应的来源与状态。

## 7. 响应式与无障碍

- 沿用现有断点（≥1700 / 1440–1699 / 1280–1439 / 1100–1279 / 1000–1099 / 701–999 / ≤700）：左列 306→260px 递减；≤1000px 来源抽屉与助手互斥；≤700px 卡片与主面板纵排（来源卡片改为纵排单列）。
- 卡片、来源行、导入按钮均为键盘可达焦点；弹窗保留 Escape、Tab 循环、关闭后焦点恢复。

## 8. 埋点与上线验收

**埋点事件**

- `script_source_select{source: synopsis|novel|import|blank}`——空态通道点击；
- `script_source_drawer_open{source}` / `script_generate_submit{source, model}`；
- `script_candidate_adopt` / `script_confirm`；
- `script_import_submit{mode: paste|file, chars}`。

**关注指标**：各通道使用占比、首份剧本产出时长、生成→采用转化率、导入→采用率、确认率。

**验收清单**

1. 四态走查：空态 → 生成中 → 候选预览 → 采用编辑 → 确认，外加导入路径（粘贴/上传各一次）；
2. 步骤一名与状态文案正确（无剧本/待确认/已确认）；
3. 保护路径：导入不覆盖当前稿、冲突不自动覆盖、生成前等待保存回执；
4. 1440 / 1280 / 1024 / 390 四档走查；键盘与焦点循环；空/失败/加载三态齐全。

## 9. 实施提示（供后续评审通过后执行，本次未改代码）

1. **步骤与文案**：顶部步骤一名称、`aria-label`、「剧本设置」「来源素材」「创作要求」等文案调整；
2. **空态**：`NovelScriptGeneration` 的正文区渲染需新增空态分支（三通道卡片组件）；卡片点击 → 打开对应抽屉（小说/梗概）或导入弹窗；
3. **来源行**：左列在画幅/风格字段下新增「来源素材」行，读取当前稿的来源类型与素材统计；
4. **导入弹窗**：新增组件（粘贴文本域 + 文件选择 + 字数），提交动作需服务端评估：**导入剧本作为候选**是否可复用现有剧本候选接口；如暂不支持，可降级为「导入后进入本机草稿，保存为新稿」并明示；
5. **抽屉**：复用现有「查看原文」抽屉，按来源类型切换标题/统计/导入按钮；
6. **文档同步**：评审通过后同步更新 `frontend/PRODUCT.md` 对应段落与 `frontend/DESIGN.md` 的局部文案。
