## 1. 现状与本轮要解决的问题

当前「剧本创作」（`source` 阶段）的实际结构是：左列「剧本设置」放文本模型、创作要求、来源素材；右侧一张「本集剧本」面板，里面是 Quill 富文本 + 场次跳转按钮；候选结果用「当前稿 / 最新生成」两个标签切换，整篇「采用并编辑」。

它的问题不在边角，在结构：

| # | 问题 | 具体表现 | 影响 |
| --- | --- | --- | --- |
| 1 | 名字和产品模型对不上 | 面板仍叫「本集剧本」，但项目早已没有分集，一部作品只有一份正文 | 用户不知道这一页到底在写"整部剧"还是"某一集"，也不敢多写 |
| 2 | 只有"一次生成整篇"这一条主链路 | 没有故事层（一句话、大纲、人物小传）→ 场次 → 正文的中间结构 | 每次生成都靠一段自由文本描述要什么；生成结果没法按场调整 |
| 3 | 正文是"富文本"，场次不是一等对象 | 只有正则提取的场次跳转按钮，没有场号/日夜/内外/地点/出场人物的可见结构 | 到素材、分镜阶段要重新解析一遍，剧本里的人和场景在这一页不可见、不可点 |
| 4 | 版本能力弱 | 只有两个标签切换 + 生成记录列表，不能看差异，不能只采用改动的那几场 | 改一版就得整篇替换，不敢用 |
| 5 | 短剧的硬指标没有反馈 | 页面只有字数和场次数，没有时长、钩子分布、人物一致性 | 写到 3000 字才发现节奏塌了，返工成本最高 |
| 6 | 空态与设置栏职责重叠 | 正文区四个入口卡片，左栏又有一份来源摘要和生成入口 | 第一次进来不知道先点哪；两处入口状态不同步 |

结论：这不是"换个好看的皮肤"，而是要把**剧本当作有结构的生产文档**来承载，并且让这一页成为四阶段（剧本 → 素材 → 分镜 → 成片）真正的上游。

## 2. 市场研究：同类产品在这一页放什么

按形态分四类，各自解决的是不同问题。

### 2.1 短剧一站式工作台（国内，最接近本项目）

| 产品 | 这一页的核心内容 | 布局 | 值得注意的点 |
| --- | --- | --- | --- |
| 小云雀 AI · 短剧 Agent（剪映/字节） | 前期策划案（集数、受众、核心梗、类型、故事梗概、人物小传）→ 分集大纲 → 标准场次剧本（场次、场景、出场人物、剧情描述）→ 角色/场景资产 | 剧本助手独立面板 + 画布；资产、分镜、3D 导演台在同一工程里 | 剧本产出直接进资产与故事板；有版本管理、热点库、系列剧、小说改编、对话共创 |
| 创一AI（公开测评口径） | 大纲 + 人设 + 世界设定一体；按短剧公式控制爽点间隔；对话式改稿（"第 3 集节奏太慢，压缩 30 秒"）；16 维过稿评估 | 对话 + 结构化大纲 | 把"改稿"做成对话指令，而不是重新生成整篇 |
| 蛙蛙写作 / 豆包 / Kimi | 批量分集初稿、长文拆主线、设定梳理 | 通用对话 | 产出停在初稿，缺结构化与下游衔接 |

共同点：**先策划案，再分集大纲，最后才是剧本正文**；剧本正文必须是标准场次格式，因为下游要按场拆资产和分镜。

### 2.2 专业编剧软件（国际，结构与版本做得最细）

| 产品 | 这一页的核心内容 | 值得注意的点 |
| --- | --- | --- |
| Final Draft 13 | 剧本正文 + Beat Board（节拍板/索引卡）+ Scene Navigator（场次导航）+ 修订色 | 场次导航是标配；修订版本用颜色区分，不改正文也能看出改过哪 |
| Arc Studio Pro | 干净编辑器 + 大纲/卡片 + 角色关系 | 结构化大纲与正文同屏 |
| WriterDuet | 实时协作 + 版本控制 + 制作拆解 | 版本与协作是核心卖点 |
| Celtx | 剧本 + 拆解 + 通告单 + 预算 | 剧本直接生成制作要素 |
| Novelcrafter | Codex（人物/地点/设定库，自动注入 AI 上下文）+ Grid/Matrix/Outline 三种规划视图 + Scene Beats（逐场生成）+ 章节摘要 | 设定库不是摆设，是每次生成的固定上下文；逐场推进而不是整篇重写 |

共同点：**场次导航 + 设定库 + 版本/修订** 是专业工具的三角，缺一个都会在长篇里崩。

### 2.3 网文平台作家工具（中文写作习惯）

- 阅文作家助手：大纲/角色/设定模板、章纲提取、多平台读者视角预览、错字检测。
- 番茄作家助手：每本书一份独立大纲、模板、自动保存、错字检测、码字统计。

共同点：中文作者习惯「大纲」和「人物」放在正文旁边随时翻，而不是藏在设置里；也习惯"先有模板再动笔"。

### 2.4 共性规律（可直接借的）

1. **双层结构**：故事层（一句话/梗概/人物/大纲）+ 正文层（场次），两层同屏可见。
2. **场次是一等对象**：有编号、时间、内外景、地点、出场人物、时长，可导航、可排序。
3. **设定即上下文**：人物与设定不是给人看的装饰，是每次生成的固定输入。
4. **改稿要能定位**：局部改写、逐场重生成、版本对比，比"整篇再来一版"更常用。
5. **格式即交付**：剧本最终要能拍，格式（△动作、OS/VO、闪回）必须可插入、可校验。
6. **空态即引导**：新作品的第一个画面就是"从哪开始"，而不是一个空白编辑器。
7. **短剧特有指标**：单场时长、钩子密度、爽点间隔——国际编剧软件不管这些，但短剧必须管。

### 2.5 明确不借的

- **分集管理**：本项目一部作品一份正文，没有分集；引入分集等于改产品模型。
- **多人协作/评论/审阅**：当前是个人创作者独占项目。
- **节拍板卡片墙**：拖拽卡片对短剧（场次多、单场短）收益低，先做列表 + 节奏条。
- **专业排版与 PDF 交稿**：本期导出仍是文本；PDF/标准格式排版单列。
- **通用 Codex 库**：素材阶段已经有角色/场景/道具，另建一套设定库会重复且冲突。

## 3. 取舍：落到本项目是什么形态

| 龙头做法 | 采纳 | 在本项目的形态 | 理由 |
| --- | --- | --- | --- |
| 故事层策划案（梗概/人物/大纲） | ✅ | 左栏顶部「故事设定」三段：一句话卖点、故事大纲、人物小传 | 短剧投稿本来就要求这几件；同时是 AI 的固定上下文 |
| 分集大纲 | ❌ → 改造 | 不做分集，改成"场次列表"（场号 + 日夜/内外 + 地点 + 人物 + 估算时长） | 产品无分集；场次就是最小生产单位 |
| 场次导航（Final Draft） | ✅ | 左栏场次列表，与正文滚动联动，可跳转/新增/拖拽排序 | 12 场以上就必须有导航 |
| Codex 设定库 | ✅ → 复用 | 不新建库，人物小传与素材阶段角色双向打通（已提取 4/6） | 避免两套人物数据 |
| 节拍板/卡片墙 | ❌ | 用「节奏条」替代：按场次时长比例的色块 + 钩子标记 | 短剧看的是时间轴上的钩子分布，不是卡片位置 |
| 逐场生成/局部改写 | ✅ | 选中台词/动作 → 浮条「更狠/更短/更口语/加动作」；右栏可"从第 N 场续写" | 改一版比生成一版更常用 |
| 版本对比/修订色 | ✅ | 候选态按场对齐 diff（− / +），可勾选场次采用 | 替代现在"整篇采用"的粗暴做法 |
| 一致性检查 | ✅ | 底部体检条：未登记人物、时长超标、缺钩子 | 前端从正文即可算出，不需要新接口 |
| 多人协作 | ❌ | — | 产品边界 |
| 导出 PDF/交稿格式 | ⏳ | 本期仍导出文本，PDF 排版进 P2 | 不影响主链路 |

## 3.5 实施时的简化（当天追加）

首版落地后按「功能不变、减少常驻控件」做了一轮精简，评审以此为准：

- 去掉正文区的节奏条（整行），钩子只在场次列表用小菱形和底栏计数表达；
- 场头只留「场号 · 日夜内外 · 地点 · 钩子」，出场人物放回左栏；
- 底栏去掉进度条、场次数与「下一步」（步骤导航本身可跳转）；
- 左栏保留一句话卖点、故事大纲、人物小传三个独立入口（不合并），弹窗内三段一起编辑，点哪项就聚焦哪段；
- 右栏去掉「生成范围」独立分组和候选列表，只保留来源、要求、约束（含从某场续写）、上次生成；
- 文档头部把重复的「版本」「生成记录」合成一个「记录」入口。

净效果：少一整行节奏条、左栏两行、右栏两个分组，正文多出 30px 高度；场次列表与所有生成能力不变。

第二轮（同日）继续收：

- 场次列表只保留场号、日夜内外、地点与出场人物，**不再显示每场时长**（时长无法从文字精确得出，只在底栏给全篇估算）；
- 结构栏可收起为 36px 图标条，写作时正文占满；
- 创作台从常驻列改为**按钮唤出**：默认两栏，点正文标题栏「AI 生成」展开第三列，再点收起；对比态自动展开。不做浮层抽屉，避免遮住标题栏按钮和正文右缘；
- 对比态右栏只保留统计、变更摘要、采用勾选，采用动作统一放在底部操作条，去掉重复按钮。

## 4. 新页面：剧本台

> 本节是初版结构。节奏条、右栏「生成范围」独立分组、右栏候选列表已按 §3.5 简化，不再实施；其余仍然有效。

### 4.1 设计主张

> 一页三栏，一条链：**故事设定 → 场次 → 正文 → 下游资产**。
> 左边看得见结构，中间写得动正文，右边管得住 AI 与版本。

三栏不是"设置 + 编辑 + 聊天"，而是三种工作视角：结构、写作、生成。任何一栏都能独立滚动，互不挤压。

### 4.2 布局与栅格

| 窗口 | 结构栏 | 正文 | 创作台 | 说明 |
| --- | --- | --- | --- | --- |
| ≥1440 | 300 | 自适应（阅读宽 720） | 340 | 基准稿 |
| 1200–1439 | 272 | 自适应（阅读宽 680） | 320 | 收窄不换行 |
| 1000–1199 | 260（可收起） | 自适应 | 300 | 结构栏可折叠为图标条 |
| 701–999 | 抽屉 | 全宽 | 抽屉 | 两者互斥 |
| ≤700 | 抽屉 | 全宽 | 底部抽屉 | 顶部分段：正文 / 结构 / AI |

外围内距 10px，栏间距 8px（沿用 `source` 阶段现有 8px 规则）。正文阅读列 720px 居中，字号 14px / 行高 1.95，与现编辑器一致，不改阅读手感。

### 4.3 左栏：剧本结构

三段，自上而下：

1. **故事设定**（可折叠）
   - 一句话卖点：两行内，直接显示，不点开也能读到；
   - 故事大纲：折行显示字数，点开抽屉编辑；
   - 人物小传：折行显示人数，点开抽屉编辑（人物列表 + 每人一句人设）。
   - 文案提示"设定会作为生成的固定上下文"，让用户明白为什么值得填。
2. **场次**（默认展开，主体）
   - 每场两行：`01 | 日 内 | 民政局·大厅 | 22s` / `林晚 · 顾霆琛`；
   - 钩子场次编号后有琥珀色菱形；
   - 当前场次：深灰选中面 + 左侧 2px 白条；
   - 底部：`+ 场次`、`从小说拆场`、总时长。
3. **数据来源**：全部从正文解析（见 §5），不要求用户先建结构再写。

### 4.4 中栏：正文

- **标题行**：`剧本正文` + 状态（草稿 v3 / 待确认 / 已确认）+ 来源；右侧：版本、生成记录、导出、专注。
- **工具栏**：加粗/斜体/引用/撤销/重做 ｜ 插入「场次 / △动作 / 对白 / OS / VO」｜ 右侧 `输入 / 插入场次或角色`。
  - 插入按钮是这版新增：短剧格式（△、OS、VO、闪回）不该靠用户背，点一下就是正确的行。
- **节奏条**：按各场估算时长比例排布色块，钩子场次上方琥珀菱形，当前场次高亮。它回答的是"钩子间隔是否均匀"，这是短剧最关心的结构指标，也是卡片墙给不了的。
- **正文区**：场次块化排版。
  - 场头：`场 03 —— 日·内 沈氏集团·顶层`，右侧出场人物，钩子用角标；
  - 动作行 `△` 前缀弱化，正文灰；
  - 对白：`角色（情绪）：台词`，角色加粗、括注与冒号压低；
  - OS/VO 用 9.5px 小标签，不靠全大写；
  - 选中文字浮出操作条：`改写 ｜ 更狠 · 更短 · 更口语 · 加动作 ｜ ⌘K`。
- **底部体检条**：`预估 2'58" / 目标 3'00"` + 进度条 ｜ `钩子 5` ｜ `场 07「周医生」未登记人物`（可点，定位到该场）｜ 右：字数 / 场次 / 同步状态。
  - 只放三类能算出来的事实：时长、钩子、人物一致性；不做假统计。

### 4.5 右栏：AI 创作台

- **来源素材**：小说原文 + 字数 + 章节范围，点开左侧抽屉；没有来源时是虚线空态。
- **创作要求**：150px 输入区 + 框内模型选择 + 圆形发送（沿用现有 Composer 几何，不新造控件）。
- **快捷约束**：压缩支线 / 强化钩子 / 台词口语化 / 统一人设 —— 可多选，写进本次请求，不必每次手打。
- **生成范围**：整篇重写 / 从场 04 续写。
- **素材联动**：已提取 4/6 人物 + 去素材生成（接第四阶段）。
- **版本记录**：v3 当前 / v2 已采用 / v1 初稿，带对照入口 + 上次生成结果条。

右栏只放"这次要生成什么"，不放正文工具。

**与 AI 创作助手的关系**：助手仍是独立右列（默认 380px、可拖拽 320–560）。为避免第四列挤压，打开助手时创作台自动收起为 40px 图标条，关闭后恢复；两者不同时展开。这是对现有"打开助手、主面板让出空间"的延伸，不改变助手本身。

### 4.6 候选对比（替代"当前稿 / 最新生成"标签）

- 左栏切换为「变更场次」：全部/仅变更筛选，每场标 `已改写 / 新增 / 未改动`，可看出改动分布。
- 中栏按场对齐 diff：未改动场次折叠为一行；改写场次展开 `− / +` 行；新增场次整块绿色标记。
- 右栏「本次生成」：模型、用时、字数与时长增量、**变更摘要**（每场一句"改了什么"）、一致性提示、采用场次勾选、采用按钮。
- 底部动作：放弃 / 逐场采用 / 整篇采用。

关键规则不变：**候选不自动采用**；采用后可继续编辑，旧稿保留在版本记录。

### 4.7 空态

- 中栏：`开始创作这部剧` + 四个起点（从小说改编 / 从梗概起稿 / 导入已有剧本 / 空白剧本），主次分明，右侧给动作词。
- 左栏：设定显示为空占位，场次区给一句说明"写完第一场，这里会自动出现场次导航"。
- 右栏：来源空态 + 生成禁用 + **剧本格式四条提示**（场头、△、对白、OS/VO/闪回）。
- 底部一句说明剧本与下游的关系："下游的素材和分镜会直接读这套结构。"

### 4.8 手机端

- 顶部：返回 + 作品名 + 更多；四步横向滚动；分段 `正文 / 结构 / AI`。
- 正文：场头一行显示 `场 03 日·内 沈氏集团·顶层`，正文 13px；底部常驻 `字数 · 时长` + `AI 生成`。
- 结构：设定三段 + 12 场列表，一屏可扫；底部 `+ 新增场次`。
- 创作台为底部抽屉，与结构互斥，不叠三层。

### 4.9 状态与反馈（沿用现有规则，不新增弹窗）

| 状态 | 表现 |
| --- | --- |
| 保存中 / 已保存 | 顶部一个固定尺寸状态点 + 相对时间；不弹成功提示 |
| 保存冲突 | 顶部详情入口，保留本机内容，可下载/重试/用服务端版本 |
| 生成中 | 右栏发送按钮转 loading，正文区保持可编辑；不锁页面 |
| 候选待采用 | 顶部 chip「待采用」；中栏进入对比；不自动替换 |
| 受理不明 | 只核对原请求，不重发（沿用现有幂等规则） |
| 解析失败 | 场次解析失败时不动正文，只在体检条提示"第 N 场场头无法识别" |

### 4.10 无障碍与键盘

- 三栏均可 Tab 到达；场次列表支持 ↑/↓ 切换、Enter 定位；`⌘K` 打开选中改写；`⌘↵` 生成。
- 焦点可见（2px 浅灰轮廓，外移 2px）；候选 diff 的 +/− 不只靠颜色，带符号与底色。
- 降低动效偏好下关闭浮条与抽屉动画。
- 触控目标 ≥44px（手机工具栏、底栏按钮）。

## 5. 实现映射与数据

| 能力 | 现状 | 改法 | 是否改接口 |
| --- | --- | --- | --- |
| 场次解析（场号/日夜/内外/地点/人物） | `script-document.ts` 只有 `scriptScenes()` 返回位置 | 扩展为 `parseScenes()`，返回结构化场次；解析失败降级为纯文本 | 否 |
| 时长估算 | 无 | 台词按 4.2 字/秒 + 动作行 ×1.5s + 场头 2s，标注"估算" | 否 |
| 钩子识别 | 无 | 场末 2 行含 `？`/反转词/`【闪回】`/`OS` 结尾视为钩子，可手动标记覆盖 | 否 |
| 人物一致性 | 无 | 场次人物 vs 人物小传名单求差集 | 否 |
| 故事设定（一句话/大纲/人物小传） | 无（项目梗概已于 2026-10-21 退役） | **方案 A（推荐）**：作为剧本附属文档 `script_brief` 存服务端，与 `project_scripts` 同版本号；**方案 B**：作为正文前的固定区块存进正文。A 不污染正文与导出，B 零接口 | A 需新表/新接口 |
| 版本对比与逐场采用 | 只有候选列表 + 整篇采用 | 服务端提供按场 diff 与按场采用；前端对比视图 | 是（P1） |
| 素材联动 | 已有素材提取（角色/场景/道具） | 只读展示已提取数量，跳转素材阶段 | 否 |
| 选中改写 | 无 | 复用文本生成接口，指令前置，结果原位预览替换 | 是（P1，可复用现有生成） |
| 文案 | 「本集剧本」「本集」 | 全部改为「剧本正文」「这部剧」 | 否 |

存储建议：`script_brief` 与 `project_scripts` 一对一，字段 `logline / outline / characters(json)`，共用 `content_version`，采用同一套串行保存与 409 规则；不复活"项目梗概"。

## 6. 分期

**P0（不改接口，先让页面成立）**
1. 文案去掉"本集"；三栏结构（左结构 / 中正文 / 右创作台）；
2. `parseScenes` + 场次列表 + 节奏条 + 体检条（全部前端计算，失败降级）；
3. 正文场次块排版 + 插入按钮 + 选中浮条（浮条先只做样式与埋点，动作 P1）；
4. 空态四起点重排；手机端分段；
5. 助手打开时创作台收起。

**P1（版本与改写）**
1. 候选对比（按场 diff + 变更摘要 + 逐场采用）；
2. 选中改写四动作；
3. `script_brief` 结构化（若评审选方案 A）。

**P2（交付）**
1. 标准剧本格式导出（PDF / Fountain / 分场表格）；
2. 场次拖拽排序与合并；
3. 批量重生成选中场次。

## 7. 验收

- 四档宽度（1600 / 1366 / 1024 / 390）逐屏对照视觉稿；
- 空 / 有稿 / 生成中 / 候选 / 冲突 / 解析失败 六态齐全；
- 键盘：Tab 顺序 结构 → 正文 → 创作台，场次 ↑↓ 可切换，⌘K 可用；
- 数据：解析 12 场、时长估算与人工核对误差 <10%、人物差集命中"周医生"；
- 指标：首份剧本产出时长、生成→采用率、逐场采用占比、候选对比打开率、体检条点击率。

## 8. 风险与不做

- **解析脆弱**：用户不按格式写会导致场次识别不到。降级为单场 + 提示，不阻塞写作；P1 再考虑结构化存储。
- **三栏信息密度**：1440 以下优先收结构栏，其次收创作台，正文阅读宽度不低于 680。
- **不做**：分集、协作评论、节拍板卡片墙、通用设定库、本期 PDF 排版。
