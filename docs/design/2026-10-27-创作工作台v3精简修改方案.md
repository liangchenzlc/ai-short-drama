# 创作工作台 v3 精简修改方案

> 日期：2026-10-27。状态：待评审的设计建议，尚未修改原型或业务代码。
> 对照：[v3 设计文档](2026-10-26-创作模式工作台设计v3.md)、[v3 交互原型](../data/创作模式工作台v3/index.html)。
> 本次取舍依据：用户明确表示，主要问题是熟悉的功能、按钮和路径发生变化，以及新增功能和提示使工作台变复杂。
>
> 后续说明：本轮改稿以[第二版四流程方案](2026-10-27-创作工作台v3修改方案第二版.md)为准。AI 创作助手保持当前实现，本文有关助手补画、布局和打开态的建议不再执行；“素材生成”统一调整为“资产生成”，剧本页补充 Laper 参考。本文件保留为第一版记录。

## 1. 建议方向

**以当前工作台为母版，把 v3 改成精简增强方案。保留既有制作流程、生成区和操作位置，借鉴成熟平台的参考素材、逐镜迭代与按需展开方式。**

这是一张供个人创作者持续操作的工作台，采用 Impeccable 的 Operate 模式。评判标准是：能否快速找到素材和镜头，调整输入，生成图片／视频，比较与恢复结果，最后完成剪辑。视觉风格沿用项目现有中性炭黑、中文系统字体和紧凑控件。

第一轮无需新增业务功能。设计稿最需要的是补回已有能力、减少重复信息、让当前内容更容易辨认。分镜总览、复制素材等增强另列为可选项，不能反过来决定默认工作流。

### 信息依据与验证边界

- 产品边界以 [PRODUCT.md](../../frontend/PRODUCT.md)、[DESIGN.md](../../frontend/DESIGN.md)、[创作模式维护说明](../instruction/创作模式维护说明.md)为准，并核对工作区当前源码，包含现有未提交改动。
- 实际查看了 v3 四页图稿、原型源码，并在浏览器打开 `index.html?view=board`。
- 通过现有前端测试替身渲染了当前剧本、素材、分镜图／视频界面；成片使用现有多轨测试 fixture 渲染。界面证据用于判断布局和入口，不代表真实供应商生成、音视频播放或导出验收。
- 竞品依据截至本次调研可读取的官方页面与帮助文档。没有登录这些产品的付费后台，不把文档中的能力当成本项目已经支持的能力。
- 当前剧本页已包含一句话卖点、故事大纲、人物小传、场次与对比采用。这些不是本方案新增功能，也不能因它们同时出现在 v3 中就全部删掉。

## 2. v3 为什么让工作台变陌生

| 具体问题 | 当前与 v3 的差异 | 修改结论 |
| --- | --- | --- |
| 素材列表失去图像识别优势 | 当前是缩略图卡片；v3 交互原型变成名称、角度和状态组成的文字列表 | 恢复缩略图卡片，名称与类型保持原位置 |
| 分镜默认任务被改变 | 当前默认逐镜制作，有“分镜图／分镜视频”；v3 默认是网格加“本批生成”侧栏 | 恢复当前逐镜制作为默认，补齐视频制作，不让批量面板常驻 |
| 同一内容重复出现 | v3 左侧镜头序列与中间网格重复；左栏和右栏各有批量生成；状态和统计多处复述 | 同屏只保留一套序列，一处当前任务操作和必要的局部状态 |
| 有布局，缺制作能力 | 原型展示固定模型、尺寸和“每镜候选”，缺少与当前代码等价的模型选择、视频输入及完整图片工具 | 按现有组件补全；固定演示文字不能代替控件 |
| 为低频行为增加常驻负担 | 六类角度、对照、最近生成、队列、统计卡与解释文字占据主要空间 | 低频动作进现有更多／历史入口，可选能力延后 |
| 状态语义混淆 | “已生成”“已确认”“已完成”混用，分镜图和视频也没有清楚区分 | 状态必须说明是哪种媒体、哪项任务；选中、保存、生成各表达各的含义 |
| 演示数据被当成设计依据 | 以 12 镜为前提固定四列一屏；显示约 66 秒、队列位次等模拟信息 | 内容量和列数自适应，只显示有真实数据支持的进度与时长 |
| 窄屏缺少可操作方案 | 实测原型分镜页在 390px 视口有 560px 文档宽度，顶栏重叠，画面区不可用 | 沿用当前抽屉与响应式机制，不能把三栏直接压到手机 |

v3 文档还需先消除内部矛盾：§1.2／§1.6 要求复用图片组宫格，§4.1／§5 又保留“大图＋候选条”；§2.4 示意图有胶片条，正文又明确不设。后续设计稿应只保留一种明确做法。

## 3. 从成熟平台借鉴什么

参考对象按工作流相关性选择：即梦、可灵覆盖中文图像／视频创作，Runway 覆盖生成与迭代，LTX Studio 覆盖叙事分镜，Google Flow 覆盖生成与片段编排。

| 参考对象与官方依据 | 可借鉴的做法 | 在本项目的落点 | 不引入的部分 |
| --- | --- | --- | --- |
| [Runway：参考图](https://help.runwayml.com/hc/en-us/articles/40042718905875-Creating-with-Gen-4-Image-References)、[生成流程](https://help.runwayml.com/hc/en-us/articles/37425232841875-Getting-Started-with-Generative-Video) | 参考图参与提示词，模型可选择，围绕同一结果反复迭代 | 保留现有参考图片、`@` 引用、模型选择与生成记录 | 不照搬另一套会话、资产分类或候选采用规则 |
| [LTX Studio：分镜](https://ltx.io/studio/platform/ai-storyboard-generator)、[单镜编辑](https://ltx.io/studio/platform/shot-video-editor) | 整体叙事检查与单镜修改服务不同任务；人物／物件参考贯穿制作 | 默认逐镜制作，后续按需提供总览；继续使用当前角色／场景／道具 | 不增加品牌套件、团队协作、提案幻灯片和新的资产层级 |
| [Google Flow：视频生成](https://support.google.com/flow/answer/16353334?hl=en)、[场景编排](https://support.google.com/flow/answer/16935718) | 提示词区域集中模型、参考和参数；片段生成后再编排、裁剪、预览 | 保留当前生成输入区与成片编辑器各自的职责 | 不承诺当前视频接口尚未开放的多种参考模式，也不另造第二条剪辑时间轴 |
| [可灵：O1 使用指南](https://docs.qingque.cn/d/home/eZQCg5xHvxDaE-jP2GcnaNc6O?identityId=2E1MlYrrPk4)、[官方多图参考介绍](https://ir.kuaishou.com/zh-hans/news-releases/news-release-details/kuaishoukelingaituichuduotucankaogongneng) | 用可见参考与自然语言表达创作要求，支持围绕已有内容修改 | 图片输入保留参考缩略图与提示词；视频继续遵循本项目实际能力 | 不为每种创作意图增加永久表单；不因竞品支持就把多参考视频画进当前可用界面 |
| [即梦官方产品页](https://jimeng.jianying.com/) | 中文描述、主体保持、局部修改和图像编辑围绕内容展开 | 继续保留图片上的编辑工具与中文生成要求 | 不把创作模式改成无限画布；本项目已有独立画布模式 |

综合这些依据，本项目现有“对象列表 → 媒体预览 → 生成输入”的制作路径值得保留。竞品的价值是帮助确认操作组织方式，不能成为增加按钮数量的理由。

## 4. 页面布局与视觉方向

### 素材与分镜：沿用当前主面板

```text
返回／作品名称          剧本创作—素材生成—分镜制作—成片合成    保存  AI创作助手
┌──────────────┬────────────────────────────────────────────────────┐
│ 当前素材/镜头 │ 当前对象名称        图/视频〔分镜页〕 历史 更多 设置 │
│ 搜索、筛选   ├───────────────────────────────────┬────────────────┤
│ 新增、提取   │                                   │ 名称、类型/脚本 │
│              │ 原图片组 / 当前镜头视频            │ 参考图片       │
│ 缩略图卡片   │                                   │                │
│              │                                   │ 本次生成要求   │
│              │                                   │ 模型 参数 发送 │
└──────────────┴───────────────────────────────────┴────────────────┘
```

- 素材、分镜继续共用预览和生成区的交互语言，设置可收起。保留现有响应式列宽，不再分别强定 258／320 与 240／344 两套几何规格。
- AI 创作助手仍由右上角打开，默认关闭，保留现有宽度调节与项目会话。桌面打开后让出空间；1000px 以下沿用抽屉，手机设置与助手互斥并保留输入。
- 若以后增加“分镜总览”，让网格替换序列与预览所在的内容区域，避免左侧仍留同一套镜头列表。选择镜头后回到现有制作界面，并恢复原选择与滚动位置。
- 剧本继续“可收起结构栏＋正文＋按需打开的 AI 生成区”；成片继续现有“素材／预览＋时间轴＋按需属性”。四页无需被迫套成同一种三栏模板。

### 精简后的视觉令牌

| 角色 | 建议 | 原因 |
| --- | --- | --- |
| 工作区底色 | `#101010` | 延续当前主题 |
| 编辑表面 | `#181818` | 内容区与背景有明确层次 |
| 悬停／选择表面 | `#242424` | 通过明度表达交互 |
| 结构边线 | `#2D2D2D` | 细分区域，减少层层套框 |
| 正文 | `#F3F3F5` | 保持可读性 |
| 次要文字 | `#B4B4BC` | 元信息清楚但不抢画面 |

主操作继续使用项目已有近白填充，状态色继承现有成功／警告／错误令牌。字体沿用 Segoe UI、苹方、微软雅黑系统栈；普通内容以 13px、编辑正文以 14px、辅助信息以 12px 为基准。时间码可用等宽数字，普通中文标签不全部换成等宽字体。

按钮、面板与媒体框沿用当前不同用途的圆角，不统一加白色外泛光。文字和字段左对齐，媒体按实际比例居中 contain。画面是唯一需要突出的位置，不增设装饰卡片或持续动画。

## 5. 逐页取舍

下表“补回”均表示当前项目已有、v3 未完整呈现的能力，不应计入新增业务需求。

### 5.1 剧本创作

| 对象 | 处理 | 原因与具体做法 |
| --- | --- | --- |
| 场次导航、正文编辑、结构栏收起、专注模式 | 保留 | 当前已有，直接服务写作与定位 |
| 小说原文、导入、空稿起点 | 保留原入口 | 不增加新的来源中心或前置配置页 |
| 一句话卖点、故事大纲、人物小传 | 保留、保持可选 | 当前已有；用现有紧凑入口，不能变成三个必填面板 |
| AI 生成、历史、导出 | 保留位置 | 避免用户重新寻找高频工具 |
| 候选对比、明确采用 | 保留现有规则 | 对比必须保留原稿；本轮不额外增加逐场审核层级或采用前确认步骤 |
| “更狠／更短／更口语／加动作” | 仅选中文字后出现 | 这是局部操作，不应常驻占据正文工具栏 |
| 场次／字数／估算时长 | 保留一处简短统计 | 时长标明估算，不同时在页头、场次栏和底栏重复 |
| 多处“钩子”标签、未登记人物警示 | 减少默认露出 | 关键词命中不能证明剧情有钩子；人物小传未填写也不等于素材错误。保留必要的非阻塞建议，不作为创作质量结论 |
| 正文上方长期格式教程、空态教学文字 | 有内容后收起 | 空白时提供一个格式例子即可；已有正文以内容为主 |

故事设定目前有本机保存边界，不应在设计稿中暗示它已经作为可靠的服务端设定参与所有生成。补齐该能力涉及独立数据与调用契约，不借这次 UI 调整扩大范围。

### 5.2 素材生成

| 对象 | 处理 | 原因与具体做法 |
| --- | --- | --- |
| 当前缩略图卡片、类型筛选、搜索、新增、从剧本提取 | 保留并还原到稿 | 创作时靠图识别人，文字列表会增加辨认成本 |
| “一张卡＝一个素材” | 保留 | 不引入父资产、多视图容器与额外层级 |
| 名称＋类型同排、素材描述 | 保留 | 延续现有表单；不把三种类型改成占整行的额外大分段 |
| 图片组、第一张默认主图、切换主图、预览 | 保留 | 生成图已直接保存，不增加“候选确认”流程；第二格写“2”，不写会误导流程的“候选2” |
| 单图编辑、更多图片工具、历史、下载 | 补回 | 复用现有工具菜单；不以只有下载／重试的简化预览替代 |
| 上传、媒体资产库选择、私人参考图片与 `@` | 补回 | 真实制作的重要输入；媒体资产库与已退役的项目／全局素材库须分清 |
| 本次画面要求＋可选模型＋参数＋发送 | 保留现有组合 | 比 v3 的数量一行、模型一行、大按钮一行更紧凑，且参数是可操作的 |
| 六类角度按钮、独立“角度”常驻区及说明 | 本轮删除 | 为低频需求增加大量入口；`label` 是已有通用字段，不能假定旧值全是角度 |
| “加一个角度” | 延后为可选“复制素材” | 真有多角度需求时再进入现有更多菜单；复制后仍由用户明确生成，不自动建立一套角度系列 |
| 角色强制 3:4、场景强制 16:9、道具强制 1:1 | 删除强制规则 | 预览服从实际媒体尺寸；生成比例沿用模型默认与用户选择，不能由素材类型悄悄覆盖 |
| 对照入口、最近生成常驻区、预览底部模型／耗时／版本条 | 对照延后，其余收进记录 | 当前核心任务是生成与修改；需要溯源时打开原有生成记录 |
| “已确认”绿点、图上状态、标题状态、底部保存状态 | 减少重复 | 不把业务确认、出图成功与保存成功混为一件事；正常结果无需多处报喜 |
| 素材被谁引用、引用计数 | 主界面不加 | 删除受引用保护的素材时保留限制和原因，不能写成确认后即可强删 |

“素材描述”用于定义对象，“本次画面要求”用于本次生成，两者职责不同，不能仅为少一个输入框就盲目合并。通过标签、间距和默认占位文案区分即可，不再追加解释卡片。

### 5.3 分镜制作

| 对象 | 处理 | 原因与具体做法 |
| --- | --- | --- |
| 左侧镜头缩略图＋当前大预览＋生成设置 | 保留为默认 | 与当前逐镜制作一致，单镜修改无需切换到另一套“单卡模式” |
| “分镜图／分镜视频”切换 | 必须补回 | 同一个镜头有两种媒体产物，必须能分别编辑、生成和回看 |
| 镜头名称、镜头脚本、前后镜、提取分镜与新增 | 保留 | 不用动作描述代替名称，不让一张卡塞三行重复文本 |
| 图片模式的参考素材／参考图、模型、画面要求、生成选项 | 必须补回 | 现有生图流程完整保留，继续复用图片组 |
| 视频模式的当前主图参考、运动要求、视频模型、清晰度／时长 | 必须补回 | v3 的固定“Kling 2.1／16:9／2个候选”不能替代真实参数；图组数量也不能当成视频段数 |
| 对白与音色 | 保留视频内原有折叠入口 | 沿用现有能力和开关，避免再造平行的台词／音效输入与声音绑定 |
| 图／视频生成记录、图片编辑工具、当前视频播放 | 必须补回 | 直接决定能否迭代素材；历史视频不增加新的采用步骤 |
| 网格／表格／单卡三段切换 | 从默认工具栏删除 | 单卡就是现有制作界面；表格增加维护和学习成本；网格后续作为单独可选总览 |
| 全屏大图 | 保留为预览浮层 | 点击图片查看即可，不作为第四套视图；保留关闭、翻页及下载，生成操作仍在原制作区 |
| 固定四列、一屏十二镜 | 删除硬要求 | 列数随空间变化，不为演示数据牺牲画面辨认与文本阅读 |
| 常驻“本批生成”、两个统计大卡、两处批量按钮 | 删除 | 没有批量任务时无需占据右栏；批量复用已有更多入口和任务详情 |
| 批量制作 | 保留实际能力，统一一处入口 | 明确生成图片还是视频、对象范围与数量；任务运行时可回到原镜头继续工作 |
| 运镜选择面板、表格中的独立台词／音效字段 | 本轮不加 | 当前缺少对应的完整结构化契约；运镜要求可由现有视频提示词表达，不为图稿先扩表 |
| 生成中／失败／需要核对 | 局部显示 | 不把失败做成遮住旧图的整幅红罩；保留原图、已输入参数与就近查看原因入口 |

分镜状态必须与当前媒体模式对应。“有分镜图”不能写成整镜“已完成”；图模式待制作和视频模式待制作分别按真实数据判断。修改描述不等于所有历史结果一律作废；待更新依据实际来源快照与版本关系，不靠前端点过输入框就永久打标。

批量状态若只有任务级结果，显示“已完成 2／3、1 项生成中”；只有后端真实提供百分比、位次和预计耗时时才显示这些数字。暂停、取消也只暴露现有任务实际允许的控制，不预先设计“暂停整队列／全部取消”的承诺。

### 5.4 成片合成

| 对象 | 处理 | 原因与具体做法 |
| --- | --- | --- |
| 现有预览、素材入轨、时间轴、裁剪、分割、撤销／重做、缩放 | 保留现有编辑器 | 原型不能用更简单但规则不同的时间轴替代已实现能力 |
| 原声、对白、字幕、配乐、音效 | 按现有轨道能力补齐 | v3 固定五轨漏掉独立原声；空轨可折叠，精简的是露出，不是声音控制 |
| 锁定、静音、片段关联、声音／字幕与画面属性 | 保留、按选择对象展开 | 复用现有属性区与声音入口，不再增加第二套检查器 |
| 当前剪辑预览与成片回看 | 保留 | 区分正在编辑的草稿与已有导出结果 |
| 同步分镜视频、历史、专注剪辑、导出 | 保留原位置 | 用同一套快捷工具，不把导出搬到常驻右栏才能找到 |
| 常驻检查清单、“素材齐全”“字幕无重叠”等成功项 | 删除常驻区 | 正常状态不需要用户逐条读；真实问题在相关片段、同步层或导出层出现 |
| 1080p／画幅的多处切换、24fps固定说明 | 删除重复或不实展示 | 输出参数集中到现有导出设置；实际代码采用 30fps 口径，不能照搬原型数据 |
| “同步” | 改成“同步分镜视频” | 清楚说明会更新哪个来源；继续遵循已有剪辑保护与版本规则 |

本轮不新增导出前检查向导，也不新增独立素材箱页面。保留现有导出弹窗里确实需要用户处理的问题即可。

### 5.5 AI 创作助手与公共反馈

| 对象 | 处理 | 原因与具体做法 |
| --- | --- | --- |
| 右上角助手入口、项目会话、可调宽度面板 | 保留并在稿中补出真实打开态 | v3 目前点击助手只有提示；只画入口无法验证它与设置区同时打开后的空间 |
| 模型、附件、引用、Skill、发送／停止 | 沿用当前助手 | 不再设计另一套创作模式切换或任务管理界面 |
| 记忆管理、任务设置、上下文控制台 | 不恢复 | 当前已退役的前端入口与本次精简方向一致 |
| 顶栏保存 | 保留现有保存状态入口 | 不在每个面板底部再写一次保存时间；正常自动保存不弹成功 Toast |
| “设计说明”、自动欢迎 Toast、清空演示数据 | 仅留评审环境 | 不是创作者的业务工具，不能成为正式页面上的常驻按钮 |
| 失败、冲突、受理不明、来源变化 | 必须保留 | 精简文字不能删掉恢复入口；同一问题只在当前操作层集中说明，保留输入和已有结果 |

## 7. 修改设计稿的顺序

| 优先级 | 设计稿工作 | 交付判定 |
| --- | --- | --- |
| P0：先还原工作流 | 以当前截图重画素材与分镜；补图／视频生成输入、记录、图片工具、助手打开态；成片对齐现有多轨；消除 v3 文档矛盾 | 用户能按熟悉路径完成从素材图到分镜视频的操作，无需学习新的视图体系 |
| P0：同步减负 | 移除文字素材列表替换、角度墙、常驻批量控制台、重复统计与说明、常驻成片检查器；统一文案 | 每个动作有一个稳定主入口，正常界面没有任务解释面板 |
| P1：验证真实需要后增强 | 最多先尝试“分镜总览”一个入口，网格自适应、选择返回原镜头；可选复制素材放更多菜单 | 不改变默认制作路径；总览中不同时保留一套重复左栏 |
| 暂缓 | 表格编辑、结构化运镜／台词／音效扩展、批量多角度、素材对照、CSV／PDF 分镜表、独立检查中心 | 另有真实使用需求、数据契约和验证范围时再评估 |

后续改原型主要涉及 `index.html`、`proto.css`、`proto-core.js` 及四个 `proto-*.js` 页面文件；先改稿并对照当前组件，不直接把模拟逻辑搬到业务代码。若正式实施，再按照项目规则说明跨文件与接口影响。

## 8. 下一版设计稿验收标准

1. 当前素材、分镜图、分镜视频的高频入口与位置可直接对应；已有上传、参考、模型、参数、历史、图片编辑与视频播放没有遗漏。
2. 图片组直接保存、第一张默认主图、视频成功归档后自动采用、剧本文本明确采用，继续各自遵循现有规则。
3. 默认进入逐镜制作；没有重复的序列、多个同义生成按钮或无任务时的队列侧栏。
4. 正常、空白、筛选无结果、生成中、部分失败、版本冲突、来源变化均有明确表现；不通过新增整块横幅挤压编辑区。
5. 用真实比例与不同内容量评审：1／2／4 张图，长素材名，少量／较多镜头，横竖画幅；不再只证明 12 镜演示稿好看。
6. 至少对照 1440px、1920px 和窄屏；助手开／关、设置开／关都能操作。390px 视口不再出现当前原型的 560px 页面横向溢出。
7. 图片工具同时支持悬停、键盘焦点与触屏入口；状态有文字，不能只靠绿／红小圆点；弹层能关闭并恢复原位置。
8. 当前没有真实数据与接口支持的能力，明确标为未来建议，不伪装成可用按钮、精确进度或完成状态。

本轮交付仅为上述修改方案。原 v3 文档与 HTML 保持原样，便于下一步逐项评审和修改。
