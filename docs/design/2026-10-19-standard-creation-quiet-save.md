# 标准模式创作流程：无感保存与无弹框切换方案

> 状态：已实施，工作区验证见第 10 节，独立提交范围与验证见第 11 节。验收依据为代码、受控测试及本机隔离 MySQL；不代表真实模型或供应商验收。
> 日期：2026-10-19。依据本轮用户要求及当前源码制定。
> 范围：标准模式分集创作的剧本、素材、分镜、成片四个阶段。
> 设计方法：Impeccable Shape；使用 Operate 模式，延续现有冷黑、紧凑的中文工作台。
> 关联：[产品范围](../../frontend/PRODUCT.md)、[设计约定](../../frontend/DESIGN.md)。

## 1. 设计结论

**编辑即保留，停顿即同步，切换直接走，使用时校验。**

1. 四步切换、切分集、切素材与镜头，不弹“未保存”“待确认”“是否放弃草稿”等确认框；保存失败和冲突也不阻止这些导航。
2. 删除独立的“确认当前剧本”操作，以及“草稿待确认”“已确认定稿”等常驻流程状态。点击提取或生成，即表示使用当前剧本作为本次任务来源。
3. 日常保存不弹 Toast，不展示成排的草稿说明，不要求下载、恢复、核对后才能继续日常编辑。
4. 后台保留串行保存、版本校验、本机恢复和账号隔离。冲突不自动覆盖，输入不因切换卸载丢失。
5. 保存故障只影响依赖该内容的提交动作；用户仍可浏览其他阶段、编辑其他对象，稍后回来处理。

这是交互流程改造，不更换页面视觉体系，不恢复已撤回的 V2 列宽、卡片和生成输入布局。

## 3. 新的创作体验

### 3.1 剧本直接进入制作

手写：编辑剧本 → 自动保留与保存 → 点击“从剧本提取”或“生成分镜”。

AI：生成 → 预览结果 → 点击一次“采用并编辑” → 继续编辑或进入制作。

- “采用并编辑”本身就是明确选择，删除其后的二次确认弹框；采用前保留当前版本供历史找回，不再接一个“确认定稿”。
- 剧本标题不再显示“草稿 · 待确认 / 已确认定稿”；编辑区底部删除确认条。
- 候选仍标明“新结果 · 未采用”，不会因为查看候选、切换步骤而自动写入当前作品。
- 点击提取或生成时，按钮就地显示“准备中…”并等待相关正文及参数保存；成功后冻结本次来源，直接受理。
- 当前没有剧本时，在对应操作附近提示“先编写或采用一份剧本”，提供回到编辑区的入口；浏览该阶段不受限制。
- 用户只改格式后，内容照常保存，不出现重新定稿提示，也不让正文相同的已有提取结果失效。

选择已有剧本版本时保留原服务端记录；覆盖型导入先在本机保留替换前副本，并在保存详情中提供找回入口，不将本机副本宣称为跨设备历史。若无法保留副本，就近阻止这一次替换并保留双方内容，不追加弹框，也不阻止导航。

### 3.2 四步切换不再承担保存审批

用户点击任一步骤，立即切换。导航路径不等待 HTTP，不打开确认框，不自动展开异常面板。

切换之前记录最新输入；后台继续原会话的保存。回到原阶段时，立即显示自己刚才的输入，再增量更新任务与服务端数据。

同一规则覆盖：

- 四个步骤和浏览器前进、后退。
- 切换分集、素材、前后镜头，以及分镜图 / 视频标签。
- 返回项目、应用内打开模型配置，再回到创作区。
- 窄屏关闭设置抽屉、切换助手；分镜对白和成片声音编辑也不能成为导航弹框的遗漏入口。

未补齐名称或类型的新素材仍保留为本机条目，允许离开；再次进入继续填写。完全空白的占位不计为保存异常，不宣称已写入服务端，也不触发“放弃草稿”询问。

### 3.3 保存只占一个安静入口

沿用当前顶栏右侧保存位置，不新增底栏、横幅和常驻说明。此处是一个可聚焦的轻量状态入口，点击或键盘打开非模态的保存详情；不自动抢焦点。

```text
正常：   [四步导航]                                      ✓   AI 创作助手
慢保存： [四步导航]                                  保存中…   AI 创作助手
异常：   [四步导航]                             待同步 · 2 项   AI 创作助手
冲突：   [四步导航]                             需处理 · 1 项   AI 创作助手
```

| 实际状态 | 默认呈现 | 用户能做什么 |
| --- | --- | --- |
| 空白初始参数，没有任何输入或恢复记录 | 不提示“草稿”，不计异常 | 正常编辑、切换 |
| 服务端已保存 | 中性勾选图标，可访问名称“已保存” | 按需查看最近同步时间 |
| 编辑中、正常防抖等待 | 不切换大段文案，不显示警告 | 继续输入、切换 |
| 请求超过 800ms 尚未完成 | 同一位置显示“保存中…” | 继续输入、切换 |
| 本机已持久保留，服务端同步失败或离线 | “待同步 · N 项”，不用红色报错刷屏 | 按需查看、重试；继续其他操作 |
| 版本冲突、恢复记录损坏或无权限 | “需处理 · N 项”；当前对象有一句就近说明 | 自主打开版本核对，其他对象不受影响 |
| 本机无法持久保留且服务端未保存 | 明确显示“保存失败”，不可伪装成“已保留” | 继续应用内切换；内存会话保留并提供复制或下载 |

状态计数按“对象 + 保存用途”去重，不按重试次数累加。私人参数属于“生成设置”，正文属于“剧本”，避免都叫“草稿”。详情明确哪一集、哪个对象、哪项尚未同步；私人内容只在本人会话中展示。

成功回执不弹提示；恢复成功不弹提示；重连完成后入口恢复正常。错误只在首次发生或原因改变时向辅助技术播报，不能每次键入都播报“保存中 / 已保存”。仅图标状态也必须有文字工具提示及可访问名称，不能只靠颜色。

## 4. 异常处理与弹框规则

| 场景 | 新行为 | 是否自动弹框 |
| --- | --- | --- |
| 无修改时切换 | 直接切换，不写入、不询问 | 否 |
| 刚输入就切换，保存仍在进行 | 保留输入，直接切换，后台完成保存 | 否 |
| 离线或普通网络故障 | 保留输入、显示待同步；网络恢复后安全续存 | 否 |
| 409 冲突 | 暂停该对象写入，保留本机分支；生成按钮就近提示先处理版本 | 否 |
| 同版本本机恢复稿 | 自动还原编辑内容并续存，不要求手动恢复 | 否 |
| 本机内容与服务端完全一致 | 核实后清除多余恢复记录 | 否 |
| 恢复稿基准已变化、记录损坏 | 保留原记录；不覆盖远端、不自动上传；入口提示需处理 | 否 |
| 采用剧本、采用正常视频候选 | 用户点击一次明确动作即执行，替换前版本可找回 | 否 |
| 采用来源已变化的候选 | 在候选操作区展开差异说明，明确“仍采用此结果” | 否 |
| 主动载入服务端版本 | 用户打开版本对照，在面板里明确选择，不再追加确认框 | 否 |
| 永久删除、清空历史、项目共享权限变化 | 沿用有对象、有后果的危险操作确认 | 仅主动执行时 |

冲突面板提供“继续保留本机内容”“使用服务端版本”“复制 / 下载”。版本不同不能自动整篇覆盖；用户明确选择以最新版本为基础保留本机内容时，须重新读取版本并提交，若再次冲突就继续保留双方内容。任何放弃动作只作用于当前对象，且先保留可找回副本。

**页面内切换没有例外弹框。**真正刷新、关闭标签页或离开应用属于文档退出：本机已经可靠保留或服务端已保存时不触发 `beforeunload`；只有仍存在仅存于内存、退出确会丢失的输入时，保留浏览器原生退出保护。该保护不得出现在四步切换、切集、选对象和应用内路由导航。

## 5. 实现结构

### 5.1 会话先独立于页面，再移除导航拦截

新增标准模式专用的编辑会话注册表和保存状态聚合层，置于已登录应用作用域；组件只订阅会话，不拥有保存队列的寿命。

- 会话按账号与实际服务端资源身份管理；正文、共有作品信息、本人生成设置分别保存，继续沿用现有 HTTP 客户端和业务会话逻辑。共享素材以 `asset_id` 建立唯一作品字段写队列，被多个分集引用时分集只是订阅上下文，不能产生多条相互冲突的保存队列；私人生成设置仍按账号、项目、分集、对象、用途分别隔离。尚未创建的条目使用稳定本机标识，创建成功后原位关联服务端身份和原请求。
- 写入先更新内存与本机恢复记录，再安排现有防抖保存：正文及普通对象沿用约 1 秒，剪辑沿用当前约 650ms；本机写入失败仍保留内存内容，并显示真实失败状态。
- 同一资源只允许一条串行写队列；服务端回执不能覆盖较新的输入。保存中再次输入，前次结束后继续保存最新内容。
- 页面卸载只解除订阅，不销毁脏会话、不取消在途保存。账号切换隔离会话与旧响应，旧账号队列不得使用新账号凭据继续提交；旧账号恢复记录继续保留在原命名空间。
- 只按需创建当前或有未完成工作的会话，不把全部分集页面常驻隐藏，也不靠关闭路由卸载掩盖问题。
- 干净且没有在途请求的会话可以回收；待同步、冲突、创建受理未知的记录不能因缓存淘汰丢失。
- 会话使用已有恢复存储格式和校验能力作为基础；新增字段显式版本化，兼容旧记录读取。不能无条件清空旧键，也不能将本机记录计作服务端成功。
- 恢复记录补充请求前基准、已提交快照及待核对请求标识；刷新后先读取服务端核实丢失的回执，再决定续存、清理或进入冲突。恢复了输入后必须重启保存队列，不能长期停在 `local/dirty`。

顺序必须是“完成持久保留与会话托管 → 验证跨页续存 → 移除保存失败时的离开询问”。仅删除 `confirmAction` 或直接移除导航守卫不满足方案。

### 5.2 导航和提交使用不同条件

导航只切换视图，可以发起后台 `flush`，不以其返回结果决定是否放行；不通过重放、回退历史来等网络。切换前捕获编辑器尚未同步到业务会话的内容，包含中文输入法组合期间的本机输入，不因卸载丢失最后几个字，也不能因捕获而误发生成请求。

生成、提取、采用、渲染、发送带作品引用的助手消息，仍等待**本次实际依赖**的保存并校验版本。无关对象或另一用途的参数失败，不应锁住整页。等待期间按钮只表示准备或提交，不阻止用户导航；继续编辑导致来源变化时重新取稳定快照，不能提交混合版本。

明确区分“续存数据”和“重发业务请求”：

- 网络恢复后可续存，但先核对基准版本与先前受理结果；409 不自动重试覆盖。
- 创建新素材、生成、提取、合成受理不明，沿用原请求标识和既有幂等核对，不自动新建另一请求。
- 后台重试不能重复触发模型、渲染或其他付费调用；会话恢复也不自动点击任何业务动作。

### 5.3 取消定稿门禁，使用明确来源

标准工作台的提取和分镜生成改为接受当前已保存的非空编辑剧本，不依赖 `state === confirmed`，也不通过导航时偷偷调用 `confirm()` 来绕开旧规则。

受理、结果过期判定、结果采用三处必须一起调整：

1. 受理：核对可信 Actor、项目归属、当前 `script_id`、请求内容版本，并冻结当前正文及相关生成参数。
2. 结果判定：以当前编辑剧本身份和实际使用内容的哈希判断是否过期；去掉确认状态对结果有效性的影响。
3. 结果采用：保留资源范围、采用权限、当前来源与正文哈希检查；未采用的私人或历史 Agent 候选仍不能直接作为共享制作来源。

当前编辑指针不能单独证明候选已采用。受理前复用 `EpisodeWritingService._requires_agent_adoption` 所依据的来源校验，或提取等价的共用只读校验；保留跨作者来源检查及无 Agent 表旧环境的兼容，不能加载或暴露他人的私人候选。

素材提取和分镜采用服务也供历史 Agent 结果使用，因此不能全局删除确认检查。新标准任务在服务端生成的 `source_snapshot` 中写入 `script_source_policy = current_saved_v1`：有该标记的任务按当前已保存来源校验，无标记的历史任务继续原合同。标记由可信服务端受理路径产生，不接受客户端自报，利用现有 JSON 快照保存即可。

沿用现有 `content_version` 处理并发写入；富文本格式仍正常保存并推进版本，但纯格式变化不应单独让依赖正文的任务结果过期。不要将所有依赖都简化为“只看正文”：主图、参数、镜头、对白和音色仍按各自真实合同校验。

保留数据库 `confirmed` 状态字段、旧确认接口及其既有兼容行为，不批量重写历史数据。本轮无需新增表或执行 DDL。标准页面不再展示、触发或依赖确认步骤；历史 Agent 运行的批准合同和无限画布行为继续按各自规则处理。对白、音色等既有业务审核标记也不能被普通自动保存偷偷置为已审核；关闭编辑面板只负责保留编辑内容。

## 10. 实施记录（2026-10-19）

### 已落地的行为

- 标准编辑会话按账号与资源托管；页面卸载只释放订阅，未完成的保存队列继续运行。正文、个人生成设置、素材、未创建素材、分镜、剪辑、声音和对白均接入。未完成的上传回填原会话；账号切换暂停旧队列。
- 应用内四步、分集、素材、镜头及媒体标签直接切换。原导航守卫不再等待网络，也不显示保存/放弃确认。只有内容仍仅在内存且无法保留时，刷新或关闭文档才使用原生退出保护。
- 正常保存只显示顶栏图标，连续保存超过 800 ms 才显示文字。错误与冲突集中为一个入口，点击后展开非模态详情；不会自动打开弹窗。手机端保留该入口，浮层自动避让屏幕边界。
- 同基准本机输入自动恢复；冲突与损坏记录保留原稿，等待就近选择。使用服务端版本前保留可下载副本，读取失败不清空本机稿；替换声音、字幕和候选前先备份，备份失败不替换。
- 剧本候选只需一次“采用并编辑”。新标准素材提取/分镜任务使用当前已保存的非空剧本，以服务端 `current_saved_v1` 策略冻结来源与正文哈希。纯格式修改不让正文来源过期；旧任务和历史 Agent 继续原来的采用合同。
- 未知回执仍保留 pending。即便读取到旧值，也要使用版本条件写入最终输入；小说/剧本、私人参数、素材和分镜的合法 no-op 保存推进并发版本，阻止迟到旧请求覆盖最终内容。参数 `draft_version`、作品历史及内容状态仍按语义变化处理。
