## 1. 素材创作

### 1.1 一张卡 = 一个素材

素材列表的每一行就是一条 `AssetRead`，字段直接对应现有接口：

| 界面元素 | 现有字段 | 说明 |
| --- | --- | --- |
| 卡片主标题 `林晚 · 正面` | `name` + `label` | `label` 就是角度。一张卡只能有一个角度 |
| 副标题 `角色 · 已确认` | `kind` + `state` | `kind` 三值：角色 / 场景 / 道具 |
| 缩略图 | `image.url` | 没有图就用类型图标占位 |
| 右侧状态点 | 由 `image` / `state` 推导 | 实心绿=已确认，空心=未生成，琥珀=待更新，红=失败 |

**多角度不新增任何结构**：想要侧面，就再建一张 `name=林晚, label=侧面` 的卡。它和正面那张完全平权——可以单独生成、单独改描述、单独删、单独设成某个镜头的参考图。

列表里同名的卡会按 `name` 相邻排列（数据库按 name 排序即可），视觉上自然连在一起，但**没有折叠、没有组头、没有层级**。这正是「用多张卡表示多角度」的字面实现。

### 1.2 三栏

```
左 258            中 自适应                      右 320
┌──────────┬────────────────────────────┬──────────────┐
│ 搜索/类型 │  素材名 · 角度  [角色][已确认]  │  类型 seg     │
│ 卡片列表 │                            │  名称         │
│          │        大图（3:4 / 16:9）    │  角度 / 视图   │
│          │                            │  描述         │
│          │  图片组宫格（1 / 2 / 4 张）  │  参考图       │
│ 新建素材 │                            │  提示词       │
│          │  生成时间 · 模型 · 尺寸       │  [生成这张]   │
└──────────┴────────────────────────────┴──────────────┘
```

- **画幅跟着类型走**：角色 3:4（396×528），场景 16:9（600×338），道具 1:1。不强制统一，因为素材本来就不是同一种东西。
- **预览区沿用现有的 `ImageGroupPreview` 图片组**，不另起一套：一次生成 1 / 2 / 4 张，就按 1 / 2 / 4 格排布，每格左上角是序号 + 「主图」徽章、右下角是分辨率、悬停才出现工具条。上一版画的"大图 + 下方候选缩略条"作废——候选本来就是宫格里的格子，不需要再加一条。
- **右栏「角度 / 视图」是一个普通输入框**，下面一行小字：「同一对象要多角度，就再建一张卡，名称不变、这里写侧面」。这是把约定写在用户操作的地方，不靠文档。

### 1.3 「加一个角度」

舞台标题栏右侧一个按钮，展开 6 个常用角度：侧面 / 背面 / 四分之三侧 / 面部特写 / 表情·冷笑 / 换装·礼服。

点一个 → 复制当前卡（`name`、`kind`、`描述`、`提示词` 都带走），只把 `label` 换成所选值，**新建一张未生成的卡**并选中它。用户按一次「生成这张」就得到新角度。

这不是批量生成：不点就不花钱。想要三个角度就点三次，每次都看得见结果。

### 1.4 引用关系去哪了

| 位置 | v2 | v3 |
| --- | --- | --- |
| 素材列表行 | 「被 8 个镜头引用」 | **删除** |
| 素材预览底部 | 「角色基准会被所有引用镜头继承」 | **删除** |
| 删除素材确认 | 「已被 8 个镜头引用，删除后这些镜头会失效」 | **保留** |
| 分镜右栏 | 「引用资产」chip 组 | 保留，改名为**「参考素材」**，属于这一镜的输入 |

区分标准很简单：**"谁引用了我"是关系查询，用户不该看；"我用了谁"是生成输入，必须能改。**

后端 `reference_count` 继续算、继续用于删除前校验和级联提示，只是不进主界面。

### 1.5 四种状态

| 状态 | 表现 | 触发 |
| --- | --- | --- |
| 未生成 | 空心点 + 虚线占位图 | 新建卡，`image = null` |
| 已确认 | 实心绿点 | `state = confirmed` |
| 待更新 | 琥珀点 + 图上角标「描述已改，图还是旧的」 | 改过描述/提示词，但没重新生成 |
| 失败 | 红点 + 图上红色遮罩 | 生成失败，遮罩里给原因和重试 |

「待更新」是这一页最重要的一条状态：素材改了描述，下游镜头不会自动重画，用户必须看见这个差。

### 1.6 预览区：只调一点，不重做

素材和分镜的预览区在代码里是**同一个组件** `ImageGroupPreview`（`presentation="asset-creation"`），结构是：

```
.image-subject-grid-{1|2|4|many}
  .image-subject            ← 格子：1px 描边、8px 圆角、contain
    .image-subject-label    ← 左上：序号 + 「主图」徽章（黑底、11px）
    img
    .image-subject-toolbar  ← 悬停才出现：下载 / 历史 / 设为主图
    .image-subject-size     ← 右下：1024 × 1365（等宽、10px）
```

上一版设计稿把这块换成了「一张大图 + 下方候选缩略条」，等于另造一套预览，没必要。这一版只做三处微调，其余完全不动：

1. 格子左上角的序号后面加**角度**（`1 · 正面`），因为一张卡只有一个角度，用户需要确认自己在看哪张；
2. 主图徽章从绿色改成和现有一样的**黑底白字 + ✓**，不引入新颜色；
3. 生成失败的第 N 格，在格子内显示原因 + 「重试」，不在预览区外面再加一条横幅（会和设置里的报错重复）。

宫格张数直接跟着 `image_settings.count` 走：素材默认 1 张，分镜默认 1 张，用户选了 4 张就是 2×2。**不新增任何布局状态。**

### 1.7 空态

一屏给出两个动作，并说明代价：

- `从剧本提取（10 个）` — 从已确认剧本里扫角色/场景名，**只建卡、不生成图**
- `手动新建`

底部一行小字：「提取只建卡，不自动生成图片，可以逐个确认后再跑」。这是为了避免"点一下扣 10 次费"的惊吓。

## 2. 分镜制作

### 2.1 为什么是四套视图

四个问题，四个答案，不能合并：

| 视图 | 回答的问题 | 什么时候用 |
| --- | --- | --- |
| **网格** | 这 12 个镜头排下来顺不顺？ | 通读全片节奏，找缺镜、重镜 |
| **表格** | 景别/运镜/时长/台词对齐了吗？ | 逐行核对参数，批量改 |
| **单卡** | 这一镜的画面和台词对不对？ | 改一镜，看大图，重生成 |
| **大图查看** | 这张图本身好不好？ | 纯看画面，左右翻，不进设置 |

v2 只有网格，等于只回答了第一个问题。用户要"查看每张分镜卡的详细画图"，指的就是后两个。

### 2.2 网格（主视图）

```
左 240                     中 自适应                       右 344
┌─────────┬──────────────────────────────────────┬──────────────┐
│ 全部 12  │ 分镜表 [12 镜]      [网格|表格|单卡]   │ S03 近景·推进 │
│ 待生成 3 │ 全部 待生成3 待更新1   导出分镜表       │ 缩略图        │
│ 已生成 9 │ ┌────┐┌────┐┌────┐┌────┐              │ 画面          │
│          │ │S01 ││S02 ││S03 ││S04 │              │ 台词          │
│ S01 全景 │ └────┘└────┘└────┘└────┘              │ 景别/运镜      │
│ S02 中景 │ ┌────┐┌────┐┌────┐┌────┐              │ 时长          │
│ S03 近景 │ │S05 ││S06 ││S07 ││S08 │              │ 参考素材      │
│ ...      │ └────┘└────┘└────┘└────┘              │ [生成这一镜]  │
│          │ 共12镜 · 1'03" · 已生成9 待生成3        │              │
└─────────┴──────────────────────────────────────┴──────────────┘
```

卡片 = 16:9 画面 + 三行字（动作 / 景别·运镜 / 台词），画面左上角镜号、右下角时长、右上角状态点。**一屏 12 镜全见**，这是选 4 列而不是 3 列的唯一理由：12 镜是短剧一集的常见量，一屏看完比"看得更大"重要。

### 2.3 表格

一行一镜，8 列：镜号 / 画面（缩略 88×49 + 动作）/ 景别 / 运镜 / 时长 / 台词 / 状态 / 更多。行高 62，12 行正好一屏。

- 表头可排序（按镜号、时长、状态）
- 单元格双击就地编辑，不跳详情
- 斑马纹极淡，只用来防止横读串行
- 奇数行 hover 整行高亮，选中行左侧 2px 白条

表格不是网格的替代，是同一批数据的另一种密度。切视图不改变选中镜。

### 2.4 单卡

```
左 240            中 自适应                          右 344
┌─────────┬──────────────────────────────┬──────────────────┐
│ 镜头序列 │ S03 [沈氏·顶层][已生成] ‹ 3/12 › │ 画面              │
│          │ ┌──────────────────────────┐ │ 台词 / 音效        │
│          │ │                          │ │ 景别 [远景 全景 近景 特写] │
│          │ │   图片组单格（16:9 居中）    │ │ 运镜 [固定 推进 拉远 跟拍 横移] │
│          │ │                          │ │ 时长 5.0s         │
│          │ └──────────────────────────┘ │ 参考素材          │
│          │ [S01][S02][S03][S04]...胶片   │ [重新生成这一镜]  │
│          │ 5.0s · Kling 2.1 · 14:41     │                  │
└─────────┴──────────────────────────────┴──────────────────┘
```

- 预览区 = 图片组单格铺满（与素材页同一个组件），16:9 图 contain 居中，上下留格子底色
- 不设底部胶片条：左侧「镜头序列」已经是同一批镜头的列表，再加一条是重复
- 翻页用标题栏的 ‹ 3/12 ›，与现有 `selectAdjacent` 一致
- 右栏字段顺序 = 写分镜的顺序：先画面，再台词，再景别运镜，再时长，最后参考素材
- 景别只用 6 个枚举，与现有 `ShotSize` 对齐：远景 / 全景 / 中景 / 近景 / 特写 / 双人

### 2.5 大图查看

全屏黑底，只有画面（就是点格子后打开的那层，对应现有 `PreviewImage`）：

- 顶部 54px：`‹ S03 林晚站在长桌尽头 [近景][5s]`，右侧 重生成 / 下载 / 关闭，中间提示「← → 切换 · Esc 关闭」
- 画面 1348×758（16:9），内阴影暗角，四周留黑
- 左右圆形翻页按钮，垂直居中

这个层的唯一职责是"看"。所有编辑都不在这里做，Esc 直接回到原视图原位。

### 2.6 三套异常态

**生成中**（图 24）：网格不阻塞。

| 元素 | 表现 |
| --- | --- |
| 卡片 | 图区 74% 黑遮罩 + 进度环 + 「生成中 45%」，底部 2px 琥珀进度条 |

## 5. 分期

**P0 — 不改接口，只重排**

1. 素材卡标题拼 `label`；状态点；空态两个入口
2. 素材中栏大图 + 候选条；右栏「角度/视图」输入 + 「加一个角度」（复制建卡）
3. 分镜网格（4 列 / 一屏 12 镜）+ 大图查看层
4. 四态状态点与「待更新」判定

**P1 — 小改接口**

5. `camera_move` 字段（网格与表格要显示，单卡要能选）
6. `dialogue` / `sfx` 从 `script` 拆出
7. 表格视图 + 单卡视图
8. 批量生成队列（含暂停、重试、进度）

**P2 — 交付**

9. 导出分镜表（CSV / PDF）
10. 素材「加一个角度」支持一次点多个（仍然逐张确认）

## 6. 取舍与风险

1. **不分组会变长**。13 张素材平铺，找"林晚的侧面"要靠搜索。用类型 tab + 名称搜索兜住；如果实际超过 30 张，再考虑按 `name` 折叠——但那是列表交互，不是数据模型。
2. **`label` 是约定不是约束**。用户可能写"侧"也可能写"侧面"。P1 加一层输入建议（已有角度做成下拉可选项），不做强制枚举，因为角度本来就会长出新词。
3. **四套视图成本不低**。如果只能先做两个，做**网格 + 大图查看**；表格和单卡是同一批数据的另一种排布，后补不影响数据层。
4. **运镜没有字段**是这版最大的落地风险。设计稿里网格、表格、单卡三处都用到了它，P1 之前只能用 `video_prompt` 里的文字兜底，显示会不准。
5. **生成中改描述**会产生"待更新"，但当前没有字段记录"生成时用的描述快照"。要么加 `prompt_snapshot`，要么用 `context_hash` 比对——后者已有，够用。

## 8. 交互原型（2026-10-27 追加）

图纸只能看，不能判断"点下去会怎样"。这一轮把四页做成可点的纯前端原型，放在同目录，直接用浏览器打开 `index.html`：

```
docs/data/创作模式工作台v3/
  index.html          四页外壳 + 顶栏四步 + 图标雪碧图
  proto.css           全部样式（深色、与项目 DESIGN.md 同一套令牌）
  proto-data.js       演示数据：剧本正文、12 个素材、12 个镜头、19 个时间轴片段
  proto-core.js       剧本解析、状态、路由、浮层、Toast、设计说明
  proto-script.js     剧本创作（可编辑 + 对比采用）
  proto-assets.js     素材生成（一张卡一个素材 + 多角度 + 四态）
  proto-board.js      分镜制作（网格 / 表格 / 单卡 / 大图 + 生成队列）
  proto-assembly.js   成片合成（监看 + 五轨时间轴 + 检查器）
```

`?view=script|assets|board|assembly` 可以直接落到某一步，方便评审批注时指位置。全部是原生 JS，没有构建步骤、没有外部依赖，双击就能开。

### 8.1 四页各自能点到什么

| 页面 | 可交互 |
| --- | --- |
| 剧本创作 | 直接改正文（场次、时长、钩子、未登记人物实时重算）；左栏场次跳转；结构栏收起；专注模式；插入场次/动作/对白/OS/VO；选中台词→「更狠/更短/更口语/加动作」写进创作要求；AI 生成（带进度）→ 逐场对比 → 勾选采用；故事设定三段编辑；小说原文抽屉与 TXT 导入；生成记录；导出 txt；空稿四个起点 |
| 素材生成 | 搜索/按类型筛选；单张选择；改名称、类型、角度（重名会拦）；改描述→自动标「待更新」；数量 1/2/4；生成进度与失败重试；加一个角度（复制当前卡新建未生成）；多选对照；删除（唯一显示引用数的地方）；全屏查看；从剧本提取角色/场景；清空看空态 |
| 分镜制作 | 三种视图切换 + 大图；双击卡片进单卡；表格单元格直接改景别/运镜/时长/台词；批量生成 → 队列进度 → 完成/失败重试；筛选；新增镜头；单卡里改景别/运镜/时长/描述；参考素材 |
| 成片合成 | 播放/暂停、跳 5 秒、点标尺移动播放头；拖片段改起点（0.25s 吸附）；选片段改名称、看来源、删除；从分镜同步（补 S11 并重排）；导出设置与进度；素材箱点一下入轨 |

### 8.2 原型验证后改掉的三处

1. **对比态改成行级 diff**。图纸里是「整场旧文 − / 整场新文 +」，实际点下来会把没改的行也标成删除再添加，噪声太大。原型用 LCS 逐行比对，未改动的行只出现一次，连续 3 行以上折叠成「… N 行未改动」。
2. **选中改写浮条固定在正文底部**，不再贴着选区浮。textarea 拿不到选区坐标，用镜像元素测量在滚动和缩放下会漂 40–60px，反而挡字。固定条永远在正文下沿，不遮当前行。
3. **素材对照的右栏从"当前素材设置"改成"对照清单"**。并排看三张时右栏还显示第一张的描述是错的，现在只列这三张的名称/角度/状态，改参数必须先退出对照。

### 8.3 哪些是模拟的

| 行为 | 原型 | 真实实现 |
| --- | --- | --- |
| 生成剧本 | 定时器推进度，完成后用预置的三处改写 + 一场新增构造候选 | 走现有 `generations` 接口与队列，候选来自服务端 |
| 生成素材 | 定时器 1.6 秒出图，画面是占位 SVG | `assets` 生成任务 + 对象存储 |
| 批量生成分镜 | 队列在本地推进，S11 固定失败用来演示重试 | `storyboard` 批量任务 |
| 导出 | 剧本真下载 txt；成片只走进度不产文件 | 服务端导出 |
| 故事设定 | 内存 + 刷新即还原（点"重置演示数据"恢复） | 需 `script_brief` 表（见 §4） |
| 引用数 | 固定值，只在删除确认里出现 | 服务端 `reference_count` |

### 8.4 原型里刻意没做的事

- 没做分集、没做协作评论、没做节拍板卡片墙——这三件在 §0 就排除了。
- 没把「引用关系」做成可查列表；素材页任何位置都不显示"被谁引用"。
- 没在素材页引入"资产/多视图"层级，多角度仍然是多张平铺的卡。
- 没做时间轴的波形与转场预览，那属于剪辑器深水区，先把"从分镜来、还差什么"表达清楚。
- 拖片段只改起点，不做碰撞检测与波纹联动，允许互相重叠——原型只验证"拖得动、位置对"，剪辑规则要真做时再定。

### 8.5 从原型到代码的顺序

1. 剧本页替换 `SourceStage` 的呈现层（解析、diff、合并三个纯函数可直接搬 `script-structure.ts` 的口径）；
2. 素材页把 `ImageGroupPreview` 的格子补上角度标签与失败格，状态四态落到 `AssetRead`；
3. 分镜页先做网格 + 大图，表格与单卡复用同一份 `ShotRead`；
4. 成片页先接「从分镜同步」，再做拖拽与导出。
