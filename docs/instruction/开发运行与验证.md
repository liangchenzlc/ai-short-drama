# 开发、运行与验证

命令按 Windows PowerShell 编写；除明确标注外，后端命令在 `backend/`、前端命令在 `frontend/` 执行。Linux/macOS 使用相同 uv/npm 命令，环境变量按对应 shell 设置。

宿主项目页“画布导入导出”复用独立画布桥接：开发从`/canvas-app/src/services/host-archive-entry.ts`加载，统一生产构建输出`dist/canvas-app/host-archive.js`。两包build后再运行宿主preview；只构建创作模式不能提供生产归档桥接。原源项目库页面保持移除。

当前使用单层项目的创作模式，内部 `workspace_mode=standard` 保留。旧分集/协作版本须按[创作模式维护说明](创作模式维护说明.md)离线备份、预演并重建；以下历史功能迁移记录仅用于旧版本维护，不能叠加到本版数据库。

## 环境准备

| 依赖 | 要求 |
| --- | --- |
| Python | 3.12+，依赖由 `backend/uv.lock` 固定 |
| Node.js | 两套前端统一运行推荐 22.18+ 的 22.x 或 24.x LTS；依赖分别由 `frontend/package-lock.json` 和 `frontend/canvas/package-lock.json` 固定 |
| MySQL | 8.0.21+，InnoDB、utf8mb4、严格模式、UTC |
| RabbitMQ | 可访问的 AMQP 服务；5672 默认明文，TLS 端口按部署配置 |
| MinIO | 预先准备图片和视频两个 bucket，应用不会自动创建 |
| FFmpeg / FFprobe | 成片探测、预览和导出需要；加入 PATH 或设置 `RENDER_FFMPEG_PATH` / `RENDER_FFPROBE_PATH` |

画布本地字幕转写执行器通过 `CANVAS_WHISPER_BASE_URL` 调用独立 whisper.cpp 服务的
`/inference`，服务须支持 multipart `file`、`response_format=verbose_json` 和可选 `language`。
执行器使用现有 FFmpeg 将音视频转成 16kHz、单声道、16-bit PCM WAV，临时文件在退出时清理；
服务 HTTP 超时为 20 分钟，结果读取上限为 8MiB。模型由该独立服务准备，不由应用自动下载。
私人任务通过 `/api/v1/canvas-runtime/timeline/transcriptions` 准入，复用现有 render Worker；
旧库须显式补齐014迁移，并同时部署API、scheduler和Worker。固定源的整站剪辑页按当前
产品范围已删除；画布音视频节点的“编辑字幕”弹窗已接入转写按钮。配置地址和受控HTTP通过都不代表真实
ASR模型验收；API 和负责本地执行的 Worker 应使用相同配置。

字幕也可选择宿主手动配置的 OpenAI 兼容转写模型。模型须启用并声明 `openai-audio` 协议、
`api_format=openai` 及 `capability_config.audio.transcriptionSupported=true`，可在字幕弹窗
刷新列表。服务端解密密钥，冻结配置版本，预处理 WAV 后单次请求 `/audio/transcriptions`；
需要返回带时间戳的 `verbose_json`，不自动回退其他模型。云端发起标记持久后出现断连或
进程中断，任务保持待核实且不能恢复重发，须到渠道核实。未选择模型仍走 Whisper。

标准成片编辑器同样复用该 Whisper／云端转写执行器和 render Worker，不依赖画布界面。
先执行[标准成片多轨迁移](../database/migrations/2026-10-21-assembly-editor/README.md)，
部署同版 API、scheduler、render Worker；仅启动 API 不执行识别、波形或响度分析。
识别只混合实际原声与对白，结果先预览后应用，云端受理不明保留原请求并要求明确核实。
未配置 Whisper 不会自动选收费模型；`local_available` 仅代表地址已配置。
旧配音生成仍需要 `AUDIO_PRODUCTION_ENABLED=true`、音频存储桶及独立 audio Worker。
烧录中文字幕可设置 `RENDER_SUBTITLE_FONT_PATH`、`RENDER_SUBTITLE_FONT_FAMILY`；
未指定路径时仅回退实际存在的微软雅黑或 Linux Noto CJK，部署建议显式提供同一字体。
组合保存、素材入轨、音画关联及验证范围见[成片编辑器维护说明](标准成片编辑器维护说明.md)。

画布视频解码失败时可异步准备 H.264/AAC 兼容副本，原件继续保留。需要同版 API、
scheduler、render Worker、FFmpeg/ffprobe 与 MinIO；仅启动 API 不会生成兼容副本。
scheduler 同时重试清理取消或租约中断后留下的未登记播放对象，写入前的对象定位已持久化。
旧库先执行[画布风格与兼容播放迁移](../database/migrations/2026-10-16-canvas-alignment/README.md)，
包含三张风格表及本地任务 CHECK 扩展；不由应用自动迁移。

画布“深度动作捕捉”使用独立 Video Depth Anything Small 组件，任务同样由 render Worker
执行，支持 Windows x64 与 Apple Silicon Mac。已有部署组件时同时设置
`BEEFTV_DEPTH_PYTHON`、`BEEFTV_DEPTH_TOOL_DIR`、`BEEFTV_DEPTH_RUNTIME`：前者为独立
Python 可执行文件，工具目录含 `depth_capture/`，其同级 `vda/` 使用源固定提交
`4f5ae23172ba60fd7bc11ef671cca678842c7072`，模型目录保存固定权重。组件依赖独立安装，
不添加到应用 `uv.lock`；FFmpeg/ffprobe 沿用现有服务端配置，Windows 组件须包含可加载的
VC++ 运行库。仅填写一部分路径会明确失败。

未配置三项路径时，组件安装器使用 `CANVAS_DEPTH_RUNTIME_ROOT`（默认 `.runtime/depth`）
持久保存运行包、模型和下载缓存。`BEEFTV_DEPTH_MANIFEST_URL` 可指定部署发布清单；
Windows 必须配置发布方提供的 `BEEFTV_DEPTH_MANIFEST_PUBLIC_KEY`（Base64 编码的32字节
Ed25519公钥），验签后才下载。固定源公钥由发布流程注入，仓库没有可直接沿用的公钥；
不能生成一个临时公钥或关闭校验来替代。下载校验SHA-256和大小，支持断点/分片，并在
发布失败时恢复旧组件；API、scheduler、render Worker 须使用同版代码及一致配置。

标准深度配置保持输入280、最长边960、输出1920×1080、最长15秒；准入与真实探测均保留
源15100ms边界。Windows先检查NVIDIA设备再探测CUDA，只有组件退出码42允许回退CPU，
CPU处理可能较慢；macOS使用MPS，其他平台持久返回不支持。处理期间续租和检查取消，
退出清理临时文件；结果以 `depth:<task-id>` 归档，恢复已完成上传时不重复推理。
模型推理、组件安装、AMQP和浏览器范围分别记录，受控组件通过不代表真实模型质量或
CUDA/MPS验收。接口及权限见[画布API](../api/canvases.md#私人深度动作捕捉)。

静态图片的“深度图/AI线稿/姿态骨架”属于独立 Framefield Local Runtime，默认地址为
`http://127.0.0.1:17371`。前端保持固定源的 runtime-info、ECDSA挑战/签名会话和受限scope；
可在画布构建时用 `VITE_FRAMEFIELD_LOCAL_RUNTIME_ENDPOINT` 指定一个精确的127.0.0.1
HTTP origin。该服务的实际模型与安装程序不在当前Python仓库；没有服务时沿源显示
不可用/重试连接，不在API里返回伪造ready或模拟算法。灰度和Canny继续使用原浏览器算法，
视频高级模型仍保留原“打开视频剪辑”边界，透明抠图保留源未就绪状态。

转换成功后先通过宿主资源上传永久归档，再把 `resource:<id>` 写入原节点及结果状态；
上传键包含冻结账号/画布、来源、操作、输出SHA和尺寸，同输出重放复用原身份。来源、
账号、操作或画布变化后停止旧回填，保存失败在原节点反馈并允许用户重试；不把仅存于
IndexedDB的Blob标为完成。转换作品、来源及处理状态均由项目所有者访问。灰度/Canny浏览器恢复通过不等于三类Framefield模型真实运行验收。

```powershell
# backend/
uv sync --locked
# 仅首次执行；不要覆盖已有 .env。
Copy-Item .env.example .env
```

填写 `backend/.env`。Settings 从当前工作目录读取 `.env`，所以 API、调度器、Worker 和脚本都应从 `backend/` 启动。

账号认证默认启用，两种模式均为所有者独占。启动只检查结构和归属，不自动迁移。配置精确的 `PUBLIC_ORIGIN`、安全 Cookie 和 SMTP；本机 HTTP 开发设 `AUTH_COOKIE_SECURE=false`。旧版本切换与保留数据范围见[创作模式说明](创作模式维护说明.md)。

| 配置 | 含义与注意事项 |
| --- | --- |
| `DB_HOST/PORT/USER/PASSWORD/NAME` | 应用数据库连接；不要把测试临时库写成应用库 |
| `ENCRYPTION_KEY` | Base64 编码的 32 字节 AES 主密钥；已有密文依赖原密钥 |
| `SNOWFLAKE_WORKER_ID` | 0–1023，每个同时运行的进程必须不同 |
| `RABBITMQ_*` | AMQP 连接；15672 是管理 UI 端口，不能用于任务连接 |
| `MINIO_ENDPOINT` | `host:port`，不带协议或路径，浏览器也必须能访问该地址 |
| `MINIO_ACCESS_KEY/SECRET_KEY/SECURE` | 凭据及是否 HTTPS，与实际服务一致 |
| `MINIO_IMAGE_BUCKET/VIDEO_BUCKET` | 默认 `image/video`，两者必须不同 |
| `MINIO_PRESIGN_EXPIRY` | 默认 300；账号模式最多五分钟 |
| `MINIO_PUBLIC_ENDPOINT` | 可选供应商引用签名主机及端口，不含协议、用户信息、路径、query 或 fragment；固定使用 HTTPS，必须指向同一 MinIO 对象 |
| `MINIO_PROVIDER_PRESIGN_EXPIRY` | 与公网 endpoint 配对，空值禁用；没有默认值，按供应商延迟取图窗口显式设置 1–604800 秒 |
| `MODEL_DISCOVERY_ALLOWED_HOSTS` | 仅需内网模型网关时设置精确主机名 JSON 数组，默认 `[]` |
| `GENERATION_*_BUDGET_SECONDS` | 文本/图片/视频执行和媒体归档预算，详见 `.env.example` |
| `AGENT_ENABLED/LEASE_SECONDS/POLL_SECONDS` | 默认开启；启动前需完成显式迁移并准备独立 Worker，见 [Agent 部署](Agent模式部署与排障.md) |
| `EXTRACTION_MAX_*` | 提取输入字符、候选数和输出 Token 上限，默认 30000/100/8192 |

完整可用配置及限制以 [Settings](../../backend/src/short_drama/core/config.py) 为准。`GENERATION_QUEUE_NAMESPACE` 默认 `short_drama`；自定义时需同步修改 Worker 队列名，见下文。

仅新部署可生成主密钥：

```powershell
uv run python -c "import base64,secrets; print(base64.b64encode(secrets.token_bytes(32)).decode())"
```

将结果保存到本机 `.env` 或部署密钥系统。不要提交、发到日志或覆盖已有主密钥；数据库备份需配套妥善保管原主密钥。

## 启动后端

API、scheduler 与已使用的任务队列各自运行独立进程。默认流程需启动文本、图片、视频、成片和 Agent Worker；启用音频时增加音频 Worker。以下各段分别在独立终端执行，默认队列下：

```powershell
# API
$env:SNOWFLAKE_WORKER_ID = '1'
uv run uvicorn short_drama.main:app --host 127.0.0.1 --port 8000
```

```powershell
# Publisher + Recovery
$env:SNOWFLAKE_WORKER_ID = '10'
uv run python -m short_drama.tasks.runtime
```

```powershell
# 文本 Worker
$env:SNOWFLAKE_WORKER_ID = '2'
uv run celery -A short_drama.tasks.celery_app:app worker --pool=threads --concurrency=4 -Q tasks.ai.text --hostname='text@%h' --loglevel=WARNING
```

```powershell
# 图片 Worker
$env:SNOWFLAKE_WORKER_ID = '3'
uv run celery -A short_drama.tasks.celery_app:app worker --pool=threads --concurrency=2 -Q tasks.ai.image --hostname='image@%h' --loglevel=WARNING
```

```powershell
# 视频 Worker
$env:SNOWFLAKE_WORKER_ID = '4'
uv run celery -A short_drama.tasks.celery_app:app worker --pool=threads --concurrency=2 -Q tasks.ai.video --hostname='video@%h' --loglevel=WARNING
```

```powershell
# 成片渲染 Worker
$env:SNOWFLAKE_WORKER_ID = '5'
uv run celery -A short_drama.tasks.celery_app:app worker --pool=threads --concurrency=1 -Q short_drama.tasks.render --hostname='render@%h' --loglevel=WARNING
```

```powershell
# 音频 Worker（启用音频时）
$env:SNOWFLAKE_WORKER_ID = '6'
uv run celery -A short_drama.tasks.celery_app:app worker --pool=threads --concurrency=2 -Q tasks.ai.audio --hostname='audio@%h' --loglevel=WARNING
```

```powershell
# Agent Worker（默认开启，先完成显式迁移）
$env:SNOWFLAKE_WORKER_ID = '7'
uv run celery -A short_drama.tasks.celery_app:app worker --pool=threads --concurrency=2 -Q short_drama.tasks.agent --hostname='agent@%h' --loglevel=WARNING
```

Agent 默认开启，需要 `AUTH_ENABLED=true`，按 [Agent 部署](Agent模式部署与排障.md) 执行 `agent_migration.py --precheck / --apply` 并统一重启；已有库迁移前或暂不使用 Agent 时显式设置 `AGENT_ENABLED=false`。Agent 与渲染队列始终带 namespace 前缀，例如 `studio_dev.tasks.agent/render`；原生队列自定义 namespace 时为 `studio_dev.tasks.ai.text/image/video/audio`。

线程池里的线程共享同一进程雪花生成器。不要直接改成共用同一节点 ID 的 prefork 多进程或多个 Uvicorn Worker。重启复用节点前，应确认旧进程已停止且时钟超过旧进程最后发号时间。

自定义 namespace 为 `studio_dev` 时，队列是 `studio_dev.tasks.ai.text/image/video`，所有进程配置必须一致。默认 namespace 不加前缀。不同数据库或独立开发环境共用 RabbitMQ 时必须使用不同 namespace，避免另一环境消费并丢弃本环境的任务。手动启动时同步修改 `-Q` 队列名。

Windows 可选用 `scripts/start_generation.ps1 -Role api|scheduler|text|image|video|audio|render|agent` 分别后台启动，PID/输出写入 `backend/.runtime/`。脚本使用现有 `.venv`，从后端 Settings 自动解析实际队列名，并使用上表节点号；每个角色只启动一次，不与手动进程重复启动。成片与 Agent 队列分别始终为 `<GENERATION_QUEUE_NAMESPACE>.tasks.render` 和 `<GENERATION_QUEUE_NAMESPACE>.tasks.agent`。加 `-DryRun` 可只解析并显示命令，不启动 Worker 或写入 PID。它不是通用生产进程管理器，也不会因进程启动成功就保证依赖健康。

## 启动前端

```powershell
# frontend/
npm run install:all
npm run dev
```

地址 `http://127.0.0.1:8080`。`install:all` 分别按两包锁文件安装，`dev` 在一个 Node 进程内启动宿主 8080 和独立画布子包 8082，并将 `/canvas-app/` 代理到画布。退出时关闭本次创建的两台 Vite 服务器；端口被占用时退出，不自动换端口。开发服务器将 `/api` 转发至 `http://127.0.0.1:8000`。`npm run dev:standard`、`npm run dev:canvas` 可分别运行，画布也保留 `frontend/canvas/` 下的独立 `npm ci`、`npm run dev`。

统一 `dev` 可传 `--port`、`--host`、`--mode`、`--open`、`--force`、`--strictPort`，`CANVAS_DEV_PORT` 控制画布端口。两包分别保留依赖目录、锁文件、HTML 和 React root；共同声明但版本不同的直接依赖采用宿主版本，画布独有依赖继续单独锁定。画布测试依赖 Node 类型剥离，nanoid 6 不支持 Node 20。

如需调整，复制 `frontend/.env.example` 为 `.env.local`，设置 `API_PROXY_TARGET` 后重启 Vite。`VITE_API_BASE_URL` 默认 `/api/v1`，会进入浏览器产物，只能放公开配置。

后端快速验证，不依赖真实模型或业务数据库：

uv run ruff check src tests scripts
uv run ruff format --check src tests scripts

前端验证：

```powershell
npm test -- --feature standard.assets
npm run typecheck
npm run build
```

`build` 包含两包类型检查与生产构建，将独立画布 `frontend/canvas/dist/` 复制到 `frontend/dist/canvas-app/`。`npm run preview` 只启动宿主预览进程，从统一 `dist/` 提供 `/canvas-app/index.html` 和标准 `/index.html` 的各自回退，API 使用当前代理配置。画布独立构建、测试与来源检查可在 `frontend/canvas/` 运行；从宿主目录等效执行 `npm --prefix canvas test -- --feature canvas.models`、`npm --prefix canvas run test:e2e -- --feature canvas.characters`、`npm --prefix canvas run source:check`。宿主 `npm test`、`test:e2e` 保持标准测试范围，必须明确功能或文件。

另可执行 `npx playwright install chromium` 后 `npm run test:e2e -- --feature standard.assets`，使用无付费调用的 API 测试替身验证素材功能的桌面与窄屏；可用环境变量 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定已安装的 Chromium。端口 4175 必须可用。

功能编号、目录和维护要求见[测试规范](按功能执行测试.md)与[逐文件清单](测试文件清单.md)。仓库根目录执行 `node scripts/test.mjs --changed --dry-run` 可预览改动影响；源码未映射、路径失效必须先修正。日常按功能运行，集中回归时才显式使用 `--all`。

Node 测试覆盖纯逻辑、保存会话、请求契约和部分组件源码约定，不是浏览器端到端测试。生产构建不能证明真实模型可用或桌面/移动端交互已验收。

项目读取的历史测量方法、修改前后数据、隔离 MySQL 管理入口及前端生产预览性能脚本见[性能测量说明](工作台读取与加载性能.md)。

要使用独立测试服务器，显式设置 `TEST_DATABASE_URL` 后运行上述功能命令，也可向 `uv run pytest` 传入明确的集成测试文件；连接协议必须是 `mysql+pymysql`，所提供数据库名以 `_test` 结尾。fixture 仍会创建新的随机库。没有配置该变量时，直接调用 pytest 会跳过 MySQL 集成测试；统一选测入口会将跳过报告为 `incomplete`。

## 只读检查与故障定位

```powershell
uv run python scripts/check_generation_infra.py
uv run python scripts/check_minio.py
```

`check_generation_infra.py` 按当前 Settings 对原生、成片和 Agent 队列做 passive 查询，显示消费者数量，并只读检查 Agent 九表 readiness、聚合执行状态、unknown 与过期活动租约；不会创建队列或调用模型。详细处理见 [Agent 排障](Agent模式部署与排障.md#只读观测与故障处理)。

已成功生成且有持久化媒体记录的 `save` 消息，若投递后超过一个执行租约周期仍无人接手，调度器会增加消息版本并仅重投保存动作；旧版本消息失效，归档按输出标识幂等保存，不重新调用模型。超过归档预算则转为可恢复的保存超时。`submit/poll` 的已投递消息不使用此规则，避免重复付费生成。

HTTP 检查：`GET /api/v1/test`、`/api/v1/test/db`、`/api/v1/test/minio`。API 启动不主动探活数据库和 MinIO，因此不能只凭进程存活判断系统可用。

| 现象 | 先检查 |
| --- | --- |
| 任务一直排队 | scheduler 与对应 Worker 是否运行；namespace、AMQP 端口及连接是否一致 |
| 任务失败且不能重试 | 读取 `can_resume/can_retry` 和错误码；未知受理不能自动重新提交 |
| 保存返回 409 | 保留草稿，重新读取版本后核对；不要自动覆盖 |
| 生图参数拒绝 | 模型是否支持参考图、画幅、分辨率与张数；独立任务可先省略可选参数 |
| 图片 URL 无法显示 | 签名是否过期；浏览器是否能访问 MinIO endpoint；HTTPS 页面是否引用 HTTP 资源 |
| Agnes 已保存首帧返回 `reference_media_requires_url` | 供应商公网签名配置是否完整；缺失时在创建任务前返回 422，不产生供应商请求 |
| 旧库缺字段/表 | 核对迁移索引和 schema；重启 API 不能补数据库结构 |
| 读配置正常但保存 Key 失败 | 检查 `ENCRYPTION_KEY` 是否为有效的 Base64 编码 32 字节主密钥；旧密文无法解密时，可在编辑页明确输入新 Key 并保存以修复，或明确清除。留空保留旧值，不会修复旧密文 |

Agnes 视频的稳定参考使用单独的供应商签名 client，复用服务端既有凭据和显式非空
`MINIO_REGION`。普通上传、stat、下载与浏览器展示仍走内部地址；账号模式展示 URL
仍最多五分钟。公网签名绑定 host、对象路径及 query，不能先签内部 URL 再替换主机，
代理必须保留这些部分。配置校验、纯结构测试和本地签名不证明公网可达；启用前须从
授权的外网环境实际 GET 独立测试对象并校验字节、Content-Type 和 TLS。

Worker 在第一次 submit 的权限检查后重新核对真实媒体及对象元信息，再签名并构建
临时请求副本。数据库、冻结记录、幂等身份及画布仍保存 `resource:<id>`，签名 URL
不进入持久化参数或日志。poll/save 沿用已受理身份，不重新签名或提交。离线 signer/
供应商替身、隔离数据库/MinIO、公网 GET 与真实供应商首帧内容检查须分别报告；
测试跳过或尚未配置公网 endpoint 不算真实首帧验收通过。

发送 POST 前，Worker 在持有当前 lease/version 的短事务中将输入 URL 及
`X-Amz-Signature/Credential/Security-Token` 的 SHA-256 指纹保存到执行记录的
`agnes_reference_guard`，提交事务后才调用供应商。指纹不含 URL 或签名原文；缺失、
损坏或提交失败返回 `reference_guard_unavailable`，不能靠重新签名继续提交或轮询。
提交及轮询返回复用原 URL、换路径的同一签名 query 或敏感签名值时，以
`reference_output_rejected` 停止；归档前再次检查，禁止将输入签名加密进 `source_cipher`。
POST 后拒绝回显仍保留安全的供应商任务 ID 与未知受理状态，不自动重发。检查最多
8 个输入 URL、每个 8192 字符、24 个敏感值指纹；返回值检查有总字符和节点预算，
不扫描 base64 媒体。正常独立视频 URL 使用原下载归档链路。

RabbitMQ 消费确认超时需要覆盖单次 Worker 调用时长。较长文本/视频预算应同步评估 broker 的 `consumer_timeout`；应用不会替部署者修改 RabbitMQ 配置。

## 部署与维护

- 非 loopback 地址访问使用 HTTPS；生成请求依赖安全上下文中的 Web Crypto（crypto.subtle/randomUUID）。localhost/127.0.0.1 是本地开发例外，普通局域网 HTTP 不满足该前提。
- API、调度器与 Worker 交给进程管理器或容器管理，分配唯一雪花节点，保留可检索日志和异常退出告警。
- 部署统一 `frontend/dist/`。静态站点先将 `/api/` 代理到后端，对 `/canvas-app/*` 页面使用 `/canvas-app/index.html` fallback，其余标准页面使用 `/index.html` fallback；实际静态文件优先，避免 Worker、wasm、字体和脚本请求误返回 HTML。Vite 开发与预览代理不会进入静态构建产物。
- **部署前核对 Vite `base`。** 当前配置为 `/`，路由采用 BrowserRouter，适用于域名根目录部署。子路径部署需同时协调资源 base、路由 basename 和代理路径，并验证直接打开创作阶段 URL。
- 账号与多用户隔离默认启用；部署前完成[账号迁移](账号与共同创作部署说明.md)、邮件与安全 Cookie 配置。Agent 额外部署与关闭步骤见 [Agent 部署](Agent模式部署与排障.md)。
- 备份 MySQL、MinIO 对象和加密主密钥，验证恢复流程；不能只备份数据库中的临时媒体 URL。
- 不按名称批量删除验收数据。若存在旧 `.runtime/*manifest*` 清单，先核实具体 ID、对象与引用，再按清单精确处理；仓库历史验收记录不能证明这些对象仍存在。
- SQL、接口、产品能力变化时同步对应维护文档；不在当前文档里累计机器 PID、一次性截图路径或历史通过数量。

播放恢复、分镜/素材批量任务及配音字幕配乐的部署、开关、worker 和验收方式见[制作功能说明](播放恢复批量生成与声音制作.md)。新增声音制作依赖音频桶及配音 worker；烧录中文字幕还需配置字体。
