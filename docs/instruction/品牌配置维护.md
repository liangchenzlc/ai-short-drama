# 品牌配置维护

## 唯一配置

[brand.json](../../backend/src/short_drama/core/branding/brand.json) 是运行时品牌值的唯一维护入口，随 Python 包分发。标准前端、无限画布及后端各进程共同消费该文件；不再使用 `APP_NAME` 或另存一份前端品牌默认值。

| 字段 | 用途 |
| --- | --- |
| `name` | 产品名称，用于侧栏、可访问名称、API／MCP 名称、邮件主题与助手身份 |
| `tagline` | 侧栏品牌下方的短说明 |
| `titles.app` / `titles.canvas` | 标准前端／画布的浏览器标签标题 |
| `descriptions.app` / `descriptions.canvas` | 标准前端／画布的页面描述；画布分享元信息沿用对应值 |
| `assets.mark` | 独立图形，侧栏等比显示 |
| `assets.lockup` | 图形与字标的横向组合，账号入口等比显示 |
| `assets.icon` | 方形应用图标，用于浏览器标签 |

标题与描述中的 `{name}` 会替换为 `name`；不使用其他占位符。所有字段必须填写，图片路径相对于配置文件所在目录，只引用该目录内的图片。配置 JSON 无效、字段缺失或资源不存在时，构建／后端读取明确失败，不静默退回旧品牌。

## 更换步骤

1. 修改上述 JSON 的品牌文案与图片引用；只改名称时，引用 `{name}` 的标题和描述会随之变化。
2. 按需在同目录 `assets/` 放入新的独立图形、横向组合和方形图标，并修改对应引用。字标已包含在图片中时，需要一并提供新字标图片。支持 SVG、PNG 等常见图片；保持设计原有比例，不拉伸图形。
3. 在 `frontend/` 执行 `npm run build`，发布统一 `dist/`；开发时重启前端服务。两个应用会各自输出带内容哈希的图片，不需要手动复制到两个 public 目录。
4. 同步部署后端包，重启 API、scheduler 及相关 Worker，使各进程读取新配置。前端与后端发布同一版本，避免显示名称不一致。
5. 核对标准首页、账号入口、画布及浏览器标签；文档中的产品名称也应在本次发布中同步。

当前采用的三份运行 SVG 原样来自[Miniart v8 素材](../data/brand/miniart/v8/README.md)。设计档案、历史计划与验收记录保留当时内容，不作为运行配置使用。仓库、包名、数据库、队列及本机存储的技术标识符不随品牌变化。

## 实现与验证

后端 `core.branding.get_brand()` 从包资源读取并在进程内缓存；FastAPI、MCP、邮件及助手提示词读取统一结果。前端 `frontend/branding/` 适配器同时服务两个 Vite 应用，输出带类型的 `virtual:brand` 模块，并注入初始 HTML 的标题、描述和图标；画布经宿主集成入口使用同一品牌值。

仓库根执行 `node scripts/test.mjs --changed --dry-run` 预览影响范围，再运行品牌相关单测、双前端运行验证和品牌浏览器用例。交付前执行双前端生产构建、画布来源检查、`node scripts/check-docs.mjs` 及 `node scripts/check-quality.mjs`。浏览器验收使用 1280×720、1440×900、1920×1080 桌面视口，确认图片比例、资源加载、品牌链接键盘操作及画布初始化后的元信息。
