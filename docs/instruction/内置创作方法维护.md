# 内置创作方法维护

当前九类能力由 12 个独立 Skill 包提供。目录读取 MySQL 已发布版本，正文和资源使用不可变版本及 MinIO manifest；本地部署文件仅作为发布输入。方法不会授予主体读取、作品写入、生成数量或模型调用权限。

| 稳定 ID | 内容版本 | 方法 | 能力 |
| --- | --- | --- | --- |
| `planning.v1` | 1 | 创作任务规划 | 规划 |
| `novel.v1` | 2 | 小说创作 | 小说／剧本 |
| `script.v1` | 2 | 剧本创作 | 小说／剧本 |
| `extract.v1` | 2 | 素材设计拆解 | 素材 |
| `asset_patch.v1` | 2 | 素材定点修订 | 素材 |
| `storyboard.v1` | 2 | 分镜规划 | 分镜 |
| `shot_patch.v1` | 2 | 镜头定点修订 | 分镜 |
| `image.v1` | 2 | 图片提示词 | 图片提示词 |
| `video.v1` | 2 | 视频提示词 | 视频提示词 |
| `voice.v1` | 1 | 配音声音规划 | 配音 |
| `canvas.v1` | 1 | 画布搭建 | 画布，仅 `infinite_canvas` |
| `continuity.v1` | 1 | 连续性检查 | 连续性 |

ID 中的 `.v1` 是稳定身份的一部分，与 `content_version` 独立。原八项内容版本 1 的全文仍保留，迁移回填不会将其改写成新内容；它们不再作为当前目录中未发布方法的回退。当前目录只展示已显式发布的完整方法包；缺少发布版本时需执行下方发布流程。发布更新后，新任务选择最新已发布版本；原任务、停止后继续及已领取操作保持原冻结版本。用户明确“改用 vN”才替换方法版本。

## Harness 的渐进披露

新任务只冻结手选版本的索引，执行相关工作前调用 `load_skill(name, content_version, purpose)`；自动方法由 SOP 缺口触发。正文首次保存在 Operation，重复加载返回原操作引用，压缩保留活动方法的真实调用／结果对，独立配额 8000 估算 tokens，目录 2000。手选变更版本或遗忘原来源时撤销旧正文保留资格。

方法包仅支持文本 references、模板及 PNG／JPEG／WebP 示例图；导入、发布、复制及更新发现脚本、`scripts/` 下文件或未知格式时拒绝整个包。旧脚本资源已不受支持，涉及的方法需重新导入或发布。图片管理接口采用 `encoding=base64` 传输，运行时只保存受管对象引用并按需水合。资源按原始字节校验，已发布版本仍不可变；这不改变内置包许可或发布流程。完整边界见 [Harness 运行机制](AI创作助手Harness运行机制.md)。

## 源文件与许可

包位于 [`skill/builtin_skill_data/`](../../backend/src/short_drama/agent/skill/builtin_skill_data)，由 `catalog.json` 登记稳定身份、内容版本和能力。每包包含 `SKILL.md`、`references/method.md` 和 `assets/output-template.md`；加载器通过与个人导入一致的受限 ZIP 解析器验证包。

除画布方法外，11 包根据本地 2026-10-20 归档的 `zenstory-ai/drama-skills` MIT 内容适配，发布 manifest 随附完整 [MIT 许可](../../backend/src/short_drama/agent/skill/builtin_skill_data/LICENSE-drama-skills.txt)。画布方法为本项目原创；未使用许可不明确的其他归档。适配移除了分集、默认读取全作品、外部 CLI、强制逐项审批、子 Agent 编排及旧候选采用步骤，沿用当前单层项目与原生工具边界。

## 显式发布

先完成 [005 迁移](../database/migrations/2026-10-21-agent-system/README.md#skill-内容包与个人设置2026-10-22-接续)，并确认 MySQL／MinIO 可访问。在 `backend/` 执行：

```powershell
uv run python scripts/publish_builtin_skills.py
uv run python scripts/publish_builtin_skills.py --apply
```

第一条仅验证和预览，不连接业务存储；第二条按当前 Settings 发布，不调用模型。应用启动不会自动发布。需要更新时，修改对应包并增加 `catalog.json` 的 `content_version`，核对方法及模板，再预览和显式发布；不要覆盖历史内容版本。

发布先保存并读回核验 MinIO 资料，I/O 不占用 SQL 事务或连接，再以 005 已回填的 `novel.v1` 历史版本行串行化发布事务。相同身份、版本与校验重跑核验已发布资源并返回 `existing`，不同内容占用相同版本会拒绝且整批回滚；存储失败不发布 SQL 版本。新资源使用独立暂存键，同批相同正文去重；不会重用未引用的旧暂存对象。发布不修改个人启停设置，也不删除旧资源。

## 未引用资料回收

所有 API 和发布进程升级到当前暂存协议后，可在 `backend/` 显式执行：

```powershell
# 默认只预览，不删除。
uv run python scripts/collect_skill_resources.py
# 核对候选后删除，至少保留 24 小时，每次最多处理 1000 个对象版本。
uv run python scripts/collect_skill_resources.py --apply --grace-hours 24 --limit 1000
```

回收限于当前图片桶 `agent-skills/` 下的已知个人／内置资料键。它保留全部不可变版本引用，包括停用、目录软删除和原任务使用的历史版本；不按当前目录是否显示来判定资料可删。对象列举及精确版本删除均在 SQL 事务外，未知键和缺失时间信息跳过。删除失败逐项保留上下文并使脚本退出非零；重跑可继续核对剩余对象。宽限期不能短于 24 小时，批次上限范围为 1–10000。

发布和回收快照使用相同账号行锁，内置方法共用历史版本目录锁。新上传在最终事务内核对数据库 UTC 时间，超过一小时或明显时钟偏差拒绝发布；回收还核对对象修改时间与暂存键时间。因此回收先取得无引用快照后，过期上传不能再发布；发布先提交时，回收能看到其版本引用。已发布资源复用不受暂存时限影响。旧进程仍可能使用旧内容寻址规则，必须完成同版升级后再开启回收。

当前业务库只执行了回收预览：25 个对象全部受版本引用保护、候选 0、删除 0。实际删除验收使用随机测试库和独立 MinIO 前缀，不删除业务历史资料。
