# 代码索引（优先于全文检索）

本仓库用 `codebase-memory-mcp` 建立了结构化代码图谱（约 3.2 万节点 / 17 万条边）。**定位代码时先用它，不要一上来就全仓库 grep**：问"谁调用了这个函数""改这里会断掉谁""这个模块的入口在哪"这类结构性问题，图谱能一次答完，而逐文件搜索要读几十个文件。

## 先确认可用性

- **有 MCP 工具**（如 `search_graph`、`trace_path`）→ 直接用，优先于 `Grep`/`Glob`。
- **没有 MCP 工具**但存在 `.codebase-memory/` → 用命令行包装器，功能相同：

  ```bash
  scripts\cbm\cbm.cmd cli list_projects        # Windows
  scripts/cbm/cbm      cli list_projects       # macOS / Linux
  ```

- **两者都没有**（例如刚 clone 到新机器）→ 先跑一次引导脚本，它会下载二进制、注册各 agent 的项目级 MCP 配置并建立索引（约 30 秒）：

  ```powershell
  powershell -ExecutionPolicy Bypass -File scripts\cbm\bootstrap.ps1   # Windows
  ```

  ```bash
  bash scripts/cbm/bootstrap.sh                                        # macOS / Linux
  ```

## 常用查询

先用 `list_projects` 拿到本机的项目名——它由仓库的绝对路径派生，**换台机器就会不同**，不要硬编码：

```bash
cbm cli list_projects
```

拿到项目名后（下面用 `<项目名>` 代替）：

```bash
cbm cli get_architecture --project <项目名> --aspects overview
cbm cli search_graph     --project <项目名> --query <符号或关键词>
cbm cli get_file_outline --project <项目名> --file-path backend/src/short_drama/service/xxx.py
cbm cli trace_path       --project <项目名> --function-name <函数> --direction inbound
```

`--direction` 取值为 `inbound`（调用者）/ `outbound`（被调用）/ `both`。`--aspects` 可用 `overview`、`structure`、`dependencies`、`routes`、`hotspots`、`entry_points`、`layers`、`cycles` 等。

## 边界

- **改代码前**用它查反向依赖，确认不会断掉调用方。
- 图谱给的是**结构事实**，不替代读源码：需要逐行理解实现时仍然直接读文件。
- 它会漏掉动态派发、反射、配置驱动的调用，这类情况以实际代码为准。
- 结构门禁另以 Python／TypeScript AST 检查实际源码，包括函数内导入与类型导入。索引可能滞后于工作区，循环依赖是否消除以 `node scripts/check-quality.mjs` 为准，不能用图谱未显示某条边证明无环。
- `.codebase-memory/` 是本机产物，已被 `.gitignore` 忽略；每台机器自行建立，不要提交。
