# 按功能执行测试

品牌集中配置使用功能编号 `shared.branding`：快测覆盖前后端配置与消费者，浏览器覆盖工作台／账号入口及画布动态元信息，runtime 覆盖双前端开发和生产预览。runtime 前先执行统一前端构建；配置位置和更换步骤见[品牌配置维护](品牌配置维护.md)。

日常修改使用仓库根目录的 `scripts/test.mjs` 选择测试。`test-map.json` 是功能归属、源码范围、反向依赖和环境要求的执行清单；[逐文件目录](测试文件清单.md)由它生成，不表示测试已经执行。

  e2e/support/                     共享浏览器夹具
  runtime-tests/                   双前端启动与产物

两套前端继续使用自己的运行器和工作目录。后端保留原 `conftest.py` 继承范围及随机 MySQL 临时库。pytest 使用 `importlib`，Python 导入使用 `tests.unit.standard.assets...` 等完整路径。已有测试工厂的复用导入保留，新增公共夹具放入 `support/`。

## 命令

仓库根目录：

```powershell
node scripts/test.mjs --list
node scripts/test.mjs --check
node scripts/test.mjs --feature standard.assets
node scripts/test.mjs --feature canvas.video --level fast
node scripts/test.mjs --changed --dry-run
node scripts/test.mjs --changed --base <基准分支或提交> --dry-run
node scripts/test.mjs --feature standard.assets --level fast,mysql,browser
node scripts/test.mjs --inventory
```

`--feature` 可重复或用逗号分隔，默认级别为 `fast`，补充该功能声明的快速公共契约。`--changed` 合并已暂存、未暂存和未跟踪文件；`--base` 再合并 merge-base 至 HEAD 的分支改动，包含重命名两端。源码变更沿 `depends_on` 的反向关系扩大功能范围；测试工厂或夹具修改选择实际引用者。清单中的 `previous_path` 支持搬迁前路径。

工作区有其他任务时，优先用 `--feature` 明确本次范围。代码未匹配或该级别没有测试会报错；纯文档或无改动输出 `no_tests_required`。`--dry-run`、`--json` 只输出计划，包含选择原因、精确文件、工作目录和未选择的级别。

正式连续运行回归使用 `test_agent_runtime.py` 与 `test_workspace_reliability.py`，走真实 execute、框架、SDK、saver 和隔离 MySQL，模型 HTTP 受控；旧逐轮 Harness／reviewer 测试已删除。

`assistant-runtime-v17` 在既有持续执行、停止后当前目标及真实终态约束上补 root 当前 Run 的可信启动身份，并要求委派保留必需操作、方法、来源、验收与主助手亲自范围。它不强制普通讨论加载方法，不改变授权、排除、skip、服务端版本或对象交接边界。定点验证复用提示装配、设置冻结、根／子助手和问答恢复的既有消费者；不新增只匹配提示字面的测试。受控模型通过不能证明自然长任务或委派已修复，原真实长任务、三子任务并行与完整45参数矩阵仍须按新冻结版本独立验收，旧版本通过项不能计作新版最终通过。

当前来源回归在 `test_agent_runtime.py` 与 `test_graph_answer_sources.py`：真实 ask→停止→迟答409→只读新 Run 后，直接核 SDK selector／主模型的 current_run 与新触发消息相符、原来源各一份；32条合格后补造成原有界省略时不能误标 withheld。官方摘要不复述启动事实、新 Runtime／Session 恢复、同 Run 后补及已消费答案不改 trigger、真实撤回不复活身份／正文均由实际请求验证；双 compiled child 核规范委派／答案来源隔离与完整工具组。相邻验证复用原 prompt_prefix、compiled child 公共 API、设置新 Run 冻结、问答 answered／skipped、压缩、方法权限与 Task25 canonical 受控消费者，不用提示字面匹配替代语义验收。

`test_agent_summary_budget.py` 用正式 middleware、公开摘要和 SDK 准入验证16个合法 L3 的完整最新组、仅该组及大量历史；核对较小 helper 窗口下连续片段完整覆盖、活动 load 配对与来源元数据、小输入及不可压负对照。`test_agent_runtime.py` 另以两份 Skill、两轮16路真实资源读取验证至少两次独立 graph_compaction、最新更正和原始游标读回；`test_assistant_model_ledger.py` 核对 main／selector／summary 发送前拒绝均不创建 Turn 或消耗父用量。模型与存储替身不代表真实供应商验证。

摘要单测另覆盖首／中／末片分别返回空文本或纯空白：经正式 ProtectedChatModel／SDK 明确失败，保留原历史且不发布压缩结果。账本集成测试用真实 MySQL 检查点验证空摘要没有 `graph_compaction` 或主模型请求，已发送 helper 的回执、输入／输出用量与预留释放仍准确保存。

账号 MCP 的 `api/shared/mcp/test_business_mcp.py` 属于 fast，验证完整挂载前缀的 Bearer、代理链与实际启动脚本禁用 Uvicorn 来源重写；`api/shared/identity/test_mcp_tokens_api.py` 和 `integration/standard/identity/test_mcp_tokens.py` 属于 mysql，使用真实 Cookie／CSRF、令牌归属、到期/IP边界、真实 ClientSession 发现／调用、跨令牌写幂等、撤销后旧session、重叠请求身份隔离及读写审计。生成与实际PNG读取经过真实原生Worker流程，供应商及存储样本受控，不代表真实媒体供应商验收。

在 `backend/` 可运行 `uv run python scripts/run_integration.py tests/integration/standard/identity/test_mcp_tokens.py tests/integration/standard/assistant/test_business_invocations.py tests/api/shared/identity/test_mcp_tokens_api.py tests/api/shared/mcp/test_business_mcp.py -q`；先配置仅用于随机 `_test` 库的 `TEST_DATABASE_URL`。MCP-only目录和冻结助手工具池合同在 `unit/standard/agent/test_tool_catalog.py`。

`test_agent_subtasks.py` 使用相同正式入口与隔离 MySQL，验证原生 task、真实三并发／第四排队、共享模型预算与原生媒体收据额度、明确交接授权、跨 Worker 定向恢复、停止和删除；同步屏障验证实际进入工具，不靠 sleep 推断并发。`test_framework_runtime.py` 验证 compiled 子图的同轮／跨轮 namespace 和私有 state 隔离。正式 task 的真实 Docker 父子文件隔离、显式导入／导出及等待后文件恢复在 `test_agent_sandbox.py`，仍需独立 infra 开关；受控模型测试不能称作供应商自主委派验收。

`test_subtask_delivery.py` 定向验证真实子业务收据交付后的父读回／更新／再次明确交接、原生生成查询／等待／成果读取，以及摘要伪造、未交付兄弟成果和剧本提案显式 script／冻结恢复边界。媒体供应商使用 mock，运行时与 MySQL 使用真实实现。

`test_agent_runtime_migration.py` 直接加载 `tests/fixtures/agent_runtime_legacy/` 中逐字冻结的 119 表基线 DDL，再执行 001–006。验证四项历史工具身份与原名审计、重复 apply、已外发媒体延迟归档／collector／预占与历史 undo、人工采用冲突，以及尚未外发请求取消且 submit 为零；仅随机 `_test` 库和本地媒体适配器，不验证应用库或真实媒体供应商。

`test_agent_media_budget.py` 验证正式运行时中 low／high 图片的可压历史与不可容纳内容，并经本地 HTTP 的 Chat／Responses／Claude 真实 SDK 验证原生摘要和父 Run 账本。三协议图／MySQL 用例以合法 9000 字指令和冻结旧 Skill 并行图片组验证固定成本与候选不重选过时图片；完整 execute 用例实际加载方法、读取图位、接收补充输入并摘要掉较新的 AI，确认旧图不重复发送或读取存储。`test_harness_resources.py` 覆盖无存储 I/O 的冻结引用计量、过时及撤回工具组，以及同调用 ID 的不同消息、并发／线程继承与异常后作用域恢复；图片授权和冻结／实际 JPEG 像素交付沿正式图位路径验证。`test_agent_questions.py` 验证回答／跳过、跨 Worker 使用原冻结选择提示词、完整候选目录和真实保存一幕；受控选择结果不能证明真实模型选择质量。真实 live 脱敏报告另记录 selector 的候选名、选中名及最终绑定名。

`test_agent_runtime_live.py` 为显式真实文本验收，默认跳过，旧 `test_harness_live.py` 已退役。45 个参数场景包含42幕长任务3次，其他场景各至少2次：协议与自然并行、主／子问答和跳过、三子任务、原生异步等待、五个停止边界、三个故障窗口、双子图定向恢复、Skill 冻结与撤回、设置／数量及轨迹刷新重连。每次正式执行使用独立 Python Worker 进程和同一 `AgentRuntime.execute`，恢复重新建进程；不逐模型回合重投。受控 runner 回归在 `test_agent_acceptance_runner.py`，使用同一 live 场景断言和显式模型替身，不能称为供应商验收。

仅42幕长任务在创建 Run 前通过正式模型声明接口将该测试模型窗口设为 65536；其余场景仍由 live 夹具声明 32768。长任务仍须达到至少40次执行模型、80次真实工具、两个 Skill 与 L3、至少两次独立真实上下文压缩并连续通过三次；独立 graph_compaction 与 summarization helper 调用数分别核对，同一次压缩的多个分批调用不能凑次数，窗口调整不替代规模、依赖链或摘要断言。

`test_agent_acceptance_runner.py` 的报告回归在真实随机 MySQL 中制造大 JSON 回执，并对测试体通过／失败分别注入回执或诊断收集1038：须保留原子小报告、准确错误和未知用量，收集失败仍向外报错。诊断按 ID 有界读取，不全行排序大 JSON，也不修改 MySQL 全局 sort_buffer。

同文件的主／子问答回归直接执行 live 验收断言，覆盖首尝试有效、失败 ask 后纠正、回答和跳过。问题卡按 `wait_state.kind=user_input` 的登记事实计数，等待前后的唯一卡、interrupt、过期版本409、重复回答幂等、跨 Worker、一份答案和一幕成果均保留；两张真实问题卡仍被单卡场景拒绝。受控 SDK 与随机 MySQL 的通过不代表真实供应商验收。

`test_model_receipt_identity.py` 验证真实摘要后重载方法、误读旧激活并幂等释放时，严格撤回完整组后相同输入仍进入新图决策；测试只把原生调用上限降为12以快速暴露循环，生产额度不变。三个本地 HTTP SDK 协议逐字段验证公开 thread／checkpoint／完整 namespace／task 隔离、相同任务恢复和内容校验，invoke 的 run_id／attempt／时间不影响命中。根图和真实嵌套子图均通过正式模型提交故障钩子在跨 Worker／MySQL 恢复中核对公开身份稳定、无重复文本发送或用量。受控响应不代表真实供应商验收。

`test_graph_answer_sources.py` 使用正式 Runtime／SDK／随机 MySQL，验证同组与分组 load／ask 在答案消费、释放、摘要及重载后的独立原文投影，selector 与主模型都保留目标和合格答案，忘答不重新注入。真实双子图同时验证自己的答案与冻结目标、父子及兄弟隔离、完整工具配对；当前 Skill 五字段投影区分旧 canonical 历史加载回执与新旧激活状态，历史回执原文不改写。固定受控回复用于核对实际输入，不能证明供应商自主决策或原 main4 的失败原因，真实 canonical 与完整45参数验收另行执行。

仅在获准后向父测试进程注入 `RUN_AGENT_RUNTIME_LIVE=1`、`AGENT_LIVE_URL`、`AGENT_LIVE_MODEL`、`AGENT_LIVE_API_KEY`，可用 `AGENT_LIVE_REPORT_DIR` 指定脱敏报告目录。授权按站点／模型对校验：`https://t8api.com` 或 `https://sub2.de5.net` 仅对应 `gpt-6.1-terra`，`https://api.deepseek.com` 仅对应 `deepseek-flash`。2026-10-31 用户将后续真实验收切至 DeepSeek 官方，`deepseek-flash` 对应 DeepSeek-V4.1-Flash-1017；旧结果保留原站点与模型，不改写或重放。父进程及独立 Worker 复用同一目标校验，不接受错配或其它模型。主模型、selector 和 summary 全部走实际受保护工厂；文本请求受理不明不跨站重放。Worker 通过 stdin 接收凭据与连接设置，命令行和落盘报告不保存密钥，子环境移除文本 key。MySQL 必须为专用 `127.0.0.1:13307`，账号须能创建和删除随机 `_test` 库；MinIO 使用随机对象前缀，OpenSandbox 使用专用控制服务与工作区。网络策略为 default deny，仅放行 pip／npm 注册表；可选 `AGENT_LIVE_FIXTURE_HOST` 只供本次受控测试主机。媒体供应商始终使用显式替身，真实原生受理、归档、采用和等待不能记为真实媒体供应商验证。终态回收沙箱和本次 MinIO 前缀，数据库夹具删除随机库；失败保留脱敏报告。

清单将其归入 `live`，普通 `fast/mysql/infra` 不会选中。根目录运行 `node scripts/test.mjs backend/tests/integration/standard/assistant/test_agent_runtime_live.py --level live`；追加 `-- -k <场景>` 可分批，运行器自动将 pytest basetemp／cache_dir 放入 `.runtime/`。在 `backend/` 直接运行 pytest 时也必须显式指定本计划 `.runtime` 下的 basetemp／cache_dir。实际供应商验收以该次脱敏结果和退出码为准，收集或受控通过不代表真实矩阵通过；历史结果见[Harness 验收记录](../reviews/2026-10-26-AI创作助手Harness重构验收.md)。

## 桌面浏览器基线

宿主与画布仅支持内容视口宽度 ≥1280 CSS px。布局矩阵为 1280×720、1366×768、1440×900、1920×1080；较矮桌面窗口检查内部滚动与操作可达。测试不再创建手机／平板 viewport、`isMobile`、`hasTouch` 设备上下文，普通 Pointer Events、键盘、降低动效和媒体比例测试继续保留。原手机场景中的保存、冲突、权限和恢复断言迁移到桌面，设备专属抽屉、44px 触屏尺寸和互斥断言退役，不用 skip 隐藏业务失败。

## 改动范围

| 改动 | 验证要求 |
| --- | --- |
| 逻辑、请求构造、状态、保存会话 | 功能 `fast` 及公共契约 |
| HTTP、事务、DAO、ORM、DDL、并发 | `fast`，追加功能 `mysql`；有外部依赖的文件按清单选择 `infra` |
| 页面交互、导航、键盘、桌面窗口变化 | `fast`，追加功能 `browser` |
| RabbitMQ、MinIO、真实媒体工具链 | 功能 `infra`；需要浏览器的文件另位于 `browser` |
| OpenSandbox代码、持久文件与pip／npm | `standard.agent` 的 `infra`，显式 `RUN_AGENT_SANDBOX_INTEGRATION=1`；准备真实Docker／OpenSandbox／MinIO及隔离MySQL，命令见[代码环境部署](Agent模式部署与排障.md#代码环境与持久工作区) |
| 共享权限、任务、模型、存储、契约 | 核对 `--changed --dry-run` 的反向依赖范围 |
| 双前端启动、构建、部署入口 | `shared.runtime` 的 `runtime`，先准备相关构建产物 |
| 性能或供应商兼容性 | 显式 `performance` 或 `live`，单独准备环境和记录边界 |
| 纯文档 | 核对内容、命令和链接 |

文件内有多类测试时，按最高资源要求保守划分；其中低成本用例也随文件进入更高一级。需要更细时按独立场景拆分文件并同步清单。不能通过删除开关或跳过断言扩大通过数量。

入口优先使用现有 `backend/.venv` Python，缺少时尝试 `uv run python`，不安装依赖。MySQL 经原 `backend/scripts/run_integration.py` 运行，Settings 在 `backend/` 读取，仍使用随机临时库。所需 `RUN_*` 开关必须显式设置为 `1`；入口不自动开启、不输出配置值。`live` 不随快速测试执行，即使 shell 已设置供应商开关也不会被选中。浏览器、FFmpeg 和性能样本前提继续按相邻维护说明准备。

实际执行报告写入忽略目录 `.runtime/test-results/<时间与随机标识>/`，区分 `passed`、`failed`、`incomplete`；有跳过、零用例或仅收集时为 `incomplete`，退出码为 `2`。未选择级别单独列出，不计入通过。报告不记录凭据、配置正文或请求载荷。浏览器原有截图和 trace 位置保持原配置。

## 维护清单

1. 在功能目录编写测试，修 bug 优先先复现。
2. `tests` 登记精确 `path`、`features`、`runner`、`level`、`requires`、`support`；夹具、样本和验收脚本登记到 `auxiliary`。
3. 新模块维护 `features.<id>.sources`，跨功能依赖维护 `depends_on`。已声明功能目录的通配规则覆盖新文件；其他新模块显式登记。不要添加覆盖整个源码树的规则绕过未映射检查。
4. 删除和搬迁同步修正导入、资源路径与清单；`removed_tests` 只保留整理前已经删除文件的归属，不代替当前路径校验。
5. 执行 `--check`、功能 `--dry-run`、对应测试，再用 `--inventory` 更新文档。静态检查、类型检查和构建按实际改动范围执行。
