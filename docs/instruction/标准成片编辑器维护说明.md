## 功能边界

成片工作台采用一条连续画面轨，以及原声、对白、字幕、配乐、音效五类辅助轨。画面支持分镜视频、项目视频、个人媒体库导入及本地视频／图片；图片默认展示 5 秒，可调整。主画面删除后自动合拢，不增加多视频叠层、转场、变速或导出前检查。成片导出成功后仍需明确设为当前成片。

左素材、中央预览、下方轨道与可收起的右侧设置沿用冷黑主题。区域间距 8px，设置内距 10px；内容视口最低 1280px，编辑设置统一桌面内联检查器，可按需收起，播放器和轨道保留拖动调高及内部滚动。普通读设置和模型能力仅使用控件 loading，报错、警告、冲突及后台任务恢复遵守[反馈规则](../design/创作反馈规则.md)，不向编辑桌追加提示段落。

## 编辑与保存

- 标准前端通过 `GET /assembly/editor` 读取组合状态，通过 `PUT /assembly/editor` 同时保存画面与 `SoundDocument.schema_version=2`。视频和声音版本须同时匹配，任何一个冲突都回滚整个事务。`request_id` 重放相同请求，不能换内容复用。
- 声音 v1 文档不能覆盖已保存的 v2 多轨草稿。旧数据在客户端转换为稳定片段标识，兼容已有配音和配乐；声音入口保留配音生成／试听／明确采用，采用后进入对白轨。多轨字幕与配乐在设置区编辑。
- 撤销／重做包含画面、声音、字幕与构图，最多 100 步。串行自动保存及本机恢复包含整份组合草稿，版本使用十进制 BigInt 编码，不能转为 JavaScript Number。恢复文件不保存签名 URL；读取时按媒体 ID 补齐本人有权读取的当前项目素材。
- 轨道锁定阻止直接编辑；跟随镜头的辅助片段继续按画面编辑联动。原声、对白、字幕、音效默认关联当前位置镜头，配乐固定整集位置；可手动解除或重建关联。分割／裁剪按来源坐标重新计算，镜头重排不累加时间误差。
- 同步分镜视频保持画面编辑决定；按同一事务重建声音与字幕关联，视频检测完成后补齐新增原声。独立声音静音不会因重排被重置。明确换成过短视频时先确认新裁剪，取消保留原片段。
- 总画面时长最多一小时、画面最多 300 段、声音最多 600 段、字幕最多 2000 条。辅助声音／字幕可保留在片尾之外，预览与输出按画面结束截断；字幕需非空、按时间排列且不重叠。无效输入仍保留草稿，由保存反馈引导修正。

## 预览与输出

浏览器使用一个 AudioContext 时钟驱动画面、独立声音轨与字幕。视频解码器始终静音，避免重复原声；每段声音使用独立增益节点，支持来源裁剪、循环、循环分割偏移、音量、响度增益、淡入淡出与人声期间压低配乐。切换画面、跳转及新声音缓冲时暂停时钟，后台标签暂停播放。

FFmpeg 使用相同的裁剪、构图与声音参数生成合成预览和正式输出。画面按 30fps 累计帧计算；辅助轨使用整数毫秒。配乐在对白或显式对白压低区间降为原音量的四分之一，预览／输出使用相同区间规则。统一响度通过真实音频分析计算增益，目标为 -16 LUFS、峰值 -1dB；这不是语音增强或音质修复。波形由实际音频采样，并按裁剪、循环与偏移显示。

画面可选择适应／填充、缩放、水平与垂直位置，也可直接拖动构图；安全区只用于辅助预览。字幕支持校对、分割／合并、整体偏移、按标点断句、UTF-8 SRT 导入／导出及字号、位置、描边、底色与安全边距。按标点或跨镜头分段采用字符比例估计时间，不宣称词级对齐。

字体通过 `RENDER_SUBTITLE_FONT_PATH` 和 `RENDER_SUBTITLE_FONT_FAMILY` 配置。未指定文件时，只在实际存在的 Windows 微软雅黑或 Linux Noto CJK 路径中回退，并在快照中冻结字体名、路径和校验和；部署时推荐明确提供相同字体。

## 语音识别与私人任务

识别混合原声及对白，排除配乐、音效和已静音轨道。默认使用 `CANVAS_WHISPER_BASE_URL` 指向的独立 whisper.cpp 服务；复用现有 `/inference` 协议与 render Worker，不自动下载模型。配置须在 API 和 render Worker 中一致，随后重启这些进程。

云端识别仅在用户主动选择本人已启用的模型后执行。模型须声明 `openai-audio`、`api_format=openai` 及 `capability_config.audio.transcriptionSupported=true`。不因本地不可用而自动改选收费模型。

识别支持当前片段和整集，冻结实际人声音轨、范围、画面时间与模型版本。结果先在识别弹窗预览／导出 SRT，点击应用后才替换所选范围内的字幕；范围外保留，替换可撤销。应用时重新保存并检查 `voice_context_hash`，人声或画面时间变化会保留两份内容并拒绝覆盖；仅校对字幕、配乐、构图、轨道锁定或声音名称变化不应作废识别。

媒体任务、模型、记录、取消及结果按发起人隔离；波形／响度缓存也按本人隔离。任务离开弹窗后在 render Worker 继续，可从本人识别记录恢复。网络受理不明保留原请求体和原幂等键，只能核实同一次提交。云端发出前先持久标记 `submitted`；发出后断连／Worker 中断不自动重发，也不能换键绕过。用户在渠道核实后明确点击“已核实原任务”，记录时间后才允许主动提交新请求；原错误、任务和输入继续保留。

## 部署与验证

1. 旧分集/协作库按[创作模式离线切换](创作模式维护说明.md)备份、预演并重建，新库使用完整 SQL。
2. 部署同版 API、scheduler 和 render Worker；配音生成仍需原音频功能开关及 audio Worker。
3. 安装可执行的 FFmpeg／ffprobe，准备字体；需要本地识别时配置独立 Whisper。
4. 运行 `node scripts/test.mjs --feature standard.assembly,standard.sound --level fast`，根据环境追加 `mysql`、`browser`；MySQL 必须能创建／删除随机测试库。

本次验证包含真实 FFmpeg 音画合成、ASS 中文字幕、实际音频分析及隔离 MySQL；浏览器使用 API 测试替身和真实本地视频。ASR 执行测试使用真实音频预处理与识别模型替身，不代表真实 Whisper、收费渠道、识别准确率或人工听感验收。
