## 实际结果

- **能力校验**：所选用户文本模型通过真实工具调用与工具结果续接，协议为 `openai_chat.v1`，流式状态为 `verified`。能力缓存绑定当前模型、凭据身份和配置版本。这证明所选供应商配置兼容，不代表所有供应商或官方同名模型的可用性。
- **文本**：两个成功决策段的完整原始响应、归一化历史与工具意图均持久化；后继请求确实消费对应延迟工具结果。唯一小说候选为 156 字，明确采用后分集正文等于候选，回执和版本一致。
- **图片**：两个成功 Agent 决策段；原生任务与生成记录成功，唯一候选明确采用。实际 PNG 为 `1672×941`、`1,847,665` 字节。MinIO 完整读取、长度、SHA-256、图片格式和尺寸与归档记录一致；当前镜头图片指向该候选，上下文和采用回执正确。已查看实际生成画面。
- **视频**：两个成功 Agent 决策段；冻结步骤、有效原生请求和参考图均指向上一阶段已采用的图片。原生任务与记录成功，唯一视频候选明确采用。实际 MP4 为 `864×496`、`5042ms`、`1,583,173` 字节，完整读取、SHA-256 和完整解码通过；当前镜头视频、原生上下文与采用回执一致。已查看视频抽帧。

视频请求的 `480p` / `5000ms` 与供应商实际输出尺寸、容器时长分别记录，不能把输出称为精确 480 行或 5.000 秒。普通视频归档当前不填充 `MediaFile.video_metadata`；上述实际尺寸与时长由本地 ffprobe 从归档字节观察，未伪造数据库元数据，也未为验收修改生成文件。

## 本轮修复与复核范围

真实验收前离线发现 `SafeTransport` 的默认请求头与 SDK 小写请求头由普通字典合并，线上序列化会重复发送四个同名头。改为大小写无关合并后保留固定 Host、实际 JSON/Multipart Content-Type、调用方凭据和原生默认 User-Agent。新增六项真实 urllib3 序列化的离线回归、六项既有传输回归及六十项 Agent 网关测试通过；两个变更文件经过独立限定 review，无未解决问题。不从此前供应商拒绝码推断其唯一原因。

验收脚本的两处校验取值已修正：共享成果的公开来源快照不包含私有原生上下文，应通过成果与原生生成记录的关联读取冻结快照；`omni_reference` 使用参考图列表，旧 `first_frame_media_id` 只对应首帧输入。当前校验核对原生上下文、冻结/有效参考图及真实采用指针，没有放宽生产 DTO 或修改生产采用逻辑。

各阶段既有本地验证及后续定向验证的范围保持明确：后端曾完成 668 项 unit/API 回归，之后窄改动使用对应定向证据；前端最终 build 和 133 项 unit 通过，35 个 Agent E2E 场景在最终 34/35 与修正后的四项定向运行中均逐项有通过证据。没有声称最后一个版本重新执行了全部后端测试或一次完成 35/35 E2E。

## 交付环境

真实调用在独立验收数据库中执行，使用合成身份和精确三条既有加密模型配置副本。原业务库已有 Agent 七表迁移、严格 readiness 为 `ready`；累计 50 张表。该次验收结束时业务环境 `AGENT_ENABLED` 为 `false`，Agent Worker 未启动。实际 Celery/RabbitMQ 消费已有隔离基础设施用例证据，真实供应商联调由受保护运行时和原生执行器驱动，两类证据分别记录。

后续用户明确要求操作真实数据库并默认开启。2026-10-03 已重新导出完整 50 表 / 542 字段 SQL、核对真实库全部结构并执行可重入迁移；默认和实际环境开关均为 `true`，后端角色已重启且独立 Agent Worker 已启动。这个部署状态更新不改变上述隔离模型验收范围，也没有新增模型调用。当前启用、维护时显式关闭与回退按[部署说明](agent-deployment.md)操作。
