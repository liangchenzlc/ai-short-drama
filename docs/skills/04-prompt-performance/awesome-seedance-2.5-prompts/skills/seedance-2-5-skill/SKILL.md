# Seedance 2.5 技能

## 语言路线

- 英文请求：遵循本文件及 `*.md` 参考文档。
- 中文请求：先阅读 [中文工作流](references/workflow.zh-CN.md)，再使用对应的 `*.zh-CN.md` 参考文件。
- 模型 ID、JSON 键名、命令、媒体占位符与原生音频符号一律保持代码原样，不要翻译。

不要把每个请求都硬塞进同一条"图像网格"流水线。先选定视频路线，再只启用该任务所需的准备模块。

## 1. 选择创作路线

| 需求 | 路线 | 输入 | 结果 |
|---|---|---|---|
| 一个简短、简单的场景 | T2V | 文本提示词 | 一条自洽的镜头 |
| 带可读分格的多镜头序列 | R2V 分镜 | 一张完整的分镜图 | 一次请求把分格顺序转成连续视频 |
| 由人物、产品、场景或风格素材控制的片段 | R2V 素材参考 | 一个按角色细分的小素材包 | 用这些参考搭出的一条片段 |
| 有精确开头与结尾的镜头 | I2V 镜头对 | 起始与结束关键帧 | 一条可独立审查的镜头 |
| 超出支持时长的连续动作 | 扩展 / 串接 | 上一条生成的尾帧与下一段提示词 | 同一镜头的续接 |
| 承载多个事件的连续成片 | 分阶段整片 | 文本加可选参考 | 一次请求覆盖有序阶段，每段落在一个明确的终态 |
| 对已有视频做局部修改 | 编辑 | 源视频加目标参考 | 仅被点名的区域或元素被改动的源视频 |
| 两条已完成的片段之间的过渡 | 无缝转场 | 两段视频 | 它们之间生成的桥接内容 |
| 运动、走位与镜头取自 3D 预览 | 区块分镜参考 | 粗模或精模区块视频加观感参考 | 跟随区块预览的时序与场面调度的最终渲染 |

默认以 Seedance 2.0 作为可执行模型。只有当所选供应商确实暴露了 Seedance 2.5 模型及其真实限制时，才提供 2.5 整片路线。

最后四条路线依赖因模型与供应商而异的能力。在提供之前先核实可用性；见 [能力对比](references/capabilities.md)，了解 2.0/2.5 的差别，以及哪些已发布能力属于平台特性而非 API 参数。

### 分镜图还是单张关键帧

- 只要各分格在视觉上仍可读，默认把**整张分镜图放进一次 R2V 请求**，不要先裁切。Seedance 能把有序分格理解成一条连续的多镜头视频。
- 只有当独立的重拍，或精确的起止状态，比一次 R2V 生成的转场质量更重要时，才用 **I2V 镜头对**。
- 不要把每一格分镜都默认当作 R2V 素材包上传。只有在每个镜头有独立角色（如主体、产品、场景、风格或运动参考）时，才使用多个 R2V 图像。

## 2. 只启用必要的准备工作

### 主体简报

仅当某个必须反复出现的人物、产品、道具、手、载具或场景才使用。记录 3–5 个不变量：剪影或比例、标志性材质或着装、关键颜色，以及任何必须保留的标记。一次性氛围镜头可跳过。

对于反复出现的人物，做一张干净的正脸特写和一张独立全身参考。不要把前/侧/后三合一拼图当作身份输入——它可能被理解成多个人。当物体本身需要从多个侧面展示时，多角度产品参考仍然有用。

### 关键帧

为每个 I2V 镜头创建起始关键帧。只有当镜头必须落在一个特定动作、构图、产品姿态或手部位置时，才加一张结束关键帧。每个关键帧保持一个干净的单一场景。

### 分镜图

直接把已有分镜图用作 R2V 参考。Seedance 通常能理解分格顺序，不需要事先去掉分格序号、分隔线、箭头或注释。只有当一次实测生成确实渲染出了不想要的分隔线、序号、字幕或多格布局时，才做一张干净副本。

当一个多镜头请求没有分镜图时，使用 [提示词模板](references/prompt-templates.md) 中的 Seedream 模板来制作一张。\*\*在宿主 UI 中展示这张分镜图，自己审查它，通过后再继续 Seedance R2V。\*\*展示分镜图是一次进度更新，不是用户审批关卡。

对于提供的分镜图，除非它已在对话中可见，否则展示它。检查计划顺序、可读的关键节拍、反复出现主体的一致性，以及解剖、产品形态或关键文字等特定约束。在视频生成前，先精修肉眼可见的失败分镜。只有在一个创作选择无法推断时才问用户。

如果路线刻意改成 I2V 镜头对，到那时才裁切分格。先审查布局：自动裁切能核对位置，却无法核对图像模型是否画出了预期的面板布局。

## 3. 设计连续性与剪辑

首尾帧控制的是**一个镜头**；它们不意味着每个镜头都必须继承上一条片段的尾部。

| 转场 | 用上一条尾部作为下一条起点？ | 设计规则 |
|---|---:|---|
| 一个不间断的动作 | 是 | 顺序生成并审查接缝 |
| 硬切到新的角度、地点、产品或时间 | 否 | 每个镜头独立设计 |
| 匹配剪辑 | 通常否 | 匹配运动方向、形状、颜色或构图 |
| 遮挡或甩镜转场 | 否 | 以遮挡动作收尾；下一条镜头从遮挡内部或之后开始 |
| 插入或切离 | 否 | 用物体、环境或产品细节作为桥接 |

把重要的剪辑、匹配与遮挡放进分镜图与提示词。不要依赖交叉溶解去修补互不相干的镜头。

## 4. 撰写视频提示词

### 范围：把每条指令放在它管用的地方

写模块之前，先按"它管辖什么"来归类已知信息。指令放错位置是漂移最常见的根源——写在节拍 1 里的全局规则会在节拍 4 失效。

| 范围 | 管辖 | 内容 |
|---|---|---|
| 全局 | 整片 | 影片类型、场景、风格、一句话前提、镜头原则 |
| 锁定项 | 任何不可漂移的东西 | 身份、参考角色、音频来源、连续性、反向约束 |
| 时间 | 一个节拍或阶段 | 阶段事件及其终态 |

把两三条最"昂贵"的锁定项在提示词的**物理尾部**重申一遍；就近原则有帮助。这是一种放置惯例，而非第四个范围——内容仍属于"锁定项"，并首先在锁定项里出现。

这与 [通用视频提示词技能](../universal-video-prompt-skill/SKILL.md) 中那个与模型无关的规范格式一致。当一个简报必须在多个模型上运行时用那个技能；Seedance 专属的撰写用本文件。这是完整的 Seedance 2.5 技能配置所必需的配套件。如果链接解析失败，请先帮用户安装 `universal-video-prompt-skill` 再继续；不要凭空编造缺失的共享规范。

### 模块

只使用影响该镜头的模块：

```text
[主体/参考绑定]
+ [一个可观察的动作]
+ [空间与重要物体关系]
+ [一个主镜头运动、连贯的复合运动，或一次剪辑]
+ [光/风格，当它在意时]
+ [音频或对白，启用时]
+ [终态，对任何必须落在特定位置的阶段]
+ [必须保留的约束]
```

### 终态承载多事件工作

对于任何多于一个事件的镜头，说明每个阶段结束时**可见地为真的状态**。这是多阶段提示词里杠杆最高的一处补充：它把"保持一致性"变成模型可瞄准、你可检查的东西。

```text
弱：   他们俩继续做那束花
强：   终态：花艺师左手握着那束花；
       剪刀回到工作台右侧
```

终态必须可见。"她感到如释重负"不是终态；"她肩膀下垂、眉头舒展"才是。完整的有序结构见 [长视频](references/long-video.md)。

### 时间粒度：写节拍前先决定

粒度是前置决定。先按秒级写节拍再降级，等于重写。

| 粒度 | 用于 |
|---|---|
| 无——仅事件顺序 | 一个连续动作、情绪片段、单镜头。这里加时间戳会切碎镜头 |
| **阶段 + 终态** | 大多数叙事工作。**默认** |
| 秒级 | 仅在外部硬约束下：音乐、口型同步、参考交接、必须落在固定时刻的节拍 |

当输入已经定下来时推断它——提供了音乐或配音轨意味着秒级，声明了情绪片段意味着无，明确的固定节拍意味着秒级。当请求是一个无外部约束的多事件叙事时，**先问，并带理由地推荐**，而不是甩出一个光秃秃的菜单。

时间戳是分配时间预算；它们不是逐帧精确的剪辑点，动作可能落在边界前后一点点。不要强求不可能的高密度，比如一秒内三个截然不同的动作。

- 显式命名参考角色，例如 `Image 1: person`（人物）、`Image 2: product`（产品）、`Image 3: kitchen setting`（厨房场景）。
- 对于多镜头 R2V，按事件顺序列出 `Shot 1`、`Shot 2`、`Shot 3`。时长在供应商控件里设置，而不是在文本里强求精确秒数。
- 每个镜头优先一个主运动。当复合运动的方向、与主体的关系与速度表达一个同步的意图时，复合运动才成立。
- 启用原生音频时，用 `（）` 表示音乐、`<>` 表示音效、`{}` 表示对白、`【】` 表示屏幕字幕。
- 只陈述重做代价高的约束。

## 5. 生成、审查与收尾

1. 对于生成的分镜图，先只生成静态首图，展示在对话中，在任何视频请求前先审查它。
2. 对于提供的分镜图，除非已可见，否则展示输入，然后核实它适配所选路线。
3. 如果分镜图通过审查，先生成一次代表性视频跑通，不等审批。否则先精修或重生成分镜图。
4. 按 身份 → 锁定项 → 阶段终态 → 构图 → 运动 → 接缝 → 音频 的顺序审查，第一个失败处就停下——身份错了，后面的检查都是白费。只重生成失败的镜头或片段。
5. 串接类按顺序生成，因为下一段需要真实的前一段尾部。基于剪辑的镜头独立生成，再剪辑计划好的转场。

随附脚本是一个草稿装配器，不是调色或混音系统。

## Atlas 执行层

把创作路线选择与任务如何提交解耦。默认模型为静态图用 Seedream 5.0 Pro、视频用 Seedance 2.0；用户只有在核实路线支持后才能覆盖它们。

在智能体对话中，默认用 **Atlas Cloud 技能** 作为直接生成路线。它能发现模型、上传本地媒体、提交图像或视频请求、轮询并取回输出。只有在它确实提交了生成时，才报告 `Execution: atlas-skill`。

只有用户显式选择 MCP 且其生成工具已暴露时，才用 `atlas-mcp`。只有用户显式选择终端、脚本、CI 或批处理运行时，才用 `atlas-cli`。如果 Atlas Cloud 技能缺失，在选择退路前先帮用户安装 `AtlasCloudAI/atlas-cloud-skills`。

在报告缺少 Atlas Cloud API 密钥之前，先检查**所选执行流程**里的凭据。对于 REST runner，先查 `ATLASCLOUD_API_KEY`，再以 `ATLAS_CLOUD_API_KEY` 作为兼容别名。不要从另一个供应商、插件或流程去推断凭据可用性；每个执行通道可以有独立的凭据作用域。

如果两个密钥都不存在，引导用户到 `https://www.atlascloud.ai/console/api-keys?utm_source=github&utm_campaign=awesome-seedance-2.5-prompts-skills`。绝不要让他们把密钥粘进聊天。告诉他们把 `ATLASCLOUD_API_KEY` 设在提交流程或宿主的安全环境变量里，必要时刷新或重启执行会话。如果密钥存在于父级或宿主配置中、却不在提交流程里，应报告"环境作用域不匹配"，而不是说用户没有密钥。

### 计费任务状态机

把这些规则应用到每一次图像与视频生成：

1. 提交后，立即记录预测 ID 与逻辑阶段。
2. 把 `starting`、`queued`、`pending`、`processing` 视为活跃。每 2 秒轮询同一个 ID；绝不要为该阶段再提交另一个任务。
3. 把 `completed` 与 `succeeded` 视为成功终态。在开始依赖阶段之前，先下载并审查输出。
4. 把 `failed`、`timeout`、`canceled` 视为终态失败。新任务需要显式的重试决定；先报告旧 ID 与可能的额外成本。
5. 处理时间字段为零或缺失、输出延迟、本地轮询超时、回合中断，或临时状态查询错误，**不**构成失败证明。保留 ID 并继续轮询。
6. 把 `continue` 理解为"恢复既有任务"，绝不是重试许可。在其所需的分镜图仍处于活跃状态时，不要提交视频。

2 秒间隔适用于本工作流中每一个 Atlas 执行路线。对于 `atlas-skill`，用同一个 ID 重复它的预测结果步骤。对于 `atlas-mcp`，每 2 秒用同一个 ID 调用 `atlas_get_prediction`。MCP 服务每次工具调用只做一次状态查询；循环归智能体所有。随附的 REST 与 CLI 适配器在代码里强制这个间隔。状态查询是只读的，绝不能用另一次生成调用取代。

当 runner 必须恢复时，把 `execution.resumePredictionIds.<stage>` 设为既有 ID。支持的阶段键包括 `grid`、`ref1`、`ref2`、`seg1`、`shot1`、`clip1`。绝不要仅仅因为先前的轮询流程结束就新建一个替代。

`scripts/generate.mjs` 无法调用智能体技能或 MCP 服务。它是一个独立的批处理 runner：默认 `atlas-rest`，只有当 `execution.adapter` 显式设为 `atlas-cli` 时才能用 `atlas-cli`。它从不自动选择 CLI。见 [执行适配器](references/execution-adapters.md)。

```bash
# 仅生成分镜图。runner 会打印带绝对路径的 [storyboard-preview]；
# 在开始视频工作前展示并审查那张图。
GRID_ONLY=1 node scripts/generate.mjs scripts/myjob.json

# 只跑第一段独立镜头或片段作为质量关卡。
CLIPS_MAX=1 node scripts/generate.mjs scripts/myjob.json
SEGS_MAX=1 node scripts/generate.mjs scripts/myjob.json
```

```json
{ "execution": { "adapter": "atlas-cli" } }
```

可用的 runner 模式：

- `grid`：裁切模型分镜图，为每个分格各做一条独立 I2V 镜头；适合硬切蒙太奇。
- `shot-pairs`：从 `segments[]` 做独立 I2V 镜头，带 `first` 与可选的 `last` 关键帧索引。
- `reference`：发送一个按角色细分的小 R2V 参考集。一个参考可由提示词生成，也可从本地文件读取。
- `chain`：把生成的尾帧喂给下一段，以延续一个动作。它是对齐辅助，而非无缝接缝的保证。

针对故障的修复见 [故障排查](references/troubleshooting.md)。
