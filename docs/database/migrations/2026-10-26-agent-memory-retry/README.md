# 记忆抽取重试终态约束

Harness 前三批收尾回归发现：原运行时在抽取三次失败后使用 `abandoned`，原水位查询也识别该状态，但数据库 CHECK 与接口枚举遗漏，导致终态写入失败。本增量补齐既有状态，不新增表、字段或回填业务内容。

已有当前创作模式库执行 [001_retry_status.sql](001_retry_status.sql)，或在 `backend/` 使用 `uv run python scripts/agent_system_migration.py --apply`，后者逐项核对结构并只执行缺失增量。升级前备份并停止 Agent 写入；先核对工具报告的目标库及待执行项。完整 SQL 已包含该状态，新空库不叠加本增量。应用启动不会自动迁移。

凭据、配置和明确鉴权失败直接 `failed`，不会循环排队。明确限流可退避；仅抽取任务的已持久化无效输出可以重新请求，最多三次发送。允许重试的抽取耗尽后为 `abandoned`，可越过该抽取范围；一般失败及受理不明仍阻塞该范围，不自动重发。摘要／任务约束不因抽取策略自动跳过。HTTP 接口与前端 DTO 同步允许 `abandoned`，不开放新的手动重试权限。

真实独立 MySQL 回归覆盖旧 CHECK 检出、单项升级、重复执行无操作、终态提交、接口序列化与抽取水位；当前业务库执行结果见 [前三批验收](../../../reviews/2026-10-26-Harness前三批可靠性与上下文优化验收.md)。表总数保持 118。回退旧 CHECK 前必须确认不存在 `abandoned` 行，不能为回退删除任务记录。
