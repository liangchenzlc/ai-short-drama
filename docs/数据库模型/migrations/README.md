# 旧数据库升级入口

[完整建表脚本](../schema.mysql8.sql) 已包含当前全部 50 张表。新库只运行完整脚本；本目录保留旧库升级所需的增量 SQL、回填工具和操作说明。应用启动不自动执行迁移；账号模式会在结构、归属或关键约束缺失时拒绝启动。

完整 SQL 从当前 Domain 模型生成。在 `backend/` 运行 `uv run python scripts/export_schema.py` 更新文件，运行 `uv run python scripts/export_schema.py --check` 检查是否同步；这两个命令不执行数据库迁移。具体约定见[数据库说明](../MySQL8数据表设计.md#保持完整-sql-同步)。

## 公共执行边界

1. 使用 MySQL 8.0.21+、utf8mb4、UTC 和严格 SQL 模式。确认目标数据库、可恢复备份和现有表定义，记录受影响数据行数。
2. 暂停 API、调度器、Worker 和其他相关写入进程，按该迁移 README 执行预检、结构更新、回填及核验。生产工作流和分镜时长迁移依赖连接内临时基线表，预检到核验必须保留同一个 SQL 连接。
3. MySQL DDL 隐式提交，跨文件迁移不是一个可整体回滚的事务。失败时保留现场，从已执行状态核对重入条件，不删除业务表重新开始。
4. 核验字段、默认值、索引、CHECK 的表达式与启用状态、外键、行数和业务引用。结构以[当前数据库说明](../MySQL8数据表设计.md)及完整 SQL 为准；早期字段注释语言或列的物理排列可能不同，但不应有类型、默认值或约束的语义差异。
5. 部署兼容的新 API/Worker 后恢复写入。已产生新格式数据时优先向前修复；不要自动删除新增字段或恢复旧唯一索引。

文档不记录某个个人业务库“已经完成升级”的状态。发布人员应在部署记录中保存执行时间、脚本版本和验证结果。

## 测试

各阶段的表数是该阶段的历史基线；当前完整建库 SQL 为 **50 张表**。

[2026-09-30 原生视频与角色音色](2026-09-30-native-video-voice/README.md)：三张增量表，阶段基线为 32 张表。既有项目保持历史模式，迁移并部署同版 Worker 后才启用原生视频功能。

[2026-09-28 成片合成与导出](2026-09-28-episode-assembly/README.md)：三张成片表和 `media_files.video_metadata`，可使用 Python 升级程序安全重入；阶段基线为 24 张表。

[2026-09-29 时间轴剪辑](2026-09-29-assembly-timeline/README.md)：同一分镜的多个片段、稳定片段标识、删除保留记录、保存幂等回执及合成预览任务；阶段基线仍为 24 张表。

[2026-09-30 批量生成](2026-09-30-generation-batches/README.md) 和 [2026-09-30 声音制作](2026-09-30-audio-production/README.md)：两张批次表、三张声音表及音频类型约束扩展；阶段基线为 29 张表。升级后再启用对应功能开关。

[2026-10-02 用户与项目协作](../../plans/2026-10-02-project-collaboration.md)：独立 MySQL 测试覆盖权限、撤权和复制，迁移测试覆盖拆分、回滚和重入。历史作者保持未知，所有权必须显式指定；注册不会领取历史数据。

[2026-10-02 Agent 创作模式](2026-10-02-agent-mode/README.md)：独立 MySQL 测试覆盖旧库关闭功能时的启动兼容、显式迁移重入、严格结构核验、私有会话层级和共享候选边界。

迁移测试保留在 `backend/tests/integration`，通过[开发说明](../../development.md)中的 `backend/scripts/run_integration.py` 运行。测试 fixture 创建随机隔离数据库，从当前总 SQL 建库，再在隔离库内模拟旧结构和历史数据，验证迁移、重入和数据保留。迁移 SQL 和 Python 回填是运维交付的一部分，不能因为它们不被运行时 import 就当作无引用代码删除。
