# 数据模型设计

本文件为本轮核对稿，按已明确的修改要求重整为 17 个逻辑模型，不绑定数据库，不编写后端或迁移代码。每个模型列出用途、完整字段及必要约束；需要你决定的调整集中列在文末，未确认为最终设计。

## 字段约定

- PK 为主键，FK 为外键；未注明可空的字段均必填。各表 id 由应用通过公共雪花算法工具类生成，不使用数据库自增；id 不替代业务唯一约束。
- position 为允许空隙的正整数排序值；界面显示的分集号、镜头号按排序计算。
- 时间统一为 UTC。正常新建时 created_at 必填；有修改字段的表，updated_at、updated_by 初始与创建信息相同，实际修改时更新。历史时间确实未知时允许为空，不用当前时间伪造历史记录。
- created_by、updated_by 保留为用户 ID 预留字段，当前不声明外键，不新增用户表；尚未引入用户或历史操作人未知时允许为空，不填虚构用户 ID。后续引入用户模型时统一定义引用及新数据必填规则。三个素材库关联表仅有创建审计；生成结果记录、回收站记录也仅有创建审计。其他可编辑模型保留创建和修改信息。
- 各表只保存本身职责内的数据：项目、分集不保存下游数量或正文副本。逻辑外键及唯一约束的具体实现由后续数据库选型决定。
- 素材库归属、镜头引用均通过关系表组织；移除关系和删除素材是不同操作。被引用实体默认禁止直接删除，不设计隐含的级联删除。
- 第三范式为基线。本轮指定保留的分镜子表 episode_id 是受控冗余；生成记录中的批次信息为少建批次表作有限反范式，规则见对应表及文末。

## 1. 项目 — projects

用途：保存短剧项目的基本信息和新建分集时使用的默认制作设置。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| name | 字符串，非空，最长120字符 | 项目名称，允许重名 |
| synopsis | 字符串，默认空 | 故事梗概 |
| style | 字符串，默认空 | 新分集默认风格 |
| aspect | 字符串，16:9或9:16 | 新分集默认画幅 |
| target_ms | 整数，1000–3600000 | 项目目标时长，单位毫秒 |
| last_opened_at | 时间点，可空 | 最近打开时间 |
| created_at | 时间点，必填 | 创建时间 |
| updated_at | 时间点，必填 | 最近修改时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |
| updated_by | 标识符，可空，预留用户ID，暂不设外键 | 最近修改人 |

约束：分集数量联查计算。打开项目仅更新 last_opened_at。按要求删除 row_version，其他业务字段保留。

## 2. 分集 — episodes

用途：保存分集归属、排序、标题及制作设置；小说和剧本通过各自的 episode_id 联查。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| project_id | 标识符，FK→projects.id | 所属项目 |
| position | 正整数 | 项目内分集排序 |
| title | 字符串，非空 | 分集标题 |
| synopsis | 字符串，默认空 | 分集简介 |
| aspect | 字符串，16:9或9:16 | 本集画幅 |
| style | 字符串，默认空 | 本集风格 |
| created_at | 时间点，必填 | 创建时间 |
| updated_at | 时间点，必填 | 最近修改时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |
| updated_by | 标识符，可空，预留用户ID，暂不设外键 | 最近修改人 |

约束：(project_id, position) 唯一。画幅、风格从项目初始化后独立修改。不保存 novel_text、script_draft、script_revision、source_review、row_version，也不反向保存小说或剧本 ID。

## 3. 小说原文 — episode_novels

用途：保存用户在分集详情中输入、粘贴并保存的小说正文。通过 episode_id 关联分集，作为生成剧本的来源；小说与剧本分别保存，不在分集表重复存储正文。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| episode_id | 标识符，FK→episodes.id，唯一 | 所属分集 |
| content | 长文本，默认空 | 分集详情中用户输入的当前小说正文 |
| created_at | 时间点，必填 | 创建时间 |
| updated_at | 时间点，必填 | 最近修改时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |
| updated_by | 标识符，可空，预留用户ID，暂不设外键 | 最近修改人 |

约束：每集零或一份小说原文，episode_id 唯一。首次保存创建记录，后续保存更新同一记录的 content 和修改审计，保留 id 及创建信息；未输入时可无记录，空正文不能用于生成剧本。生成产出通过 novel_script_records 关联，不在本表保存剧本 ID 列表。修改小说不自动覆盖已经生成的剧本。暂不设计小说版本、候选或确认快照。

## 4. 剧情（剧本） — episode_scripts

用途：合并原剧本候选与最近剧本确认，直接保存剧本正文和是否确认的状态；后文“剧本 ID”均指本表 id。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| episode_id | 标识符，FK→episodes.id | 所属分集 |
| position | 正整数 | 同一分集内剧本排序，沿用原候选排序 |
| content | 长文本，默认空 | 剧本正文 |
| state | 字符串，unconfirmed / confirmed，默认unconfirmed | 未确认 / 已确认 |
| created_at | 时间点，必填 | 创建时间 |
| updated_at | 时间点，必填 | 最近修改时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |
| updated_by | 标识符，可空，预留用户ID，暂不设外键 | 最近修改人 |

约束：(episode_id, position) 唯一，同一分集可有多条剧本，但最多一条 state=confirmed。确认新剧本时，须在同一原子操作中将该分集原已确认剧本改为 unconfirmed，再将目标剧本改为 confirmed；并发确认也必须保证每集最多一份已确认剧本。已确认剧本的 content 实际发生变化时，在同一操作中将其 state 改为 unconfirmed；无内容变化的保存或仅调整 position 不取消确认。实际发生变更的记录更新 updated_at、updated_by，保留创建信息。再次确认同一份且正文未变化的剧本不重复修改记录。本表不再复制正文到分集，不保存确认快照或版本。

## 5. 媒体元数据 — media_files

用途：保存图片、视频文件的位置和实际元数据，由素材、分镜图和分镜视频直接引用。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| format_code | 字符串，非空 | 直接保存规范 MIME，例如 image/png、video/mp4；演示资源可用 demo:image |
| storage_locator | 字符串，非空且唯一 | 稳定存储定位值，不保存临时签名 URL 或 Blob URL |
| original_name | 字符串，默认空 | 原始文件名 |
| byte_size | 非负整数，可空 | 实际文件字节数 |
| width | 正整数，可空 | 实际像素宽度 |
| height | 正整数，可空 | 实际像素高度 |
| duration_ms | 正整数，可空 | 实际视频时长，单位毫秒；图片为空 |
| checksum_sha256 | 字符串，可空 | 文件校验值，不作为文件身份 |
| created_at | 时间点，必填 | 创建时间 |
| updated_at | 时间点，必填 | 最近修改时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |
| updated_by | 标识符，可空，预留用户ID，暂不设外键 | 最近修改人 |

约束：format_code 不再引用字典，不保留 availability。图片/视频类型按 format_code 校验；不再要求项目媒体登记。被素材或分镜引用的媒体不能直接删除；解除引用不自动删除文件。

## 6. 素材 — assets

用途：保存与项目、分集归属解耦的素材本体。全局库、项目库、分集库仅保存对本表的引用。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| kind | 字符串，character / scene / prop | 角色 / 场景 / 道具 |
| name | 字符串，非空 | 素材名称，允许重名 |
| label | 字符串，默认空 | 单个标签或分类文本，不存逗号分隔的多标签 |
| description | 长文本，默认空 | 素材描述 |
| prompt | 长文本，默认空 | 素材生成提示词 |
| model_id | 标识符，可空，FK→ai_model_configs.id | 使用的模型配置；手动建立、导入时可空 |
| media_id | 标识符，可空，FK→media_files.id | 当前素材图片，尚未生成时可空 |
| created_at | 时间点，必填 | 创建时间 |
| updated_at | 时间点，必填 | 最近修改时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |
| updated_by | 标识符，可空，预留用户ID，暂不设外键 | 最近修改人 |

约束：不包含 project_id、episode_id 或库归属字段；对媒体、模型的引用保留。media_id 非空时必须是图片；model_id 非空时配置类型为 image。一个素材当前只关联一份媒体，不再设计素材图片候选、文字确认、独立资源稿、复制来源或独立标签表。

共享与独立编辑规则（已确认）：默认共享同一 asset_id，直接修改素材内容会影响所有引用。某个项目或分集需要独立修改时，先复制为新的 assets 记录，通过公共雪花算法工具类分配新 id，再将当前库关联的 asset_id 替换为新 id；其他位置仍引用原素材。复制业务字段，创建和修改审计均记录本次复制时间与操作人，不沿用原素材作者或创建时间。复制时可继续引用原 model_id、media_id，无需复制模型配置或媒体文件；后续更换图片只修改新素材的 media_id，不覆盖共享媒体文件。当前关联保留 id、position 及创建信息，不增加复制来源表。镜头直接引用 assets.id，因此替换库关联不会自动改写 shot_assets；如需镜头使用新素材，须显式替换对应镜头关联。

## 7. 全部素材（全局库关联） — global_assets

用途：登记素材是否加入全局素材库及其排序；这里把“全部素材”解释为可独立管理的全局库。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| asset_id | 标识符，FK→assets.id，唯一 | 素材本体 |
| position | 正整数，唯一 | 全局库排序 |
| created_at | 时间点，必填 | 创建时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |

约束：同一素材最多登记一次。仅保存指定的创建时间、创建人；调整 position 不另记修改信息。删除记录只移出全局库，不删除素材，也不影响项目、分集引用。全局库不是所有 assets 记录的自动副本；如“全部”表示所有素材的无条件汇总，本表可取消，见文末。

## 8. 分集素材关联 — episode_assets

用途：登记某个分集使用哪些素材及显示顺序。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| episode_id | 标识符，FK→episodes.id | 分集 |
| asset_id | 标识符，FK→assets.id | 素材本体 |
| position | 正整数 | 分集内排序 |
| created_at | 时间点，必填 | 创建时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |

约束：(episode_id, asset_id)、(episode_id, position) 分别唯一。仅保存创建审计；解除关联不删除素材。不要求素材预先加入项目库或全局库。本集独立修改素材时，按 assets 的复制规则替换当前关联的 asset_id，不影响其他分集或项目的关联。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| episode_id | 标识符，FK→episodes.id | 所属分集 |
| position | 正整数 | 分集内镜头顺序 |
| script | 长文本，默认空 | 分镜脚本正文 |
| created_at | 时间点，必填 | 创建时间 |
| updated_at | 时间点，必填 | 最近修改时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |
| updated_by | 标识符，可空，预留用户ID，暂不设外键 | 最近修改人 |

约束：(episode_id, position) 唯一。另声明 (id, episode_id) 唯一，供分镜子表复合外键引用。无需文本确认、图片确认、视频确认或版本字段；图片与视频参数分别进入对应表。

## 11. 分镜素材关联 — shot_assets

用途：记录某个镜头引用哪些素材，直接引用统一素材本体。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| episode_id | 标识符，FK→episodes.id，受控冗余 | 必须等于镜头所属分集 |
| asset_id | 标识符，FK→assets.id | 镜头引用的素材 |
| shot_id | 标识符，FK→shot_scripts.id | 所属镜头 |
| created_at | 时间点，必填 | 创建时间 |
| updated_at | 时间点，必填 | 最近修改时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |
| updated_by | 标识符，可空，预留用户ID，暂不设外键 | 最近修改人 |

约束：(shot_id, asset_id) 唯一；复合外键 (shot_id, episode_id) → shot_scripts(id, episode_id)，避免误关联其他分集。此表不重复保存素材名称、描述或媒体；没有指定素材排序，因此不额外增加 position。

## 12. 分镜图 — shot_images

用途：只保存用户为镜头确认采用的那一份图片及其生成参数；未确认结果不写入本表，废弃结果进入 media_recycle_bin。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| episode_id | 标识符，FK→episodes.id，受控冗余 | 所属分集，与镜头一致 |
| shot_id | 标识符，FK→shot_scripts.id | 所属镜头 |
| layout | 字符串，single / four / five / nine，默认single | 单图 / 四格 / 五格 / 九格 |
| aspect | 字符串 | 具体画幅：16:9、9:16、1:1、4:3或3:4 |
| resolution | 字符串，默认2K | 请求清晰度，如1K、2K、4K |
| prompt | 长文本，默认空 | 本次生图提示词 |
| media_id | 标识符，FK→media_files.id | 用户确认采用的图片，不能为空 |
| state | 字符串，固定为confirmed | 已确认；沿用指定字段，不表示生成任务状态 |
| model_id | 标识符，可空，FK→ai_model_configs.id | 生图配置；手动导入时可空 |
| created_at | 时间点，必填 | 创建时间 |
| updated_at | 时间点，必填 | 最近修改时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |
| updated_by | 标识符，可空，预留用户ID，暂不设外键 | 最近修改人 |

约束：shot_id 唯一，每个镜头最多一条已确认图片；尚未确认时没有记录。复合外键 (shot_id, episode_id) → shot_scripts(id, episode_id)。media_id 只能引用图片，model_id 只能引用 image 配置。画幅保存具体值，不持久化 inherit；resolution 是生成该图片时的请求参数，实际像素读取媒体元数据。确认替换时，将旧图片及其参数写入回收站，再更新当前记录的结果、参数和修改信息，保留当前记录 id 及创建信息；两步须原子完成。再次确认同一份结果不重复回收。当前参数描述已采用结果，不用来保存下一次生成的预设。

## 13. 分镜视频 — shot_videos

用途：只保存用户为镜头确认采用的那一份视频及其生成参数；未确认结果不写入本表，废弃结果进入 media_recycle_bin。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| episode_id | 标识符，FK→episodes.id，受控冗余 | 所属分集，与镜头一致 |
| shot_id | 标识符，FK→shot_scripts.id | 所属镜头 |
| resolution | 字符串，默认1080p | 请求清晰度，如720p、1080p |
| duration | 正整数 | 请求视频时长，统一单位毫秒 |
| prompt | 长文本，默认空 | 本次生视频提示词 |
| media_id | 标识符，FK→media_files.id | 用户确认采用的视频，不能为空 |
| state | 字符串，固定为confirmed | 已确认；沿用指定字段，不表示生成任务状态 |
| model_id | 标识符，可空，FK→ai_model_configs.id | 生视频配置；手动导入时可空 |
| created_at | 时间点，必填 | 创建时间 |
| updated_at | 时间点，必填 | 最近修改时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |
| updated_by | 标识符，可空，预留用户ID，暂不设外键 | 最近修改人 |

约束：shot_id 唯一，每个镜头最多一条已确认视频；尚未确认时没有记录。复合外键 (shot_id, episode_id) → shot_scripts(id, episode_id)。media_id 只能引用视频，model_id 只能引用 video 配置。duration 为生成该视频时的请求时长，实际时长读取 media_files.duration_ms。确认替换时，将旧视频及其参数写入回收站，再更新当前记录的结果、参数和修改信息，保留当前记录 id 及创建信息；两步须原子完成。再次确认同一份结果不重复回收。当前没有保存用于生视频的输入图片关系。

## 14. AI模型配置 — ai_model_configs

用途：保存文本、生图、生视频的配置、密钥及启用状态。每条配置对应一个具体模型，以 model_key 保存供应商模型编码。原 ai_configs 统一更名为本表，删除 ai_models 后相关 model_id 引用本表 id，调用时读取对应的 model_key。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| service_type | 字符串，text / image / video | 文本 / 生图 / 生视频 |
| name | 字符串，非空 | 配置显示名 |
| model_key | 字符串，非空 | 供应商模型编码，保留大小写；每条配置仅保存一个模型编码 |
| provider | 字符串，非空 | 供应商名称 |
| base_url | 字符串，默认空 | 服务基础地址 |
| apikey | 字符串，可空 | API密钥；逻辑字段名按要求保留，持久化应加密，不向页面回传明文 |
| enabled | 布尔，默认true | 是否允许用于新操作 |
| is_deleted | 布尔，默认false | 是否逻辑删除 |
| is_default | 布尔，默认false | 是否本类型默认配置 |
| row_version | 正整数，默认1 | 沿用旧表；是否与其他表一并删除见文末 |
| created_at | 时间点，必填 | 创建时间 |
| updated_at | 时间点，必填 | 最近修改时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |
| updated_by | 标识符，可空，预留用户ID，暂不设外键 | 最近修改人 |

约束：id 为内部引用，name 为显示名，model_key 为供应商调用所需的模型编码，三者职责不同。model_key 不要求全局唯一，同一模型可通过不同服务地址或密钥分别配置；不保存逗号拼接的模型列表。同一供应商的多个模型建立多条配置，各自管理连接地址和密钥。移除 protocol、endpoint、query_endpoint，保留 base_url，连接方式由 provider 对应的程序适配器约定。每种 service_type 最多一条未删除的默认配置，默认配置必须 enabled=true；停用或删除时同时取消默认。逻辑删除不破坏历史 model_id 引用，停用/删除后不可用于新操作。apikey 仅为未来后端逻辑设计，不在当前纯前端保存真实密钥。

## 15. 剧本生成分镜脚本记录 — script_shot_records

用途：记录某份剧本通过一次生成操作产出了哪些分镜。每行对应一个产出的分镜；同一批次的多个镜头使用相同 batch_id。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的记录标识 |
| script_id | 标识符，FK→episode_scripts.id | 作为生成来源的剧本 |
| shot_id | 标识符，FK→shot_scripts.id | 生成得到的分镜 |
| batch_id | 标识符 | 一次生成的批次标识；不是外键 |
| model_id | 标识符，可空，FK→ai_model_configs.id | 本次使用的文本模型配置；演示数据可空 |
| created_at | 时间点，必填 | 创建时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 创建人 |

约束：(batch_id, shot_id) 唯一。script_id 与 shot_id 必须属于同一分集；model_id 非空时配置类型必须为 text。同一 batch_id 中的 script_id 和 model_id 必须一致。仅记录产生了镜头的结果，不增加失败任务、重试、回调等任务模型。生成结果关系不可改写，重新生成建立新分镜及新记录，因此仅记录创建时间与创建人。同批次的创建信息一致。被生成记录引用的剧本或分镜禁止直接删除；本表不保存正文快照，原文后续编辑会影响历史联查，见文末。

## 16. 分镜媒体回收站 — media_recycle_bin

用途：保存用户明确废弃的分镜图片、视频，以及确认新结果后被替换的旧结果。保留文件引用和生成参数，支持恢复；仅包含仍在回收站中的记录，不承担生成任务或完整操作日志功能。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 本次进入回收站的记录标识 |
| shot_id | 标识符，FK→shot_scripts.id | 来源镜头；分集、项目通过镜头联查 |
| media_id | 标识符，FK→media_files.id | 被废弃的图片或视频；进入回收站不删除文件 |
| model_id | 标识符，可空，FK→ai_model_configs.id | 生成该结果时使用的模型配置；手动导入或未知时可空 |
| prompt | 长文本，默认空 | 生成该结果时的提示词 |
| resolution | 字符串，非空 | 生成该结果时的请求清晰度 |
| layout | 字符串，可空 | 图片布局：single / four / five / nine；视频为空 |
| aspect | 字符串，可空 | 图片请求画幅：16:9、9:16、1:1、4:3或3:4；视频为空 |
| duration | 正整数，可空 | 视频请求时长，单位毫秒；图片为空 |
| reason | 字符串，discarded / replaced | 用户废弃 / 被新确认结果替换 |
| created_at | 时间点，必填 | 本次进入回收站的时间，不是媒体生成时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 执行废弃或确认替换的用户 |

约束：(shot_id, media_id) 唯一，同一镜头的同一媒体最多一条回收记录。媒体类型通过 media_files.format_code 判断，不重复存储类型、文件路径、分集 ID 或项目 ID。图片的 layout、aspect 必填，duration 为空；视频的 duration 必填，layout、aspect 为空；非空 model_id 的 service_type 必须与媒体类型一致。来源镜头必须存在，被回收记录引用时不能直接删除。回收记录的来源、参数和创建信息写入后不修改，因此仅保留创建审计；同一结果恢复后再次废弃，创建新的回收记录。

流转规则：

- **待确认：** 生成成功不等于用户确认。待确认结果由制作过程暂存，不写入 shot_images、shot_videos，也不自动视为垃圾；本轮不新增生成任务或候选表。用户明确废弃后，才登记到回收站。生成失败且没有文件的任务不进入回收站。
- **确认：** 新结果进入对应正式表；同一镜头中，该 media_id 不能同时作为正式结果和回收结果。已有确认结果被替换时，连同其参数先进入回收站，reason 为 replaced。其他未选结果在用户明确放弃时以 discarded 入站。确认、替换和回收记录变更必须原子完成，重试不能产生重复结果。
- **恢复：** 用户选择恢复并采用后，将回收结果及参数写入对应正式表；若已有不同的确认结果，先将其回收，再采用恢复结果，最后移除被恢复的回收记录。整个过程原子完成，仍保证每镜最多一份确认图片、一份确认视频。恢复完成后没有持久化的 restored 状态。
- **彻底删除：** 用户明确清理后移除指定回收记录。只有 media_id 不再被任何素材、正式分镜结果或其他回收记录引用时，才允许清理媒体元数据和实际文件。共享文件仍有引用时，只移除当前回收记录。文件清理与逻辑记录变更需协调并可重试，不将文件删除视为数据库事务的一部分；不默认定期清空。

## 17. 小说生成剧本记录 — novel_script_records

用途：记录分集小说通过哪次生成操作产出了哪些剧本，并保存使用的文本模型配置。每行对应一份产出的剧本；同次生成的多份剧本共享 batch_id，与剧本生成分镜记录采用相同组织方式。

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | 标识符，PK | 稳定且不可变的生成记录标识 |
| novel_id | 标识符，FK→episode_novels.id | 作为生成来源的分集小说 |
| script_id | 标识符，唯一，FK→episode_scripts.id | 本次生成得到的剧本；一份剧本最多一条生成来源记录 |
| batch_id | 标识符 | 一次小说生成剧本操作的批次标识；不是外键 |
| model_id | 标识符，可空，FK→ai_model_configs.id | 本次使用的文本模型配置；演示或来源未知时可空 |
| created_at | 时间点，必填 | 生成结果入库时间 |
| created_by | 标识符，可空，预留用户ID，暂不设外键 | 发起本次生成的用户 |

约束：novel_id 与 script_id 必须属于同一分集；非空 model_id 的 service_type 必须为 text，新生成操作只能使用已启用且未删除的配置。同一 batch_id 的 novel_id、model_id、created_at、created_by 必须一致；一次生成多份剧本时，将全部剧本及其来源记录原子写入。生成的剧本初始 state 为 unconfirmed，不自动替换已确认剧本。重新生成创建新的剧本和来源记录，不覆盖旧剧本；来源关系写入后不修改，因此仅有创建审计。手工编写的剧本不要求生成来源记录；仅失败而未产出剧本的操作不写入本表。被本表引用的小说、剧本不能直接删除。本表只记录来源关联，不复制小说或剧本正文；后续编辑正文后，联查得到的是当前内容，不能据此还原生成时的输入。

## 范式与受控冗余说明

- 小说、剧本从分集中拆出，素材本体从三个库中拆出，避免同一业务事实在多张表重复编辑。label 按一个原子值定义；如果需要多标签，应再讨论标签关系，不能改成逗号拼接。
- shot_assets 中 shot_id → episode_id 是非主键依赖，属于第三范式例外。shot_images、shot_videos 现在以 shot_id 为候选键，各自最多一条记录，因此这两张表中的同一依赖不再构成本表第三范式违规，但 episode_id 仍是跨表冗余。保留它以支持分集查询和复合外键归属校验，必须从所属镜头取得，不能单独编辑；查询收益仍需实际索引和数据量验证。
- media_recycle_bin 只保存 shot_id，不再冗余其分集、项目归属；生成参数描述该次废弃结果，不依赖当前正式分镜结果。图片与视频专属字段使用条件约束及空值区分，不用 JSON、逗号字符串或多态 source_id 存储恢复所需数据。
- script_shot_records 的 batch_id → script_id、model_id、created_at、created_by，以及 novel_script_records 的 batch_id → novel_id、model_id、created_at、created_by，都带来批次级重复，不严格满足第三范式。这里按每个生成环节使用一张记录表，避免增加批次主表，代价是同批字段必须在同一写入操作中保持一致，生成后不可修改。如果将来需要批次状态、失败重试或批次独立编辑，再拆分批次主表与结果明细，不提前添加任务体系。

## 待你确认的设计取舍

以下建议尚未作为已确认字段或约束落入上面的表结构。

1. **全部素材的含义。** “全部素材”目前理解为独立收录的全局库；若只是所有素材汇总页，可直接查 assets，本轮按要求保留 global_assets。素材默认共享、独立修改前复制的规则已确认并写入 assets，本项仅待确认“全部素材”的范围。
2. **视频输入图片的追溯。** 每镜只保留用户确认的图片、视频，废弃结果进入回收站，这部分已确认。如果还需追溯视频实际使用的输入图片，建议在视频表和回收站补 input_media_id → media_files.id，而不是引用会被替换的 shot_images 记录；该字段尚未加入。
3. **生成记录追溯边界。** 两张生成记录表均有 batch_id 和 model_id，分别关联“哪份小说生成哪些剧本”和“哪份剧本生成哪些分镜”。当前记录来源关系和使用的模型，不保证还原当时的小说正文、剧本正文、分镜内容或调用参数。如果需要历史复现，建议另存当时输入内容；未获确认不加快照、版本或任务表。批次字段重复的取舍见上节。
4. **AI 配置并发字段。** AI 配置中的 row_version 尚未明确删除；如果暂时不考虑并发控制，建议删除该字段。三个素材库关系表按你指定只留创建审计，因此重排顺序不会记录修改人和修改时间。
