## 当前能力

助手工具现按逐工具 SPEC 维护一份参数与说明。业务身份与浏览器会话分开，工作台写入按账号、工具和请求身份保存业务回执；同账号跨令牌重投复用原结果，变参明确冲突。新媒体提交直接受理原生异步任务并返回身份，后续显式查询结果；剧本建议继续通过原差异预览和明确采用入口保存。

账号可在 AI 配置的“创作助手”标签创建、列出及删除具名 MCP 令牌，作品和业务工具选项来自服务端，可选到期时间与 IP／CIDR 白名单。完整密钥只在本次创建弹层展示，关闭即清，不进入列表或本机恢复记录；列表根据到期时间显示状态，实际有效性由服务端认证判断，删除失败不会误报成功。`/mcp` 提供 12 项工作台业务工具，每次协议访问校验 Bearer，撤销即时生效；已受理的生成继续由原生 Worker 完成。接入契约见 [MCP API](docs/api/mcp.md)。

助手保存作品时仍可补充创作要求；目标、记忆、主体选入和历史剧本引用保留为任务输入，在当前操作结算后应用。素材及媒体附件继续校验来源权限，被拒绝的引用不影响并发的作品保存。

已受理媒体沿原生任务生命周期执行。助手媒体生成开关会在新的付费提交前复核，关闭后阻止尚未外发的请求；已外发任务仍可查询并保存结果。

助手业务写入后的工具结果提供 `receipt_operation_id`，直接指向本次助手操作，可在原授权范围内核对回执与成果，等待或 Worker 重建后仍使用原身份。`business_invocation_id` 保留业务幂等身份，成功子任务交付中的 `business_receipts[].operation_id` 保留子业务原操作身份。回读工具的自身回执与其返回的原保存 `operation_id` 分别表示读取和保存操作。

助手读取与修改以选入时的主体、媒体及版本快照为界；同一执行范围的成果可继续使用，成功子任务通过真实业务收据将成果交付父助手，父可读回、修改、查询／等待生成及再次明确交接。子任务读取父成果还须明确交接，平级范围的收据和生成媒体不会自动共享；摘要自报身份不授予权限。子剧本提案同样遵守明确交接的冻结身份、版本和选区。图片内容读取同时支持素材／分镜图位和实际画布节点，用户后来替换的媒体或修改后的新版本需要重新选入。

| Agent 创作 | LangGraph 工作流、LangChain 自主工具、按需媒体理解、渐进 Skill 与 L1–L5 记忆 | 当前唯一引擎为 assistant-runtime.1，支持停止、普通消息续跑及补充排队；旧图需通过006终结并保留历史；需要显式迁移和独立 Worker，真实模型兼容性分别验收 |
| 后台异步生成 | 文本/图片/视频/音频任务、取消、按条件恢复或重试 | 独立任务管理已退役，生成反馈保留在创作场景内；模型参数取决于适配能力 |
| 主页资产库 | 本人 AI 图片/视频/音频、工作台与媒体分类、名称搜索、六列分页与直接预览 | 不收录手动上传；只提供预览，不提供编辑、采用或任务跳转 |
| 成片 | 连续画面轨与原声、对白、字幕、配乐、音效辅助轨，分割裁剪、撤销重做、合成预览和 MP4 导出 | 不含多视频叠层、转场或变速；语音识别和模型效果需按配置单独验收 |

剧本页标题为“剧本”，提供“故事设定 / 剧本正文”双标签，960px 居中编辑区与两侧统一为近黑背景（#181818），故事设定输入框采用稍浅的灰色（#202020），聚焦保持同色且无边框。故事设定包含一句话卖点、故事梗概、故事类型、人物小传，使用独立版本串行自动保存，冲突保留本机输入；旧小说和大纲不自动导入。正文自然滚动，无固定字数／撤销栏及导入／导出入口，保留 Ctrl/Cmd+Z 撤销与选区 AI 改写。改写任务期间正文只读，进度和停止放在标题行；空稿可直接编辑，AI 创作助手从顶部进入；剧本页已移除“让助手起草剧本”和“最近变更”按钮。资产库和分镜表支持列表／宫格切换，列表行及侧栏底部“＋ 创建”均高45px，已有提取历史继续可查。接口见[剧本工作台](docs/api/writing-workspace.md)，实施与验证见[布局调整验收](docs/reviews/2026-10-28-创作工作台布局与故事设定验收.md)。

错误与警告的恢复操作保留在保存状态或弹窗标题的提示详情内；短提示关闭后仍可重试，弹窗内的详情操作不受外壳裁剪。旧分集、跨库素材共享与触屏尺寸验证的清理见[旧用例核查](docs/reviews/2026-10-28-旧用例核查与后端重启验收.md)。

创作模式直接提供四步：**剧本创作 → 资产生成 → 分镜制作 → 成片预览**。左侧固定40px满高图标导航，悬停显示阶段名称；顶部保留名称、保存状态、助手和返回；画幅只在成片导出设置中选择，默认跟随实际分镜视频。AI 创作助手以当前项目为会话主体，成果保存到该项目，创作模式与画布模式分别使用各自目标；已受理任务保持原目标。桌面创作助手支持拖动调宽，模型旁通过添加菜单和 Skill 列表选择附件与方法。助手运行中可补充输入，下一模型边界只应用一次；停止或暂停后普通消息沿原 Task 创建新 Run，单 Run 的模型调用与输出预算固定，Task 不设累计执行上限；`/` 选择的 Skill 在输入框内显示高亮块，用户消息下不再显示操作按钮，等待回复使用动态省略号，输入区不再展示当前任务栏；独立会话从顶部“新对话”创建；任务、上下文及记忆管理入口已移除，记忆由后台自动维护。接口、页面和模型供应商支持范围分别说明，不将存在后台接口等同于页面已完成。

助手的待发送素材在有限高度内滚动，短桌面窗口保留完整的移除与发送入口。未结束任务显示其实际运行模型，任务结束后可切换；`@` 按关键词过滤当前对象和画布节点。成功执行过程自动折叠，失败原因默认展开且分别保留；成果等待、成功与失败使用对应状态图标。

助手通过冻结工具目录和当前范围的 Skill 执行任务，由框架控制完整循环。工具调用没有正文或仅附带空白时继续执行工具，不创建空过程消息；非空过程说明保留原文。逐工具结果、真实写入与费用独立持久化，最终答复不经过强制 reviewer；记忆来源遗忘会撤回旧正文、摘要及后续推导。图片只在读取后的下一次模型请求中水合，checkpoint 保留引用。运行规则与旧流程历史见 [框架运行机制](docs/instruction/AI创作助手Harness运行机制.md)。

活动方法以含正文的原始 canonical 加载完整组保留；独立的重载或 already_loaded 元数据组可进入框架摘要，与正文同组的兄弟回执继续整体保留。历史加载回执保持原样，当前激活身份和合格问答仍沿现有来源投影读取。

自动摘要按当轮系统提示、实际工具定义、完整活动方法与保留来源计算可用输入容量；超大的纯文本完整工具组可整体进入框架摘要，摘要模型按自身容量连续分批处理全部选中历史，当前待交付媒体仍保留真实组。静态内容、摘要包络或压缩结果仍无法容纳时明确结束，并在持久 Run.error 与 run.finished 保存白名单内的预算阶段及非负数量估算；公共 RunRead.error 仍只返回原错误码。发送前拒绝不计作已调用，已经发送的摘要用量照常保留。工具选择返回不存在的名称时最多重试两次，仍失败便保存明确错误，所有实际调用照常计量。离线切换迁移仍需结算或撤销的旧工具身份，并保留原名审计；已外发媒体继续归档，尚未外发的旧请求取消，迟到结果不会恢复旧 Run。

任一摘要片段返回空文本或纯空白时，运行以 `agent_summary_empty` 明确失败，原历史保留，不发布压缩结果；已实际发生的模型用量照常结算，不自动重试。

后台记忆维护在凭据或明确鉴权错误时直接结束；限流及已回执的无效抽取输出按三次发送退避，耗尽后跳过该抽取范围，受理不明不重发。已有库先升级[记忆作业状态约束](docs/database/migrations/2026-10-26-agent-memory-retry/README.md)。后台作业重试次数不限制创作任务长度。

项目名称仅在 Enter 或失焦时提交，Escape 丢弃尚未提交的输入，版本冲突保留本机名称供核对。成片刷新媒体地址时释放旧音频缓存并保留预览位置；配乐压低区间合并显式区间与未静音的对白。声音、成片上传后的数据库操作失败时，先独立核查文件是否已被引用再补偿清理。Agent 优先收集已结束的生成任务，前面的运行中任务不会阻塞后续结果。

## 技术栈

- 前端：React 19、TypeScript、Vite、Ant Design、Axios、React Router。

**新库使用完整建表文件：[schema.mysql8.sql](docs/database/schema/schema.mysql8.sql)。** 当前包含 121 张表及延后建立的外键。旧分集/协作版本只按[创作模式离线切换说明](docs/instruction/创作模式维护说明.md)备份、预演并重建；本次不迁移旧作品。现有单层项目升级须执行[剧本工作台加法迁移](docs/database/migrations/2026-10-27-writing-workspace/README.md)。还须执行[剧本变更恢复增量](docs/database/migrations/2026-10-27-script-revisions/README.md)。本次新增[独立故事设定表](docs/database/migrations/2026-10-28-story-settings/README.md)，已在当前配置库执行，不回填旧业务数据。不要叠加历史协作增量脚本，应用不会自动迁移。
